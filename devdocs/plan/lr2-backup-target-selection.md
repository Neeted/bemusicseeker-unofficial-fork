# LR2 バックアップ対象の事前除外を廃止する

## 目的と承認

ユーザーは、設定で選択した欠落対象を呼び出し側で除外せず、保存処理で失敗として旧世代を保持する修正を承認した。検証と独立した静的レビュー後のコミットまで承認済み。push・リリース・バージョン変更は対象外。資料・コメントは日本語で記載する。

基点は `ffee7f2ed53402d6e3f3937a686f62838b282b1d`。開始時の作業ツリーはクリーン。

## 本番での到達経路と影響

`MainWindow.ContentRendered` → `ShellActivationWorkflowOwner` の初期化 → `MainWindowViewModel.InitializeAsync` / `Startup` → LR2 バックアップ分岐が本番入口。

現状の `MainWindowViewModel.cs:4366,4370,4376` は存在するパスだけを `bkPaths` に追加する。起動検証では config/song が必要だが Score ディレクトリは必須ではなく、欠落したスコア DB の解決結果 null は library/playlist の入口を通る。したがって、Config と ScoreDB を選択、config/song は正常、Score だけ欠落、保存時期到来、保持数 1、旧世代ありの条件で、config だけの新世代を保存して旧世代を消し得る。全選択対象が除外された場合は保存呼び出し自体が省略され、失敗も通知されない。

## 確定した設計と対象範囲

- `Backup` に本番用の小さな internal 入口 `SaveSelectedBackupsWithResult` を設ける。保存先・間隔・保持数・`Target`・config パス・song DB パス・Score ディレクトリパスを受け取り、設定フラグだけで対象を選んで既存の `SaveBackupsWithResult` へ渡す。
- 起動側はこの入口へ設定フラグと設定パスを直接渡す。保存対象の存在確認による除外と、除外後の件数で保存を省略する旧経路を廃止する。対象リストだけを公開する中間 API や、別の汎用サービスは追加しない。
- Config と ScoreDB を選択して Score が欠落する場合、ScoreDB だけ選択して欠落する場合とも、保存失敗・旧世代不変・新世代なしとする。未選択の対象が欠落していても保存は妨げない。
- `Target.None` は保存しない。バックアップ無効・単独動作モードの起動側ガード、既存の保存間隔、staging、保存後の世代削除、互換 API を維持する。
- DB 最適化用の `songDBPath` / `scoreDBPaths` の選択・事前列挙と保存対象を混同しない。最適化側の既存の存在確認・列挙失敗処理は今回変更しない。`Saved` が false なら最適化へ進まない条件を維持する。
- 空白パスの既存扱い、対象欠落と同日スキップの優先順位、DB の同時点スナップショット、旧版の不完全世代移行、復旧・再試行は変更しない。新しい永続状態、テスト専用 public API、タイミングフックは追加しない。

## 担当と検証

一つの `implementation-worker` が次を担当する。

- `BeMusicSeeker/ViewModels/MainWindowViewModel.cs`: 本番呼び出しの接続と事前除外の廃止。
- `BeMusicSeeker/Models/LR2/Backup.cs`: 設定選択から保存までの入口。既存保存処理の動作は維持。
- `BeMusicSeeker.Tests/BackupTests.cs`: 本番と同じ入口を通す回帰検証。既存テストを維持して拡張する。
- `devdocs/spec/lr2-backup.md`: 設定からの対象選択と検証対応の更新。
- `devdocs/spec/startup-initialization-flow.md`: 新入口への参照更新が必要な場合のみ。

この計画はルートが所有する。他の変更は破棄・整形しない。実装担当はコミットしない。

計画点検は完了し、追加のユーザー質問はない。実装前に独立したテスト契約設計担当が `B5-LR2-SELECTION-1` を凍結する。テストは GUID 所有の実ファイル群で設定選択から保存結果・旧世代保護までを検証し、選択結果の配列だけの検証に留めない。新しい本番入口が基点に存在しない場合は、その制約を明記し、元の存在フィルターを戻す一時的な誤実装で検出能力を確認して必ず戻す。

標準検証は `pwsh -NoProfile -File .\scripts\verify-refactor.ps1 -Mode Quick -TestFilter 'FullyQualifiedName~BeMusicSeeker.Tests.BackupTests'`、最終 Functional 一回、実装担当終了後の独立した静的レビュー。レビュアーは設定フラグ・元パスが事前除外なく新入口へ届くこと、失敗時に旧世代削除・最適化へ進まないことを確認する。レビュー中はルートのリポジトリ操作を停止する。

テストのために全起動処理や新しい共有状態を持ち込む必要がある場合、保存対象と最適化対象を一体化する必要がある場合、失敗契約・スレッド構成を変える必要がある場合は実装を止めて再計画する。

## 承認済みテスト契約 B5-LR2-SELECTION-1

変更種別は不具合修正。2026-09-06 にルートが独立した設計担当の S1〜S6 を承認した。根拠はユーザー承認事項であり、A1 は選択・欠落の扱い、A2 は正常保存と世代数、A3 は None、A4 は失敗時の最適化禁止を指す。根拠・到達経路の不足はない。

設計担当はユーザー承認と運用規則だけから期待結果を凍結し、実装本体・既存アサーション・仕様書本文・翻訳・現在の出力を期待値の根拠にしていない。その後の配置調査でも期待結果は変更していない。

共通経路 R は、本番起動 → 設定フラグと元パスを渡す新入口 `SaveSelectedBackupsWithResult` → `SaveBackupsWithResult` → 実ファイル保存結果。テストの入口条件は LR2 連携・バックアップ有効、保存先存在、非空白パス、保存時期到来とする。Score 欠落は起動検証を通ることを確認済みで、競合タイミングや同時点スナップショットは要求しない。

許容する変更は、内部配置、列挙順、一時名、合成データ、テスト分割、例外の具体型・文言、通知文言。失敗と no-op の区別、旧 Score の内容保護、未選択対象の除外、保持数、最適化禁止は変更しない。空白パス・同日欠落優先・最適化用列挙の失敗・復旧保証は対象外。

### 配置と実行の安全性

- S1〜S5 は既存 `BackupTests` を拡張する。`WithBackupTree`、`CreateOldGenerations`、読み書きヘルパー、既存の `InternalsVisibleTo` を利用できる。
- S1/S2 では、旧世代の Score 配下にも合成ファイルを配置し、その内容保持を直接確認する。汎用の確認用ファイルだけで代用しない。
- GUID で分離した実ファイル群と同期的な戻りを使う。共有設定、WPF、外部プロセス、DNP、固定待機、新しい監視機構は不要。
- 既存の保存 API に対する欠落・空入力・保持数・staging・削除警告・長パス・互換 API・同日スキップのテストは維持する。設定スナップショットのテストを保存動作の代替にしない。
- S6 と、無効・単独動作モードのガード、最適化用列挙との分離は静的レビューで確認する。全起動処理の動作実行まで保証したとは報告しない。

### 誤実装の検出証拠

基点に新入口が存在しないため、新テストのコンパイル失敗は変更前の不具合検出と数えない。新しい本番入口へ旧 Exists 除外を一時的に戻し、同じ S1/S2 テストで一部保存・旧世代消失、および例外なしの no-op を検出することを必須とする。誤実装を取り除き、同じ filter で成功を確認する。

S3 では選択を無視した全対象追加、またはフラグとパスの交換を区別できる対象集合・内容の検証を行う。テスト側で対象配列を組んで既存保存 API へ渡すだけでは不十分とする。

実装担当は契約 ID、誤実装の検出と復元後の成功証拠、廃止した事前除外・件数スキップ経路、静的補完と限界、変更ファイル、検証結果を引き継ぐ。
