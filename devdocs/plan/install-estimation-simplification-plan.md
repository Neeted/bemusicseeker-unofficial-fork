# 導入先推定と保留操作の受付・処理順の統合

## 目的と確定した契約

取り込み、保留登録、導入先推定、結果反映の間で受付を取り直す構成をなくし、一つの受理済み操作として終端まで追跡します。利用者と合意した変更は次のとおりです。

- 起動時の保留復元は復元だけを行い、自動推定しません。復元した保留の推定は明示的な手動操作で行います。新規取り込みに伴う自動推定は維持します。
- 実行中の追加ZIP予約と保留への途中追加を廃止し、新しい競合要求は副作用を始める前にBusyで拒否します。一度の操作で指定する複数ファイル・フォルダは維持します。拒否した要求は予約・自動再実行しません。
- 推定中のライブラリ・保留変更、新しい試聴の開始、設定の保存・適用はBusyとします。一覧の閲覧・検索・並べ替え・選択、設定画面の閲覧・編集・取消は維持します。
- 内部並列度、候補評価・自動設定の判定、所持・未所持の扱い、再グループ化、入力の互換性を維持します。新しい推定先自動導入機能は追加しません。
- 取消・最初の評価例外を観測した後は新規の評価開始と結果反映を止め、開始済みの評価Taskと後片付けの終端まで受付を保持します。観測後に正常終了した兄弟評価も適用しません。確定済みの登録・導入や適用済みの推定結果は全体巻戻しせず、未適用対象を保留に残し、実際の成功・失敗・未処理を報告します。

本番では取り込み確定後に受付を解放し、診断の後処理から別の推定キューを起動しています。背景推定は保留受付を取り直します。手動操作や背景の入力更新がその間へ入る構成を変更し、競合後の再評価を保証対象から外します。内部APIへの任意の状態差替えを要件にしません。

## 責務と実装方針

既存の共通受付を唯一の論理的な変更受付へ統合し、アプリケーション構成から同じ受付を機能別管理主体へ接続します。モデルの物理変更権限、LR2との排他、DBトランザクション、索引の短いロックは別の役割として残します。ルートのViewModelへ機能判断・可変状態を戻しません。

取り込みは「受付 → 入力確保・再生停止 → 取り込み・保留登録の確定と必須反映 → 推定入力の確定 → 推定 → 結果反映・再グループ化 → 後片付け → 受付解放 → 操作結果通知」とします。短命なドロップ入力はドロップの受付中に確保します。新規取り込みの推定は同じ操作の継続として直接呼び、完了を待ちます。モデルの物理変更リース解放後も、外側の論理受付を保持します。URL通信は既存の独立した受付を維持し、取得済み入力を渡すときに導入可否を判定します。

手動推定は受付後に現在対象を一度解決し、必要な入力を捕捉して同じ評価・反映経路を実行します。処理中の再解決・世代再照合・再評価は削除します。準備済みの入力元リソース情報と分割を同一操作内で再利用し、余分な走査・全件複製を増やしません。

起動・再読込みの譜面情報読込み、ハッシュ・譜面情報補完、所持保守など、推定入力を実際に更新する背景経路も同じ論理受付または明示的な実処理の順序へ接続します。受理済みの必須更新をBusyで捨てません。既に受理した背景処理が先行操作の実終端を非同期に待つことは許可し、新しい利用者要求の予約とは区別します。任意の通信・表示キャッシュ・リソース健全性の読取り表示は全体の待機条件へ増やしません。受付制御が成立してから、推定用の最新性照合を削除します。

## 作業範囲と単位

1. 起動復元の自動推定、追加予約の例外、必要のなくなる受付・進捗状態を退役させます。
2. 共通受付の所有と全本番入口を統合します。保留目録操作、設定保存、試聴、背景入力更新も含め、受理から終端までの責任を接続します。
3. 新規取り込みの自動推定を直接待機へ移し、独立推定キュー、保留専用受付、推定専用セマフォ、推定専用世代照合・準備結果の版照合・再捕捉・再評価を削除します。
4. 仕様、実装とテストの対応、日英マニュアル、表示リソース、関連する未完了計画を新契約へ揃えます。

一つの受付保証を成立させる変更は分割コミットのために途中状態へ分けません。独立して動作する単位で検証・レビューを行い、ルートが日本語のプレフィックス付き件名・箇条書き本文でコミットします。ユーザーからローカルコミットの許可を受けています。送信・リリース・バージョン更新は対象外です。

## 対象外と維持する境界

LR2起動・再読込みの全面的な順序統合は[別の計画](lr2-startup-procedural-orchestration-plan.md)に残します。物理ファイルの存在・衝突確認、部分成功・確定後失敗・後片付け失敗、外部ファイル変更への既存の防御は維持します。独立キャッシュ・所持集合の版、通知順序、終了・再接続の識別、リソース健全性の入力保護を、推定の世代監視と一緒に全廃しません。

## 検証と完了条件

恒久テストの追加・意味変更・置換は、独立した判定基準と検証境界を実装前に確定します。既存の候補・警告・再グループ化・並列度・取消・結果通知の保証は移管し、世代変化の再評価・追加予約・起動自動推定の保証は廃止します。

反復中は関連する`Quick`、最終統合はWindowsの`Functional`を実行します。受付、背景入力更新、取消・寿命の実現方式とテストの保証を変更するため重大変更として扱い、凍結後に予備レビューと独立した`critical-static-review`を行います。文書は構文・相対参照・UTF-8・LF・`git diff --check`を確認します。

全本番入口で副作用前のBusy、取り込みから推定までの連続した受付、開始済みTaskの終結、拒否した要求の非実行、閲覧・設定編集の維持、既存の推定結果と性能を確認できることが完了条件です。[安全性改善計画](safety-improvements-plan.md)の解消済み自動推定課題と追加ZIP例外、LR2順序統合計画の復元自動推定・追加ZIP維持を整理します。完了時に必要な契約・検証対応を仕様へ移し、本計画と参照を削除します。

## 承認済みの独立テスト設計

ユーザー要件と維持する機能仕様から先に判定基準を定め、独立したテスト設計担当が実装・既存期待値を読む前にルートへ提示しました。ルートは以下の検証境界と保証の分担を承認しています。クラス・API・内部同期道具・独立対象の完了順・診断書式・進捗の中間値は担当の裁量とし、利用者結果・副作用前Busy・候補順位/確信度/警告・並列度・入力再利用・全Task/後片付け待機・確定と失敗分類は変えません。

専用推定キューの逐次配送・残数、追加batch予約、起動自動推定、任意内部APIで所持集合を差し替える推定再評価、物理実行中に公開推定を再入させる保証は廃止します。旧テストのSEARCHING解除・並列度・入力寿命・所有一時領域だけの回収・全cleanup待機・結果通知・終了の保証は上表へ移管します。`InstallPendingPackagesToEstimatedDestinations_ReevaluatesResourceOnlyAfterEarlierPhysicalSuccess`は同じ導入セッションの先行成功を使う判定であり、推定世代再評価と区別して維持します。ResourceHealth・Catalog・表示・再接続の独立した版は名前だけで削除しません。

実DBは所有一時rootと専用DB、明示options、固定scannerを使い、利用者DB・実Everything・音声deviceに依存しません。同期は既存observerと`RunContinuationsAsynchronously`のTCSを使い、barrierはfinallyで解放し全処理をjoinしてから資源を回収します。通常完了用のSleepや短い局所期限を足しません。WPFは既存Dispatcher/Window scopeを使い、共有設定・辞書・終了接続を触るクラスの分離規則を維持します。複数owner接続だけを理由にFullやProcessIntegrationへ移しません。
