# LR2 バックアップの保存確定（B-5）

完了日: 2026-09-05。現行の動作契約は [lr2-backup.md](../spec/lr2-backup.md) を正本とする。以下の判断と承認済みテスト契約は、この変更の受入条件を凍結した履歴であり、別途保守する機能仕様ではない。

## 目的と根拠

ユーザーは、保存先と同じファイルシステム上の一意な staging ディレクトリへコピーし、上書きしないディレクトリ名変更で保存を確定した後に旧世代を削除する方針を承認した。旧版が残した不完全な日付ディレクトリの移行・検出は、ユーザーの明示指示により対象外とした。コミット、リリース、バージョン変更は承認されていない。

基点: `597176e63d009f1242a584154dde23c63a111962`（作業開始時の作業ツリーに差分なし）。

## 決定事項

- 日付ディレクトリの構成、保存間隔、同日に保存済みの場合のスキップを維持する。
- コピーまたは保存確定の失敗では既存世代を変更せず、`Saved=false` と主例外を返す。
- 保存確定前の失敗時は、今回の呼び出しで作成した staging ディレクトリだけを、一度だけ削除する。削除失敗時は主例外を置き換えず、パスを含む警告を追加する。
- 残留 staging ディレクトリは世代に数えず、自動復旧や一括削除を行わない。
- 保存確定後は新バックアップを保持する。旧世代の削除に失敗しても `Saved=true` を返し、削除失敗は警告で知らせる。
- 保持数には新世代を含める。削除失敗時は、警告付きで設定数より多くの世代が残ることを許容する。
- 完了は選択した全対象のコピー完了を意味する。チェックサム、DB スナップショットの仕組み、永続マニフェスト、再試行、ロールバックの仕組みは追加しない。
- 呼び出し側が選択した空でないパスが、バックアップ処理の入口で一つでも欠落していれば、保存全体を失敗として既存世代を保持することをユーザーに確認済み。対象の列挙が null または空の場合は、引き続き何もしない。

## 本番の呼び出し経路と担当範囲

LR2 連携が有効な起動処理は `config.xml`、`song.db`、Score ディレクトリを選択し、`Backup.SaveBackupsWithResult` を呼ぶ `Task.Run` の完了を待つ。戻り値の `Saved` が DB 最適化の実行条件となり、警告と失敗例外は起動時の UI で表示する。これらのファイルシステム操作中に、コピー元や保存先がアクセス不能になることがあるため、ファイルシステムの失敗は今回扱う外部要因に含める。

一つの実装単位が `Backup.cs`、`BackupTests.cs`、機能仕様 `devdocs/spec/lr2-backup.md`、および `startup-initialization-flow.md` からの参照追加を担当する。リソース・アクセサー・各言語・整合性テストの変更は、この単位の利用者向けメッセージに必要な場合だけ許可する。既存の `LongPathFileSystem` 操作を再利用し、汎用的なファイルシステム抽象化は追加しない。

実装担当には `implementation-worker-frontier` を使う。コピー、ファイルシステム上の保存確定、旧世代の削除の間にある失敗境界が、正しさを左右するためである。一つの単位として扱い、並列実装や重複実装は行わない。

ルートが承認した検証範囲は次のとおり。実際のファイルロックでコピー失敗を、テスト所有の読み取り専用ファイルで staging・旧世代の削除失敗を、最終日付パスを占有する通常ファイルで名前変更の失敗を発生させる。重複する最終パスの事前確認は削除し、上書きしない名前変更処理に衝突の拒否を任せる。保存確定の直前に競合ディレクトリが出現する場合、コピー途中で対象が消失する場合、削除を一度だけ試みることは、保存処理と既存 I/O 境界の静的な追跡で補完する。これらのタイミングだけを制御するフックやファイルシステム抽象化は追加しない。テストだけでは、呼び出し箇所の上書き指定やコピー途中のスキップを改変した全誤実装を検出するわけではない。

## 検証と作業順序

計画点検は完了し、対象欠落の扱いに関する質問も解決済み。独立したテスト契約設計担当が `B5-LR2-BACKUP-1` を凍結した後、一つの実装単位を委譲する。GUID で分離した一時ディレクトリ群と保存処理の同期完了を使い、共有状態や固定待機は導入しない。既存の `BackupTests` を拡張し、互換 API と長パスの検証を維持する。設計担当は、決定的に失敗を発生させるテスト構成と、変更前の失敗・変更後の成功、または対象を絞った誤実装の検出方法を指定する。

`BackupTests` と、該当する場合は `LocalizationResourceParityTests` を対象に絞った Quick を実行し、最後に `scripts/verify-refactor.ps1` から Functional を一回実行する。実装エージェントを終了し、差分を固定して独立した静的レビューへ渡す。レビュー中はルートによるリポジトリ操作を行わない。差分・文字コード・参照の確認と簡潔な結果報告で完了する。合意した失敗契約を満たすために、新しい復旧ライフサイクル、広範な I/O 境界の変更、起動処理のスレッド構成変更が必要になった場合は再計画する。

## 承認済みテスト契約: B5-LR2-BACKUP-1

変更種別は不具合修正。ルートは独立した設計担当のテスト契約を 2026-09-05 に承認した。根拠 A1 はユーザーの B-5 不具合報告、A2 は承認済みの staging・名前変更・旧世代削除の設計、A3 は保存確定前後の失敗の区別、A4 は対象欠落についての明示回答、A5 は上記の互換性と対象範囲の決定、A6 は AGENTS のリソース整合性契約、A7 はルートが承認した動作テスト・I/O 境界・静的確認を組み合わせる検証範囲である。根拠の不足はない。

期待結果の凍結: 設計担当は、実装本体、既存のアサーション、翻訳文言、現在の出力を読む前に、これらの根拠と運用規則から C1〜C9 を凍結した。その後のリポジトリへの配置確認でも、期待結果は変更していない。実行時の契約はすべて、上記の本番起動経路に従う。コピー元・保存先は外部から削除、ロック、アクセス制限され得る。失敗テストでは保存時期に達しており、同日世代が存在せず、保持数が正である条件を使う。入力欠落と同日スキップの優先順位について、新しい契約は追加しない。

変更を許容するものは、staging 名、内部構造、コピー順序、警告の文言と順序、OS 例外の文言と付随的な例外分類である。チェックサムや同一時点の DB スナップショットは保証しない。テストでは翻訳全文、ソース本文、リフレクション、実装の呼び出し順序を固定しない。内容確認用のバイト列とパスは観測対象データであり、完全一致検証の例外扱いではない。C1〜C8 と警告結果は動作テスト、C9 の整合性に関する変更はリソーススキーマのテストとする。

検証の配置: 既存の長パス、保存先欠落、互換 API の再スローを検証する `BackupTests` を拡張する。キーを追加する場合だけ `LocalizationResourceParityTests` を拡張する。新しいテストクラス、DNP（並列実行禁止）、グローバルフック、監視機構、外部プロセス、設定状態、固定待機、広範なファイルシステムアダプターは追加しない。各テストが GUID の一時ディレクトリ群、ストリーム、ファイル属性を所有する。同期的な戻り・例外を完了とし、実行時間の監視はテスト実行スクリプトが担当する。テストの後処理ではロックを解放し、所有する読み取り専用属性だけを解除してからディレクトリ群を削除する。既存の長パス用ヘルパーは適切な範囲で維持する。

本体変更前の失敗証拠: 複数の旧世代とロックされた後続コピー対象がある場合は、旧状態・最終ディレクトリの不変条件で失敗すること。正常対象と欠落対象の混在、および全対象欠落では、必要な失敗結果が得られないことを検出する。保存成功時の世代保持では、総世代数の不一致を検出する。旧世代が保持数を超える状態で最終日付パスにファイルが衝突する場合は、想定どおりの衝突を返すだけではなく、旧状態が保護されないことを検出する。コンパイル、テスト準備、無関係な失敗は証拠に数えない。C4・C7 は変更後に実ファイルシステムで失敗条件を検証する。C5 は必要に応じて `overwrite=true` を I/O 境界の誤実装として使う。テストだけでは、保存処理の上書き引数を改変した全誤実装やコピー途中の消失タイミングを検出しないため、最終レビューでこれらと一度だけの削除を追跡する。専用のタイミング制御フックは必須ではなく、追加も承認しない。

実装担当はテスト構成などの具体的な方法を変更できるが、必須結果や誤実装を区別する条件を弱めてはならない。新しい再試行、属性補正、コールバック、テスト専用 API、復旧処理、失敗の優先順位変更が必要な場合は、作業を止めてルートへ確認する。日付先への直接コピー、保存確定前の旧世代削除、欠落対象の黙示的スキップを同じ単位で廃止する。引き継ぎには契約 ID、変更前失敗・変更後成功の証拠、静的確認による補完、検証の限界、変更ファイル、検証結果を記載する。
