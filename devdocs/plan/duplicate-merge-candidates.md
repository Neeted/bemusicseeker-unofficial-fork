# 重複グループの統合候補一覧と一括整理

## 目的

重複ファイルチェックは、グループを一つずつ手動で統合・整理する操作しか持ちません。複数のグループについて、統合しても作品としての意味が崩れないことを推定したうえで、まとめて整理できるようにします。

## 現状と不足

現行の契約は[重複譜面の確認と整理](../spec/library/duplicate-files.md)と[ライブラリ変更](../spec/library/mutations.md#フォルダ統合と確定後の保守)が正本です。着手時に確認した事実と不足は次のとおりです。

| 現状 | 不足 |
| --- | --- |
| `LibraryMutationOwner.MergeChartDirectory` は統合一件ごとに変更セッションを開始・確定し、必須保守まで行う。 | 複数の移動元を一つの変更セッションへ集める入口がない。 |
| 統合は、移動元を除く所持集合に同じ主ハッシュが残る譜面を移動対象から除く。 | 確定を最後にまとめると、未確定の別の移動元を「残るコピー」と数え、最後のコピーを失い得る。 |
| 統合元の配下は `Directory.EnumerateFiles`（全階層）で列挙し、リンクを拒否しない。 | リンク先のファイルを移動・削除し得る。 |
| `CustomTableView` は行ごとに独立したセルを描き、背景は行番号の偶奇で決める。チェックボックスのセルはある。 | 行グループ、同一列の縦結合、ラジオボタン、グループ単位の背景がない。 |
| 重複ツリーの子は `ObservableCollection<DuplicateGroup>` で、グループだけを並べる。 | 一覧を開くためのノードを置けない。 |
| 同一フォルダ内の重複削除は、件数確認とフォルダ全体の確認を経て `RemoveLibraryCharts` へ進む。 | 確認を挟まない一括の経路がない。 |

## 採用する方針

### 手動統合のリンク拒否

リンク（シンボリックリンクとジャンクション）を含む統合は、物理変更の前に拒否します。拒否の対象は、統合元の本体と配下の全階層、統合先の本体、統合元の項目と同じ相対パスにある統合先の既存項目のリンクです。OneDrive のプレースホルダーなどリンク以外の再解析ポイント、統合元と対応しない統合先のリンク、祖先のリンクは拒否しません。統合元・統合先・リンク先のファイル、DB、登録を保持し、理由を案内します。リンク先には入りません。既存の手動統合（統合先メニュー、Ctrl+G）にも適用します。従来受理していた操作を拒否する互換性変更で、利用者の合意済みです。理由は、リンク先のファイルを作品の一部として移動・削除する危険を避けるためです。

### 統合候補一覧

重複ツリーの子の先頭に「統合候補一覧」ノードを置きます。選択すると、現在の重複検索結果から一覧を構築します。事前計算はしません。

- 一行は一フォルダ、一覧の最小単位はグループです。一フォルダだけのグループも表示します。
- 背景色はグループごとに交互に変えます。
- グループ内の行はPATHの昇順（大文字小文字を無視）に固定します。
- 並べ替えは、グループの先頭行の値で行います。SELECT・STATUSはグループの値を使います。
- 検索は、一行でも一致したグループの全行を残します。STATUSの表示文言も検索対象に含めます。
- 行のダブルクリックは、重複ツリーの対応するフォルダノードへ移ります。SELECT・KEEPのセル上のクリックは値の切替えだけを行います。
- 右クリックメニューは「チェックを入れる」「チェックを外す」「このグループを確認」「エクスプローラーで開く」で、複数行の選択にまとめて作用します。前三者はグループごと、最後は選択したフォルダごとに一度です。
- Spaceキーは選択行のグループのSELECTを切り替えます。

| 列 | 内容 |
| --- | --- |
| SELECT | グループの処理対象を示すチェックボックス。グループの行を縦に結合した一つのセル。初期値はオフ。統合不可のグループはオンにできない。 |
| STATUS | 安全性確認の状況。グループの行を縦に結合した一つのセル。要約を表示し、ツールチップに理由と該当パスを出す。 |
| KEEP | 残すフォルダを選ぶラジオボタン。グループで必ず一つ。初期値は直下の所持譜面数が最多のフォルダで、同数ならPATH昇順の先頭。登録BMSルートを含むグループはそのルートに固定する。一フォルダのグループは固定。 |
| PATH | フォルダのパス。 |
| FOLDER | フォルダ名。 |
| TITLE / ARTIST | [導入先の代表ペア](../spec/library/install-estimation.md#比較用の基本情報と導入先の代表ペア)と同じ候補プロフィールの実在最頻ペア。 |

一覧の状態（SELECT、KEEP、確認結果）は `DuplicateGroup` のインスタンスに対応付けて保持します。重複結果の再検索で同じインスタンスが維持されたグループは状態を保ち、再判定で新しいインスタンスになったグループと消えたグループの状態は破棄します。一括整理の後も、処理しなかったグループの確認結果が残ります。永続化はしません。

### ツールバー

保留譜面の操作バーと同じ位置に、統合候補一覧の表示中だけ出すバーを置きます。

- 「表示中をすべて選択」「表示中をすべて解除」: 検索で表示中のグループだけに作用し、非表示のグループのチェックは保ちます。統合不可は選択しません。
- 「選択グループを確認」: 表示中でSELECTがオンのグループに安全性確認を行います。
- 「選択グループを整理」: 表示中でSELECTがオンのグループに一括整理を行います。
- 「優先統合先…」: 優先するディレクトリを複数登録するウィンドウを開きます。確定時に一覧全体へ適用し、グループ内で優先先自身またはその配下に当たるフォルダがちょうど一つなら、そのフォルダをKEEPにします。該当なし・複数、KEEPが固定のグループは変えません。判定はパス成分の境界で行います。登録内容はアプリの起動中だけ保持します。
- 「サイズと更新日時が同じファイルは読まずに同一とみなす」チェック: 既定はオフ。オンにしたとき、内容が異なるファイルを同一と判定し得ることを案内します。
- 件数表示: 「表示中 n グループ／選択 m グループ」。

### 安全性確認

読み取りだけの処理です。共通のライブラリ変更受付を非待機で取得し、競合時は既存のBusy案内で未開始とします。モーダルの進捗を表示し、取消は処理中のグループを終えてから止まります。取消で未着手のグループは未確認のままです。

対象はグループの各フォルダの配下全体（全階層）で、リンク先には入りません。相対パスの比較は大文字小文字を無視します。検査結果はフォルダ別・フォルダ対別に保持し、KEEPの変更では再走査せずにSTATUSを導き直します。

| 段階 | 理由 | 条件 |
| --- | --- | --- |
| 統合不可 | リンク | いずれかのフォルダの本体または配下に、手動統合が拒否するのと同じリンク（シンボリックリンク、ジャンクション）がある。 |
| 統合不可 | 登録ルート | 登録BMSルート本体、または空の登録子ルートを含む祖先が二つ以上ある。一つならKEEPへ固定して続ける。 |
| 統合不可 | 親子関係 | グループ内のフォルダ同士が同一または親子。 |
| 統合不可 | 型の衝突 | 同じ相対パスが、あるフォルダではファイル、別のフォルダではディレクトリ。 |
| 統合不可 | 別グループを巻き込む | 移動元になるフォルダの配下に、別のグループのフォルダがある。 |
| 統合不可 | 解析不能 | 権限・列挙・読取りの失敗。 |
| 要注意 | 親ディレクトリ参照 | 移動元になるフォルダの譜面が、使用中のリソース参照に親ディレクトリ参照を持つ。`ChartResourceReference.RestrictsAutomaticDestination` と同じ判定。 |
| 要注意 | 同名音源の拡張子違い | 同じ相対ディレクトリ・同じ拡張子なしの名前の `.wav`・`.ogg`・`.mp3`・`.flac` が、異なる拡張子で別のフォルダにある。 |
| 要注意 | 別内容ファイル衝突 | 譜面と `.bmx`・`.pmx`・`.txt` を除く同じ相対パスのファイルが、別内容と判定される。 |
| 要注意 | 同一内容ファイルなし | 比較対象の資源を持つフォルダが二つ以上あり、「同じ相対パスで同一内容の資源を共有する」関係でそれらが一つに連結しない。全フォルダに共通する一ファイルは要求しない。 |
| 要注意 | 配下に別の譜面フォルダ | 移動元になるフォルダの配下の子フォルダに所持譜面がある。 |
| 安全 | （付記）保護対象名の衝突 | `.bmx`・`.pmx`・`.txt` が同じ相対パスで衝突する。安全のままとし、ファイル名と、上書き設定によっては別内容でも一方だけが残ることをツールチップに出す。 |

一フォルダだけのグループは、リンクと解析不能だけを検査します。資源の配置が変わらないためです。

確認が終わったグループは、SELECTを「安全ならオン、それ以外はオフ」に置き換えます。

内容の比較は次の順で行います。

1. サイズが異なれば別内容。
2. 簡易確認が有効で、サイズと更新日時が一致すれば、読まずに同一内容。更新日時は完全一致で、スマート上書きの2秒の許容幅は使いません。
3. 一定の大きさ以下のファイルは全量、それより大きいファイルは先頭・中央・末尾の区間を読み、XXH3（128ビット）で比べます。初期値は一区間64 KiB、192 KiB以下は全量です。`C:\BMS\songs` と `C:\BMS\songs2` の実ファイルで所要時間を測って確定します。

一回の確認の中では同じファイルを相手ごとに読み直しません。ハッシュは保存しません。

### 一括整理

確認ダイアログを一度表示し、承認後にモーダルの進捗の下で実行します。統合の確認を表示しない設定でも、この確認は表示します。未確認・要注意のグループを含むときは、その件数を警告色で示します。安全性確認の再実行と、確認後の外部変更の追跡は行いません。

グループごとの処理は、手動操作と同じ結果になるようにします。

- 二フォルダ以上のグループ: KEEP以外のフォルダを、PATH昇順でKEEPへ統合します。ファイルの移動・採番・上書きは既存の統合と同じ共通のパッケージ処理を使い、スマート上書きの設定に従います。一括整理のための移動規則は作りません。続けて、KEEP内に残る同一主ハッシュの譜面を、既存の規則（更新日時が古いもの、同日時ならファイル名が短いものを残す）で一件にします。
- 一フォルダのグループ: 同一主ハッシュの譜面を、同じ規則で一件にします。
- 同一フォルダ内の整理は、主ハッシュごとに必ず一件を残すため、件数確認とフォルダ全体の確認を表示しません。フォルダは削除しません。削除した譜面はごみ箱へ送ります。

全グループを一つの変更セッションに集め、カタログ・DB・索引・通知への反映と必須保守を最後に一回行います。

最後のコピーを守るため、「既所持」の判定と残存物削除の裏付けには、今回のすべての予定移動元と予定削除譜面を除いた所持集合と、今回実際に配置へ成功した譜面だけを使います。未着手・失敗した対象と予約した宛先を裏付けにしません。

物理変更の前に、手動統合と同じ拒否条件（リンク、登録ルートの移動元、親子関係、型の衝突）と、別グループの巻き込みを検査します。拒否したグループは理由付きでスキップし、独立した次のグループへ進みます。物理処理の途中で失敗したグループは、成功済みの移動元の結果を保って「一部統合」とします。予期しない物理失敗で継続の安全を確認できない場合は後続を止め、未着手を「未処理」とします。既存宛先を復元できなかった場合は、現行の終了手順に従います。

取消は、処理中のグループを終えてから止まり、実行済みの分の確定・後片付け・必須保守はモーダルのまま終えます。

結果は最後に一度だけ表示します。「完了／一部統合／スキップ／失敗／未処理」のグループ数と、ごみ箱へ送った譜面の実数を示し、完了以外のグループはKEEP・移動元・理由を一覧にします。グループごとのKEEP・移動元・結果はログへ記録します。

### 表示文言

新しい文言はリソース化し、六言語を揃えます。確定する文言は実装単位の引継ぎで定めます。

## 対象外

- グループの一部のフォルダだけを統合する操作。ツリーでの手動操作で行います。
- スマート上書き・通常上書きの規則の変更。
- 確認結果・ハッシュ・優先統合先の永続化。
- 確認から実行までの外部変更の検出。

## 作業範囲

実装単位は次のとおりです。番号はこの計画の中だけで使います。

| 単位 | 内容 | 区分 | 依存 |
| --- | --- | --- | --- |
| 1 | 手動統合のリンク拒否。 | 重大変更（入力の拒否、物理変更の前提） | なし |
| 2 | `CustomTableView` の行グループ対応（グループ背景、同一列の縦結合、ラジオボタン、ヒット判定・ツールチップ・キー操作・コピー・UI Automation）。 | 通常変更 | なし |
| 3 | 統合候補一覧（ツリーのノード、行の構築、列、並べ替え、検索、SELECT、KEEP、優先統合先、ツールバー、状態の保持）。 | 重大変更（一覧の所有と寿命） | 2 |
| 4 | 安全性確認（走査、内容比較、判定、進捗、受付）。 | 重大変更（大規模な走査、受付） | 3 |
| 5 | 一括整理（モデルの入口、ワークフロー、確認、進捗、結果、ログ）。 | 重大変更（削除、変更セッション、受付） | 1, 3 |
| 6 | 仕様の移管、ユーザーマニュアル、v3.3.0.0のリリースノート。 | 軽微な修正に当たらない文書変更 | 1〜5 |

## 完了条件

- 各単位が、独立テスト設計、予備・最終レビュー、`verify` に合格している。
- 安全性確認の区間の大きさと全量読取りの上限を、実測に基づいて確定している。
- 代表的な規模で、一括整理のDB確定・索引再構築がグループ数に比例して繰り返されないことを確認している。
- 現行の契約を[重複譜面の確認と整理](../spec/library/duplicate-files.md)、[ライブラリ変更](../spec/library/mutations.md)、[一覧の描画・操作・仮想化](../spec/ui/table-view.md)、[操作の競合ポリシー](../spec/core/operation-concurrency-policy.md)へ移し、本計画を削除している。
