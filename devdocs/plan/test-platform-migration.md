# テスト基盤の残課題

実行区分・期限・所有と回収・結果判定は[テスト検証](../spec/development/testing.md)、module選択と配布物の受渡しは[標準入口](../../tools/BeMusicSeeker.Verify/README.md)を正本とする。

## 不具合修正と追加検証

既知の製品不具合の修正を、追加Scenario/Desktopの拡充より先に進める。既知の誤期待は現行仕様へ格上げせず、製品修正時に仕様・期待と合わせて見直す。

追加SC-05fは[Deferred](../../tests/Deferred/Scenarios/README.md)で保留し、初回Drop Busyの操作前提を見直してから再開する。SC-15a/SC-15b/SC-16の広範な拡充と追加Desktopも、既知不具合の修正を優先した後に再開する。

## 追加速度目標と未実施条件

日常中央値60秒・p95 90秒、Full10分の追加速度目標は後段で判定する。旧基盤からの時間非退行とは別の目標とし、運用上限の延長を性能改善と扱わない。

権限不足のシンボリックリンク6条件と入力不足の外部encoder 1条件は、合意どおり未実行・未成功として残す。必要な権限・入力が揃った時点で再開し、移行対応済みであることと実行成功を区別する。
