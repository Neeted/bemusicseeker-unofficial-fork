## MainWindowViewModel nested type 依存

`BeMusicSeeker/ViewModels/MainWindow/*.cs` では、root nested type が presentation contract の置き場になっている。

代表例:

| 型 | 代表依存先 | 方針 |
|---|---|---|
| `MainViewUpdateMode` | `ChartListRefreshCoordinator`, `MainViewRefreshDecisionService`, `RegularChartListRefreshTypes` | 最優先で top-level contract 化。numeric value / 意味は維持 |
| `MainWindowViewModel.cSortParameters` | `RegularChartListSortCoordinator`, `RegularChartListFilterService` | sort descriptor snapshot として切り出す候補 |
| `MainWindowViewModel.ModeFilterType` | regular / playlist filter services | play-mode filter contract として切り出す候補 |
| `PlaylistRequestIdentity`, `PlaylistSourceIdentity`, `PlaylistFilterType` | `PlaylistBuildRequest`, `PlaylistRequestFactory`, `PlaylistWorkspaceViewModel` | playlist request / view identity 境界を整理してから扱う |

今は触らない領域:

- `PanelState` / player panel state: persisted setting / XAML / converter と結合。
- SettingDialog partial: 6,697 行あり、`Settings.Default` と persistence schema の影響が大きい。
- `MainWindowRuntimeContext`: 失敗を隠さない provider として維持。便利な状態保存は増やさない。

## source-text / private reflection test 方針

残存例:

- `SourceTextTestHelper` / `File.ReadAllText` 系: root ファイル分割で壊れやすい。
- `BindingFlags`, `GetMethod`, `GetField` 系: private 実装配置を固定しやすい。
- `new MainWindowViewModel()` 系: root shell を直接作るため、child VM / service 直接テストの妨げになりやすい。

方針:

- 削除を急がず、抽出した service / child VM の public / internal API テストへ置き換える。
- 次の実装を妨げる上位数件だけを各 ticket の前処理として扱う。
- `BMSLibrary` / `MainWindow` / `MainWindowViewModel` の source-text helper は、分割後の複数ファイルを読む形に維持する。
