# 例外処理の簡素化と停止境界の修復

## 目的と範囲

元の全パッチと関連する本番入口・結果利用先を確認し、失敗を対象・操作の所有境界へ集約する。入力の互換性、正本と確定結果、通常の資源所有を保ち、例外の分類・包装・終了接続を必要な範囲へ減らす。

変更は実装単位ごとに検証・独立レビュー・コミットまで完了させる。次の単位へ進む前に作業ツリーを確定する。退避した差分は参考資料とし、必要性と検証を確認できた変更だけ採用する。

## 採用済みの縮小方針

[共通仕様](../spec/core/exception-handling.md)を適合先とし、処理境界と失敗後の状態で停止範囲を決める。各単位で実装と対応する機能仕様を更新する。全機能が移行済みという意味ではなく、旧規定の「未知なら終了」や完全な回収保証を完了基準にしない。

既存のFailFastと妥当な修正は保持する。未実装範囲へOOM専用捕捉を横展開せず、全経路の即時終了や通知・診断・解放の二次故障の網羅を追加の必須範囲にしない。保存失敗の隠蔽、失敗範囲の不適切な拡大、不要な例外集約、不完全走査の誤反映、通常の受付・処理の放置など、具体的な利用者影響を優先する。

## 単位の区切り

単位は一つの挙動と必要な依存・利用先で区切り、実装・仕様・必要なテストを含める。ファイル別の分割や、未検証の共通API変更だけのコミットにしない。

1. 本番入口、失敗後の状態、変更範囲、対象外を確定する。
2. 必要なテストの判定基準を独立して定め、既存の保証へ配置する。
3. 一人の実装担当が許可範囲を実装し、構文だけでなくビルドと関連する標準Quickで確認する。
4. 書込みを止めて予備レビュー、続いて変更の重大性に合う独立レビューを受ける。
5. 指摘を元担当へ戻し、必要な再検証・再レビュー後にコミットする。

共有依存を後の単位で変更した場合は、確認済み領域への影響を調べ、必要な範囲を再確認する。結果はGit上の版と作業引継ぎで使い、恒久的な成功履歴台帳は作らない。

## 残る範囲

元パッチと本番の利用先を確認して残った具体的な不備、および未確認の接続を以下へ絞る。一つの行が大きい場合も、挙動と依存が閉じる単位へ分け、前の単位を完了させてから着手する。適合を確認した境界の追加実装や、仮想的な二次故障の条件網羅へ広げない。

| 範囲 | 確認する契約 |
| --- | --- |
| 有効な保存スコアがない場合の表示と操作 | 初回取得失敗を未プレイへ変換せず、通常データで未取得として正常空と区別する。行・集計・検索等の結果依存操作だけを止め、未取得から正常0件への遷移も表示へ反映する。スコア条件の絞り込み・検索は利用者回答を待って受付の扱いを確定する。 |
| 履歴の採用と集計 | 読取り不能を空一覧・ゼロ集計として採用・キャッシュしない。同じ取得元・期間・表示条件の有効旧結果だけを保持し、なければ未取得とする。beatorajaの期間実績だけの失敗は、正常な履歴一覧の利用を妨げない。 |
| 残る接続と仕様の整合 | 全修正後に共通規定と各機能仕様・テストの分担を照合し、最終版で単位間の接続と全体検証を確認する。 |

## 完了条件と追加の制限

元の全実装単位について、互換性、停止範囲、正本・確定結果、必要な通常所有、確認・診断・案内を本番入口から利用先まで確認する。適合済みの境界を再実装しない。

新しい型・状態・通知経路は、防ぐ具体的な被害と既存の所有・transactionで済まない理由がある場合だけ追加する。仮想的な二次故障、全原因保存、監視、再試行、回復日誌、永続無効化、全件事前検査、汎用重要度の仕組み、独自death-test基盤を追加しない。

追加の必須対策と受入阻害指摘は、本番入口と現実的な到達条件、具体的な誤採用・データ損失・誤操作・通常寿命への影響を示す。callbackへの例外注入が可能なだけでは採用しない。通知・診断の耐性は当該修正に必要な代表条件へ絞り、同じ二次故障の分類表を全層へ複写しない。

各単位の必要検証・独立レビュー・コミットが揃った最終版で、全体検証と単位間の整合を確認する。配布・更新にも関わる最終検証は `pwsh -NoProfile -File scripts/verify-refactor.ps1 -Mode Full -FunctionalTimeoutSeconds 360` とし、後続受入の期限は変更しない。失敗を期限・skip・表明の弱化で隠さない。

必要な契約と依存の限界を[共通仕様](../spec/core/exception-handling.md)と各機能の正本へ移し、未完了項目がなくなった時点で本計画と参照を削除する。
