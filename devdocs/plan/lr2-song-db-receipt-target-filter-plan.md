# LR2同期の確定パスを処理対象から除外する

## 目的と現状

直前のファイル差分（file diff）が確定したBMSパスを、LR2同期の譜面パイプラインへ投入する前に除外します。全件が確定済みの場合だけを一括スキップする専用経路は作らず、一部確定済みと全件確定済みを同じ対象集合の構成で扱います。

現行の [LR2同期仕様](../spec/integration/lr2-song-db.md#読込みと確定結果の再利用)では、有効な `CommittedPathReceipt` に含まれるパスも譜面パイプラインへ入り、読取り・解析を省いた結果として1,000件単位で回収されます。譜面段階の分母にも含まれます。本計画は未実装であり、順序枠を採番前に取得する停止防止の制御や、現行の1,000件単位処理とは別の後続改善です。

## 採用する方針

### 対象集合を投入前に固定する

現在の有効な楽曲行集合を `A`、今回利用できる確定パスの証票を `C` とし、譜面処理対象を「`A` のうちパスが `C` に含まれない行」に限定します。証票の件数を機械的に引くのではなく、現在の入力行との照合で対象を決め、残った行の順序は保ちます。

証票の有効性・比較規則・寿命は現行仕様を維持します。単に解析済みであることや `chart_info` が存在することを、ファイル差分の永続確定と同一視しません。版不一致・証票なし・再試行・手動実行では、その実行に有効な証票で除外できない行を通常どおり対象にします。別パスにある同一MD5の譜面を連動して除外しません。

対象の構成は `Lr2SongDbSyncService.Run` の総数・初期進捗・実行状態の確定より前に一度だけ行います。証票対象には順序枠、読取り候補、計算結果、チャンクを作らず、reader・worker・writerのどの段階にも流しません。除外後は残った対象を連続した番号で処理し、元の入力位置による欠番を残しません。全パスの二重整列、除外専用の世代や永続状態、新たな全件コピーは増やさず、現在の対象行リストの構成を置き換えます。

### 分母・処理位置・結果の意味を揃える

譜面段階の総数と処理済み件数は除外後の対象を基準にします。20万行のうち10万行が有効な証票対象なら、最初から譜面段階の分母は10万です。除外した10万行を処理済み件数へ足して分母だけ元へ戻す表示にはしません。

同期全体の `TotalCount` / `total_count` はフォルダ処理分と除外後の譜面対象数の合計とし、`ProcessedCount` / `processed_cursor`、段階境界、チャンクの位置、結果件数、状態表示、ログを同じ対象集合に揃えます。永続化した処理位置を次回の再開位置にしない契約は変えません。

`SongRowProcessedCount` は実際にパイプラインで処理した件数へ揃えます。既存の `SongRowSkippedCount` / `receiptSkipped` の参照元を調べ、投入前の除外数を診断に残す場合は、その意味が明確な件数へ置き換えます。互換用の二重カウンターを残さず、元の候補数・除外数・実処理対象数の関係を入口の集計で確認できるようにします。

全件が証票対象なら、同じ対象構成の結果が0件になります。空の譜面パイプラインやスキップ用チャンクを起動せず、対象0件として後続の検証・完了処理へ進みます。画面は存在しない譜面作業を不定進捗として待たず、0件の扱いを既存の状態表示へ接続します。

### 完全な入力を必要とする後続処理を維持する

除外は譜面の再処理対象だけに適用します。フォルダ生成に必要な全 `ChartPaths`、祖先ディレクトリ、フォルダ候補、現在の所属集合は削りません。フォルダ表の検証・確定、入力全体の最終現行性確認、完了状態の永続化は、譜面対象が0件でも維持します。不完全なフォルダ入力、入力の失効、終了取消、DB失敗を成功に読み替えません。

## 対象外と依存関係

証票の永続化、失効条件の緩和、保存cursorからの再開、再試行・自動復旧の追加、フォルダ処理の省略、非除外対象のチャンクサイズや並列度の変更は対象外です。今回の停止解消へ本計画の対象除外を混ぜません。

[起動からLR2同期までの順序統合](lr2-startup-procedural-orchestration-plan.md)が先に実装された場合は、直接渡される型付きの確定結果を同じ除外判定へ接続します。その際に、廃止済みの共有証票の公開・取得経路を復活させません。順序統合自体は本計画の前提条件にしません。

## 作業範囲

`Lr2SongDbSyncService` の対象構成・段階境界・件数計算をまとめて変更し、`SongRowSyncReadCandidate` / `SongRowSyncComputedItem` の証票スキップ表現、`ShouldSkipCommittedReceiptPath`、チャンク内の除外分岐など、不要になる経路を削除します。共通パイプラインの採番前の枠確保は維持します。

同期結果・ログ・`Lr2SongDbSyncStatusMapper` とその利用先、確定パス・同期サービス・進捗に関する既存テストを同じ件数定義へ揃えます。機能仕様は実装と同時に更新し、本計画の完了後は必要な契約を正本へ移して本書と目次の項目を削除します。

## 完了条件

| 条件 | 期待結果 |
| --- | --- |
| 20万行中10万行が有効な証票対象 | 譜面パイプラインの入力と分母が10万。残りだけが読取り・解析・チャンク処理へ進む。 |
| 全件が証票対象、または元の譜面入力が0件 | 譜面パイプラインは起動せず、必要なフォルダ処理・最終検証・状態保存を経て終端へ進む。 |
| 証票なし・版不一致・再試行・手動実行 | その実行の対象集合を先頭から処理し、以前の証票を復元・流用しない。 |
| 一部一致、現在の入力にない証票パス、別パスの同一MD5 | 入力行とのパス照合だけで除外し、過剰除外・負の件数・採番の欠落を生じない。 |
| 除外対象だけが存在するディレクトリ | フォルダ生成に必要な入力を失わず、期待するフォルダ行を維持する。 |
| 入力失効・不完全なフォルダ入力・終了取消・DB失敗 | 除外件数にかかわらず既存の非成功結果を維持し、0件を全体成功の証明にしない。 |

全件専用の一括スキップ経路を設けず、入力除外・処理対象数・実際の読取りと保存件数が一致することを確認します。利用者保存列や楽曲行の所属を変更せず、同じ仕事を完了するまでの処理量と時間を[性能仕様](../spec/core/performance-and-scale.md)の条件で比較します。
