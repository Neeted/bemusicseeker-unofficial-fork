# 作業計画と完了記録

このディレクトリは、作業の進捗把握と再開のための計画を置く。現在の仕様は [../spec/](../spec/README.md) を参照する。

## 進行中・着手待ちの関連計画

- [ライブラリ変更操作の性能課題と実装計画](BeMusicSeeker-library-mutation-performance.md): install / delete / move / rename / mergeの局所更新、exact path整合、R2とは別単位のRELINK-1。実装済みの入力取得制御と未実装課題を区別する。
- [v3 安全性改善計画](v3-safety-improvements-plan.md): 30件の修正・確認・説明改善。受付方針の適用範囲と未実施の検証を含む。
- [LR2 startup 手続き化計画](lr2-startup-procedural-orchestration-plan.md): 起動・reloadの直接結果引渡しと操作受付。製品方針は採用済み、runtimeの再構成は未実装。

## 運用

- 冒頭に全体の状態、目的、完了条件を示し、作業項目ごとに現在の状態と短い要約を更新する。
- 進行中は、決定事項、担当範囲、依存順、検証方法など、再開や委譲に必要な情報を保持する。詳細は [エージェント運用契約 section 4](../spec/codex-agent-workflow.md#4-最終計画と記録の使い分け) に従う。
- 完了した項目は、実施内容の要約、残課題、反映先の仕様へ整理する。恒久的な契約は `spec/`、今後も必要な採用理由は `decisions/` へ引き継ぎ、計画は短い完了記録として残す。

進捗は次の形を基本とする。表の一行を、結果を説明できる作業単位にする。

| 作業項目 | 状態 | 実施内容の要約・残課題・反映先 |
| --- | --- | --- |
| 意味の分かる作業名 | 未着手／進行中／完了／保留 | 現在の判断、または完了内容と仕様へのリンク |
