# 未完了の計画

現行仕様は[仕様の入口](../spec/README.md)、採用理由は[設計判断](../decisions/README.md)を参照します。ここには、着手・再開に必要な未完了事項だけを置きます。

| 計画 | 残る作業 |
| --- | --- |
| [例外処理の簡素化と停止境界の修復](exception-handling-simplification-plan.md) | 全主要領域の監査指摘、外部表修正の実行検証、停止・結果・診断・通知の分離と不要な例外輸送の削減。 |
| [安全性の改善](safety-improvements-plan.md) | 保存・受付・失敗報告・入力制限の不足確認と限定修正。 |
| [LR2同期の確定パスを処理対象から除外する](lr2-song-db-receipt-target-filter-plan.md) | 直接渡された確定パスの投入前除外、除外後の件数による進捗・状態の統一、不要なパイプライン内スキップの削除。 |
| [起動・一覧の応答性](ui-responsiveness-plan.md) | 重い画面処理と書込み待機の測定・整理、自動改名の次操作の完了時間差の原因確認。 |

## 運用

計画には目的、現状と不足、採用する方針、対象外、作業範囲、完了条件を必要な分だけ書きます。未確認の事象は仮説・確認課題と明記し、実装済みの保証として仕様へ書きません。着手時は本番の入口と既存テストを再確認し、既に解消した課題を再実装しません。

恒久テストの必要性と設計は[テスト設計](../spec/development/test-authoring.md)、委譲・レビュー・中断時の引継ぎは[エージェント運用](../spec/development/agent-workflow.md)に従います。段階番号などの一時識別子を使う場合も、計画と作業中の引継ぎの内側に限定します。

完了時の移管対象、削除、参照更新は[現行情報の維持](../README.md#現行情報の維持)に従います。一部だけが完了した場合も、必要な情報を正本へ移した項目は計画から除き、未完了作業の判断と再開に必要な情報だけを残します。
