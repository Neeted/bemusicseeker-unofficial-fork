# 開発資料

このディレクトリは開発者向け資料の置き場です。ユーザー向けの説明は `docs/` に置きます。

## 分類

| 配置 | 役割 |
| --- | --- |
| `spec/` | 現行仕様と採用済みの設計・性能要件。現行挙動と未実装・未検証の要件を区別し、実装とテストへの入口を示す。 |
| `plan/` | 作業の目的・完了条件・進捗と、再開に必要な設計や判断。完了後は実施内容の要約、残課題、仕様の反映先を残す。 |
| `decisions/` | 設計判断の採用理由、代替案、背景。採用した契約の本文は `spec/` へ統合する。 |
| `acceptance/` | 設計・性能判断の根拠として後から参照する測定・観測記録。対象コミット、データ、環境、条件と結論を揃え、その条件下の結果として読む。 |
| `everything/` | Everything の仕様差や外部挙動の観測。回避策や設計判断の背景として読む。 |

## 書き方

本文とコメントは原則日本語で書き、コードの識別子、コマンド、製品名、外部仕様の正式名称は原表記を使う。繰り返し使う専門概念は、文書の冒頭に「日本語名・意味・対応するコード名または原語」を置き、本文では日本語名を使う。共通の概念はその正本の用語表を参照し、機能固有の概念だけを各仕様で補う。

仕様の共通書式は [spec/README.md](spec/README.md#仕様書の書式)、計画の書式は [plan/README.md](plan/README.md#運用) を正本とする。既存文書は変更対象の節からこの書式へ揃える。

## 命名

- `*-plan.md`: 作業計画または実装履歴。
- `phase-*.md`: 段階導入の履歴。
- `*-note.md`: 調査メモや外部仕様の観測記録。
- その他の仕様名: `spec/` 配下で、機能名をそのまま使う。

## 読み方

現行仕様を確認したい場合は、まず `spec/README.md` から読む。データ規模、処理速度の優先順位、性能退行の判定は [performance-and-scale.md](spec/performance-and-scale.md) を正本とする。計画・履歴を読む場合は、`plan/README.md` または対象機能の plan を読む。
