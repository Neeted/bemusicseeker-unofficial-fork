# 保留パッケージの分け方の設計判断

## 目的と適用範囲

取り込みで保留パッケージを作るときに、ディレクトリ直下の譜面を一つにまとめるか単体に分けるかを決める規則の採用理由を示します。規則・期待結果と実装・テストの対応は[ドロップ導入](../spec/library/drop-install.md#単体分割と子作品の発見)を正本とします。

## 判断

パッケージの単位は、導入される物理範囲と、導入先が一括で適用される範囲を同時に決めます。単体はその譜面ファイルだけを導入し、ディレクトリ単位は配下すべてを一つの導入先へ移します。推定は単位内の全譜面の参照の和集合で候補を選び、手動で指定した導入先は単位の全項目へ適用されます。このため、分け方の誤りは向きによって重さが違います。

| 誤り | 結果 | 扱い |
| --- | --- | --- |
| 同梱資源があるのに単体へ分ける | 単体は譜面ファイルしか導入しないため、同梱資源が導入されずに残る（導入漏れ）。 | 避ける。v1.2.1.0でStella 7475に対処した課題そのものである。 |
| 同梱資源がない譜面をまとめ損ねて単体にする | 譜面ファイルを導入する点は同じで、導入漏れは起きない。失うのはフォルダ単位の導入とツリー表示、未参照の付属物（readme等）の同伴だけ。 | 許容する。 |
| 無関係な譜面をまとめる | 和集合の推定で候補が出にくくなり、手動の導入先が全譜面へ適用されて別曲が同じフォルダへ入る（誤導入）。 | 避ける。 |

ここから次の方針を取ります。

- 同梱資源は、まとめる必須の根拠とする。previewと補助画像（STAGEFILE・BACKBMP・BANNER）も同梱資源に数える。どの譜面も参照しないファイルは根拠にしない。
- 同梱資源がなければ、同じ作品である強い根拠がある場合だけまとめ、迷う場合は単体にする。直下の譜面が1件ならまとめる。
- 子作品を持つディレクトリは、親に同梱資源がなければまとめない。まとめると子作品も親の導入先へ動き、誤導入になるためである。親に同梱資源がある場合は親子一体の作品とみなし、親子の両方が自己資源を持つ場合は入れ子の導入拒否で止める。
- 同じ作品の根拠には、導入先推定と同じ正規化による `(タイトル, アーティスト)` のキーの完全一致を使う。この正規化は難易度・差分の表記を吸収し、MIX名や異なるリミックス作者は区別する（[導入先推定のメタデータ照合](install-estimation-metadata-matching.md)）。タイトルが空の譜面があれば揃わないとする。
- 単位は発見時に確定し、推定の後に組み替えない。フォルダ指定・全項目選択・書庫・直接指定の昇格・重複保留の登録整理・起動時の復元は同じ判定を使う。

## 採用しない代替案

| 代替案 | 採用しない理由 |
| --- | --- |
| v3.1.0.0の参照名の共通率で分ける | `01.wav` のような汎用のキー音名で別曲を一致させ、まとめ過ぎの側に誤る。逆に譜面ごとに別のキー音を使う同じ作品の差分（Stella 7475）は分け、同梱物の導入漏れを起こす。 |
| タイトル・アーティストの類似度で一致させる | 同じ作者の別の曲や別のリミックスを一致させ、誤導入の側に誤る。 |
| 推定後に導入先が揃った単体を再統合する（v1.2.1.0〜v3.1.0.0） | 推定の成否でまとまるかが決まり、各譜面の音源充足を要求する現行の自動設定では成立しにくい。重複保留の登録整理と再ドロップで再統合済みの単位が単体へ戻り、手動の導入先を失う。再統合した単位は親ディレクトリ全体を導入するため、未発見の子作品を巻き込む。v1.2.1.0で再統合が必要だったのは、previewと補助画像を同梱資源として数えず同梱物を持つ差分集を単体へ割っていたためであり、同梱資源を発見時の根拠に含めれば要らない。 |
| 同梱資源も子譜面もなければ直下の譜面数によらず一つにまとめる | 別々の曲の差分を集めたフォルダが一つになり、推定の候補が出にくく、手動の導入先で別曲が同じフォルダへ入る。 |

## 受容する割り切り

- 同梱資源を持つ平坦なフォルダに別々の曲の差分が混ざる場合（例: 全譜面が共通のバナーを参照する複数曲の差分集）は、一つにまとまる。分けると同梱資源の導入漏れになるため、まとめる側を選ぶ。各譜面の音源充足を求める自動設定は成立しないため自動では誤導入しないが、手動の導入先は全項目に適用される。
- 同梱資源がない同じ曲のリミックス集や、タイトル表記が揃わない差分は単体になる。導入漏れは起きない。
- 規則で単体に分かれた全項目選択では、どの譜面も参照しないreadmeや内包書庫を導入せず、展開もしない。フォルダ指定で配下の書庫を展開しないことと揃える。
- 同梱資源も子譜面もない複数譜面を一つのディレクトリとして保存した保留行は、重複しない限り起動時に分け直さない。v3.1.0.0が参照名の共通率や推定後の再統合で作った行も含め、既存の行は現状のまま残る。起動時に利用者の操作なしで保留の単位を変えないため（重複群だけを再分類する現行どおり）、移行処理は設けない。
