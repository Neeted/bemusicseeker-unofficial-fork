# 詳細解析の座標索引と出力

## 適用する判断

BMSの詳細解析はdecodeした文字列の範囲と予約語を一度準備し、RANDOM候補ごとに最終BASEで必要なチャンネルペアだけを変換します。0を除く有効要素と無効要素の位置を残し、制御イベントとノートを従来の要求順で再生する疎な操作列へまとめます。モード判定の最初の有効値での短絡と、本解析の診断順を別に維持します。

機能契約と回帰検査は[譜面解析の互換性](../spec/library/parser-compatibility.md)を正本とします。解析入口、保存主体、並列度、parser_versionはこの判断で変更しません。

## 座標の索引化と時刻の生成

候補が要求する座標を重複除去・整列して圧縮し、Fenwick索引で実際に生成した座標の個数と前駆順位を管理します。事前の座標集合には未来の要求も含まれるため、整列済み集合から一括で時刻を計算しません。

同じ小節でも制御イベントを先に生成し、その後に以前の座標のノートを要求する場合があります。0や負の小節長では要求と物理座標の順も異なります。生成済み前駆がないときの最小座標、double累積の丸め、非有限値の失敗時点を維持するには、要求時の生成が必要です。CompareToで同値のキーと生成時のSectionも区別し、最初の実要求値を保持します。

座標の事前圧縮は操作列と作業索引の領域を必要とします。全レーンに同じ座標を要求する密な入力では、重複座標を整列前に除き、操作種別・レーン・値の領域を共有します。入力規模による旧ストア切替や別パーサーのフォールバックは持ちません。

## 現存ノートと完成LN被覆

LNOBJまたは専用LNを使うレーンだけに、現存ノート位置のFenwick索引を作ります。最初の通常ノートから更新し、LNOBJは厳密に直前の非nullノートだけを観測します。ノート更新口が本体と索引のnull境界を同時に変更します。

完成LNの被覆は端点セルが上書きされても残るため、現存ノートの索引から導出できません。必要なレーンで区間差分を別のFenwick索引へ加え、両端を含む照会を行います。全タイムラインの後方走査や完成LNリストの全件探索を避けます。どちらも一候補の解析中に必要な状態であり、保存用・将来用途のキャッシュではありません。

## 数値互換と出力

JDK 17のdouble読取りとJDK 21の文字列化を維持します。.NET標準の数値変換へ置き換えると、同じ表示値でもビット列や末尾桁が変わり、時刻と譜面ハッシュへ伝わります。既存のJava変換アルゴリズムとキャッシュの寿命は変更しません。

LN確定後の共有要約と、TOTAL確定後の分布生成を分けます。長いLNの継続数は区間差分を累積し、速度とレーン情報は保存文字列へ直接書きます。

譜面文字列相当のUTF-8は伸長可能な一つの連続バッファへ書き、一回のSHA-256へ渡します。全文領域は必要ですが、ノート・行ごとにhash APIを呼ぶコストを避けます。通常結果では全文stringを保持せず、詳細検証要求だけが同じバイト列から文字列を作ります。出力書式を二系統にせず、保持要求によってrowやhashを変えません。
