# bmson再生の時刻と音声区間を分ける判断

## 適用する判断

bmson専用の再生解析とBMS解析結果の投影を、一つの不変な再生データへ接続します。既存の復号、準備結果、発音予約、内蔵プレイヤー、音声Writerを共通に使い、`chart_info` の解析・保存とBMSの入力・時刻・発音互換性は維持します。

bmsonの位置は全曲共通の整数pulseで保持します。時間は入力十進数に基づく有理数で区間計算し、制御境界の寄与を100nsの `2^32` 分割刻みへ最近傍偶数丸めして `BigInteger` へ累積します。全曲の経過時間を単一の厳密な `Fraction` として保持しません。音源ファイルの共有と発音区間の識別も分けます。

機能・入力・失敗条件と実装の対応は[bmson再生仕様](../spec/library/bmson-playback.md)を正本とします。本書は採用理由、代替案、測定の適用条件を扱います。

## 表示情報と再生一時状態の境界

明示bmsonのpulse0線は初期線情報として保持し、小節番号へ加算しません。時刻0へ量子化された正pulse線は小節を進めるため、判別には元pulseを使います。重複した初期線の有無で前進・seekのカウンタや音声区間を変えません。

譜面情報は所持カタログを正本とし、ライブラリ変更時は停止します。再生状態は現在譜面とbitを持つ `PlaybackPanelViewModel` に集約し、行のstatus読取りへだけ合成します。各行の登録・状態辞書・保存主体へのPLAY書戻しを削除し、既存の表キャッシュ再評価で表示を更新します。未訪問行を作ることなく重複行と遅生成行に現在値を返せ、スコア・警告・編集値の投影も維持できます。

選曲と表示は共通の譜面を対象にします。素材Aから素材B、素材なしへの更新を一つの表示契約とし、形式固有の切替条件や表示状態を増やしません。実選曲から `DisplayedChart` 通知、compiled Viewの素材読込みまでを検査し、共通の保証とテスト対応は[再生パネル](../spec/ui/playback-panel.md)へ集約します。

## 整数pulseでも時間の分母は増える

位置の単位を `resolution` へ揃えることと、経過時間の分母を小さく保つことは別の問題です。

```text
区間tick = Δpulse × 600,000,000 / (resolution × BPM)
```

BPMは除数です。異なる厳密な十進BPMを全曲の一つの分数へ加算すると、約分後も各BPMの分子に由来する因子が分母へ入り、最小公倍数が成長します。pulseが整数であっても防げません。固定小数を作者の意図した単純な分数へ推定し直すことも、入力とは異なる値を計算するため採用しません。

### 実譜面の根拠

対象は「ピアノ独奏曲 『赤い靴』」の `Another_7key`、作者はOnasです。[マニフェスト](../../BeMusicSeeker.Tests/TestData/chart_info_bmson_real/manifest.json)の譜面識別SHA-256とファイル名は `146963e794cf8cd7f17c29af5685e5015a492473a043c99eb64cdc3b02846865` です。測定で読んだ固定入力は2,314,543 byte、実byteのSHA-256は `c2087ea805145d9e46d902889a551bede9f684a51f9eeb073e8456436d506082` です。[固定譜面](../../BeMusicSeeker.Tests/TestData/chart_info_bmson_real/charts/14/146963e794cf8cd7f17c29af5685e5015a492473a043c99eb64cdc3b02846865.bmson)は `resolution=96`、BPMイベント24,919件、異なるBPM値19,664種類、音源チャンネル58件、ノート1,611件です。STOPはありません。

厳密な区間係数の分母の最小公倍数は746,973bit、全曲を単一 `Fraction` へ加算した実際の累積分母は最大746,938bitになりました。この譜面を、音源なしの時刻計算方式の比較に使います。

## 微小誤差を許容する固定刻み

JSON数値は元の字句から厳密に読み、BPM区間とSTOPの寄与を有理数で求めます。近似を入れる箇所を制御境界の最近傍偶数丸めへ限定し、全曲の基準時刻を整数加算で保持します。音符は基準時刻＋局所差から求め、小節線やノートごとに時計を丸め直しません。小節線を増減して音声時刻が変わらないことも必要です。

K回の丸め寄与の累積誤差上限は `K / 2^33 tick` です。24,919回なら約 `2.901 × 10^-6 tick`、約0.29psです。局所時刻の丸めや二つの境界の差については、それぞれの誤差上限を合成します。上記三試験で、厳密累積に対する最終誤差は約 `4.647 × 10^-9 tick` でした。

ただし、この誤差上限から整数tick・音声frame・PCMの一致は導けません。境界付近では整数化結果が異なり得ます。上記比較では整数tickに最大1tickの差がありました。この微小差を許容する方針を採り、固定刻み方式を完全な有理数時計とは表記しません。

固定刻みの累積に単一の `long` は使いません。1tickを `2^32` 分割すると約215秒で上限に達するためです。`BigInteger` で累積し、表示時刻や音声frameへ変換する境界で表現範囲を確認します。途中で `TimeSpan` の整数tickへ落とす案も、音声frameの半分付近の丸めを変えるため採用しません。

### BMSの小節境界を維持する理由

BMSは小節境界で整数tickを確定し、次の小節へ分数端数を持ち越しません。[BMS時刻の採用判断](ribbit-exact-timing-adoption.md)は、その受理・整数化規則を維持した評価です。bmsonの小節線は表示情報であり、同じ時計へ無理に統一すると小節線の追加で時刻が変わります。

共有するのは数値演算の道具と再生結果の形です。BMSの整数tickを正確に固定刻みへ昇格させ、BMSの時刻規則をbmsonの固定刻み方式へ置き換えません。BMSの次同indexによる打切りや、再発音後も開始＋音源全長を曲長・書出し長の下限へ使う互換性も保持します。

## 復号元、論理区間、継続発音列の分離

同じpathは曲内で一度だけ復号できますが、別の音源チャンネルや、別の再開から重なるEOF尾部は独立voiceです。PCM共有のキーを発音の排他キーにすると音を欠落させます。BMS専用の同index重複除去・次発音打切りをbmsonへ流用しない理由です。

解析器はチャンネル内の同 `y` を一組とし、次が継続なら有限の論理区間、次が再開または末尾ならEOFを残します。音源内位置は再開からの譜面経過時間であり、STOPも含みます。`l` だけを音源長へ読み替えず、明示upはその `y` に置きます。この論理計画と判定統計は、実際に作るvoice数とは別です。

### 継続音を一つのvoiceで出力する理由

論理出力境界の最近傍偶数丸めと音源内境界のfloorは、同rateでも異なる長さを作り得ます。論理区間ごとに有限PCM窓を作り、切れ目を物理EOFとしてネイティブへ渡すと、元PCMが十分にあるのに区間末尾で使い切り、1 output frameの穴ができます。`EndFrame` を延ばすだけでは、既にEOFになったsourceの無音を直せません。

全自動再生では、同じ元チャンネルの再開から続く `c=true` 列を、量子化とPCM終端への制限より前に一つの連続voiceへまとめます。ネイティブcursorとSRCは再開原点に固定し、論理継続位置で再生成しません。frame化で0長になる論理区間を先に捨てることも避けます。別の `c=false` 再開のEOF尾部と、別チャンネルのvoiceは独立させます。

100 source framesの48kHz音源を44.1kHzへ出す全列は92 output frames、92 source framesの44.1kHz音源を48kHzへ出す全列は101 output framesです。論理境界から別voiceを作る93・102という終端は採用しません。論理source floorが99になる計算は正しいままですが、継続時にcursorを99へ置き直す指示ではありません。seekも再開原点から経過frameを求め、重なる全発音列を復元します。

共有PCMを複製せず、継続ノートの挿入・削除で同じ列の音声と出力長が変わらないことを、小入力と一つの連続sourceとの対で検査します。異rateのSRC位相を別voice間で一致させる保証は追加しません。BMSの既存時刻・再発音打切り・曲長下限は変更しません。上記1,045件の測定は変更しない解析器の論理計画の結果であり、この連続voiceの音声検証結果ではありません。

音声scheduleには非空voiceだけを保持します。欠落・正常0frame・空source窓の開始位置を音声終端へ混ぜると、実際には鳴らない後方ノートが無音の尾部を延ばします。論理イベントを解析結果に保持したまま、完成したvoiceの実出力を判定して除くことで、通常ロード・準備結果採用・Writerは同じ物理EOFへ揃います。BMSの既存末尾無音下限は変更しません。

## 不正LNの進行統計を回復する理由

[bmson規格のLayered Notes](https://github.com/bemusic/bmson-spec/blob/master/doc/index.rst#layered-notes)は同位置の異音源を融合し、異長をerrorとします。不正入力を仕様違反だけで拒否する代わりに、進行統計の回復では[beatorajaの組込](https://github.com/exch-bms2/beatoraja/blob/master/build.xml)が使う[jbms-parser固定版の登録処理](https://github.com/exch-bms2/jbms-parser/blob/f32572b91b60690f6fb322156b471a290b23643e/src/bms/model/BMSONDecoder.java#L176-L301)を第一参照にします。[Bemuse](https://github.com/bemusic/bemuse/blob/master/README.md)は比較参考です。正常意味論、今回の不正LN回復、比較実装の役割を分け、全フィールドの不正入力処理を一つの参照へ固定しません。

channelの登録順とchannel内のstableなy順で、先に採用したplayableを維持します。同headのnormal/LN・異長LN、既存LNの内側/末尾、新LN内の登録済み位置を衝突として後続だけを進行統計から除きます。最長headの合成では先行LNを延長し、全LN終端のDistinctでは不採用LNの判定を残してしまうため、どちらも使いません。正常な同長LNとnormalのlayerは従来どおり融合します。

利用者が求める範囲は「音を維持し、ノート進行だけbeatorajaに合わせる」ことです。音声group・音源参照・再開/継続・source窓・論理表示終端を進行の採否から独立させ、孤立upも音を残します。LN競合をBGMへ降格してゲーム音声を再現する経路は追加しません。判定位置の回復を音声へ広げると、既存の全自動再生・書出しPCMを変えてしまいます。

各noteの同期ログや永続診断状態を増やさず、解析正常完了時に不採用normal/LNの件数をWARN一回へまとめます。登録は解析中のlane別順序付き集合を使い、直前headと新LNの範囲検索で衝突を判定します。全LN走査を繰り返さず、音声・UIに別のregistryを持たせません。回復条件と独立テストの対応は[bmson再生仕様](../spec/library/bmson-playback.md#不正lnの進行統計回復)を正本とします。

## 採用しない代替案と互換性の境界

| 代替案 | 採用しない理由 |
| --- | --- |
| 全曲を一つの厳密な `Fraction` で累積 | 実譜面で分母が肥大化し、時刻計算だけで秒単位とGB単位の累計割当になる。 |
| `double` だけの全曲累積 | 元の十進入力と位置比較を近似へ落とし、誤差の発生箇所と上限を明示しにくい。 |
| 小節線で端数を捨てる | bmsonの表示線は時間単位ではなく、線の追加・削除で発音時刻を変えてしまう。 |
| `chart_info` の時刻・統計を再生へ転用 | 保存情報と音声区間は責務・入力条件が違い、既存DBの受理互換性へ影響する。 |
| bmson用BMS保存行・別プレイヤー・別Writer | 保存主体を偽造し、復号・先読み・取消・音声区間の所有を形式ごとに重複させる。 |
| 音源path単位のvoice排他・slice PCMコピー | 重なりを失うか、同じ復号PCMを区間ごとに複製してメモリを増やす。 |
| 論理区間ごとの物理EOF・継続点のcursor再配置 | 量子化差で区間末尾に無音を作り、継続ノートを足しただけでPCMや音声終端を変えてしまう。 |
| 全フィールドで特定プレイヤーの処理を唯一の正解にする | 今回の不正LN進行回復は固定版を参照するが、同位置STOPなど標準と異なる処理や、ゲームの採点・操作専用の意味まで固定しない。 |

旧0.21はフィールド名と固定240pulseを正規化する入力境界で扱い、別の時計・音切り実装は増やしません。未知の新形式の版や拡張は、既知の音声構造を処理できる範囲で読む方針です。将来仕様や全プレイヤーへの完全互換を主張しません。既存の譜面情報用解析器の受理範囲も変更しません。

### 非正値BPM変更を無視する理由

[Teunim / 48 KEYS](../../BeMusicSeeker.Tests/TestData/chart_info_bmson_real/charts/75/759f8d195d0ef3bc2a8a1f861ee863fd20abc0fc7f148314cfc85275e690821e.bmson)と[同24 KEYS](../../BeMusicSeeker.Tests/TestData/chart_info_bmson_real/charts/ea/eaf8da3b6e7a0a6550dbd57dbb475b09f296fff828dc56dfce479e5cb70c1ecc.bmson)は、正の初期BPM90を持ちますが、途中にBPM0の変更イベントが各10件あります。有効な後続音符も存在し、初期値の不正や到達しない末尾ではありません。

参考とした [jbms-parserの固定版のBPM変更処理](https://github.com/exch-bms2/jbms-parser/blob/f32572b91b60690f6fb322156b471a290b23643e/src/bms/model/BMSONDecoder.java#L158-L164)は正の変更値だけを採用します。通常のbeatoraja向け譜面の実用互換のため、有限の非正値変更を無視して直前BPMを維持します。同位置の有効変更を取り消さず、min/max・丸め境界・譜面終端へも無視対象を加えません。付加的な `duration` をBPMへ推測変換する根拠はありません。初期BPMの欠落・非正値・非有限値は引き続き入力不良です。

これは参考解析器の該当ソースと固定入力を根拠とする判断です。配布プレイヤーの同梱解析器版の一致や、そのプレイヤーでの実再生を確認したものではありません。上記の実DLL全件確認には、この規則を適用した両譜面の解析成功を含みます。

## 数値入力の実用上限と共通音源候補

bmson数値は従来、字句の指数をそのままべき乗へ渡し、係数・scaleにも実用上限がありませんでした。極端な指数・桁数では時刻表現の失敗より先に巨大整数の生成で停止・メモリ枯渇へ至るため、再生用解析に限って仮数全4096桁と明示指数値±4096を採用します。一般的なbeatoraja・Bemuse（旧0.21を含む）向け譜面の実用互換を目標とし、規格上の理由だけで受理を狭めません。4096超を拒否する互換変更は、上記の処理失敗と通常用途に十分な余裕を根拠に合意した境界です。時刻方式・Fraction・BMS入力・chart_infoの受理を変更しません。指数の先頭0やscaleとの相殺まで拒否する追加条件は置きません。

共通音源ローダーは、存在する最初のファイルを選んでから復号する方式を退役し、既存候補順の最初の復号成功を採用します。壊れたwavの後に再生可能なogg/mp3がある譜面を、省略や全失敗にしないためです。サブフォルダーのmp3をbasenameのwavより優先する既存順と0frame成功を保ちます。候補段階間の曲内path結果共有は、成功だけでなく入力失敗も一回read/decodeにするための呼出しローカル状態です。永続cache・一般再試行・別decoderによる同一入力の復号救済は追加しません。PCM共有と独立voice、途中失敗を出さない最終省略、fatalと取消の全体返却を共通pipelineで扱います。
