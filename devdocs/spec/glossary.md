# 共通用語集

仕様で繰り返し使う概念の日本語名と、コード上の対応を示します。型名・列名・設定値は原表記のまま使います。ここで定義するのは語義であり、各操作の具体的な保証はリンク先の仕様を正本とします。

## アプリケーションと譜面

| 用語 | 意味 | 対応する表記・コード |
| --- | --- | --- |
| BMS | テキスト形式の譜面と、その形式固有の処理。BME・BML・PMSを含む範囲は各仕様で示す。 | BMS、`BMSFile`、LR2 `song` |
| BMSON | JSON形式の譜面。BMSの保存行へ偽装せず扱う。 | BMSON、`bmson_song` |
| 譜面共通モデル | 保存形式の違いを越えて、参照・表示・操作に使う譜面モデル。 | `ChartFile` |
| 保存モデル | DBの保存行と形式固有の値を保持するモデル。 | storage model、`BMSFile`、`bmson_song` |
| 読取りモデル | 表示や判定に必要な値を、書込み用の内部状態から分けて提供するモデル。 | read model、projection |
| 投影 | 元データから、特定の用途に必要な値を取り出した表現。 | projection、`ChartFileProjection` |
| カタログ | 管理対象の譜面とフォルダの正本。ファイルの実在確認やリソース逆引きとは別の役割。 | catalog、`OwnedChartCollectionState` |
| 所持譜面 | カタログ上で管理される譜面。未実行の導入予約や推定先だけでは所持としない。 | owned chart |
| パッケージ | 導入・保留・移動などで扱う譜面と関連ファイルのまとまり。 | package、`ChartPackage` |
| 保留 | 導入先未確定などの理由で、通常の所持譜面として導入していない状態。 | pending |
| リソース | 譜面が参照する音声・画像などのファイル。WPFリソースや翻訳リソースとは区別する。 | WAV、BMP、BGA、resource |
| 譜面情報 | 解析で得たノート数・長さ・密度など。所持行やスコアとは別に管理する。 | chart info、`chart_info` |
| 譜面形式別の保存主体 | 形式固有の保存行を保持し、値の変更に責任を持つ対象。 | storage owner |

関連仕様: [譜面モデル](library/chart-model.md)、[データと索引](core/data-and-indexes.md)。

## データの識別と索引

| 用語 | 意味 | 対応する表記・コード |
| --- | --- | --- |
| 正本 | 他の値を導く基準となるデータまたは文書。キャッシュや表示値では代替しない。 | canonical、source of truth |
| 識別条件 | 同じ対象と判断するための値と比較規則。パス・ハッシュを用途なく混同しない。 | identity |
| 完全一致 | 規定の比較で値全体が一致すること。DBのパスは原則として大文字小文字を区別する。 | exact match、ordinal |
| 正規化 | 決められた規則で表記を揃えること。用途ごとに規則を限定する。 | normalization |
| MD5・SHA-256 | 譜面等の内容から求めるハッシュ。所持識別、候補探索、外部照会で使い方が異なる。 | `md5`、`sha256` |
| 索引 | 特定のキーから必要な対象へアクセスするための構造。 | index |
| 逆引き | リソース等のキーから、それを含むフォルダや参照元を求める索引。 | reverse lookup |
| 世代番号 | 特定の状態の更新を識別する番号。用途と更新主体を定め、完了の証明には流用しない。 | version、generation、revision |
| スナップショット | ある時点で捕捉した値の集合。変更不能であることは、全件複製を意味しない。 | snapshot |
| 差分 | 操作で追加・削除・移動・変更された対象集合。全カタログと区別する。 | delta |
| キャッシュの失効 | キャッシュを再利用できなくすること。必要な入力と影響範囲に限定する。 | invalidation |
| 先行読込み | 後の処理に備え、必要な情報を事前に取得・計算すること。必須完了とは区別する。 | prewarm、prefetch |
| 遅延読込み | 必要になるまでデータ取得・計算を行わないこと。未計算と計算済みの空集合は別状態。 | lazy load |
| DB行 | DBテーブルに保存された一行。譜面数・ファイル数・逆引きキー数とは同じでない。 | row |
| 分割問い合わせ | SQLのパラメーター数などの制限に合わせ、対象集合を分けて取得・更新すること。 | chunk query、chunking |
| 入力の完全性 | 取得した集合で、対象範囲の有無を確定できること。部分結果を全件取得と見なさない。 | completeness、complete scan |

関連仕様: [パスの識別](core/path-identity.md)、[ワークフローと並行性](core/workflow-concurrency.md)。

## 責務と処理の境界

| 用語 | 意味 | 対応する表記・コード |
| --- | --- | --- |
| 管理主体 | 状態とその変更手順、結果の整合に責任を持つ型・処理。 | owner |
| DB窓口 | DBへの問い合わせ・書込みを担当する境界。 | gateway |
| 画面の枠組み | 画面全体の構成と機能の接続。個別機能の判断・保存は抱え込まない。 | shell、composition |
| 操作の入口 | 利用者要求や外部入力を受け付け、前提と対象を確定する境界。 | ingress、entry point |
| 処理経路 | 入口から管理主体、結果の反映・表示までの呼出しのつながり。 | route |
| 操作の受付 | 実行を引き受けたかを決めること。処理成功や将来の対象発見とは別。 | admission、acceptance |
| 競合拒否 | 競合する未受理要求を待ち行列へ入れずに拒否すること。 | `Busy` |
| 排他権 | 特定の変更範囲を一つの操作が使う権利。物理ロックの長時間保持とは別。 | lease、gate |
| 操作権限 | 既に取得した排他権に基づき、許可された変更を行うための証票。 | capability |
| 変更セッション | 一回の利用者操作で成功した変更を集め、正本・派生状態・通知へ反映する単位。 | mutation session、`LibraryMutationSession` |
| 確定事実 | 実際に確認した変更前後の値や成功対象。予約・推測と区別する。 | facts、confirmed change |
| 操作内の成功差分 | 後続対象の判定に先行成功を反映する一時的な情報。正本の確定の代用ではない。 | operation-local overlay |
| 永続確定 | 対象のDBやファイルへの保存が確定した段階。操作全体の成功とは限らない。 | durable commit、durable point |
| 反映 | 確定した変更を、対象のDB・メモリ状態・索引などへ適用すること。 | apply |
| 結果記録 | 確定した変更、失敗、後処理の結果を返す値。 | receipt |
| 必須反映 | 正常完了に必要な内部状態更新や処理。失敗を任意通知の失敗へ格下げしない。 | required apply、required finalization |
| 公開 | 確定状態を読取り側や通知先から参照可能にすること。 | publication |
| 任意通知 | 失敗しても既に確定した本体結果を取り消さない通知。失敗自体は観測可能にする。 | optional notification |
| 終端 | 成功・取消・失敗が決まり、必要な後片付けまで完了した地点。 | terminal |
| 補償 | 既に行った物理変更の影響を、規定の範囲で戻す処理。完全な原子性を意味しない。 | compensation |
| 前方回復 | 確認できる現在の事実から整合へ進む処理。全履歴の再実行とは異なる。 | forward recovery |
| 一時退避 | 元ファイルや上書き先を、操作が必要とする間だけ保全すること。 | staging、backup |
| 後片付け | 一時領域・予約・資源などを解放する処理。元の失敗原因と区別する。 | cleanup |
| 段階 | 起動や操作内の意味を持つ処理区間。計画の実装順番号とは区別する。 | phase |

関連仕様: [ライブラリ変更](library/mutations.md)、[ファイルとDBの整合性](library/file-db-consistency.md)。

## 並行性と画面

| 用語 | 意味 | 対応する表記・コード |
| --- | --- | --- |
| UIスレッド | WPFの画面オブジェクトを操作するスレッド。 | UI thread、Dispatcher |
| スレッド制約 | 特定の処理・オブジェクトを指定スレッドで使う制約。 | thread affinity |
| 応答性 | 画面操作・取消等に応答できる性質。変更要求の同時実行を許可する意味ではない。 | responsiveness |
| 並行性 | 複数の処理が進行し得ること。 | concurrency |
| 並列処理 | 独立した計算等を同時に実行すること。操作の受付規則とは別。 | parallelism |
| 通知の集約 | 同じ変更で重複する通知・再計算をまとめること。受理済み作業の破棄ではない。 | coalescing、batching |
| 操作可能 | 規定の操作に必要な準備が整った状態。全起動処理の完了とは区別する。 | operable、readiness |
| ヒット判定 | 座標・入力から対象の行や画面要素を求める処理。 | hit-test |
| データ連結 | 表示とモデルの値を結び付けるWPFの仕組み。 | binding |
| 画面固有処理 | フォーカス・スクロール・選択など、View側で完結する処理。 | terminal UI behavior |

関連仕様: [起動](runtime/startup.md)、[画面](ui/README.md)。

## 解析・検証・計測

| 用語 | 意味 | 対応する表記・コード |
| --- | --- | --- |
| 解析器 | 譜面を読み、ノートやメタデータへ変換する処理。 | parser |
| 補完解析 | 不足・古い譜面情報を対象に行う解析。 | backfill |
| スコアの読込み | DB等から確定データを読取りモデルへ反映すること。譜面情報の読込みも用途を明記する。 | hydration |
| 継続可能な解析異常 | 当該部分を規定どおり扱って解析を継続できる異常。 | recoverable |
| 致命的な解析異常 | 当該入力の解析結果を成功として保存できない異常。 | fatal |
| 診断 | 利用者への表示や原因調査に使う観測情報。処理結果の代用にはしない。 | diagnostic |
| テスト設計書 | 実装から独立した根拠、期待結果、許容範囲、誤実装との区別を定める作業資料。 | Test Contract Packet |
| 判定基準 | テストで結果の正否を判断する根拠。現在の実装出力だけから作らない。 | test oracle |
| テスト群 | 同じ対象・準備・資源を共有するテストのまとまり。 | fixture |
| 共通補助処理 | テスト間で共有する準備・待機・解放などの仕組み。 | helper、infrastructure |
| 検証区分 | 目的・規模・共有資源による実行の切り分け。 | lane、category |
| 検証データ集合 | 解析や性能比較に使う入力一式。 | corpus、fixture data |
| 失敗再現 | 修正前の対象経路が、仕様に反する結果になることの確認。 | red evidence |
| 識別力の確認 | 意図した誤実装をテストが見逃さないことの確認。 | negative control、targeted mutant |
| 一時的な誤実装 | テストの識別力を確認するために入れ、必ず取り除く誤り。 | mutant |
| 実時間 | 定義した開始から完了までの経過時間。CPU時間や最初の表示時間と区別する。 | wall-clock time、elapsed |
| 処理量 | 一定時間に正しく完了した仕事の量。 | throughput |
| 計測点 | 名前付きの性能記録。記録範囲と完了条件を明示する。 | marker |
| 制限時間 | 実行や失敗後の後片付けに認める上限。正常完了の待ち方とは分ける。 | deadline、timeout、budget |

関連仕様: [テスト作成](development/test-authoring.md)、[検証](development/testing.md)、[性能](core/performance-and-scale.md)。

## 外部形式と実行基盤の略語

| 用語 | この資料での意味 |
| --- | --- |
| DB・SQL・SQLite | DBは保存用のデータベース、SQLはその問合せ・更新言語。SQLiteは本アプリが利用するDBエンジン。 |
| JSON・XML・TSV | 設定・外部表等に使うデータ表現。TSVはタブ区切りのテキスト。許容する形と値は各機能の仕様に従う。 |
| URI・URL・HTTP(S) | URIは資源の識別表記、URLはアクセス先の表記。HTTP(S)はWeb通信。ローカルパスやファイルURIの許可範囲と混同しない。 |
| CRC32 | LR2のフォルダ識別等に使う32ビットの検査値。計算対象の文字列・文字コードはLR2連携仕様に従う。 |
| UTF-8・Shift_JIS・CP932 | 文字とバイト列の対応方式。CP932はWindowsの日本語コードページ。コード上の選択・エラー処理は譜面読取りとパス仕様を正本とする。 |
| UI・WPF・Dispatcher | UIは利用者との入出力、WPFはWindows用の画面基盤、Dispatcherは画面スレッドへ処理を渡す実行機構。 |
| HWND・DPI・IME | HWNDはWindowsのウィンドウ識別子、DPIは表示倍率の基礎となる密度、IMEは日本語等の文字入力を仲介する機能。 |
| Task・DTO・API | Taskは非同期処理の完了と結果を表す値、DTOは受渡し用のデータ、APIは呼出し側へ公開する操作の契約。 |
| DLL・ABI・SDK | DLLは動的に読み込むライブラリ、ABIはバイナリ間の呼出し規約、SDKは外部機能を利用する開発用の部品と定義。 |
| x64・AMD64・PE | この配布の64ビット実行対象と、Windowsの実行ファイル形式。ネイティブDLLの配置・形式検査に使う。 |
| TRX・FQN | TRXはテスト結果ファイル、FQNは名前空間・クラス・メソッドまで含むテストの完全修飾名。 |
| WASAPI・ASIO・DirectSound | 音声出力の接続方式。選択・初期化・共有資源の扱いは音声仕様で定める。 |
