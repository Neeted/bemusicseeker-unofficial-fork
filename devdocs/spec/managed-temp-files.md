# 一時ファイル管理

## 目的

プレイリスト URL 取り込みやアーカイブ導入では、ダウンロードしたアーカイブと展開済みファイルを Windows の一時領域に作成する。これらは容量が大きくなりやすいため、アプリ終了時の一括削除だけに依存せず、処理中にも不要になったものから削除する。

## 管理一時領域

アプリが所有する一時ファイルは `TempDirectoryPublisher` 経由で作成し、`%TEMP%\BeMusicSeeker\<session>\...` 配下に置く。session ディレクトリ名は `session-` で始まり、アプリ作成済みであることを示す marker ファイルを持つ。

現在プロセスが `TempDirectoryPublisher` で作成した session 配下のパスだけを「アプリ管理一時パス」として扱う。ユーザーがドラッグ & ドロップした通常のファイル、手動選択したアーカイブ、インストール済み譜面フォルダーは、同名や同内容であっても自動削除対象にしない。`%TEMP%\BeMusicSeeker` 配下にユーザーが手動で置いたファイルも、現在 session 配下でなければ管理一時パスとはみなさない。

## 削除タイミング

- 起動時
  - `Application_Startup` で mutex 取得後、過去セッションの管理一時ディレクトリ削除をバックグラウンドで開始する。
  - 起動処理は削除完了を待たない。
  - 現在セッションのディレクトリは削除対象外にする。
  - 過去 session 風の名前でも marker がないディレクトリは削除対象外にする。
- URL ダウンロード後
  - ダウンロードファイルは管理一時領域に保存する。
  - アーカイブ展開が成功し、導入処理が展開先へ切り替わった後、元アーカイブが管理一時パスなら削除する。
- アーカイブ展開後
  - 展開に失敗した一時ディレクトリは、その場で削除を試みる。
  - 展開は成功したが導入対象が見つからない、またはキャンセルで pending に残らない管理一時ディレクトリは、その場で削除を試みる。
  - pending package として保留画面に残る展開先は、ユーザー操作に必要なため削除しない。
- 保留一覧からの削除時
  - 保留 package を一覧から削除したとき、その package の `path` が管理一時パスなら削除を試みる。
  - 管理一時パスでない package は、ユーザー所有のファイルやフォルダーとして扱い削除しない。
- アプリ終了時
  - 現在セッションの管理一時ディレクトリを削除する。
  - 削除失敗はログへ残し、終了処理自体は継続する。

## 削除失敗時の扱い

一時ファイル削除は、成功すれば容量を早く回収できる補助処理であり、導入結果の意味を変えてはいけない。削除に失敗してもダウンロード、導入、保留一覧からの削除は成功扱いのままにし、失敗内容はログへ残す。

強制終了や OS 再起動では終了時 cleanup が実行されないため、次回起動時の非同期 cleanup で過去セッションの管理一時ディレクトリを回収する。
