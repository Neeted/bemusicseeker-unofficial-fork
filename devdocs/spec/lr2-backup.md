# LR2 バックアップの保存確定

## 処理の責任と呼び出し経路

LR2 連携が有効な起動処理は、`config.xml`、`song.db`、Score ディレクトリを選択し、`Backup.SaveBackupsWithResult` を呼ぶ `Task.Run` の完了を待つ。戻り値の `Saved` がデータベース最適化の実行条件となり、起動処理が警告と `FailureException` を表示する。起動順序とスレッドの責任分担は、引き続き [startup-initialization-flow.md](startup-initialization-flow.md) に従う。

## 保存契約

- 保存先ディレクトリは事前に存在していなければならない。対象コレクションが null または空の場合は保存しない。空白の対象パスは無視するが、選択済みの空白でないパスが一つでも欠落していれば保存全体を失敗とする。コピー前に対象が消失した場合も失敗とし、ファイル・ディレクトリのコピーエラーは保存の主失敗として返す。
- 日付ディレクトリは、カルチャに依存しない `yyyy-MM-dd` 形式を維持する。最新の日付世代を基準に保存間隔を判定し、間隔は日単位で最低 1 日とする。同日に保存済みなら、上書きせずスキップする。
- 既存の長パス対応ファイルシステム境界を使い、選択した全ファイルとディレクトリ配下を、最終日付ディレクトリと同じ親にある一意な staging ディレクトリへコピーする。全コピーが正常終了した後だけ、`MoveDirectory(overwrite: false)` で保存を確定する。最終パスに競合するファイルやディレクトリがあれば、それを保持して保存失敗とする。
- 保存確定前の失敗では、`Saved=false` と主例外を返し、既存世代を変更しない。今回の呼び出しで作成した staging ディレクトリが残っていれば、削除を一度だけ試みる。削除失敗時は staging パスを示す警告を追加し、主例外を置き換えない。
- 保存確定後に、日付世代を古いものから削除する。`genNum` は新しく確定した世代を含み、最低 1 に補正する。削除失敗時も `Saved=true`、`FailureException=null` を維持し、対象世代を示す警告を返す。この場合、設定数より多くの世代が残り得る。
- staging ディレクトリは日付世代に含めない。残留 staging は無視し、再利用や一括削除を行わず、後続の保存を妨げない。旧版が作成した既存の日付ディレクトリは世代として扱い、不完全バックアップの移行・検出は行わない。
- 完了が保証するのはコピー呼び出しの正常終了であり、データベースの同一時点のスナップショットや、チェックサムによる内容の整合性ではない。再試行、ロールバック、復旧用マニフェスト、属性補正は追加しない。互換 API の `SaveBackups` は保存の主例外を再スローし、それ以外は `Saved` を返す。

## 検証との対応

正本となるテストクラスは `BeMusicSeeker.Tests/BackupTests.cs` であり、承認済みのテスト契約 `B5-LR2-BACKUP-1` に従って拡張する。各テストは GUID で分離した小さな一時ディレクトリ群、ファイルロック、読み取り専用属性を所有し、保存処理の同期的な戻りを完了とする。共有設定、WPF、外部プロセス、固定待機、直列化の指定は不要で、対象を絞った Quick と通常の Functional で実行する。

| 契約 | 検証内容 |
| --- | --- |
| C1, C8 | 長パスのファイル・入れ子ディレクトリの内容、保存間隔と同日スキップ、保存先欠落と互換 API の例外伝播 |
| C2, C3 | 後続コピー対象のロック、最終パスのファイル衝突、一部・全対象の欠落、null・空コレクション、旧世代の内容保持と不完全な保存確定の防止 |
| C4, C9 | 読み取り専用の staging コピーとロックされた対象による主失敗・パス警告の保持、後続保存で残留 staging を無視すること |
| C5 | 実ファイルシステム境界でのディレクトリ衝突時に双方の内容を保持すること、保存処理での最終パスのファイル衝突 |
| C6, C7, C9 | 新世代を含む 1 世代・複数世代の保持、読み取り専用の旧世代を削除できなくても保存成功とパス警告を返すこと |

動作テストは静的レビューで補完する。保存処理の明示的な `overwrite: false` が、同じ親・同じファイルシステム上の移動経路を通って `Directory.Move` に渡ることを追跡する。競合先をマージ・削除する経路がないこと、選択済み対象の消失を黙ってスキップしないこと、保存確定前の失敗時に削除を一度だけ試みることも確認する。テストでは、競合ディレクトリの出現やコピー途中の消失を厳密なタイミングで発生させたり、削除呼び出し回数を計測したりしない。これらのタイミングを制御するテスト専用の仕組みやファイルシステム抽象化は追加しない。

警告には `Warn_FileOrDirDeleteFailed`、対象欠落の失敗には `Error_FileNotFound` を再利用する。新しい多言語リソースキーは不要である。
