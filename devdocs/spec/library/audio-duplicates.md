# 重複音源の確認と整理

## 目的と適用範囲

一つの譜面フォルダの中に、同じ名前の音源がWAVとOGGの二つの形式で置かれた状態（例：`foo.wav` と `foo.ogg`）の探索、一覧表示、同等性の確認、片方の形式の削除を定めます。フォルダをまたぐ統合は扱いません。複数フォルダの統合で生じる同名のWAVとOGGは[重複譜面の確認と整理](duplicate-files.md#wavoggの衝突整理)が扱います。

探索の結果は整理の候補であり、二つの音源が同じ内容であることを保証しません。同じ内容かどうかは、[確認](#確認)で利用者が確かめます。保留入力、導入先の一時状態、プレイリストだけの情報は対象に含めません。`.mp3`・`.flac` は探索・確認・整理のどれでも対象にせず、変更しません。

## 用語

[共通用語集](../glossary.md)を参照します。コードの識別子は原表記を使います。

| 用語 | 意味 |
| --- | --- |
| 対象フォルダ | 所持譜面を直下に一件以上持つフォルダ。所持譜面は重複検索と同じ所持集合の行（パスとMD5を持つ行）です。 |
| 所有範囲 | 対象フォルダの本体と、その配下のディレクトリのうち、別の対象フォルダとその配下を除いた範囲。配下に別の対象フォルダがあれば、そのフォルダ以下は内側の対象フォルダの所有範囲です。 |
| 衝突名 | 所有範囲の同じディレクトリに、拡張子を除いた名前が一致する `.wav` のファイルと `.ogg` のファイルが両方ある名前。対象フォルダからの相対ディレクトリと拡張子なしの名前を `\` でつないだ文字列で表します（[`DuplicateMergeVerificationResult.WavOggCollisionNames`](duplicate-files.md#wavとoggの同等性検査)と同じ書式）。 |
| 重複音源フォルダ | 衝突名を一つ以上持つ対象フォルダ。 |

名前・拡張子・ディレクトリの比較は大文字小文字を区別しません。拡張子は最後のピリオドより後ろで、`foo.v2.wav` の拡張子なしの名前は `foo.v2` です。拡張子なしの名前が空のファイル（`.wav`）は音源として数えません。同じ名前に `.mp3`・`.flac` があっても、`.wav` と `.ogg` が両方あれば衝突名です。

## 仕様

### 探索

モデルの入口は `BMSLibrary.SearchAudioDuplicateFolders` です。呼出し側が共通のライブラリ変更受付を保持している間に呼びます。

- 有効な結果があれば、探索せずに戻ります。
- 所持集合の行と登録BMSルートを、探索の開始時に一回だけ捕捉します。捕捉の後は、ライブラリのロックを保持せずに列挙と集計を行います。
- 登録BMSルートの配下の `.wav` と `.ogg` のファイルを列挙し、同じディレクトリで拡張子なしの名前が一致する組を集めます。列挙の範囲と除外は、ライブラリの走査と同じです。
- 組のあるディレクトリを、そのディレクトリ自身から祖先へたどって最初に見つかる対象フォルダへ割り当てます。対象フォルダが見つからないディレクトリの組は結果に含めません。
- 取消の要求には、列挙と集計の段階の境界で応じ、`OperationCanceledException` を送出します。取消と失敗では、途中までの結果を公開せず、保持している状態を変えません。
- 進捗は、列挙と集計の段階だけを報告します。件数は報告しません。報告は探索を実行するスレッドから同期に呼び、受け手は待たずに戻る責任を持ちます。受け手が送出した例外は探索の失敗として呼出し側へ伝えます。
- 新しい結果を格納したときは、ロックの外で、呼出しスレッドから結果の変更を一回通知します。0件の結果は空の一覧で、`null` ではありません。

#### 列挙の経路

Everythingを利用できる場合（ライブラリの走査と同じ判断）は、[ネイティブブリッジ](../../../native/EverythingBridge/README.md)の `EBridge_FindWavOggCollisions` で列挙と組の集計を行います。ブリッジは問い合わせの結果をネイティブ側でディレクトリと拡張子なしの名前ごとにまとめ、`.wav` と `.ogg` が両方ある名前だけを、ディレクトリのパスと拡張子なしの名前の組として一つの結果バッファで返します。音源の全パスを管理側へ具体化しません。パスの取得を確認できなかった問い合わせは全体を失敗とし、部分集合を成功の結果にしません。Everythingの索引に含まれない範囲の扱いは、[索引の範囲の判断](../../decisions/everything-query-boundary.md#索引の範囲を完全な走査とみなす)に従います。

Everythingを利用できない場合と、問い合わせが失敗した場合は、管理側の列挙（`FastRootFileEnumerator`）で同じ範囲を列挙し、同じ規則で組を集めます。管理側の列挙が不完全に終わった場合は、探索の失敗です。存在しない登録BMSルートのうち、ライブラリの更新前検査が存在を必須とするもの（出力基点の配下を除く登録ルート）は列挙の範囲に含めて不完全の理由にし、更新前検査が必須としないものは範囲から外します。ブリッジにこの入口がない場合と契約の不一致は、ライブラリの走査と同じく、管理側の列挙へ切り替えずに探索の失敗とします（[ネイティブ連携](../core/architecture.md#ネイティブ連携)）。

Everythingの問い合わせが成功した結果は、組が0件でも完全な結果として採用し、管理側の列挙で確かめ直しません。

衝突名とディレクトリの表記は、`.wav` のファイルの表記を使います。表記の大文字小文字は列挙の経路で異なり得るため、衝突名の同一性は常に大文字小文字を無視して比べます。

どちらの経路も、リンク（シンボリックリンクとジャンクション）の扱いはライブラリの走査と同じで、探索のための追加の確認は行いません。探索の結果は候補であり、整理の対象は[確認](#確認)が実フォルダから確定します。

#### 結果

結果は、重複音源フォルダごとに、一フォルダの `DuplicateGroup` と、探索時点の衝突名の一覧を持ちます。

| 項目 | 内容 |
| --- | --- |
| フォルダ | 重複音源フォルダ一つ。表記は、捕捉した所持集合の行の順で最初に現れた表記です。 |
| 譜面 | フォルダの直下にある所持譜面のすべてを、捕捉した所持集合の行の順に並べます。警告は捕捉時の現在値のままで、探索は警告を付与・解除せず、カタログを変更しません。 |
| 見出し | 先頭の譜面の題名です。 |
| 衝突名 | 大文字小文字を無視した昇順です。 |
| 並び | 見出しの序数順で、同じ見出しはフォルダのパスの昇順（大文字小文字を無視する序数比較）です。 |

同じ所持集合と同じファイル配置からは、列挙の経路によらず、表記の大文字小文字を除いて同じ結果を返します。

#### 結果の保持と失効

`BMSLibrary` は現在の結果を一つだけ保持し（`AudioDuplicateFolders`）、保存しません。結果がない状態は `null` です。

- 重複検索の結果が失効する契機のすべて（統合・削除・移動・導入・再調査などによる所持集合・フォルダ構成の変更、所持集合の全置換、ライブラリの解除）で、結果は失効し、変更を通知します。失効は、重複検索の結果と同じ失効点へ接続します。
- 結果は、探索に使ったリソース索引の世代を持ちます。世代が現在と異なる結果は有効な結果として扱わず、次の探索の要求で探索し直します。画面は、結果があり世代が現在と一致するかを `HasCurrentAudioDuplicateFolders` で読みます。
- 直近に格納した結果は、失効の有無によらず、次の探索でグループのインスタンスを引き継ぐための基底として保持します。新しい結果のフォルダのうち、フォルダ（大文字小文字を無視）、譜面の所持項目の識別・パス・順序、衝突名の集合（大文字小文字を無視）が基底と一致するものは、基底の `DuplicateGroup` インスタンスをそのまま使います。一致しないものは新しいインスタンスです。譜面のパスは完全一致（大文字小文字を区別）で比べます。引き継いだインスタンスは捕捉時の見出しと譜面値を保ち、並びは各インスタンスが保持する見出しで決めます。衝突名の一覧は新しい探索のものを持ちます。
- [整理](#整理モデルの入口)は、リソース索引を変えないため結果を失効させず、処理したフォルダの結果を自分で更新します。

### ツリーと一覧

メンテナンスのツリーの「分裂配置チェック」の次に「重複音源チェック」のルートを置きます。子は、[整理候補一覧](#整理候補一覧)のノード（結果が一件以上あるときだけ）、グループ（重複音源フォルダごとに一つ。見出しを表示）、その子のフォルダです。

| ツリーの選択 | 一覧 |
| --- | --- |
| 重複音源のルート | 全フォルダの譜面 |
| グループ、フォルダ | そのフォルダの譜面 |
| 整理候補一覧 | 専用の表 |

譜面の一覧は `AudioDuplicateFilterSelected` による仮想的な部分集合で、選択の値は重複と同じ `DuplicateViewContext` で捕捉します。列設定は重複の一覧と共用します（`DuplicateCustomTableColumnSettings`）。捕捉したグループやフォルダが現在の結果にない場合と、結果がない場合は空の一覧とし、別のフォルダや全件へ広げません。

ルートまたはその子を選んだときに有効な結果（`HasCurrentAudioDuplicateFolders`）がなければ、探索を始めます。入口は `AudioDuplicateSearchWorkflowOwner.SelectAsync` で、受付・進捗・取消・失敗・失効の扱いは、[分裂配置の探索](split-placement.md#ツリーと一覧)と同じです。異なる点は次のとおりです。

- 探索条件を持たず、「再探索」の入口はありません。
- 進捗は、段階だけを示す不定進捗です。

結果が失効すると、ツリーの子と一覧は空になり、自動では探索し直しません。子が消えて起きるルートの自動の選び直しは利用者の選択として扱わず、探索もBusy案内も行いません。選択済みのルートのクリックとEnterキーは、有効な結果がなければ探索を始めます。

重複のツリーにある統合操作（Ctrl+G、統合先メニュー）、同一フォルダ内の整理、整理後の自動選択は出しません。フォルダ項目の「エクスプローラーで開く」は使えます。

### 整理候補一覧

一覧は、重複の[統合候補一覧](duplicate-files.md#統合候補一覧)と同じ表を使い、表示する一覧だけを切り替えます。一行は一つの重複音源フォルダで、既定の並びは探索結果の順です。表示中は、統合候補一覧と同じく、譜面一覧の表とメインの検索欄などを表示しません。状態は重複・分裂配置の一覧とは独立に持ちます。

| 列 | 内容 |
| --- | --- |
| SELECT | チェックボックス。初期値はオフ。整理不可は操作できない。 |
| STATUS | 「未確認」、または[確認](#確認)の結果。ツールチップに該当を出す。 |
| CONFLICTS | 衝突名の数。未確認と整理不可は探索時点の数、安全と要注意は確認が確定した数。 |
| PATH、FOLDER | フォルダのパスと名前。 |
| TITLE、ARTIST | 統合候補一覧と同じ規則の表示値。 |

KEEPの列は出しません。列の幅と順序は起動中だけ保持します。

状態（SELECT、確認結果）は `DuplicateGroup` のインスタンスに対応付けます。探索し直しや整理で同じインスタンスが維持されたフォルダは状態を保ち、新しいインスタンスは初期値（未確認・SELECTオフ）、結果から消えたフォルダの状態は破棄します。ライブラリの解除・交換ですべて破棄し、永続化しません。別の画面へ移って戻っても、状態・並べ替え・検索語・除外語を保ちます。結果がない間は行を空にし、状態は捨てません。

- 並べ替え：列見出しで並べます。SELECTはオフが先、STATUSは表示文言の比較、CONFLICTSは数値の比較です。同値は既定の結果順です。
- 検索と除外：統合候補一覧と同じ検索欄と除外欄を使います。項目は path、folder、title、artist、status です。`status:` の入力候補には、この一覧の段階と理由の語（未確認、安全、要注意、整理不可、WAV/OGG非同等、リンク、解析不能）を出し、統合候補一覧の理由の語は出しません。
- 件数表示：「表示中 n フォルダ／選択 m フォルダ」。n は検索と除外を当てた後の表示中のフォルダ数、m はそのうちSELECTがオンの数です。

| 操作 | 結果 |
| --- | --- |
| SELECTのセルのクリック | そのフォルダのオン・オフ。 |
| それ以外のセルのダブルクリック、行でのEnterキー | 重複音源のツリーの対応するグループを展開し、フォルダノードを選択して譜面の一覧へ移る。現在の結果で解決できなければ何もしない。 |
| Space | 選択行のSELECTを切り替える。整理不可を除いてオンとオフが混在していればすべてオン。 |
| 右クリック | 「チェックを入れる」「チェックを外す」（整理不可は変えない）、「このフォルダを確認」、「エクスプローラーで開く」（存在する選択フォルダごとに一度）。 |

操作の行は一行で、左から次の順に並べます。優先統合先、簡易チェック、同等性検査のチェック、分裂配置の探索条件の行は表示しません。

| 項目 | 内容 |
| --- | --- |
| コンボボックス「衝突整理」 | 「OGGを残す」「WAVを残す」。既定は「OGGを残す」で、アプリの起動中だけ保持する（ライブラリを交換しても保つ）。切替えで案内は出さない。確認には使わず、整理の開始時の値を使う。 |
| 「表示中をすべて選択」「表示中をすべて解除」 | 検索と除外を当てた後の表示中のフォルダだけに作用する。整理不可は選択しない。 |
| 「選択フォルダを確認」 | 表示中でSELECTがオンのフォルダを[確認](#確認)する。 |
| 「選択フォルダを整理」 | 表示中でSELECTがオンのフォルダを[整理](#整理候補一覧からの整理)する。 |

### 確認

フォルダごとに、衝突名を実フォルダから確定し、各衝突名のWAVとOGGが同等かを判定します。読み取りだけで、ファイルとDBは変更しません。

| 入口 | 対象 |
| --- | --- |
| ツールバー「選択フォルダを確認」 | 表示中でSELECTがオンのフォルダ。0件なら、受付・進捗・案内なしで何もしない。 |
| 右クリック「このフォルダを確認」 | 選択行のフォルダを、SELECTの状態によらず対象にする。整理不可になったフォルダの再確認もここから行う。 |

受付、進捗、取消、予期しない例外の扱いは、統合候補一覧の[安全性確認](duplicate-files.md#安全性確認)と同じです。共通のライブラリ変更受付を非待機で取得し、競合時はBusy案内を一件だけ出して未開始とします。検査の開始から結果の書込みまで受付を保持し、書込みの後、結果の案内の前に解放します。確認中はモーダルの進捗に「[何番目/総数] フォルダ名」を示します。取消は、処理中のフォルダを最後まで処理して書き込んでから止まり、着手しなかったフォルダの確認結果とSELECTは変えません。

フォルダの検査は次の順に行います。走査と読取りはUIスレッド外でフォルダごとに逐次行い、モデルのロックとDBトランザクションを保持したままファイルを読みません。

1. フォルダの本体がリンクなら、整理不可（リンク）です。フォルダが存在しない場合と、属性の取得に失敗した場合は、整理不可（解析不能）です。どちらも以降の手順を行わず、衝突名の一覧は空です。
2. 所有範囲を一回列挙します。リンクの先へは入らず、配下の別の対象フォルダ（確認の開始時に捕捉した所持集合で判定）以下へも入りません。隠し・システム属性のファイルとディレクトリを含みます。列挙の失敗は整理不可（解析不能）で、該当するパスを持ちます。
3. 列挙したファイルから衝突名を求めます。リンクのファイルは音源として数えません。
4. 衝突名ごとに、WAVとOGGを[WAVとOGGの同等性検査](duplicate-files.md#wavとoggの同等性検査)の判定（二つの音源の判定の手順、しきい値、復号の方法）で比べます。復号できない音源を含む名前は同等でないものとして扱います。読取りの入出力の失敗は整理不可（解析不能）で、該当するパスを持ちます。一つのフォルダの中では、衝突名を論理プロセッサ数を上限に並列で処理します。

確認結果は、段階、理由ごとの該当、衝突名の一覧、同等と判定した衝突名の一覧を保ちます。

| 段階 | 条件 | STATUSの表示 |
| --- | --- | --- |
| 整理不可 | リンクまたは解析不能の理由がある。二つの理由は同時に成立しない。整理不可の結果は、衝突名の一覧と同等と判定した一覧を空にする。 | 「整理不可：リンク」「整理不可：解析不能」 |
| 要注意 | 整理不可でなく、同等と判定しなかった衝突名が一つ以上ある。 | 「要注意：WAV/OGG非同等」 |
| 安全 | 整理不可でなく、すべての衝突名を同等と判定した。 | 「安全（WAV/OGG同等）」。衝突名が0件なら「安全」 |

STATUSのツールチップは、要注意では同等と判定しなかった衝突名を昇順（大文字小文字を無視）に出し、10件を超える分は「ほか{n}件」と省略します。同等と判定した衝突名が一つ以上あれば、段階によらず末尾に「同名のWAVとOGG {n}組を同等と判定しました。」を出します。整理不可では理由の説明と該当するパスを出します。

結果は次のとおり反映します。

- 確認を終えたフォルダのSELECTを、段階によらずオフにします。整理不可はオフで無効です。再確認で整理不可でなくなれば、オフのまま操作できる状態に戻ります。取消で着手しなかったフォルダと、予期しない例外で確認を終えなかったフォルダのSELECTは変えません。
- 確認中に状態表から消えたフォルダの結果は捨て、結果の案内のどの件数にも数えません。
- 確認の終端で、結果を一度だけ案内します。「{n}フォルダを確認しました。安全 {a}／要注意 {b}／整理不可 {c}。」で、取消で着手しなかったフォルダがあれば末尾を「／未確認 {d}。」にします。確認を終えたフォルダが0件なら案内を出しません。

### 整理（モデルの入口）

モデルの入口は `BMSLibrary.OrganizeAudioDuplicateFolders` です。要求は、順序付きのフォルダの列、取消の合図、進捗の受け手（任意）で、フォルダごとに、捨てる形式（`.wav` または `.ogg`）と対象の衝突名の一覧を持ちます。

一回の整理は一つの共通受付で行います。音源キーの集合は変わらないため、変更セッションを開かず、カタログ・DB・索引・LR2同期への反映と必須保守を行いません。Busy、カタログ未収束、管理出力の保護を取れない場合は、重複グループの一括整理と同じく、物理変更の前に操作全体を未適用で返し、全フォルダを「未処理」にします。管理出力の保護は、要求の全フォルダの和集合を、最初の物理変更の前に一回だけ取ります。

フォルダごとの処理は次のとおりです。

- フォルダの本体を `FolderLinkInspector.InspectFolder` で検査し、リンクが見つかる、または確認できない場合は、そのフォルダを理由付きで「スキップ」にします。フォルダが存在しない場合、パスが空または正規化できない場合も「スキップ」です。スキップではファイルを変えず、次のフォルダへ進みます。
- 衝突名ごとの観測と削除は、[WAV・OGGの衝突整理](duplicate-files.md#wavoggの衝突整理)の規則（残す形式・捨てる形式の順の観測、観測の結果の三分類、リンクの扱い、削除の窓口）と同じで、同じ部品を使います。両方がファイルとして実在する名前だけ、捨てる形式のファイルをごみ箱へ送ります。音源を復号・比較・読取りし直しません。
- 個別の観測と削除の失敗は停止の理由にせず、そのファイルを残して数え、次の名前へ進みます。

| 状態 | 条件 |
| --- | --- |
| 完了 | 送れなかった音源（削除の失敗と、実在を確認できなかった名前）がない。送った数が0件でも完了。 |
| 一部完了 | 送れなかった音源が一件以上ある。 |
| スキップ | 書込み前の拒否。 |
| 未処理 | 取消、操作全体の未適用、または予期しない失敗による停止で、開始しなかった。 |

取消はフォルダの開始前にだけ確認します。処理中のフォルダは最後まで進み、残りのフォルダは未処理になります。名前ごとの観測と削除の例外は、共用の部品の規則どおり送れなかった数に数えて続行します。部品が受けない例外は、結果を返さずに呼出し側へ伝え、探索の結果を更新しません。

進捗は、取消の確認の後、フォルダの開始ごとに1始まりの番号・総数・フォルダを同期で受け手へ渡します。モデルのロックを保持したまま呼ばず、受け手の例外で結果を変えません。結果は、要求と同じ順のフォルダ結果（フォルダ・状態・スキップ理由・ごみ箱へ送った数・送れなかった数）、取消されたか、受付を取って処理を始めたかです。フォルダごとの結果は、受付の解放後にログへ記録します。

全フォルダの処理の後、保持している探索の結果を次のとおり更新し、変更があればロックの外で一回通知します。結果がない場合と、世代が現在と異なる場合は更新しません。

- 完了・一部完了のフォルダの衝突名を、送れなかった名前（削除の失敗と、実在を確認できなかった名前）だけにします。要求の名前は確認が実フォルダから確定した一覧なので、ごみ箱へ送れた名前、どちらかが存在しない・ディレクトリであると観測した名前、要求に含まれない探索時点の名前を、すべて除きます。
- 衝突名が残らないフォルダは結果から除きます。完了のフォルダは、要求の名前が0件でも結果から除きます。
- 衝突名の集合（大文字小文字を無視）が変わって残るフォルダは、新しい `DuplicateGroup` インスタンスにします。集合が変わらないフォルダ、スキップと未処理のフォルダは、同じインスタンスのままです。

### 整理候補一覧からの整理

ツールバー「選択フォルダを整理」は、表示中でSELECTがオンのフォルダを、上の[モデルの入口](#整理モデルの入口)で一回の操作として整理します。確認・再生停止・進捗・結果の案内・失敗の報告は専用の手順の主体が扱い、`MainWindow` はクリックの接続と想定外の例外の通知だけを担います。確認を再実行せず、確認結果を書き換えません。

#### 対象と受付

要求のフォルダの順は、並べ替えと検索を当てた後の表示順です。対象が0件なら何も行いません。

対象に「未確認」のフォルダが一つでもあれば、先に確認を行うよう案内を一件出し、整理を始めません。受付の取得、確認の表示、再生停止、モデルの呼出しを行わず、SELECTと確認結果を変えません。整理の対象の衝突名を、確認が実フォルダから確定した一覧に限るためです。

共通のライブラリ変更受付は待たずに取得します（[操作の競合ポリシー](../core/operation-concurrency-policy.md)）。競合時はBusy案内を一件だけ出して未開始とし、状態を変えず、予約しません。受付が閉じている場合は案内せずに未開始とします。

フォルダごとの要求は、捨てる形式（「OGGを残す」なら `.wav`、「WAVを残す」なら `.ogg`）と、捕捉時点の確認結果の衝突名のすべてです。同等と判定していない衝突名も含みます。

#### 確認ダイアログ

受付の取得後、確認を必ず一回表示します（OKとキャンセル、既定はキャンセル）。統合の確認を表示しない設定（`ShowDuplicateFileCheckConfirmMsg`）でも表示します。キャンセル・閉じる・表示の失敗では、再生停止・進捗・モデルの呼出しへ進まず、受付を解放して状態を変えません。表示の失敗は一回だけ報告します。

確認文は、通常の本文と、警告色で表示する警告用の本文（`UiMessageRequest.WarningMessageBoxText`）に分けます。

| 本文 | 行 | 条件 |
| --- | --- | --- |
| 通常 | 「{n}フォルダにある、同名のWAVとOGG {k}組を整理します。」（kは対象の衝突名の合計） | 常に |
| 通常 | 「OGGを残し、WAVをごみ箱へ送ります。」（「WAVを残す」では形式を入れ替えた文） | 常に |
| 警告用 | 「要注意 {c}フォルダを含みます。」 | 要注意が一件以上あるとき。このときダイアログのアイコンは警告（なければ質問） |
| 警告用 | 「{c}フォルダは、同等と判定されていない同名のWAVとOGGも、一方だけを残します。」 | 要注意が一件以上あるとき |

対象に要注意のフォルダがある場合だけ、「要注意フォルダの整理を続行する」を未チェックで表示します。OKはチェック中だけ有効です。

#### 実行と終端

承認後は、モーダルの進捗（取消ボタンつき。取消の扱いを操作へ任せる設定）を開き、その内側で、再生の停止、モデルの呼出し（UIの文脈の外）の順に進みます。再生停止の失敗・取消ではモデルを呼びません。進捗は「[何番目/総数] フォルダ名」を示し、最新の値だけを間引いて画面へ渡します。受付は、モデルの終端まで保持し、結果の案内の前に解放します。受付を保持したままUIの完了を同期的に待ちません。

- 操作全体が受理されなかった場合は、既存の拒否の案内だけを一回出し、結果の案内を出しません。
- 再生停止の失敗・モデルの例外など、モデルの結果がない経路は、報告を一回だけ出し、結果の案内を出しません。
- 結果は最後に一回だけ案内します。「{n}フォルダを整理しました。完了 {a}／一部完了 {b}／スキップ {c}／未処理 {e}。」（0件の区分も出す）に、ごみ箱へ送った音源の合計が一件以上なら「WAV・OGGの音源 {t}件をごみ箱へ送りました。」、取消されていれば「取り消されました。」を続けます。完了以外のフォルダは、要求順に最大20フォルダまで「フォルダのパス：状態（理由）」を並べ、超える分は「ほか{n}フォルダはログを確認してください。」とします。理由は、スキップは拒否の理由、一部完了は「削除の失敗」です。

モデルが操作を受理して結果を返したら、対象のフォルダのうち「未処理」以外のSELECTをオフにします（一覧に残る場合）。整理候補一覧を表示したまま作り直し、別の画面へ自動で移りません。衝突名が残らないフォルダは一覧から消え、同じインスタンスのまま残るフォルダは確認結果を保ち、新しいインスタンスになったフォルダは初期値（未確認・SELECTオフ）になります。結果が0件になった場合は、一覧の行が0件になり、整理候補一覧のノードが消えます。ノードが消えた後のツリーの選択の移動は、既存の動きに従います。

### 性能

[代表規模](../core/performance-and-scale.md#代表規模)で、探索は音源の全パスを管理側へ具体化しません（Everythingを利用できる場合）。組の集計はネイティブ側で一回の整列または一回のハッシュ表の走査で行い、管理側は、組のあるディレクトリだけを対象フォルダへ割り当てます。ディレクトリから対象フォルダへの割当ては、対象フォルダの集合への問合せを祖先の段数だけ行い、所持集合の全件走査を組の数だけ繰り返しません。

計測する完了範囲は、探索の要求から結果の公開までです。`SearchAudioDuplicateFolders` は、列挙の経路、組の数、重複音源フォルダの数、引き継いだインスタンスの数と、捕捉・列挙・集計の所要時間を診断へ記録します。列挙したファイルのヒット数と、Everythingから管理側の列挙へ切り替えた場合はその理由も記録します。
