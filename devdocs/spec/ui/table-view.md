# 一覧の描画・操作・仮想化

## 目的と適用範囲

譜面、プレイリスト詳細、履歴、プレイリスト一覧で使う `CustomTableView` と、その行を供給する一覧の管理主体の契約を定めます。表示・選択・キー操作・セル編集・スクロールと、大規模な一覧を可視範囲だけで扱うための入力の捕捉・局所更新・採用の境界を扱います。

列の保存値と既定値は[列と既定値](table-columns.md)、データの正本と更新は[譜面モデル](../library/chart-model.md)と[データと索引](../core/data-and-indexes.md)、プレイリストの保存は[保存仕様](../playlist/storage-and-export.md)、外観の共通部品は[外観](appearance.md)に従います。

## 用語

[共通用語集](../glossary.md)を参照します。

| 用語 | 意味 |
| --- | --- |
| 表示先 | 一覧が表示する対象の種類。通常一覧、プレイリスト詳細、履歴、プレイリスト一覧、保守・重複・導入済み・保留などの対象集合。 |
| 元集合 | 表示先が絞込み・並べ替えの前に持つ行の集合。 |
| 採用入力 | 一覧の管理主体が捕捉し、表示に採用した変更不能な入力と、その順序。後から実体化する行も同じ採用入力を使う。 |
| 実体化 | 添字の行について、表示用の行オブジェクトを作ること。 |
| 主行 | 選択集合のうち現在の行。`SelectedIndex` が指す。 |
| 現在セル | 主行の中で、描画・単一セルのコピー・編集開始の対象となる列。 |
| 範囲基点 | Shiftによる範囲選択の起点。 |
| 未確定の入力 | セル編集中の入力。保存されるまで正本と表示用の入力を変更しない。 |
| 表示要求 | 一覧の管理主体へ、行集合・順序・条件の構築と採用を求める要求。 |
| 保持範囲 | 表が行参照・表示値・セル描画を保持する範囲。可視行と上下の余裕行から成る。 |

## 仕様

### 表示の構成

`CustomTableView` は可視範囲をコードで描画する表です。画面には次の二つの表があり、表示先に応じて切り替えます。

| 表 | 行 | 列設定 |
| --- | --- | --- |
| メインの `customTableView` | `MainChartList.Rows` | `MainChartList.ColumnsSettings` |
| プレイリスト一覧の `customTablePlaylistSummary` | `PlaylistSummaryView` | 専用の列設定 |

行の高さは19、見出しは22、文字サイズは11が既定です。外観設定は両方の表へ反映します。メイン一覧のスコア表示には `SovjetBox` を使い、クリア、DJ LEVEL、難易度、判定、履歴のクリアとBEST DJは、`CustomTableTextStyle.Score`、現在の文字サイズ、縦補正 `1d` を共用します。

並べ替え状態は、通常一覧と履歴で共通の `MainChartList.SortParameters`（`MainChartListSortPresentation`）として公開し、表示先（通常一覧・プレイリスト詳細、履歴）ごとに設定します。プレイリスト一覧は独立した `PlaylistSummarySortParameters` を使います。

### 数値・日時の表示と整列

一覧の数値は、文化圏によらず小数点を `.`、桁区切りなしで表示します。各列の丸め・割合の精度・未取得の表示は列ごとの規則に従います。日付はGregorianの `yyyy-MM-dd`、秒単位の日時は `yyyy-MM-dd HH:mm:ss` です。描画・コピー・表示値を使う検索は同じ値を参照し、表示の更新だけで元の値を再解釈・保存しません。

LEVELの整列は型付きの数値キーを優先し、文字列から読む必要がある場合だけ固定の文化圏で読みます。自然順の数値部分も `.` の固定の文法で比較し、名称やパスの比較方法は変えません。ENTRY LEVELの編集の初期値と受理する文法は[保存仕様](../playlist/storage-and-export.md)に従います。

### スクロール領域

描画面とセル編集面は表の全面を共有し、共通スクロールバーを前面へ重ねます。専用の行・列、固定の余白、ダミー列、不透明な交点は設けません。バーの表示の切替で、描画領域やセル座標の幅・高さを変えません。

バーの見た目と、固定16 DIPの入力領域は[外観のスクロールとフォーカス](appearance.md#スクロールとフォーカス)に従います。表が所有する縦横2本は、一覧用の `App.Canonical.ListScrollBarStyle` を明示して使います。背景の幅、つまみの太さ、メイン画面内の外枠補正は、いずれも16 DIPの入力領域、有効表示幅、完全表示行容量、最終行・最右列の露出の計算を変えません。

#### 横方向の範囲

全面の実幅をW、表示列の合計幅をEとします。

| 値 | 算式 |
| --- | --- |
| 有効表示幅 | 縦バーが必要なら `max(0, W − 16)`、不要ならW |
| 横の最大値 | `max(0, E − 有効表示幅)` |
| 横バーの表示条件 | `E > 有効表示幅 + 0.5` |

ViewportSizeとセルの露出判定にも同じ有効表示幅を使います。横バーを表示しない場合も、算式上の小さい最大値を0へ置き換えません。途中位置で右端のセルが縦バーの背後に入ることは許容し、最大位置では最右列の右端をバーの左端まで出せます。描画と列境界の座標系は全面の実幅を使います。

#### 縦方向の範囲

縦方向は行単位です。完全表示行容量は、本体の高さ（全面の実高 − 見出しの高さ）から、横バーが必要な場合だけ16 DIPを引き、行の高さで切り捨てて求めます。極小の場合も最小一行とします。縦の最大値は `max(0, 行数 − 完全表示行容量)` とし、縦のViewportSizeと最終行の露出判定も同じ容量を使います。描画する行数は全面の本体の高さを行の高さで切り上げ、部分表示の行と既存の余裕行を保ちます。

#### 両軸の要否

縦横の要否は、毎回バーなしの実寸法から判定を始め、有効寸法に応じて必要な軸を追加し、変化がなくなったところで確定します。前回の表示状態は判定に使いません。行列・行の高さ・寸法が変わると範囲を再計算し、現在位置を範囲内に収めます。

見出しと行の高さが20、幅100、高さ120の場合の例です。

| 表示列の合計幅E | 行数 | 結果 |
| ---: | ---: | --- |
| 90 | 5 | バーなし |
| 80 | 6 | 縦のみ |
| 120 | 4 | 横のみ |
| 90 | 6 | 両軸（横の最大6、縦の最大2） |
| 101 | 5 | 両軸（横の最大17、縦の最大1） |

### 保持範囲とセル描画の再利用

入力の行がnullの位置は空けたまま、列の値を取得せずに空のセルと通常の行背景・罫線を描きます。

全面の描画行（部分表示の行を含む）と上下各5行を保持範囲とし、行参照・変更通知の購読・表示値・警告・セル描画で共通に使います。

- 変更通知に対応しない行も参照を保持します。同じ行参照が複数の位置にある場合は、最後の参照が範囲から離れるまで値を保ちます。
- 範囲が移動しても残る行の値は失効させず、完全に離れた行の値と描画を破棄します。
- 画面外の行や列の値・描画を先行して作りません。

行参照ごとに、要求された列の表示値、警告値、表示位置ごとのセル描画を保持します。縦スクロールで値・選択・現在セル・描画環境が変わらなければ、セル群の配置だけを変えて再利用します。同じ行参照が複数の位置にある場合も、位置ごとの選択・現在セルの状態を混同しません。保持範囲を離れた位置の描画は、同じ行参照が別の位置に残っていても破棄します。

性能のため、文字レイアウトは上限つきのFIFOで共有し、行描画の再利用時には再検索しません。セル単位のFIFO、別の警告辞書、全セルキーの走査による行の失効、専用のアイコンやGeometryのキャッシュは使いません。

行背景・横罫線・挿入線は毎回描きます。

- 行背景は、選択、警告、交互色の順で決めます。セル固有の背景は非選択の行だけに描き、その上に現在セルの背景を描きます。
- 通常の文字色は、現在セル、選択、セルの通常色の順で決めます。色付きの区間は、選択・現在セルでも区間の色を保ちます。
- 最下部の部分表示の行は描画面で切り取り、横罫線の完全可視の判定は画面座標で行います。部分表示の行として作ったセル群を通常の行として再利用しても、文字・背景・縦罫線を欠かしません。

| 更新条件 | 値・警告 | セル描画 |
| --- | --- | --- |
| 縦スクロールで保持範囲に残る行 | 保つ | 同じ表示状態なら配置だけを変える |
| 行の変更通知・編集終了 | 対象行だけを破棄する | 同じ行の全表示位置を作り直す |
| 選択・現在セルの変更 | 保つ | 表示状態が変わった位置だけ作り直す |
| 元集合の交換・コレクションの変更・表示更新（`RefreshDisplay`）・列定義の交換や再構築 | 全行を破棄する | 全行を作り直す。同じ列IDでも旧定義の値を使わない |
| 横位置・幅・列配置・行の高さの変更 | 保つ。列定義を交換した場合は上の行に従う | 現在の可視列だけを作り直す |
| 高さ・見出しの高さだけの変更 | 続けて保持する行は保つ | 行の配置と保持範囲を再計算し、幅・行の高さが同じならセル群を再利用する |
| 文字サイズ・スコアの書体・DPIの変更 | 保つ | 文字の配置とセル群を作り直す |
| `CurrentCulture`・`CurrentUICulture`・テーマの変更 | 整形済みの数値・日付・ブラシも更新する | 文字の配置とセル群を作り直す |
| アプリの表示言語の変更 | 現在の言語で整形済みの値を更新する。WARNING列の要約とツールチップも、警告の種類と事実から読取り時に現在の言語で作る | 文字の配置とセル群を作り直す |
| 非表示・購読の終了 | 保持行と通知待ちを破棄する | 破棄し、再表示で最新値から作る |

行の変更通知は通知待ちの一覧で重複を除き、Dispatcherへまとめて配送します。通常のスクロールで通知待ちを消しません。変更通知に対応しない行の書換えは監視せず、コレクションの通知・表示更新・保持範囲からの完全な離脱・非表示の時点で再取得します。

差替えの待機中と空の一覧では本文を描かず、旧い行のセル群を表示に戻しません。行単位のスクロール、ツールチップ・編集・ドラッグなどの入力の契約は保ちます。横スクロールでは可視行のセル群を作り直し、全列の先行描画は行いません。

#### 表示言語の変更

アプリの表示言語の変更はスレッドの文化圏を変えないため、表は画面に読み込まれている間だけ、表示リソースの変更を購読します。画面から外れたら購読を解除し、UIへ反映するときにも読み込まれていることを確認します。

- 表示値・文字の配置・描画のキャッシュを失効させ、`INSTL DST` の保留候補の案内とツールチップを現在の言語にします。開いている旧いツールチップは閉じ、次の通常の取得で新しい言語を使います。
- 行集合・元集合・表・列とその幅、選択・現在セル・スクロール位置を保ち、編集中の入力欄・候補一覧・未確定の入力・モデルの生のパスを変えません。編集の確定、フォーカスの移動、列の再構築を起こしません。後の明示的なEnterだけが、開始時の行・属性・現在の入力を一回渡します。
- 旧い言語の写し、翻訳のキャッシュ、行ごとの購読、全行の評価・再検索は追加しません。再び読み込まれたときは、既存の初期表示の同期で最新の言語を使います。画面から外れた編集中の入力欄の保持は保証しません。

一覧上部の経路の表示は、選択を保ったまま言語を変えると、見出しと同じ現在の言語に更新します。利用者が付けた名前・区切り・省略の規則は変えません。翻訳対象の列見出し（`InstallDstTitle`、`InstallDstArtist`、プレイリスト一覧の `Status`）は、読取りのたびに現在のリソースから取得し、列・行・幅・並び・編集中の入力を作り直しません。

プレイリスト一覧の見出し（`GridHeaderText`）と自動の件数表示（`PlaylistSummaryText`）は、一覧の表示期間の購読が言語の変更を受け、画面へ反映済みの集計（`PlaylistSummaryView` の譜面合計と行数）と表示モードから現在の言語で整形し直します。

- 一覧の表示要求が採用前の間、一覧を離れた後、購読の解除後、メイン画面の閉鎖後は何も通知しません。UIへの適用を待つ結果は混ぜず、後の採用時に現在の言語で表示します。
- 明示的な `SummaryText` は自動の件数表示と区別して保持し、見出しだけを更新します。
- 行・元集合・選択・検索・並べ替え・要求の世代・処理回数は変えず、一覧の再構築・再検索・表示の再要求をしません。
- 一覧のSTATUS列とツールチップは、行が保持する同期状態の事実（種別・確認日時・取得元・診断とエントリの読込み済みか）から、読取りのたびに現在の言語で作ります。表に新しい購読は持たせません。

#### 描画環境

DPIは変更通知と描画開始時の確認で追従します。配色・DPI・書体・文化圏・文字サイズ・横方向の条件は描画の回ごとに解決します。詳細な性能記録が無効なら、セルごとの時刻を取得しません。初回表示の通知の行数・セル数は可視範囲を表し、その回に作り直した件数に置き換えません。文字の配置のヒット数は実際の検索だけを数えます。

### 外観の更新

コードで描画する部分は、`CustomTablePalette` がテーマのリソースを描画用の色と線へ変換します。テーマを変更すると描画色とキャッシュを更新します。内蔵スクロールバーも共通の `ScrollBar.*` リソースに従い、一覧用の不透明な背景は `ScrollBar.TrackBackgroundBrush` の切替に追随します。表・行・列を作り直さず、選択・現在セル・スクロール位置・編集中の入力を保ちます。

一覧の見出しの上端には `Table.HeaderGridLineBrush` による1 DIPの線を表示幅全体に描きます。線の中心は上端から0.5 DIPに置き、端で半分が欠けないようにします。通常一覧とプレイリスト一覧とも、保留・プレイログの追加のツールバーや、表示列・データ行の有無によらず上枠を表示し、追加のツールバー側には下枠を重ねません。データ行の罫線・行の高さ・スクロールの計算は変えません。

### 選択とキー操作

#### マウスによる選択

| 操作 | 結果 |
| --- | --- |
| 通常クリック | 単一選択 |
| Ctrl+クリック | 選択の切替 |
| Shift+クリック | 範囲選択 |
| 右クリック | 対象行を選択へ含めてメニューを要求する。選択済みの行なら、選択集合と範囲基点を保ち、主行だけを対象行へ移す。 |
| 空白・スクロールバーの操作 | 選択と現在セルを変えない。 |

画面の状態は `CustomTableSelectionModel` と双方向の `SelectedIndex` で同期します。

#### 選択の通知

選択の変化は、選択集合または主行の変化です。`CustomTableSelectionModel` の判定結果を表の `SelectionChanged` へ接続し、一つの入力につき一回通知します。

- Ctrl+Aの後にShiftで末尾へ移る場合のように、集合が全行のままでも主行が変われば通知します。
- 集合と主行が同じ反復入力、範囲基点だけの変更、同じ行の操作列だけの変更は通知しません。範囲基点だけが変わる操作でも内部の基点は更新し、次のShift操作に反映します。

停止中のヘッダーの更新と、再生中の現在曲の優先は[再生パネルの表示する内容](playback-panel.md#共通の再生対象と一覧状態)に従います。

#### 押下時の現在セル

セルを左右のボタンで押すと、行の選択の結果と押した列を、選択の通知と行メニューの要求より前に現在セルへ反映します。

- 同じ行の別の列を押しても、現在の列と描画を更新します。
- Ctrlで押した行の選択を外した場合は、選択モデルが選ぶ残りの主行へ押した列を引き継ぎ、選択が空なら現在セルも解除します。
- AのセルをクリックしてからBの別の列を右クリックした直後のF2・文字入力・単一セルのコピーは、Bのその列を対象にします。編集開始の時点まで同期を遅らせません。

#### 外部からの主行の変更

再生候補の採用など、外部からの `SelectedIndex` の入力で実際に主行が変わる場合は、次の順に処理します。

1. 旧い主行Aの編集中の入力を、旧い属性で一回確定（`CommitActiveEdit` / `CellEditEnded`）します。保存のTaskは同期的に待ちません。
2. 最新の主行Bを可視化し、現存する同じ列へ現在セルを移します。Bへ未確定の入力を付け替えたり、編集欄を自動で開いたりしません。

- 編集の終了に伴う同期的な並べ替えでBの添字が変わる場合は、入力された旧い添字を使わず、識別で復元した後の主行を使います。
- 同期の通知で押下の対象が消えた場合だけ、同じ元集合で捕捉した列IDを引き継ぎます。同じ順序付きIDで列定義が作り直されても同じ列とし、再入で作られた現在セルを優先します。元の列が消えたら先頭の表示列とし、0行・0表示列・選択の解除では古い対象を残しません。

外部から同じ主行が入力された場合は、編集欄・未確定の入力・現在セル・手動のスクロール位置を保ちます。主行が変わらない一時停止・再開・停止・時刻・表示の更新も同じです。内部の選択の逆通知と識別による復元は通常の経路を使い、再生状態やコピー・編集の各入口へ個別の補正を加えません。次の詳細の編集の受付は、先行する保存の終端まで[詳細の編集開始の制限](#詳細の編集開始の制限)に従います。

#### 確定変更の前後での選択の保持

通常一覧と専用の譜面一覧は、カタログ・スコア・参照・譜面情報の確定変更の前に、選択集合・主行・範囲基点を譜面の識別で捕捉し、最終的な順序で復元します。

| 状況 | 復元 |
| --- | --- |
| 主行の添字が変わらない | 副選択を旧い添字で転用しない。 |
| 主行だけが消えた | 残った選択の表示順で先頭を主行にする。 |
| 範囲基点が消えた | 主行に寄せる。 |
| 選択がすべて消えた | 解除する。未選択の譜面を代わりに選ばない。 |

後続の削除・移動は、この復元済みの選択集合から要求を作ります。

同じ元集合の再評価・並べ替え・絞込みで `SelectionPolicy.Preserve` を指定した行の差替えも同じ規則を使います。明示的な `Reset` は選択を解除します。別の区分・重複群・フォルダ・パッケージなど異なる元集合への差替えでは、旧い選択と主行を解除し、旧い添字を新しい集合の選択へ転用しません。プレイリスト一覧・詳細には、この識別による復元ではなく[プレイリストの選択の識別](#プレイリストの選択の識別)を使います。

行の識別は、通常一覧では所持項目の識別、専用の一覧ではパッケージ項目・所持項目の識別・未所持譜面の形式とパスです。専用の一覧の逆引きは、初回の依存の登録と同時に作ります。更新時は選択と範囲基点だけを索引で照合し、非選択の行の実体化や、選択を保つための全件走査を増やしません。並びに影響しない変更では、同じ編集欄と未確定の入力を保ちます。

#### キー操作

| キー | 操作 |
| --- | --- |
| 上下 | 行の移動 |
| Enter | 現在行の操作 |
| F2・文字入力 | 編集の開始 |
| Ctrl+A | 全選択 |
| Ctrl+C | 現在セルのコピー |
| Ctrl+Shift+C | 選択行のTSVのコピー |
| メニューキー | 行メニュー |

コピーは編集用の値（`GetEditText`）を使い、URLやリンクのアイコン・表示用の文字列ではなくURLそのものを取得します。履歴のMD5/SHA256も通常の列から同じ経路でコピーし、行の交換後は現在の行・列の値を渡します。ハッシュ専用のメニューは持ちません。取得元ごとの値と列設定は[履歴](../playlist/play-history.md#外部操作と診断)に従います。

再生開始の通知による表へのフォーカスの復帰は[再生パネルの面の要求とフォーカス](playback-panel.md#曲の準備開始と次候補)に従い、通知の受信時の一回の要求で終わります。その後に始めた検索・セル編集には追加の要求を出さず、検索の候補・選択・未確定の編集を保ちます。

#### 左右の移動

未編集中の修飾なしの左右キーは、現在行の表示列の順で直前・直後のセルへ移ります。

- 非表示の列を飛ばします。現在行に対応する現存の列の現在セルがなければ、右は先頭の列、左は末尾の列から始めます。古い行のセルは起点にせず、列・データの差替えを越えて現在の列を復元する状態は持ちません。
- 端から外向きの左右は受理しますが、折り返しやスクロールをしません。端のセルが手動のスクロールで画面外にあっても再表示しません。
- 未選択・0行・0表示列では受理せず、現在セルとスクロールを変えません。
- 行の選択集合・主行・`SelectedIndex`・範囲基点を保ち、`SelectionChanged` を送りません。

上下・Shift+上下は行の選択を行い、移動前の列が現存すればその列を引き継ぎ、なければ先頭の表示列へ戻ります。0表示列では現在セルを設定しません。手動のスクロールでは現在セルの識別を保ち、次の左右の起点にします。実際に別の列へ移る場合は現在行も可視範囲へ戻します。描画・単一セルのコピー・F2と文字入力による編集は同じ現在セルを参照します。

編集中の左右はテキスト入力欄へ渡し、表の移動・スクロール・編集の確定を行いません。スクロールバーで操作中の左右を奪わず、Ctrl/Shift/Alt付きの左右には表の操作を割り当てません。

#### 列の横の可視化

左右と上下で、列の横の可視化の規則を共有します。

| 列と状態 | 横位置 |
| --- | --- |
| 表示幅以下の列が全体見えている | 保つ |
| 表示幅以下の列が隠れている | 必要最小量だけ動かして全体を表示する |
| 表示幅を超える列へ右方向に進む | 列の左端を表示する |
| 表示幅を超える列へ左方向に進む | 列の右端を表示する |
| 上下の移動で、広い列の一部が見えている | 保つ |
| 上下の移動で、列が完全に右へ隠れている／左へ隠れている | 左端／右端を表示する |

横位置はスクロールバーの範囲内に収めます。配置前の幅0の列でも、無限大などの不正な値や無効なセルを作りません。可視化した後の配置からセルの位置を求め直し、以前の矩形を流用しません。

#### コピーの整形

コピーするときだけ、各セルのUnicode制御文字（U+0000–001F、U+007F–009F）を1文字につき半角空白1個へ置換します。NUL以降の文字と後続の列・行、通常の文字・既存の空白・制御文字以外のUnicodeは保ちます。null・空のセルは空文字にします。単一セルと選択行のコピーは同じ整形を使い、TSVの列区切りのTABと行区切りのCRLFは保ちます。モデルの値・一覧の表示・DB・元のファイルは変えません。

TSVは可視列の順で出力し、nullの行を除いた選択行の順序と数を保ちます。1列だけでも、先頭・中間・末尾・すべてが空欄の行を省略しません。

| 選択行 | 出力 |
| --- | --- |
| 空欄、Song | `\r\nSong` |
| Song、空欄、End | `Song\r\n\r\nEnd` |
| Song、空欄 | `Song\r\n` |
| 空欄、空欄 | `\r\n` |

実在する空またはnullの値のセル1個をコピーすると、空文字をクリップボードへ渡し、前の内容を空に置き換えます。0行、nullの行だけ、0可視列はコピー対象なしとして、クリップボードを変えません。TSVの生成は対象の有無と文字列を別に返し、選択行以外を実体化せず、選択を変えません。

#### 見出しとメニュー

見出しのクリックは `SortRequested` を送り、同じ列なら昇順と降順を切り替えます。`SortMemberPath` のない列と状態の列は対象外です。並べ替え中の見出しの上部中央に方向を描きます。見出しの境界で幅、見出しのドラッグで可視列の順序、右クリックで表示する列を変えます。状態の列は幅と位置を固定します。

ライブラリのツリーのルートのメニューは、再読込み・再初期化の項目の後に末尾の区切り線を置きません。通常のフォルダのメニューは、後に続くエクスプローラー等の操作を区切る区切り線を保ちます。

### 行のドラッグと編集

#### セル編集の開始と終端

F2と文字入力による編集は、入力の時点で同期した現在セルの行・列・編集属性を使います。開始の通知・確定の通知・実際の入力欄の初期文字列も、同じ対象に揃えます。セル編集の入力欄の文字余白は[外観の入力欄の余白](appearance.md#スクロール内容の測定)に従います。

セル編集の非同期処理は、次の順に終えます。

1. 保存
2. 必要な出力
3. 現在の表示への確定値の反映
4. 論理的な編集状態の解除
5. 受付の解放

対象は、プレイリスト詳細、プレイリスト一覧の属性、譜面のフォルダ名、保留一覧の導入先です。入力欄を閉じることと保存のTaskの完了は区別します。

- 既存の変更配送のTaskと局所的な投影を使い、少数の編集のために全体の再構築・全件の並べ替え・全行の実体化を行いません。
- 表示先を交換した後は旧い表示への反映を求めず、開始済みの処理と後片付けを回収します。後発の並べ替えや一覧の構築、構築候補の後継への完了の引継ぎを、新しい完了条件にしません。
- 保存後の出力が失敗しても、確定値の必要な表示と編集の解除を行い、先行する元の失敗を通知します。必要な表示の失敗を成功に置き換えず、先行する保存・出力の失敗があれば、二次的な原因を局所診断して後片付けと受付の解放を続けます。

各編集が待つ終端は次のとおりです。

| 編集 | 待つ終端 |
| --- | --- |
| プレイリスト詳細 | エントリの配送を一つの消費者で適用するTask |
| 譜面のフォルダ名 | 既存のライブラリ変更の配送 |
| 保留一覧の導入先 | 受信側が返す実際の表示のTask |
| プレイリスト一覧の属性 | 下記の局所反映 |

プレイリスト一覧の属性の編集は、正本の正規化済みの属性と、既定のフォルダ・更新日時を対象の行へ反映し、採用済みの絞込みと共通の比較で、局所的な加入・離脱・位置の調整を行って、現在の集合・順序・件数を揃えます。未採用の独立した要求の条件を現在の表示へ混ぜず、編集を理由に全体の世代を進めません。CompatPrefixのセル保存によるフォルダ・順序の差分は、同じ編集の対象表・開始時の版・更新内容で識別し、配送が保存の終端より後になっても、プレイリスト一覧全体の更新を予約しません。一般のフォルダ変更や、追加・削除・所持件数に依存する差分の必要な更新は保ちます。

#### 詳細の編集開始の制限

詳細のセルの先行する保存が終わるまでは、次の詳細のセル編集の開始だけを拒否します。先行する保存の終わりとは、必要な表示、未確定の入力の解除、遅延した並べ替え、選択の復元、Pの解放までを含む実際の終端です。

- 再クリック・F2・文字入力の共通の開始判定で、新しい編集欄を作る前に拒否します。選択と再生は保ちます。
- 一覧の並べ替えの延期とは別の制限です。通常の表示やプレイリスト一覧を経て別の詳細へ移っても制限は残り、新しい詳細の通常のスコアによる並べ替えは延期しません。直接別の詳細へ移る場合の延期は変えません。
- 成功・保存前の失敗・保存後の失敗・取消・無変更のすべての終端で制限を解き、次の明示的な編集を受け付けます。入力の予約・自動の再保存・保存Taskの複製は行いません。

#### 行のドラッグ

ドラッグのデータには、選択行を `SelectedRowsDataFormat`、表示先を `RowDragKindDataFormat`、開始行を `PrimaryRowDataFormat` へ格納します。通常・詳細・履歴の表は `PlaylistDropCandidateRows`、プレイリスト一覧は `PlaylistSummaryRows` を使います。

プレイリストツリーは種類と全行を再検証します。履歴は `ResolvedChart` を持つ行だけを譜面へ変換でき、未解決の行や一覧の行が一つでも混じれば全体を拒否します。見かけの行の型だけで受け付けません。

プレイリスト一覧の中での並べ替えは、`BMT SORT` の昇順表示の場合だけ許可します。画面は可視行と挿入位置を渡し、ViewModelが全プレイリストの保存順を使って非表示の行の順も保ちます。挿入位置を線で示し、更新後は添字ではなくプレイリストIDで開始行を選択し直します。

#### プレイリストのセル編集

プレイリストのセル編集は編集中の入力を保持し、正本のエントリと表示用の入力を先に変更しません。保存時は、同じ生存しているエントリ・編集属性・入力値を管理主体へ渡し、確定した差分から対象の表示を更新します。保存前の失敗と確定後の出力の失敗は[保存仕様](../playlist/storage-and-export.md)に従います。編集中の譜面・スコアの変更で入力を消さず、編集の終了後に最新の入力へ収束させます。

主な編集項目は `EntryLevel`、`Folder`、`Url1`、`Url2`、`Comment`、`Memo`、`InstallDst` です。確定時は `CellEditEnded` から対象のモデル・DBの更新へ接続します。

| 項目 | 契約 |
| --- | --- |
| ローカル表の `ENTRY LEVEL` | 地域・言語によらず、`.` を使う往復可能な精度の表現を表示・F2の初期値・コピーに使う。fr-FR/de-DEでも保存値1.5は `1.5` と表示し、無変更のEnterでも同じ値を保つ。Escapeは保存せず元の表示へ戻す。不正な入力は保存前に既存の結果記録から通知し、編集を解除して次の明示的な編集を受け付ける。受理する値と拒否条件は[保存仕様の手動編集](../playlist/storage-and-export.md#手動編集と失敗)に従う。 |
| ローカルプレイリストのURL1/URL2 | 空文字・空白だけで確定すると、その欄の保存値と補完値を解除する。空でない無効なURIは確定しない。Escapeは保存しない。保存と、別の属性の編集後の補完の保持・再適用は[保存仕様](../playlist/storage-and-export.md)に従う。 |

#### URL列の幅による役割

URL1/URL2の役割は、列の現在の幅で決めます。列幅は[列設定の幅の制約](table-columns.md#幅の制約)だけを正本とします。

| 幅 | 表示 | クリック | F2・文字入力 |
| --- | --- | --- | --- |
| 40 DIP | 取得アイコンと明示的なURLのツールチップ | 通常クリック・再クリックとも取得操作。空のURLには取得対象がない。 | 元のURLの編集 |
| 40 DIPより広い | 元のURLを左寄せの通常テキストで表示し、省略時にツールチップ | 最初のクリックは選択だけ、再クリックは編集。取得操作は出さない。空のURLも空の通常セルとして編集できる。 | 元のURLの編集 |

- どちらの幅でもF2・文字入力は元のURLの共通の編集開始判定を通り、幅を広げても外部同期中の編集の権限などを増やしません。行のダブルクリックの操作は変えません。元のURLの編集・コピー・TSVは幅に依存しません。
- 40→広い幅→40と変えても同じ列のまま、表示・配置・クリック操作・ツールチップを切り替えます。
- 幅を変えたとき編集中なら、旧い編集欄の行・属性・現在の入力を一回確定して、候補の一覧と編集欄を閉じます。候補のモデルは保ちます。古い候補の遅延した入力を受理せず、自動で編集し直しません。
- 未編集中の幅の変更では、保持済みの行の当該URL列の値だけを失効させ、他の列の値を取り直さず、未表示の行を先行して評価しません。編集の確定に伴う依存行の再評価は保ちます。列の配置が変わると描画を更新し、文字の配置のキャッシュは文字列・幅・配置で区別します。

#### 導入先の列

`INSTL DST` は、保留項目と、構成ファイルのフルスキャンの全件・欠落・欠落無視の一覧にある通常の所持行で編集できます。所持行では、編集した所持譜面一件だけを対象とし、別の導入済みパッケージの表示やプレイリストへ権限を広げません。

- 表示の案内と編集の開始・確定は、行の出自・元集合の範囲・操作の区分をまとめて扱う同じ判定を使います。Busyなど一時的な受付の拒否と、表示文脈の能力を区別し、表示のための判定で編集の受付状態を変えません。
- 能力がない文脈や文脈を指定しない列には、確定したパスだけを表示し、候補があっても▼と未設定の案内を出しません。能力がある場合だけ、候補ありの▼と未設定の案内を表示します。編集・コピー・TSVは生のパスを使います。
- 列は作成時の文脈を固定せず、表示時の現在の文脈を使います。画面に読み込まれている間の操作文脈の変更と `DataContext` の交換は、列の値と描画のキャッシュを失効させ、編集欄・候補・現在セル・選択・スクロール位置を保ちます。列の再作成や全行の実体化は行いません。画面から外れたら購読を解除し、切り離した後の旧いViewModelの通知をUIへ反映しません。再び読み込まれたときは、既存の初期表示の同期で最新の値を使います。
- 所持譜面一件の一時的な保持と保留項目の正本の区別、手動入力のパスの検証は[手動導入先](../library/install-estimation.md#比較用の基本情報と導入先の代表ペア)に従います。導入先の候補は `ChartFile.InstallDestinationSuggestions` から取得し、保留中のBMSも `PackageChartEntry.Chart` を使います。旧い保存用モデルの一時値へ代替しません。

導入先の候補の操作は次のとおりです。

| 操作 | 結果 |
| --- | --- |
| 編集の開始 | 候補が1件でも複数でも未選択で始める。 |
| 上下キーで候補を選んでEnter、または候補のクリック | その候補の生のパスを確定する。 |
| 文字入力・削除 | 候補の選択を解除する。 |
| Enter・Tab（候補未選択） | 入力文字列を確定する。Tabは通常のフォーカス移動も行う。 |
| Escape | 1回目で候補の一覧を閉じ、2回目で編集を取り消す。一覧を閉じてもモデルの候補は消さない。 |

手動の入力は、実在・所持のパスの検証を通します。既知のドライブのルート（例 `D:\`）を直接入力しても、同じルートの直下のファイルを指定した場合と同じ絶対の宛先を保ち、再編集の初期値にもそのルートを表示します。通常のディレクトリの末尾の区切りの有無とUNCパスの受理は変えません。

確定の結果は次のとおりです。

| 確定 | 結果 |
| --- | --- |
| 空文字をEnterで確定する、または未設定・候補未選択の空の編集欄から外へ移る | 導入先と代表のTITLE/ARTISTを空にし、候補と推定のWARNINGを保って「▼ 候補を選択…」へ戻す。設定済みの導入先を空へ編集した場合も同じ。 |
| 設定済みの文字列を変えずに外へ移る | 現在の値を保つ。 |
| 候補外の有効な手動入力 | 候補なしの行と同じパスの検証で受け付け、対象群と候補を共通の分類で照合した[実在ペア](../library/install-estimation.md#比較用の基本情報と導入先の代表ペア)のTITLE/ARTISTへ更新する（Relatedは根拠のペア）。候補と推定のWARNINGは保つ。 |
| 検証で拒否 | 元の状態を保つ。 |
| 「インストール先をクリア」 | 導入先・代表情報・候補・推定のWARNINGを消し、保留の登録時の元の配置の健康度とリソースの警告を戻す。その他の分類のWARNINGは保つ。 |

健康度は[保留の配置評価](../library/warnings.md#リソース状態の評価)に従い、編集・選択では評価し、明示的なクリアでは再検査せず計算済みの結果を使います。設定先があっても不足の要約を表示し、推定時の音源による見送りの理由は現在の健康度とは別に保ちます。

#### 操作セル

操作セルは `CellActionRequested` を送ります。URL1/URL2の取得は各段階でHTTP(S)を検証し、不適切な形式なら通信、ファイルの作成、ブラウザでの代替、導入へ進みません。詳細は[取得と導入](../playlist/downloads.md)に従います。プレイリストのヘッダー・データの外部同期は別の契約です。

### 譜面一覧のフォルダ名編集

`CustomTableView` は、直接の打鍵で置き換える前の編集の原文を一回捕捉し、確定した入力とともに同じ編集要求の終端へ渡します。開始時の対象と操作の範囲を保ち、確定時の最新の行から原文を取り直しません。確定・取消・終了で原文を解放し、終端を一回だけ通知します。Enter・Tab・フォーカスの離脱と、選択・現在セル・次の編集の操作を保ちます。他の列の同じ値への編集のイベントは抑止しません。

FOLDERの変更不要の判定と改名の反映は、[ライブラリ変更](../library/mutations.md#フォルダ名の変更不要判定と表記変更)に従います。

### 保留譜面の操作バー

右ペインの検索・件数表示の下、譜面一覧の見出しの上に、保留ルートと個々のパッケージで共通の操作バーを表示します。

- 表示の区分は `MainChartList.CurrentOperationContext` の `InstallPending` から求め、プレイリスト一覧・プレイログとの重複表示を避けます。対象外では `Collapsed` とし、空白の行を残しません。明暗の意味リソースと、実行中の言語切替に追随します。
- 「推定」「インストール」「クリア」は、中央の一覧の現在の選択だけを対象とし、Ctrl／Shiftによる複数選択や、ボタンへのフォーカスの移動でも対象を保ちます。未選択なら3ボタンを無効にし、差替え・空化・操作後の選択解除にも追随します。
- 実行時にも区分・選択・変更の実行状態を再確認し、左のツリーの選択パッケージで補いません。ツールチップとアクセシブル名には各操作の正式名称を使います。
- メニュー固有の配置元の検査と、イベントを処理済みにする時点を保ったまま、選択対象を取得した後の実行処理をメニューと共有します。

操作内容は[導入先推定](../library/install-estimation.md)、受付とBusyは[操作の競合ポリシー](../core/operation-concurrency-policy.md)に従います。

### プレイリストツリーの選択

フォルダ構成の更新では、プレイリスト作業領域の選択を正本にします。

- 元集合の置換中にWPFが選ぶ親を、新しい利用者の選択として採用しません。項目の生成後に、同じ選択の版の表示だけを同期します。
- 改名・接頭辞の変更は確定した対応へ追従し、別のフォルダの更新と、特殊な NO SONG の項目の選択を保ちます。同期の配送前の新しい明示的な選択を、古い復元で上書きしません。
- 通常の初回の選択、再クリック、キーボードによる選択は、通常の要求の経路を使います。選択中のフォルダの削除後の選択先は[保存仕様の手動編集](../playlist/storage-and-export.md#手動編集と失敗)に従います。

通常のフォルダの見出し・選択・詳細の要求は、保存済みの所属名の前後の空白を保ち、`A` と ` A ` を別の所属として表示します。空の名前・空白だけの名前も表のルートへ読み替えません。同じ所属の検索や並べ替えだけの変更では元集合を取り直さず、その所属の行から表示を作ります。保存と再読込みでの識別は[保存仕様の手動編集](../playlist/storage-and-export.md#手動編集と失敗)に従います。

通常の選択と再クリックは、実際に表示された親の項目の元集合を、選択の出所として渡します。モデルの確定後も旧い表示が残っている間のクリックは旧い構成の対応に従い、新しい表示から選んだ同じ名前のキーに旧い対応を適用しません。要求の複製・表の参照の差替えでも出所を保ち、現在のモデルの構成へ暗黙に読み替えません。ランプビューアも、存在確認と同じ公開済みの構成を使います。

### プレイリストツリーのドロップとホバー

表の見出し・実在する子フォルダにOSのファイルをドロップすると、通常のドロップ導入の入口（`Window_Drop`、`DroppedInstallDropTerminal`）を通して、導入の管理主体の受付へ一回渡します。表のインポートやプレイリストへの譜面追加には変換しません。一覧の行のドラッグは、実際に当たった表のルートまたは通常の所属への既存の要求を使います。空の名前・空白だけの名前の子フォルダは[保存仕様のフォルダ単位のドロップ](../playlist/storage-and-export.md#フォルダ単位のドロップ)に従います。

一覧の行をドラッグしてホバーすると、未展開の表の見出しだけを遅れて開き、展開済みの見出しは閉じません。ドラッグの離脱・ドロップ・取消の後片付けで、背景と待機中の展開を解除し、次のドラッグへ旧い要求を持ち越しません。展開状態の新しい保存や、共通のドラッグ管理は設けません。

### プレイリストツリーのフォルダ名編集

#### 遅延した編集開始

選択済みで編集可能な通常フォルダの見出しを再クリックすると、`MainWindow` がそのクリックに対応する遅延開始の要求を一件だけ持ち、1秒後に同じ対象の編集を一回開始します。最初の選択だけのクリックと、編集中のクリックでは要求を作りません。開始時の保存済みの原値から候補を作り、遅延開始だけでは改名を保存しません。

要求は見出しのマウス押下の先行イベントで作り、その開始クリック自身が対象の見出しとその項目の中へフォーカスを移すことだけを許します。次のいずれかで、要求を同期的に失効させます。

- 後発のクリック・キー・文字入力・マウスホイール・フォーカスの移動
- 選択の離脱、対象または見出しの `DataContext` の交換・`Unloaded`
- 別の編集の開始・終端
- ウィンドウの非アクティブ化・終了

後発の有効な再クリックだけが、新しい一件に置き換えます。F2・メニューによる明示的な編集も旧い要求を取り消し、通常の編集の入口を使います。取消の後に検索から戻る、A→B→Aと選び直す、別の編集を終えるといった操作で、旧い要求を復活させません。開始の直前にも、対象の参照・接続・選択・編集の許可と、未編集中であることを確認します。

文字入力は、IMEの入力開始の時点から旧い要求を失効させ、文字列の確定を待ちません。解除済みの監視へ配送中の旧いイベントは、その要求が現在の一件である場合だけ取り消し、後発の要求には適用しません。

#### 名前の表示と候補

見出しの表示名は、フォルダの項目と現在の表示リソースから作り、保存名とは別に扱います。`EditableTextBlock.DisplayText` は `PlaylistFolderNode` 自体と `ResourceService.Current.Resources` を入力とする OneWay の複合 Binding で `DisplayName` を表示し、`Text` は `FolderName` の OneWay の原値 Binding を保持します。

- 空文字だけを既存の名前なしのラベルで表示し、その文言は評価時の現在の言語で解決します。表示言語が変わっても同じ項目・同じ部品のまま案内だけを更新し、保存名・選択・展開・スクロール・編集中の候補、フォルダ一覧の参照と通知を変えません。フォルダの項目や表のモデルは言語の通知を購読しません。
- 保存済みの空白だけの名前は原値を表示します。表示用のラベルを保存キーへ逆変換しません。
- 編集欄は編集期間だけ有効な候補を更新し、表示元やモデルへ書き戻しません。編集が実際に始まった時点で、保存済みの原値を候補と無変更判定の開始値に使います。名前なしは空欄から、空白だけの旧い名前は原値から編集します。開始の要求が重複しても候補を作り直しません。編集不可の間の開始要求は成立せず、後から編集を許可しても自動では再開しません。

#### 確定と保存

| 操作 | 結果 |
| --- | --- |
| Enter、フォーカスの離脱 | 候補を確定する。Enterに続くフォーカスの離脱で二重に確定しない。 |
| Escape、`DataContext` の交換、`Unloaded` | 候補を破棄する。 |

終端では開始値と候補を破棄してから、変更不能な確定値を `EditModeChanged` へ渡します。開始・取消・無変更はnull、変更の確定は空文字を含む文字列で区別します。通知の途中で次の編集が始まっても、旧い終端の後処理でその候補を消しません。

`MainWindow` はnullでない確定値だけを処理し、最初の待機より前に、現在の表・通常フォルダ・確定した候補を一組で捕捉して、既存の `RenameFolderAsync` へ一回渡します。取消と部品の再利用から保存を始めません。改名の受付・保存前の失敗・保存後の出力の失敗と通知は[保存仕様の手動編集](../playlist/storage-and-export.md#手動編集と失敗)に従い、編集部品に再試行や回復の状態を持たせません。

### 可視行だけの実体化

#### 実体化の範囲

`MainChartList.Rows` は、`IChartListViewMetadata` を実装する仮想の `IList` を受け取れます。表は全行を列挙せず、件数を `Count`、描画・選択・説明・右クリックの対象を添字で取得します。旧い表示の破棄もメタデータを使い、処理のためだけに全行を作りません。

| 表示先 | 入力と並べ替え | 実体化 |
| --- | --- | --- |
| 通常ライブラリ・絞込み・全件確認 | `ChartListSourceRow` と `ChartListOrder` | `ChartListVirtualView` が対象の `LibraryChartRow` だけを作る |
| 保守・重複・導入済み・導入保留の対象集合 | 対象の `ChartListSourceRow` と共通の並べ替え | 可視行だけを作る |
| プレイリスト詳細 | `PlaylistDetailSourceRow` と専用の `PlaylistDetailSortEngine` | `PlaylistDetailVirtualView` が対象の行だけを作る |
| プレイ履歴 | 履歴専用の入力・並べ替え・表示 | 履歴の仕様に従う |
| プレイリスト一覧 | 件数の小さい行集合 | 通常の行集合を保持する。譜面全件の仮想化とは別に扱う |

選択行のTSVのコピーや明示的な全行の操作では、その対象の実体化を許します。初回の表示の代わりに常に全件を作ることは許しません。

通常一覧とプレイリスト詳細の所持BMS・bmson行の再生状態は、再生の管理主体の現在値を行の `status` の読取りだけで重ねます（[再生パネルの一覧の再生状態](playback-panel.md#共通の再生対象と一覧状態)）。再生状態と対象の変化は `MainChartList.RequestDisplayRefresh` へ渡し、画面に読み込まれている表の表示値のキャッシュを再評価します。行の登録、行ごとの再生通知、全件走査、未訪問の行の実体化は行わず、行集合、並び順、選択、スコア、未確定の編集、`SCORE_UNSENT`、`SEARCHING` を保ちます。時刻の進行だけでは表を更新しません。

#### 通常一覧の入力の捕捉

通常一覧の管理主体は、カタログから所属・現在値・`CatalogRevision` を一組で捕捉し、その入力から絞込み・順序・件数を求めます。所属の正本はカタログに置き、表示は捕捉した変更不能な入力と、所持項目の識別による順序を参照します。

- 通常のBMSONの同値の順序もカタログの保持順に従い、初回の入力だけをパス順に並べ替えることはしません。BMS専用の表示ではBMSONの入力を準備しません。
- 捕捉した入力と、その所属・基準の順序に対応する順序を一緒に採用します。件数が同じというだけで旧い添字を再利用しません。
- 後から取得する未訪問の行も、同じ採用入力を使います。

#### 確定差分による局所更新

カタログ、独立したスコア、参照プレイリストの変更結果は、`RegularChartListOwner` が既存の配送キューから一度だけ取得し、同じまとまりを `MainWindowViewModel` の接続を通してプレイリスト作業領域の `ApplyLibraryChanges` にも渡します。通常一覧の表示を抑止している間やプレイリストを表示している間も、構築中の要求が必要とする差分は渡します。配送中の状態は、この受渡しの終端まで保持します。正本の確定・版・差分の契約は[データと索引](../core/data-and-indexes.md)、参照の索引は[保存仕様の参照プレイリストの索引](../playlist/storage-and-export.md#参照プレイリストの索引と表示)に従います。

部分更新では、書込み側が確定した `CatalogCommitReceipt.Snapshot` と変更前後の値を使い、通知の配送時に後続の現在値を取り直しません。

- 所持項目の識別・照合キー・エントリから必要な行を求め、実際に依存する検索の適否・並び位置・件数だけを更新します。
- 変更していない入力と順序は構造を共有し、全件の長さの投影や差分の配列を毎回作りません。
- 基準の順序だけが変わる行も、旧い比較規則で順序から外してから新しい捕捉へ切り替えて入れ直します。順序だけの変更で生の値や絞込みを再投影せず、旧い捕捉値と未変更の行を保ちます。初回のBMSONの正規化の後も、同値の列の比較・選択の復元と次の局所更新は同じ規則で処理します。
- 局所更新のために元集合全体をリセットしたり、BMSONの全行を同期したり、未訪問の行を実体化したりしません。

通知の種類ごとに渡す範囲は次のとおりです。

| 通知 | 渡す範囲 |
| --- | --- |
| 基本値・パス・ハッシュの変更 | 変更の範囲。必要な行の更新と依存の判定に使う。 |
| 譜面情報 | 変更したハッシュ |
| スコア | 変更したキー |
| 保守・警告 | 変更した対象 |

#### 候補の範囲不足の閉じ方

通常一覧の候補は、採用の時点で、配送した差分がスコア・カタログ・参照の必要位置まで候補の入力を覆っている場合に限って採用します。覆えない場合、候補はUIスケジューラーにスケジュールした処理の中で例外を投げません。本番の `WpfUiScheduler` はスケジュールした処理内の例外を完了へ入れず、未処理例外としてアプリの終了へ広げるためです。処理の中では範囲不足の事実だけを記録して戻り、候補を採用しません。処理の終端を受けた継続側の既存の失敗経路で、要求の取消、保留状態の片付け、診断の記録を行い、私有の未採用の入力の失敗として閉じます（[判断の単位](../core/exception-handling.md#判断の単位)）。同じ位置での再配送・再試行はせず、`StopAsync` は完了します。`IUiScheduler` の共通契約は変えません。

通常の経路では、観測できるカタログ版の確定結果は登録済みなので（[確定の順序](../core/data-and-indexes.md#確定の順序)）、この分岐は防御用です。

#### 導入済みパッケージの変更

導入済みの項目の変更は、現在値を適用したときに捕捉した変更前後の基本値と、エントリ・パッケージの所属の参照を、通常の通知に含めます。

- 同じ所持項目への複数の通知では先行の変更も保持し、最後の現在値だけで依存を判定しません。`RegularChartListOwner` と表示更新の判断が、一回の配送の全効果をまとめて合成します。
- 同じ所属の中でタイトルを変えない純粋な移転を、検索語なし・モードすべて・タイトル順で表示している場合は、パスだけを更新し、行集合・実体化済みの行・選択・編集中の入力・順序を保ちます。パス順の表示、検索・モード・タイトルの変更に依存する場合、リセット、所属の変更、必要な変更前後の情報がない場合は、正規の最終の順序と集合を更新します。
- パッケージのパスだけの変更では、所属の集合の通知を出しません。パスと代表タイトルの表示名は、変更の受付と排他を解放した後に、既存の通知可能なオブジェクトから明示的に公開します。ツリーの見出しと選択中のパッケージは、同じ参照の最新値を使います。
- 加入・離脱・削減・リセットの集合の通知と、未所属の保留項目の導入状態・警告の通知は保ちます。後続の警告・保守の表示の更新でも、現在の並べ替え・絞込みに依存しない導入済みの表示を作り直しません。必要な健全性の索引の準備は省きません。

#### 行の表示キャッシュの有効性

通常一覧の行のキャッシュは所持項目の識別をキーとし、共通の基本の現在値、捕捉した変更不能な参照入力、譜面情報・スコア・パッケージの版から表示を再評価します。識別は項目を表し、版は表示のキャッシュが有効かを表します。互いの代わりには使いません。

実体化した行のキャッシュは、UIスレッドでの生成とワーカーからの失効の通知が重なることがあります。

- 重なった一回の読取りは、旧い入力による結果でも構いません。更新・通知と、それに先行する読取りが終わった後の、同じ行の次の読取りは新しい入力を使います。
- 通知を延期している間も、公開済みのパッケージの版を確認します。同じ版のままの元集合・提供元の接続の変更は、明示的な失効で反映します。
- 入力が変わらない列の読取りで、元集合・譜面情報・スコアの投影を作り直しません。スコアの局所的な依存を全体の版へ広げません。

このため、キャッシュは生成前に捕捉した行内の明示失効版・パッケージの公開版・スコアの版と結果を対応付けます。失効させる側（ワーカーを含む）は行内の版だけを進め、キャッシュ本体はUIスレッドの読取り側だけが書きます。

この読取りの保証は、推定などのモデルのTaskの終端と、後から要求した行集合・検索集合・順序の採用や描画の終端を区別します。表示要求の採用を確認する場合はその要求のTaskを待ち、モデルのTaskに後発のすべての表示の待機を加えません。セル編集の必要な表示と受付の終端は[行のドラッグと編集](#行のドラッグと編集)に従います。

### 並べ替えとキャッシュの有効性

#### 列定義と比較

通常一覧の列定義は、正規化した列名、別名、キーの型と取得方法、比較の方針、事前計算の優先度、表示データへの依存を持ちます。`STANDARD` の初期の可視列で並べ替え可能なものはすべて対応し、全列を可視にした場合も、詳細専用の `EntryLevelSortKey` 以外は対応します。

文字列は `OrdinalIgnoreCase`、数値は未定義を許す型付きの比較を使います。降順は昇順の配列の反転ではなく、対象キーの降順と題名の昇順を組み合わせます。`rank` は `rateDouble` の別名です。同じキーの別名から重複したキャッシュを作りません。

#### キャッシュの有効性

有効性は、捕捉した入力、要求・表示の条件、依存するデータ、列、方向で判定します。要求の寿命とデータの版を区別し、全件の内容の指紋を再計算しません。`CatalogRevision` や表のエントリの版の変化だけを、全入力・全順序の再構築の条件にしません。

| 依存するデータ | 無効化の根拠 |
| --- | --- |
| 題名・パスなどの現在値 | 確定差分の所持項目の識別・変更前後の値と、現在の列・検索・所属の条件 |
| スコア | `ScoreSnapshotChange` の版の範囲と変更したMD5・SHA-256のキー、元集合ごとの反映済みの位置 |
| 譜面情報 | `ChartInfoIndexVersion` と変更したMD5・SHA-256のキー |
| 保守の結果 | 確定した対象の現在値と、その列・検索への実際の依存 |
| 警告 | 対象の現在値と専門の警告の事実、警告・導入先の条件への実際の依存 |
| 導入先 | 表示専用の世代 |
| 参照プレイリスト | 参照の管理主体の確定した版の範囲・変更したMD5/SHA-256のキーと、元集合の処理済みの位置 |

スコア・譜面情報・保守の結果・警告の部分更新では、変更したキーに依存する入力と、必要な並び位置だけを更新します。対象集合では、ツリーの種別、集合の名前、並びの識別情報も使います。初回、明示的な並べ替え・絞込みの変更、実際の全置換では、その範囲に必要な全体の評価を行います。

重複一覧の再選択では、同じ版で捕捉した共通の現在値を使い、既存の完全な順序が列・副キーの題名・同値の場合の元の添字の順を満たすことを線形に検査してから再利用します。通知の配送前の確定値もこの入力から判断し、配送済みであることをキャッシュの妥当性の根拠にしません。

#### スコアの反映位置

スコアの照合表は所属と索引を共有し、変更可能な `BMSScore` の全値を版ごとに固定しません。表示の `ScoreSnapshotVersion` は、その位置までの変更キーをすべて反映したことを表します。

- 一件の更新で最新の照合表を読めても、別のキーの未反映分を飛ばして、元集合・検索結果・順序を最新の版として採用しません。カタログや譜面情報だけの更新でも、スコアの位置を進めません。
- 初回と必要な全体の評価では、最初のスコアの投影の前に同じ照合表と基準の版を捕捉します。その基準が覆うのは、通常一覧の選択形式、専用の対象集合、詳細の選択表・実フォルダに対応する元集合の全体です。表示の絞込みの前の非表示・未訪問の入力も同じ照合表へ接続し、別の元集合や範囲のキャッシュを更新済みとは扱いません。
- 通常一覧の準備前のスコアはNoScoreとし、表示の捕捉だけでスコアの構築を始めません。

#### 参照プレイリストの入力

参照の表示は、要求に必要なMD5/SHA-256の両方のキーと参照の版を一回の読取りで捕捉し、変更不能な入力として共有します。

- MD5が現在一致していてもSHA-256を捕捉し、MD5の分類が消えた後の代替も同じ入力と差分から求めます。
- 別の表のエントリの変更、名前・記号、参照の選択、遅い読込みも、独立した参照の差分として適用し、依存する非表示・未訪問の入力、検索集合、必要な並び位置だけを更新します。
- 詳細が保持する参照の入力は、同じ確定結果に属するすべての変更を適用した後の依存集合で整理します。同じ表の中の移動や依存の引継ぎで途中の依存数が0になっても、最終的に必要なキーの値は保ちます。変更前の影響行のMD5/SHA-256だけを最終の索引と照合し、本当に最後の依存が消えたキーだけを終端で解放します。整理のための再捕捉・版の加算・元集合全体の走査は行いません。

構築中の要求は、捕捉の前から参照の差分を受け取り、依存の登録より前の変更も保持します。新しいハッシュへの依存だけを版Rで捕捉した場合は、既存の入力へRまでの結果を適用した時点で新しい依存を加え、その後の結果も順に適用してから公開します。参照の確定の区切りを潰さず、古い差分で新しい捕捉値を巻き戻した状態を公開しません。捕捉した版と全依存の処理済みの位置を分け、最新版への付替え、行ごとの可変の索引の読取り、欠落を隠す全体の再構築は行いません。

#### プレイリスト一覧の集計

プレイリスト一覧の重いエントリの集計はワーカーで行い、生の属性の投影・キャッシュの公開・絞込みと並べ替え・表示の採用は同じUI処理にまとめます。絞込み済みの候補を別の処理の回へ残さず、未表示の生の属性も公開時の属性で評価します。初回・明示的な要求の全体の評価は一回とし、既存の構築の待機・停止は、UIへの適用のTaskの終端まで回収します。編集自身は独立した要求の終端を無条件には待たず、独立した要求は自身の条件と公開時の最新の属性で結果を採用します。

### 絞込みと画面更新

#### モードの絞込み

モードの絞込みは `5KEYS`、`7KEYS`、`9KEYS`、`10KEYS`、`14KEYS`、`24KEYS`、`48KEYS` の7種から選びます。初期値と既定の捕捉値は全選択です。

- 全選択では、null・列挙外の値も含むすべての行を通します。部分選択では、選んだ既知のモードとnullだけを通します。
- 最後の一つの選択の解除は拒否し、現在値を通知し直してチェックを戻します。
- 一覧の24/48と詳細の解析の25/50は別の値であり、相互に変換しません。

選択は実行中の状態として、検索・整列・表示の切替・捕捉の引継ぎ・差分の反映を通して保ちます。通常・保留・プレイリスト詳細の実体の行、仮想表示、差分は同じ一致規則を使い、永続設定は追加しません。

#### 健全性の索引の準備

通常一覧と、リソースの状態を投影する新規・不足・無視・重複の一覧は、入力の行・並べ替え・キャッシュの採用より前に、`GetResourceHealthIndexSnapshotForView` で索引を準備します。入力の行を再利用する場合も準備を省きません。保留は導入前の一時的な警告を表示するため、この準備の対象に含めません。警告の状態と表示の条件は[警告仕様](../library/warnings.md)を正本とします。

警告・保守の変更を通常一覧の全件の再描画だけで反映する場合も、通知の前に索引を準備します。行の読取りやログの出力へ構築の処理を移さず、構築済みで同じ入力の索引は再利用します。

#### 部分更新と表示の更新

通常一覧のフォルダ・文字列・モードの絞込みは、初回と明示的な条件の変更では現在の順序と入力の行から求め、以後の部分更新では影響する項目だけを除去・挿入・置換します。同じ順序が有効なら、部分集合を再び並べ替えません。全件確認はBMSONを含む通常のルートと同じ集合を使い、フォルダの条件を適用せず、列だけを `FULLSCAN` にします。

現在値、参照、スコア、譜面情報の通常の検索と正規表現は、入力の行から直接評価します。絞込みのための全行の実体化はしません。件数も同じ採用入力と条件に従います。

現在の並べ替え・絞込みに影響しないデータの更新では、行集合・順序・選択を保ち、影響する実体化済みの行を更新してから表示の更新を送ります。表の表示の更新（`RefreshDisplay`）はセルの値のキャッシュを捨てて再描画します。検索の適否や並び位置が変わる場合も、影響する行の除去・挿入・置換に留め、無関係な行を作り直しません。

#### 対象集合の一覧

保守、重複（全体・群・フォルダ・一覧）、導入済み・保留（全体・パッケージ）は、対象集合の仮想表示を使います。BMS専用の機能はBMSだけ、重複・導入の対象はBMSとBMSONを扱います。

- 重複の所属の更新は、モデルが群全体を置き換えた後に表示を作り直します。共通の現在値だけの更新は、検索時の所属と固有の警告を保って、カタログの確定差分の対象だけを置き換えます。再選択でも同じ版の現在値を捕捉し、検索時の古い表示値に戻しません。
- 手動・整理後のグループの選択は、現在の結果の中で一意な所属フォルダで識別し、同じ名前・空の名前の別のグループへ行の選択を持ち越しません。未解決は空の一覧、全件は明示的なルートだけとし、フォルダの配下とは区別します。詳細は[重複一覧](../library/duplicate-files.md#一覧と操作)に従います。

導入済み・保留の一覧の表示要求は、`RegularChartListOwner.PackageViews` と、対象集合の構築・採用が担当します。

- UIスレッドで、現在の経路・検索・並べ替え・列と、パッケージの所属の参照を捕捉し、派生したキャッシュの破棄、要求の使用権の取得、詳細の元集合の退役の準備までを済ませます。
- ワーカーは同じ使用権を使い、各パッケージの `ChartEntries` が返す固定の列を一回取得してから、必要な健全性の索引の準備、入力の投影、順序の構築、検索・モードの絞込み、フォルダの集計を行います。未発見のパッケージは本来の発見処理を実行し、空の所属や一部の成功に置き換えません。UIが所有する集合をワーカーから列挙せず、表示の準備のために所持カタログ全体を複製しません。初回に必要な健全性の索引は、所持全体の規模の準備を許します。
- 採用は同じ使用権の終端としてUIスレッドで行い、古いワーカーが後から始まったり完了したりしても、新しい表示要求を取り消したり上書きしたりしません。UIスレッド以外からの呼出しによる捕捉の予約にも要求IDを持たせ、使用権を発行しない画面の切替による失効も識別します。予約後に選択が変わった場合は、新しい使用権の発行・キャッシュの破棄・詳細の元集合の退役を始めずに不採用にします。
- 返すTaskは、必要な配送と実際の採用までを表し、待たれない呼出しでも故障を観測します。停止は取消だけで終えず、開始済みのワーカーを回収します。固定の待機による再試行や、パッケージ単位の例外の握り潰しはしません。

#### 導入先の操作結果

導入先の操作結果は、変更状態の反映、実体化済みの行のキャッシュの破棄、表の表示の更新の順に適用し、パッケージ項目の変更通知の有無によらずこの手順を省きません。導入先と推定の警告の変更が現在の並べ替え・絞込み・所属に影響しない場合は、全件確認や対象集合でも行集合と選択を保ちます。更新のためだけに未訪問の行を実体化せず、入力の行やライブラリ全体を無条件に作り直しません。

非対応の通常一覧の並べ替えの指定には `main_view_virtual_sort_reset` を記録し、既定の題名順を使います。仮想表示の構築の失敗は `main_view_virtual_required_failed` として扱い、全件の実体化へ切り替えて失敗を隠しません。

### 画面状態の一括確定

#### 行集合の差替え

`MainChartList.ApplyRows` は、行、列設定、選択、集計の文字列の内部状態をまとめて確定した後に通知します。別の行集合へ差し替える前に、子の管理主体から `RowsReplacing` を直接受け、編集と表示のキャッシュを準備します。

#### 機能の状態と表の状態の同時確定

履歴とプレイリスト詳細は、機能側の状態と表の状態を同じ区間で確定します。

- 差替えの準備は、鮮度の判定のロックの外で行います。
- 確定の直前に、要求・順序・検索条件・表示先（プレイリスト詳細では `PlaylistDetailBuildState` のロックの中で要求の版）を確認し、入力・表示の識別と世代、表の内部状態を一緒に採用します。
- ロックの中で公開の通知を行いません。

#### プレイリスト詳細の入力

プレイリスト詳細は、表の管理主体が同時に捕捉したエントリの値・エントリの版と、カタログが同時に捕捉した候補・現在値・`CatalogRevision` を入力にします。`PlaylistDetailRow` は共通の `PlaylistDetailSourceRow` を参照し、列の値を複製して相互に同期しません。所持の値は生存している所持項目の現在値、レベル・フォルダ・URL・コメント・メモなど表に固有の値はエントリの捕捉値を使います。未所持と固有の値の優先規則は[保存仕様](../playlist/storage-and-export.md)と[譜面モデル](../library/chart-model.md)に従います。専門のリソースの警告は通常一覧と同じ投影を使います。

詳細の最新スコアを適用するとき、正常に読み込んだ取得元に記録がなければ、明示的な空の値として採用します。

- 所持行は `NO_PLAY`、未所持行は `NO_SONG` とし、旧いクリア・ランク・スコア・達成率・ノート数・BP・コンボ・順位・順位の更新日時・偏差値・スコア難易度を消します。複製元の `Chart.Score` で旧い値を補いません。
- 検索と並べ替えにも同じ空の値を使います。編集中は未確定の入力・行・位置を保ち、編集の終了後に新しい条件へ収束させます。
- 取得に失敗した場合の扱いは[保存成績の再読込みと旧結果](../library/chart-model.md#保存成績の再読込みと旧結果)に従い、正常な記録なしと区別します。

#### プレイリスト一覧の更新

プレイリスト一覧は、表とエントリの所属・読込み状態を保ち、所持ハッシュの存在集合・エントリの照合表など実際の依存だけを更新します。タイトル・健全性・メモ・URLだけの変更で全表を再集計せず、まだ構築していない任意の索引を、無関係な更新の判定のために構築しません。非表示中の更新は次の表示要求へ渡し、全表の先行読込みを行いません。

| 主体 | 担当 |
| --- | --- |
| 画面の枠組み | 一覧の要求をDispatcherの `Background` 優先度へ一回予約する。予約と抑制の判定だけをロックの中で行い、行の構築・公開はロックの外で行う。 |
| プレイリスト作業領域 | 既存の延期の状態でデータの更新を表示の更新より優先し、予約済みの間に届いた要求をまとめる。世代による取消と古い結果の不採用を判断する。 |

- 起動・全体の再初期化でプレイリストツリーを抑制する間だけ延期します。通常一覧や導入ツリーの抑制・再描画だけでは、一覧を止めたり全表を作り直したりしません。
- 終了時の拒否・予約の取消でも予約の状態を解き、新しい構築を始めません。

表一覧の再読込みは通常一覧だけを抑制し、対象ごとの保存と必要な参照の反映の後に、一覧の現在の参照・更新日時・今回のSTATUSを公開します。取得に失敗した対象は、保存済みの内容と更新日時を保ち、今回の失敗のSTATUSへ更新します。他の対象を待っている間も表示を進めますが、全件の処理・必要な出力・通知・必須のUIの終端は実際のTaskで待ち、部分的な表示で操作全体の完了やBusyの解除を前倒ししません。

#### 詳細の局所更新と構築

詳細の局所更新では、変更したエントリの入力と、順序の木の該当の経路だけを置き換えます。末尾までの位置の索引の書換えや、実体化済みの行全体を移す一時領域を作りません。編集中は順序のキーを保ったまま最新の表示入力と未確定の入力を使い、編集の終了後に必要な行だけを再配置します。行・集合の通知は、元集合と表示の状態の確定とロックの解放の後に公開します。フォルダの編集・削除・ドロップの正規の確定差分で更新済みなら、操作後に詳細全体を再表示しません。選択中のフォルダの改名などで実際の選択が変わる場合は、追従先を評価します。

詳細の表示の重い構築と、構築中に受け取ったカタログ・エントリ・スコア・譜面情報・参照の差分への追随はワーカーで行います。

- ロックの順序は、構築の状態、次に表示の状態です。ワーカーは追随をこの順序で終え、UI側は同じ順序で、取消・要求の版・変更の合図と、正本の必要な版を再確認します。
- 採用、行集合・列・主行の公開、選択の復元は、UIの処理一回で完結させます。新しい変更の合図があれば同じ候補をワーカーで追随させ、捕捉済みの合図を使って再開の機会を失いません。採用を待つ配送とデータ変更の待機はワーカーに残します。
- 既存の元集合への譜面情報の更新は、譜面情報・スコア・参照の捕捉をワーカーで準備し、既存の保留中の投影へ登録してからロックを解きます。UIの処理の中で現在の表示の選択を捕捉し、同じロックの順序で依存・行集合の参照と有効な元集合の識別を再確認して消費し、ロックの外での公開と復元まで終えます。開始と完了の処理を別々にUIへ配送して、更新の区間を重ねません。
- UIでの参照の版の確認には、索引の排他を待たない公開済みの版の値を使い、値の捕捉はワーカーに保ちます。

登録済みの投影は元集合が所有します。登録前の取消は準備を止めます。登録後の取消・要求の失効は、要求の成功と行集合の採用を止めますが、同じ現役の元集合の保留中の投影の消費は止めません。通常の配送が先に消費した場合は、実際に反映した版を確認して再適用しません。退役した元集合の投影を新しい元集合へ移しません。別の元集合から遅れて届いた完了は、現在の元集合との参照の一致を確認するまで、現在の捕捉を変えません。

#### プレイリストの選択の識別

プレイリスト一覧は `PlaylistId`、詳細は生存する `BMSTableEntry` の参照の同一性で、選択集合・主行・範囲基点を照合します。

- 同じ文脈の並べ替え、編集による順序の変更、加入・離脱、行の投影や詳細の表示の交換でも、生存している対象を選び直します。同じハッシュの別のエントリへ選択を読み替えません。
- 主行が消えたら残る選択の表示順で先頭、選択がすべて消えたら解除、範囲基点が消えたら主行を使います。
- 詳細の同じ文脈は、表の参照・選択範囲・フォルダ名の順序付きの一致・絞込みの区分で定め、並べ替え・検索語・データの版は含めません。明示的な別の表・別のフォルダ・画面の移動では無条件に引き継ぎません。
- 履歴など識別に対応しない表示から、詳細など識別に対応する表示へ移る場合は、別の文脈として公開した後に旧い添字の選択を解除します。移動先が識別に対応しない表示なら、その表示の選択保持の方針に従います。

一般の更新は、反映の直前の選択だけを短い間捕捉し、一回の配送の複数の変更と公開の通知が終わった時点で一回復元します。要求開始時の選択を固定する状態や、新しい世代の管理は持ちません。

- 捕捉・復元の通知はロックの外で行います。開始の通知の失敗や早期の終了でも完了の通知を終え、完了の通知の失敗で先行の失敗を隠しません。
- プレイリスト一覧のIDの索引は表の参照の索引と同じ変更の範囲で更新し、詳細はエントリの索引と順序の木で探します。選択の復元のために全行の照合や全行の実体化は行いません。

プレイリスト一覧の実際の全体のリセットでは、編集中の入力を旧い行へ先に一回引き渡してから選択を捕捉します。

- 現在の要求と表示の識別をロックの中で予備的に判定し、ロックの外で型付きの開始の通知を出します。
- 表は、元集合の一致の確認、編集の終端、元集合の再確認、選択の捕捉の順に進みます。編集の終端で同期的な局所更新が再入しても、その更新を終えてから外側の選択を捕捉します。
- 保存のTaskは待たず、同じ表示の識別の再適用と通常の局所更新では編集欄を閉じません。実際の採用時には要求を再検査し、元集合の交換全体の準備や、選択の捕捉の入れ子・予約の状態を追加しません。

BMTのドラッグだけは、実際に適用したドラッグ対象のIDの集合と主行の意図を、対応するプレイリスト一覧のデータの世代の公開後に消費し、一般の復元より優先します。範囲基点はその主行に揃え、主行の可視化と現在セルの確保も同じ終端で行います。通知の途中でデータの世代が更新された旧い意図は適用しません。操作固有の意図と一般の選択は `SelectionUpdateCompleted` の一回の復元にまとめ、専用のイベントや `MainWindow` からの二重の復元は設けません。

#### 件数の集計

集計の表示の正本は `MainChartList.SummaryText` です。

- 通常一覧とプレイリスト詳細は、初回の順序の登録と同時にフォルダ別の件数を求め、以後は対象のフォルダだけを加減算します。空白だけのフォルダは除き、`OrdinalIgnoreCase` で数えます。
- 詳細の差分の公開と編集の終了時の反映でも、採用中の表示の行数とフォルダ数から集計を更新します。編集中に所属の変更を延期している間は、採用中の集合を数えます。
- 件数のためだけの元集合全体の再走査や、非同期の再集計のキャッシュは持ちません。
- フォルダ数が1以下なら曲数だけを表示します。専用の対象集合は、その表示に必要な範囲を集計します。

#### 古い表示結果を採用しない境界

通常一覧とプレイリスト詳細の構築中の要求は、捕捉以降の差分を受け取れる状態にしてから作業を始めます。

- 既知の変更は対象だけを候補へ適用し、採用の直前に要求・選択・条件・対象の生存と捕捉した版を確認します。
- カタログが先へ進んでいて、根拠の差分がまだ配送されていなければ、候補を採用待ちとして保持し、配送の合図で再開します。
- 無関係な版の差で全体の構築をやり直さず、値の版の付替え、待機の繰り返し、定期的な照合で補いません。

スコアの未反映の範囲を必要とする要求は、その時点で必要な確定位置を捕捉し、`DeliverPendingLibraryChangesAsync` による既存の配送キューの一回の配送の完了を待ちます。プレイリスト作業領域へは `SetLibraryChangeDelivery` でこのTaskを接続します。

- 正常な完了は、通常一覧からプレイリスト作業領域までの適用の完了を表します。必要な位置を覆えない成功、拒否、適用の失敗、必要な接続の欠如では、候補を採用せずに終えます。
- 同じ位置で配送を繰り返さず、後続の確定で必要な位置が進んだ場合だけ、新たな登録分を待てます。
- 要求の取消・選択の交換・終了は待機を終えますが、別の要求が使う配送は取り消しません。元のスコアの操作の確定と、通知だけの失敗の分類は変えません。

選択や条件が変わった古い要求は採用せず、採用する候補の入力・順序・画面の内部状態を短い区間で揃えます。公開の通知はロックの解放後です。履歴の鮮度の判定は[履歴仕様](../playlist/play-history.md)に従います。

これは破棄できる表示結果の契約であり、受理済みの保存・通知・必須の処理を古い要求として捨てる規則ではありません。

### 事前計算と診断

並べ替えの事前計算は、必須の実際のUIのTask・成功の公開・操作の解禁の後に明示的に登録して行う任意の処理です。

| 優先度 | 対象の列 |
| ---: | --- |
| 0 | 警告と保守の直接参照の列。起動時には計算しないが、要求時は仮想の並べ替えに対応する。 |
| 1 | 題名・フォルダ・パス・作者 |
| 2 | 主要なスコア・判定・ノート数・BPM・変速・TOTAL・長さ・密度 |
| 3 | 最大コンボを含む残り |

- 起動時の対象の上限は[ソートキャッシュの準備範囲](../runtime/settings.md#起動時のソートキャッシュ準備範囲)の0～3から選び、列定義の `PrewarmPriority` だけを使います。
- 優先度1の4列の順は `Title`・`Folder`・`path`・`Artist` とし、その他の優先度の中の順と各昇降順も列定義の順に従います。別名の列で事前生成の対象を重複させません。
- 比較の規則、キャッシュのキー、更新による失効と要求時の生成は、準備範囲によって変えません。

可視範囲の描画は[保持範囲とセル描画の再利用](#保持範囲とセル描画の再利用)に従い、保持範囲の中の行参照ごとの値と位置ごとのセル描画を再利用します。性能の記録は次のとおりです。

| 記録 | 意味 |
| --- | --- |
| `custom_table_render` | 初回や遅い描画などを間引いて記録する。全描画の回数ではない。 |
| `table_first_visible` | メインの表の初回の可視描画。 |
| `main_view_build` | 通常の仮想表示は `sortEngine=virtual`、詳細の専用経路は `isPlaylistDetailView=True` / `sortEngine=fast`。後者を仮想化の失敗とは解釈しない。同じ集合・条件の再表示では、入力と順序の再利用と `orderBuildMs=0` を確認できる。`columnMs` は差替えの準備・列の適用・表示設定の合計であり、列設定だけの時間ではない。 |

### UI Automation による操作

`CustomTableView` は表の `Selection`、`Scroll`、`ItemContainer` パターンを公開します。表と列には表示言語に依存しない `AutomationId` を付け、`Name` は画面上の名称・表示値に対応させます。`Grid`・`Table` パターンは提供しません。行は `SelectionItem`、`ScrollItem` と、画面外の項目を利用可能にする `VirtualizedItem` を公開します。

#### 行の識別

行の識別は、表示の添字や表示名から独立させます。

| 表示先 | 識別 |
| --- | --- |
| 通常の譜面 | 元集合の文脈と、形式・パスの完全一致 |
| プレイリスト詳細 | 表と生存しているエントリ |
| 履歴 | 提供元・取得元と、元の記録 |
| プレイリスト一覧 | 生存している表 |

プレイリストに永続的なエントリのIDは追加せず、既存のエントリの参照と基準の順序で画面内の寿命を区別します。再起動後は保存済みの対象の情報から探し直し、同じ値のエントリは値と件数で照合します。`RuntimeId` のプロセス間の一致は求めません。

通常の譜面の検索は、表示が捕捉したスナップショットのパスの完全一致の索引から所持項目の識別を求め、その表示の索引で位置を照合します。新しい管理主体の現在値や同じ位置の行へ読み替えません。

- 同じ表示の文脈での並べ替え・投影の交換では、生存している同じ対象に接続します。
- 別の文脈への遷移・削除・対象の消失では、旧い行・セルの提供元を無効にします。同じパスや添字に新しい行が現れても、旧い提供元の操作は失敗し、新しい行を変えません。

#### 画面外の項目と実体化

- `ItemContainer` の識別による検索だけでは、選択とスクロールを変えません。検索結果の `Realize` と `ScrollIntoView` は、対象と新しい可視範囲だけを実体化し、中間の行や全行の部品を作りません。
- `GetSelection` は画面外を含む選択集合の全体を返しますが、選択の識別から提供元を求め、行の投影は作りません。全選択の問合せで返す配列は選択件数に比例します。問合せの前の全行の提供元の生成や、恒久的な全行の索引は持ちません。
- 表の行の子の集合は、可視行と、`ItemContainer`・`GetSelection` から明示的に要求された未実体化の代理です。返す代理を標準の親子構造へ接続し、構造の変更を通知します。要求された提供元を利用側が保持している間は、次の検索・表示範囲の更新だけでは生存している対象を失効させません。不要になった代理は、表の検索・選択取得の入口、または表示範囲・元集合の更新の時点で除きます。操作のない間のガベージコレクション直後や、WPFの低水準の探索だけによる即時の回収は保証しません。過去の要求をすべて子として蓄積せず、実際に保持されている要求の件数に応じて保持します。

#### 失効した提供元

削除などで失効した行・セルは、独自のプロパティの取得とパターンの操作で利用不可を返します。WPFが管理する `Parent` や `RuntimeId` まで、すべての低水準の呼出しが失敗することは保証しません。

#### 値と編集

セルの `Value` は表示値と読取り専用の状態を公開します。

- 編集可否の問合せは編集を開始・予約せず、既存の編集許可の判定を使います。
- `SetValue` は既存の開始判定、実際の入力欄、確定の処理を一回通し、モデルへ直接代入しません。TAGなどの読取り専用の列、通常の譜面にMEMOの編集がないこと、外部同期中のプレイリスト詳細でMEMOだけを編集できる条件を保ちます。
- `SetValue` の復帰は非同期の保存の成功を意味しません。確定値と保存の終端は別に観測します。

通常の入力で開いた子の入力欄の `Value` の変更は、編集中の候補です。Enterによる確定、Escapeによる取消、候補の一覧がある場合に最初のEscapeで候補だけを閉じる動作は、[行のドラッグと編集](#行のドラッグと編集)に従います。選択・値・構造の変更はUI Automationの通知に反映しますが、通知の細かな順序や件数を操作の結果の代わりにしません。

#### 外部からの検証

外部のUI Automationの利用側から本番の実行ファイルを操作する検証の共通の規則は、[外部UIAによる操作](../development/testing.md#外部uiaによる操作)に従います。この表に固有の条件は次のとおりです。

- プレイリスト詳細のエントリの削除は、削除前の対象行の `RuntimeId` の配列を保持し、同じ表の `TreeScope.Children` の範囲で `StructureChanged` を購読して観測します。通知の種類が `ChildRemoved` で、内容が保持した配列と長さ・順序・全要素で一致する場合だけ、対象の削除の通知とします。通知の処理の中で送信元や旧い行へ追加の照会をせず、入力中や処理の終端より前に届いた通知も保持します。実際のTask・保存値・旧い行とセルの失効・近傍の行の利用可能性は、通知とは独立に確認します。
- 仮想の行の検証では一覧全体の写しを取得せず、既存の世代・件数・投影済みの件数と対象の提供元を照合します。
- 失効した行・セルは、現在の `Name` の取得が `ElementNotAvailable`（HRESULT `0x80040201`）になり、セルの値パターンの取得がnullまたは同じHRESULTになることで確認します。他の例外・nullでないパターン・時間切れは成功としません。利用側が保持していた値パターンの現在値がどの例外になるかは保証せず、空の値を失効の根拠にしません。
