# 設定の編集と反映

## 目的と適用範囲

設定画面の項目保存、局所候補の確定・取消と、それぞれに必要な実処理の受付を定めます。ファイルの保存と起動時の破損回復は[設定の永続化](settings-persistence.md)、外観は[画面とテーマ](../ui/appearance.md)を参照します。

LR2のカスタムフォルダとbeatorajaのBMTについて、本書は設定画面での局所確定、受付、候補の扱いを所有します。出力先の配置条件、生成物、整理の契約は[LR2カスタムフォルダ出力](../playlist/lr2-custom-folders.md)と[BMT出力](../playlist/bmt-export.md)を正本とします。

## 用語

[共通用語集](../glossary.md)を参照します。コードの識別子は原表記を使います。

| 用語 | 意味 |
| --- | --- |
| 確定値 | `Settings` と、実行時の設定読取り窓口に置かれた保存済みの値。 |
| 局所候補 | 設定画面の編集範囲ごとに保持する、未確定の入力。 |
| 局所確定 | 局所候補のうち、当該の編集範囲だけを保存して確定値にすること。 |
| 設定の単一操作受付 | 設定ViewModelが、非同期の局所操作と明示的な音声テストを、同時に一件だけ受け付ける仕組み。 |
| LとP | Lはライブラリ・保留・推定・保守の変更受付、Pはプレイリスト正本と必要な管理出力の変更受付([操作の競合ポリシー](../core/operation-concurrency-policy.md))。 |
| 関連媒体 | 一つの局所確定が書き込む保存先。LR2連携では `user.config` とLR2の設定XML。 |

## 仕様

### 起動時の設定診断

読取り可能な設定の正規化保存とバージョン記録の保存が失敗した場合は、同じ読込み済みの値・文化圏・テーマで起動を継続します。保存警告のコールバックや任意の診断が例外を返しても、初期化結果へ加えず、再通知しません。

保存時の再読込み、旧設定の移行、その他の必須の設定準備の失敗は、保存警告へ格下げせず、後続の初期化へ進みません。元ファイルの保全と失敗の分類は[設定の永続化](settings-persistence.md#起動時の回復)に従います。

### 編集状態と画面の所有者

#### 項目の保存

確定値だけを `Settings` と実行時の設定読取り窓口へ置きます。通常項目は次の時機に、対象の項目だけを保存し、成功した後に公開します。

- 有効な選択をしたとき。
- 自由入力でEnterを押したとき、またはフォーカスが離れたとき。
- スライダーの操作が完了したとき。

同じ値は再保存しません。保存に失敗した場合は、当該の確定値、現在の表示、次回の入力を旧値に保ち、別の項目の確定値は戻しません。項目ごとの追加の規則は次のとおりです。

- **録音形式**: 現在の `Settings.Encoder` を表示し、外部エンコーダーの実行ファイルが見つからないだけではWAVE表示に置き換えません。明示的なWAVEの選択は通常の項目保存に通し、他のセクションの候補を保存・破棄しません。別の利用できない形式を選んだ場合は、警告を表示して保存を拒否し、選択の表示を現在の設定値へ戻します。実変換の開始後の代替と共有設定への反映は、[音声変換](audio-conversion.md#出力形式と命令の生成)に従います。
- **音量**: `PlaybackPanelViewModel` と `PlaybackSettingsStore` が操作中の値を所有し、現在の再生へ即時に反映します。ドラッグ・マウス・キー操作の終了、フォーカス離脱、画面の閉鎖で、最終の有効値だけを保存します。操作中の値は確定値として公開せず、別の項目の保存や終了時の通常保存にも混ぜません。主画面と設定画面は同じ再生担当を使います。同じ値の終端と保存失敗時の扱いは[音声実行基盤](audio.md#音量の反映)に従います。
- **音声出力**: 候補と確定値に同じ正規化を使い、既定の機器の空文字とnullを差分としません。自動保存の失敗が解消していない間は、音声設定の保存の再試行であることが分かるボタンと案内を表示し、保存の成功または確定値への復帰で解消します。機器テストの再実行とは区別します。

#### 局所候補

局所候補の編集範囲は、BMS一覧、beatorajaの選択、BMT、音声出力、外部プレイヤー、外部画像、出力配置、LR2の詳細パス、レコード(右クリックの項目・履歴プリセット)に限ります。

- beatorajaの有効な選択、音声、再生方式、外部画像は、組が成立した入力イベントで、当該の組だけを自動で確定します。未成立の組と保存に失敗した入力はその欄に保持し、明示的な再操作で修復できます。
- 画面を開く、ページの初期接続、同じ値の通知では、保存要求も実処理も開始しません。他のセクションの候補は読み込まず、確定時に最新の確定値で再検証します。
- BMSの部分保存の後も候補を修正できます。次の明示確定は、その時点の一覧と、必要な明示代替の導入先を関連媒体へ再保存し、前回成功した媒体も省略しません。旧要求の読取専用の表示や、その要求だけを再開するUIは設けません。通常の閉鎖と再表示では、媒体を再読込み・再保存しません。

#### 画面の所有と単一操作受付

設定画面は、メイン画面が所有するモーダルのWindowです。ページは分類を初めて表示するときに生成し、分類を移動しても局所候補を保持します。設定Windowには進捗行を表示しません。

局所操作、非同期の自動確定、明示的な音声テストは、設定ViewModelが同時に一件だけ受け付けます。一件の操作は、実入力イベントの選択画面・確認より前から、実処理、後片付け、必須の公開、担当する失敗の回収と通知の終端まで、同じTaskが所有します。

- 競合する要求は、無効表示と入口の再検査の両方で拒否し、選択画面・確認・保存・処理を始めず、予約もしません。受理済みの処理の本体は設定の受付を再取得せず、LとPの実際の受付と採用時の最終検査は別に行います。
- 通常の使用中は、処理中も利用者の `Close`・Escを許可します。再表示は新しいWindowを同じ設定ViewModelへ接続し、同じTaskと制限を引き継ぎます。初回の利用開始・再起動・復元・撤去の間は、必須の終端まで通常の閉鎖を保留します。
- 無関係な通常項目の保存とページ移動は継続できます。BMTの未確定候補だけを戻す同期的な取消は、Table URLの取込みなど局所編集のできる別処理の実行中も、受理済みの実操作の入力とTaskを変えずに実行できます。BMS・LR2環境の取消へは、この許可を広げません。
- 所有者の終了では、表示の失効と、受理済みTask・ネイティブ資源の解放への合流を区別します。

操作の開始時に、既知の今回の入力を最初の非同期の待機より前に捕捉し、通常の閉鎖や再表示がリセットした候補を後から読みません。選択画面で初めて得る入力は実際の結果に従い、所有者の閉鎖や取消から承認を作りません。保存の前に再表示していた場合も、採用時に当該の編集範囲だけを新しい確定値へ揃えます。受理済みの操作の不変の入力とTaskは終端まで保持しますが、失敗した過去の要求と成功段階を後続の変更へ引き継ぐ修復状態は持ちません。

### 取消と閉じる操作

下部の通常操作は「閉じる」です。局所の取消は、当該セクションの最新の確定値へ入力を戻し、保存済みの部分成功は取り消しません。

通常使用中の `Close`・Esc・Alt+F4は、処理中も未確定の候補だけを破棄します。通常項目の保存済みの値は保持し、再表示は最新の公開値から作ります。受理済みの不変の入力と実Taskは、Windowより長い、当該操作の担当の寿命で、実際の終端まで保持します。初回の利用開始・再起動・復元・撤去の必須の終端中は、通常の閉鎖を保留します。

### 画面操作の失敗と結果通知

設定の実際の `Button`・`BrowseRequested`・利用者の取消の入口は、未処理の通常の操作の失敗をその操作の終端で受け止め、元の原因と経路を診断して、結果の通知を一回だけ試みます。

- 下位が既に作った失敗結果を記録のために再送出したり、重複して通知したりしません。
- 通知・診断の先自身の失敗は、その場所で診断を試みて終え、元の結果に加えず、再通知しません。検証警告・スキーマ結果・局所操作の結果通知も同じ境界を使い、任意の通知の失敗で保存済みの事実を取り消しません。
- 外部リンクの起動の失敗も、リンク操作の入口で扱います。

選択画面での利用者の取消・閉鎖は、その選択による保存を行いません。モード・LR2の再起動確認を取り消した場合は、保存済みの値へ戻します。確認の表示に失敗した場合は、承認や利用者の取消として扱わず、選択画面・削除などの後続を開始しません。非同期の局所操作は、処理、後片付け、必須の公開と通知の終端まで追跡し、競合する実操作を拒否します。通常の閉鎖の後の通知・後片付けは、古いWindowの `DataContext` に依存せず、古いWindowへ遅れて反映しません。破棄した画面を再び有効にしません。

BMSの差分再読込み・スコアの再読込み・BMTの失敗は、その操作の失敗として通知します。最新の設定での明示的な再操作を認め、旧要求や成功段階を固定して次の変更を制限しません。BMTの生成失敗には、変更・再更新の入口を案内できます。音声・画像・再生方式・レコードの同期的な確定はLとPを消費しないため、無関係な処理中も受け付けます。音声テスト中と、環境の開始・再起動中の制約は維持します。

プレイリストの復元の後の終了可否は、[保存・出力](../playlist/storage-and-export.md#json出力sqlバックアップと復元)の結果に従います。競合の拒否、受付の拒否、必須処理の失敗では、設定画面とアプリケーションを閉じません。終了が許可された場合だけ共通のアプリケーション終了処理へ渡し、任意の完了・終了案内の表示の失敗で、必要な閉鎖を妨げません。

### 分類と表示

分類は11個で、末尾は詳細設定、右クリックメニュー、このソフトについての順です。外枠と局所操作は設定ViewModelが接続し、音声の候補・照会・テストの表示は `AudioDeviceTestWorkflowOwner` が所有します。

- 左の分類はクライアント端まで、右の本文の `ScrollViewer` はペイン端まで配置し、本文の内側の16 DIPを一回だけ適用します。見出し・下部操作の左右も16へ揃え、区切り線から各領域の内容を16離します。本文は幅に追従し、分類を変更したときに本文の縦スクロールを先頭へ戻します。
- 採用する最小の寸法でも、入力と固定操作へ到達でき、長いラベル・状態文は折り返します。横スクロールや、固定の最大幅による余白は作りません。セクション・フィールド・関連操作の間隔は[共通の内容余白](../ui/appearance.md#内容余白と間隔)に従います。
- 録音設定の品質・増幅率の数値ラベルは、言語や文化圏によらず、小数点を `.`、小数1桁、桁区切りなしで表示します。スライダーの型つきの値と設定保存の意味は変えず、録音ファイル名の任意書式の文字列には適用しません。

#### インストール分類

「インストール」分類は、次の6セクションをこの順で表示します。

| セクション | 設定・表示順 |
| --- | --- |
| インストール先 | 確定済みの一覧から選ぶ `BMSInstallDir`、BMS一覧の編集先へ移動する操作・検証表示。 |
| 新規フォルダの命名 | `FolderNameFormat`、`%ARTIST%` / `%TITLE%` の案内、`UseOnlyShiftJISChars`。命名書式と文字制限は自動リネームにも共通で使用する。 |
| 取り込み・新規インストール | `EnableAutoInstall`、`KeepInstallablePackagesPending`、`RequireCompleteUsedResourcesForAutoInstall`。 |
| 導入先の自動推定 | `AutoApplyAmbiguousInstallDestination`、`InstallDestinationAutoApplyMinAudioHealth`、`AutoInstallAfterAutomaticEstimation`。 |
| 上書き・元パッケージの整理 | `EnableSmartComponentOverwrite`、`KeepSmartOverwriteProtectedFilesByRenaming`、`DeletePendingPackageSourceAfterInstall`。 |
| 確認メッセージ | `ShowDiffBMSInstallConfirmMsg`、`ShowNewPackageInstallConfirmMsg`。 |

説明は各項目の直下で常時表示し、ラベルと説明は本文の幅で折り返します。各項目の保存キー・既定値・入力検証は変えず、項目の保存と局所候補から、実処理が捕捉する確定値へ接続します。

- 取り込み後の自動推定に続く導入と、単一行のURL1/URL2のセルクリックによる取得・導入は、別の設定として説明します。`EnableAutoInstall` は、起動時スキャンも有効な場合の単一行のセルクリックを対象とし、複数行のURL取込みや通常のファイル取込み全体の可否は制御しません。
- 上書き・整理の説明では、移動・上書き・削除が起こること、元の配布物を残すには事前のコピーが必要なことを示します。スマート上書きの子設定は、親がOFFでも値を消さず、編集を無効にしません。
- 説明つきチェックボックスには `SettingsCheckBoxOption` を使います。標準のCheckBoxと設定値への直接のBindingを内容に残し、説明と余白だけを共通化します。説明はラベル文字の左端に揃え、他の設定説明と同じテーマ対応の薄い文字色を使います。保存・取消・標準のキーボード操作は変えず、説明の部品にフォーカス対象や設定状態を増やしません。

各項目の意味は、[新規としてインストールの確認](#新規としてインストールの確認)から[新規判定の保留と複数候補の説明](#新規判定の保留と複数候補の説明)までの節に示します。

#### 一般ページとその他の分類

一般ページは、言語、環境、BMSディレクトリ、LR2の手動同期、LR2プレイログ、beatoraja連携の順に配置し、LR2の場所、状態、手動同期、履歴DBの状態を区別します。

- LR2の個別パスとbeatorajaの派生パスは、初期状態で閉じた詳細欄に置き、操作グループの間に余白を設けます。
- 変更・確定のボタンは、適用できる局所差分がある場合に強調表示し、不要なときは無効にします。取消は、無効な入力を含む取消可能な編集があるときだけ有効です。レコードは選択中の一件で判断し、他のレコードの変更では有効にしません。BMSの明示再保存、出力先の明示再選択、BMTの同じ値での全表の再更新は、差分がない場合も最新の入力で実行できます。
- 環境の選択は、スタンドアローンとLR2連携を、等幅の二列・同じ高さのRadioButtonのカードにし、名称を一回と、折り返す説明を表示します。通常設定と初期環境設定で共通です。カードの全表面と標準のキー入力から確認の経路へ渡し、`IsEnvironmentSelectionEnabled`、一方向の選択表示、確認一回を保持します。設定の実操作中に入口で拒否した場合は、両方のRadioとViewModelの選択を保存済みのモードへ再通知し、確認・保存・再起動を開始しません。実際の保存の開始後に失敗した場合は、今回の入力を保持して明示的な再操作を可能にし、選択の表示を設定値への単純な双方向のBindingに置き換えません。

詳細設定は「メッセージ表示」「初期化」「LR2連携」「危険な操作」を持ち、起動時の保留の選択は「初期化」に置きます。音声設定は、出力設定、音量、専用テスト、詳細な音声設定を別々のセクションにします。プレイリストのURL対応表とプリセット、バックアップ、危険な削除操作は、それぞれの目的が分かる見出しで示します。「このソフトについて」は、バージョン、ライセンス、リンク、読取専用のリリースノートを扱います。リリースノート画面は設定画面を所有者とし、設定編集の状態を持ちません。

設定ページ内の意味上の重複した見出しは整理し、言語・テーマ・音量・録音ファイル名・LR2プレイログの単純な囲みを除きます。

- BMS一覧、インストール先、二種のプレイリストURL、右クリックのWeb／プログラム一覧は、入力名・一覧編集・検証の役割を保持して、直下の見出しだけを非表示にします。
- 再生方式は、ラジオ入力の名称一回と各説明を残します。
- 他の具体的な項目名、説明・検証状態と文言、ボタン・チェックボックスが示す操作・状態は保ち、分類や確定方式は変更しません。

表示とアクセシビリティの詳細は[設定用の表示部品](../ui/appearance.md#設定用の表示部品)に従います。

### 初回表示とページの寿命

設定画面は、外枠と最初に表示する全般ページを作成し、残りのページは最初の選択時にUIスレッドで一度だけ生成します。

- 同じウィンドウでは生成済みのページを再利用し、未確定の `TextBox` の入力も保持します。画面を閉じた後に残る全体のページキャッシュは持ちません。
- テーマ・言語を変更してから未訪問のページを開くと、現在の資源と編集中の値を使います。未作成の外観ページを、選択の更新のためだけに生成しません。
- 音声ページは生成時点の `PlaybackPanel` へ接続し、その後の変更は作成済みのページだけへ渡します。
- 共通コントロールのスタイルは `App` が読み込む辞書を参照し、設定用の辞書で重複して読み込みません。設定固有の暗黙のスタイルは、各設定ページと外枠の局所スコープに保ちます。
- 「このソフトについて」の文化圏の変更の購読は表示中だけ保持します。閉鎖時には `DataContext` を解除し、保存済みの外観を維持します。

表示窓口で要求を受信した時点の時刻を捕捉し、最初の `OnContentRendered` の入口までを、`settings_dialog_first_render` の `requestToFirstRenderMs` へ記録します。モーダル画面が閉じるまでの時間は含めません。次の計測は区別して記録します。

| 計測名 | 対象 |
| --- | --- |
| `settings_window_construct` | ウィンドウの構築。 |
| `settings_page_construct_start` / `settings_page_construct_end` | 各ページの構築の開始・終端。 |
| `settings_dialog_schema_presentation` | 描画後のスキーマ表示の更新。 |
| `settings_audio_device_list_worker` | 一覧のバックグラウンド処理の実行時間。 |

計測は `NLogWrapper` を使い、診断の失敗は編集・列挙・閉鎖の結果へ加えません。絶対時間の改善値は、対象環境での測定によって判断します。

### 言語辞書と資源の代替

表示文字列は、指定カルチャのJSON、指定カルチャの埋込み資源、日本語の埋込み資源の順で解決します。利用者が編集した日本語JSONも優先します。UTF-8・BOM、任意キー、大小文字を区別する辞書と、`DataContractJsonSerializer` による受理範囲を維持し、辞書の整合検査を実行時の拒否条件にしません。

| 失敗 | 扱い |
| --- | --- |
| JSONの欠落・アクセス・読取りの失敗、シリアライザーの入力の失敗 | 空の辞書として、資源の代替へ進む。 |
| 内部の契約型の故障、資源不足 | 入力の不良や空の成功へ変換せず、伝える。 |
| 埋込み資源自体の欠落 | 日本語の資源の取得へ進む。キー・型などの内部故障は伝える。 |
| 任意の診断の失敗 | 正常に読めた辞書を失わない。 |

`ConcurrentDictionary.GetOrAdd` の生成処理が完了しなければ、その辞書は登録しません。

言語の候補の探索は日本語を常に含み、正常な辞書を、破損・無効なカルチャ・言語名なしのファイルとは独立して扱います。完了した探索結果だけを共有スナップショットへ公開します。ディレクトリの欠落は日本語の候補だけで完了とします。既知のディレクトリの読取り・アクセスの失敗では、今回だけ日本語の候補を返し、探索済みの状態を保存しません。予期しない故障や資源不足では、未完了の候補を公開しません。

### 候補の復元と表示言語

再表示では、表示開始の時機に全候補を最新の確定値へ戻し、値を揃えた後に、選択肢・選択値・派生表示と可否を名前つきで通知します。BMTの出力・既存ファイルの保持・URL登録・ハッシュ出力方式も同じ境界を使います。固定のハッシュの選択肢は作り直さず、入力のsetterやスコア選択イベントを通知の代用にしません。保存の完了は採用した欄だけを揃え、言語の変更とページ移動は未確定の入力を保ちます。

設定画面の言語の変更は、他の画面のカードや件数の表示を直接更新しません。履歴・通常一覧の表示主体が `MainWindow` のUI接続の寿命で購読し、採用済みの小さな集計と数値だけを再整形します。履歴プリセットの保存に成功したときは、旧名と確定名を選択主体へ渡し、対応する希望識別だけを同じモードの新名へ移します。取消・保存の失敗・検証の拒否では、選択を変更しません。詳細は[プレイ履歴](../playlist/play-history.md)に従います。

LR2パスとURL入力の拒否は、受理済みの値とは別に理由・事実として保持し、現在の言語で表示します。言語の変更で入力を再検査・保存しません。

- LR2の拒否理由は、有効な入力、候補の復元、明示的な取消で解除します。
- URLの拒否は、ページ移動と閉鎖の直後まで残し、次回の表示開始で通知つきで解除します。
- 表一覧のURLはFTPを受理し、TSVのURLはFTPを拒否します。

### 音声一覧の非同期取得

設定の表示要求では、ネイティブ機器を列挙しません。当該ウィンドウの初回の音声表示時に、音声の管理主体が一覧取得のTaskを登録し、古い能力照会を失効させて取消を要求し、その実Taskの終端を非同期に待ってから、列挙だけをバックグラウンド処理で行います。

- WPF要素・バインディング・編集中の値の読み書きと通知は、UI側で行います。プロパティの取得とコンストラクターから、列挙を開始しません。
- 列挙処理の初期化確認、共有操作リースの取得、ネイティブの列挙、解放は、同じバックグラウンド処理の中で完結し、方式別の列挙は逐次です。

#### 取得の契機

- 初回の訪問は、表示が無効から有効へ遷移したときにリセットし、表示が有効で音声ページが可視の共通の入口から開始します。可視の通知と表示の有効化の到着順に依存しません。
- 同じウィンドウの再訪問では再列挙しません。開き直したウィンドウの初回の音声表示は新しい更新の機会ですが、前の取得が未完了なら同じTaskを再利用し、完了後の追加取得を予約しません。

#### 取得中と完了時の表示

- 取得中は状態を出力欄へ表示し、出力先の変更、他設定の編集・保存・適用・取消、分類の切替、通常の閉鎖を許可します。一覧の取得をテストの実行中として扱いませんが、明示的な音声テストだけは一覧Taskの実際の終端まで受付不可にします。能力照会も実際の終端まで保留します。
- 完了時に、画面が有効かつ音声ページが可視なら、その時点の編集中の値から候補と選択を作り直し、開始時の選択を復元しません。明示的な編集によるAutoへのリセット理由は保持します。非表示のページと閉じた画面へ取得結果を通知せず、後の音声の再表示は、取得済みの一覧と編集中の値を使います。
- 未知の出力方式と未接続の機器の識別子・名前を保持し、一時的なnullの選択をAuto・Defaultへの編集として扱いません。方式別の失敗と直近の正常な一覧の保持は[音声実行基盤](audio.md#要求交渉観測と設定)に従います。
- 外側の取得が失敗した場合も、既存の候補と現在の選択を残し、翻訳済みの更新失敗の状態を表示・診断します。正常な0件の成功へ置き換えず、同じウィンドウの再訪問で成功の表示に変えません。
- 取得中の状態は実際の終端で解除し、明示テストと現在の選択の能力照会を通常の受付条件へ戻します。失敗による恒久的な停止や自動の再試行は追加せず、次のウィンドウの初回の音声表示を次の更新の機会とします。

#### 画面の終了

表示の終了では、結果の反映と後続の照会を無効にしますが、取消できないネイティブ処理を強制的に解放しません。音声の管理主体が、一覧・能力照会・テストそれぞれの実際の完了Taskを保持します。`MainWindow` の終了では、表示を先に失効させてから `AudioSettingsCompletionTask` を取得し、方式間を含む一覧の実際の終端、照会・テストの解放まで待ってから、音声基盤の終了へ進みます。表示フラグの解除を処理の終端とは見なしません。

### 音声設定の編集と照会

出力方式・機器・サンプルレート・形式・バッファ・WASAPIの指定は、音声担当の局所候補です。方式・機器の変更によるAutoへのリセット、保存済みの利用不能な選択の表示、能力照会とネイティブ資源の寿命は、[音声実行基盤](audio.md)に従います。

- 有効な組の変更時に当該の組だけを保存し、次の再生開始から使います。現在の再生Task・譜面・プレイヤーは維持します。機器一覧・能力照会の結果だけでは保存せず、未成立の入力は確定値として公開しません。
- SRC品質とミキサー並列度は個別の項目として保存し、音量は現在の再生へ即時に反映します。選択肢名の言語追従、数値、既定印は[音声実行基盤](audio.md#src品質と並列ミキシング)に従います。
- 「再生を停止してテスト」は候補を試す非保存の操作で、交渉された形式を保存値へ書き戻しません。

### 起動時のソートキャッシュ準備範囲

詳細設定の「初期化」で、通常のライブラリ一覧の起動後に事前に生成するソートキャッシュの範囲を選びます。保存キーはユーザー設定の整数 `StartupSortCachePrewarmPriority`、キーがない場合の既定値は `1` です。

| 値 | 表示 | 対象優先度 |
| --- | --- | --- |
| 0 | 準備しない | なし |
| 1 | 基本のみ（既定） | 1 |
| 2 | 標準 | 1～2 |
| 3 | すべて | 1～3 |

各優先度に属する列と順序は、[一覧仕様の事前計算](../ui/table-view.md#事前計算と診断)を正本とします。準備されていない列も、選択時に通常どおり整列・キャッシュします。変更は[次回の起動](startup.md#起動後のソートキャッシュ準備)から適用し、この設定の保存だけでは、再初期化やキャッシュの削除・追加生成を開始しません。

- 選択の完了で当該項目だけを保存し、成功した後に選択値と表示へ反映します。保存に失敗した場合は、当該項目の確定値を維持します。言語の変更では、選択値を維持して選択肢の表示名を更新します。共通の `SettingsField`、`ComboBox`、警告用の `SettingsStatusBanner` がテーマに追従します。
- 保存済みの値が0～3の範囲外なら、補正せず、無選択と警告を表示します。setterへのnullや範囲外の入力では確定値を変更せず、有効な値を明示的に選択したときに、その項目だけを保存します。無関係な項目・局所操作の保存は妨げません。
- 必須の起動検査はこの任意設定を条件に加えず、範囲外の値での実行は起動後処理の失敗として扱います。

### 新規としてインストールの確認

詳細設定の「メッセージ表示」に `ShowNewPackageInstallConfirmMsg` を配置します。既定値はtrueで、旧設定にキーがない場合も確認を有効にします。変更時の項目保存と、保存に成功した後のプロパティ通知は、他の確認設定と同じ経路を使います。

falseで省略するのは、導入先が未設定の保留パッケージを新規として導入するときの確認だけです。設定済みの導入先を使わない場合の確認は常に残し、画面の説明でも、導入先が設定済みの場合は省略できないことを明記します。表示する確認はNoを既定とし、未選択で閉じても新規導入を承認しません。

### 自動新規導入に要求するリソース

インストール分類の「取り込み・新規インストール」に `RequireCompleteUsedResourcesForAutoInstall` を配置します。既定はfalseで、旧設定にキーがなくてもOFFです。確定時に当該項目だけを保存します。

チェックボックスの直下では、次の内容を別の行で説明し、推定の詳細は混在させません。

- OFF: 使用音源がそろえば、BGA・動画・補助画像が不足していても自動新規導入の対象にする。
- ON: 全ての使用リソースを要求し、不足時は保留へ追加する。
- 保留画面で不足を確認し、未制作のBGA・動画などがなくても問題ないと判断すれば「新規としてインストール」を実行できる。

| 使用音源 | 非音声の使用リソース | OFF | ON | 保留になった場合の新規リソース探索 |
| --- | --- | --- | --- | --- |
| 完全（要求0件を含む） | 完全 | 自動新規導入を許可 | 自動新規導入を許可 | 不要 |
| 完全（要求0件を含む） | 欠損または定義済み参照の照合不能 | 自動新規導入を許可 | 保留 | 省略。手動推定は可能 |
| 欠損または定義済み参照の照合不能 | 任意 | 保留 | 保留 | 実行。元の充足率が自動設定閾値以上でも100%未満なら省略しない |

「許可」はリソース条件だけを指します。

- 空・名前なし・未知の種類は対象外とし、名前つきで照合できないものは個別に未充足とします。
- 採用要求の親参照が一件でもあれば、OFF・音声0/0でも全パッケージを保留し、候補・代表情報を保って、導入先の自動確定と継続の自動導入を止めます。手動の選択・明示的な導入は通常の条件で許可し、WARNINGを保持します。
- 親参照以外の非音声の不足は、OFFなら許可、ONなら保留です。音源が完全な場合の新規探索の省略は変わりません。単体・入れ子・利用者設定など、他の保留条件も変わりません。

#### 保留後の自動推定との関係

自動推定を開始するのは、未所持の譜面を含み、同じ操作の初期分類で新規インストールの対象ではない保留パッケージだけです。全て所持済みのものと、保留維持設定などで残った新規の対象は、推定の準備から省略して導入先を設定しません。手動推定はどちらも実行できます。準備前の選別と所持の分割は[自動推定](../library/install-estimation.md#自動推定と並列処理)に従います。

自動推定の対象で音源が完全な場合に省略するのは、リソースから新たに候補を探す処理だけです。

- 混在パッケージで所持済みのハッシュの候補が分かる場合は、一意な先のStrong判定と、同点の限定候補の評価を残します。未所持の群だけを評価し、Strongと各譜面の音源許可条件が成立すれば導入先を設定します。
- Strongが不成立なら自動設定せず、候補の表示は共通の関連性ポリシーに従い、別の候補へ迂回しません。未定義のIDは必要集合へ含めず、分類・警告・推定可否へ影響させません。

初期分類、保留への追加、後続の推定は、同じ操作で捕捉した設定と取得済みのリソースを使い、途中で設定を再取得して分類を変えません。この設定は自動新規導入と保留後の自動推定の要否を変えるもので、[導入先の自動確定の音源条件](../library/install-estimation.md#確信度と画面への適用)を緩めません。

### 導入先を自動設定するときの音源充足率

インストール分類の「導入先の自動推定」に `InstallDestinationAutoApplyMinAudioHealth` を配置し、90～100%を1%刻みで選択します。既定は100%で、旧設定にキーがない場合も100%です。値の確定時に当該項目だけを保存し、操作開始時の `BmsLibraryOptionsSnapshot` に捕捉します。途中の設定変更で、兄弟パッケージの判定を変えません。

- 設定は各対象譜面の音源充足率へ適用し、候補順位、推定開始、新規インストールの分類・許可へ流用しません。欠損を許可しても一般の不足警告は残ることを、画面の説明に明記します。確認できない音源は許容しません。
- 保存済みの範囲外の値は、診断つきで自動設定を拒否します。範囲外の値を黙って90%などへ丸めず、画面で利用者が有効な値へ修正できます。

詳細な許可条件は[導入先推定](../library/install-estimation.md#確信度と画面への適用)を正本とします。

### 取り込み後の自動推定に続く導入

インストール分類の「導入先の自動推定」に、説明つきチェックボックス「取り込み後の自動推定で導入先が確定したら、自動インストールする」を置きます。ユーザー設定 `AutoInstallAfterAutomaticEstimation` はboolで、既定はfalseです。新規ファイルでも旧設定のキー欠損でも無効とし、更新だけで有効にしません。

- 有効時は、保留への登録に続く自動推定が正常に完了し、今回導入先が自動で確定した対象を、確認画面なしで導入します。説明文には、手動で開始した推定は対象外であること、上書きと元パッケージの削除は既存の設定に従うことを示します。対象・失敗・取消の正本は[推定仕様](../library/install-estimation.md#取り込み後の自動推定に続く導入)です。ダウンロード後の取り込みを制御する `AutoInstall` / `EnableAutoInstall` とは別の設定です。
- 当該項目の保存と変更通知へ接続し、保存するだけでは、推定・導入・スキャンや再起動を開始しません。取り込みの入口で捕捉した設定スナップショットを終端まで使い、処理中の編集を実行中の取り込みに混ぜません。次の取り込みは、その入口の設定を捕捉します。

### 新規判定の保留と複数候補の説明

`KeepInstallablePackagesPending` は、新規と判定されたパッケージを導入前に保留画面で確認したい場合の設定として説明します。譜面ハッシュが変わった所持済みの作品の導入先の確認と、難易度表パッケージなどを別のフォルダに分けたくない用途を、別々の行に示します。自動の導入先推定は行わず、必要ならパッケージを選択して「インストール」→「インストール先を推定」を実行することを案内します。

`AutoApplyAmbiguousInstallDestination` は、同じ構成のBMS作品が複数のフォルダにあるなど、候補が同率で残る場合の設定として説明します。ONは自動確定の条件を満たす第1候補を設定し、OFFは候補を確認して選択します。一意に決まる場合は、この設定によらず自動で確定することを案内します。譜面数の補助判断を、全リソース探索の優先条件として説明しません。判断条件の正本は[導入先推定](../library/install-estimation.md#メタデータの強一致と同順位の解決)です。

### LR2の場所と設定XML

`LR2RootPath`、`LR2SongDBPath`、`LR2ConfigXmlPath` は個別のキーで、動作モードとともに関連項目として保存します。

- 通常の起動で、子パスをルートから再生成しません。
- 保存された設定XMLのパスが欠落・読取不能・不正な場合も、別の設定の保存や画面の再表示を理由に、生のパスを消しません。パス文字列、解析済みの設定、表示用の状態を分けます。
- LR2連携モードで `LR2RootPath` が空の既存設定は非推奨ですが、互換性のため、それだけでは保存を拒否しません。一般ページのLR2ディレクトリ欄へ `Warning` と理由を表示し、値を設定するよう促します。この警告は、参照操作で不正な候補を選んだ一時的な選択エラーとは別に扱い、ルートを設定した場合と単独動作モードでは表示しません。ルートから子パスを推測する代替は追加しません。

#### 設定XMLの検査

正本が未成立の場合と、未採用の別パスの入力検証は、`Lr2ConfigSession.TryResolve` を入口とします。

- `LR2Config` の構築には `config/jukebox` 要素が必要で、XMLとして正常でもこの構造がないファイルは無効です。登録が0件の空の `jukebox` は許容し、`system` など任意の要素を読込み時に追加しません。登録されたルートが現在存在するかどうかは、別の検査で判断します。
- 無効な入力では解析結果を公開せず、生の保存パスやファイルは変更しません。起動時の案内と処理順は[起動仕様](startup.md#登録ディレクトリの検査)に従います。
- `LR2Config` の直接読込みや検索ルートの登録で生じる例外も、画面へ渡る文言は表示リソースを使います。構造エラーは `Error_InvalidLR2ConfigStructure`、ファイル名の案内は `config.xml` / `config.xmh` の許容条件に従います。ウィンドウ寸法は正値、音量は0以上100以下という入力条件と文言を一致させます。通常の設定検証では、設定不備の案内を維持します。辞書の検査は[全件共通検査](../development/test-authoring.md#表示リソースの検査)に集約します。

#### ルートの選択と採用

標準の配置は、ルート配下の `LR2files/Database/song.db` と、`LR2files/Config/config.xml` または `config.xmh` です。

- 未採用のルートの選択は、候補と設定XMLを検証し、そのルートから解決した3パスで反映処理へ進みます。`song.db` がまだなくても標準パスを候補にできますが、保存時の必要条件は別に満たす必要があります。
- 同じ正規化済みのLR2ルートを選び直した場合は、構成が採用済みのXML識別と正本を使い、更新日時でXML候補を選び直しません。個別指定のXMLもその識別を維持し、DBの標準配置への復帰とは分けます。同値の組なら再保存・再起動しません。
- 無効なルートや設定XML、選択画面の取消では、保存済みの組と解析結果を保ち、以前の有効な候補を確定しません。保存に成功した後に、詳細候補と依存する表示を確定値へ揃えます。

#### モードの選択

モードの選択は、今回選んだモードと、確認後の最新の確定LR2パスだけを保存し、詳細欄の未確定のパスを混ぜません。確定パスが未設定・不正でもモードの選択は保存でき、別のルート・DB・XMLで補いません。モードの保存にXMLの成立を要求せず、ルートの選択・詳細パスの確定と、利用開始時の必須検証は維持します。

| 状態 | モードの選択の扱い |
| --- | --- |
| 有効なプロファイルがある通常の利用中 | 保存の前に再起動を確認する。承認と必要な受付の後、選択の保存から通常の終了・合流・後継の起動へ進む。同じプロセスの稼働環境は差し替えない。確認の取消は保存済みの値へ戻す。 |
| 有効なプロファイルがない初回・修復中 | その場で保存して設定を続け、必須値を確定するまで利用開始を止める。初回かどうかの履歴だけで再起動の要否を決めない。 |

後継の起動で設定が不足していれば、設定の案内へ進みます。モードの変更で実際の保存を試みた後に失敗した場合は、保存済みのモードと非終了の状態を維持し、今回のモードの選択を画面に残します。保存先の解放だけでは再実行せず、同じ入力の明示的な再操作で保存を試みます。保存の前の取消・検証の拒否・受付の拒否では、今回のモードの選択表示を確定値へ戻します。

#### 個別のパス

一般ページの初期状態で閉じた詳細欄では、`song.db` と `config.xml` / `config.xmh` の現在値を読取専用で表示し、それぞれの「参照」から個別に選択できます。個別参照の前には、通常はLR2ディレクトリから設定される標準の配置を使うよう注意を表示し、利用者が同意した場合だけファイルの選択へ進みます。

- 選択したファイルだけを検証・変更し、もう一方のパスは変更しません。無効な候補では、現在の有効な値と解析結果を保持します。
- 個別参照は自動保存せず、両パスを同じ詳細候補で編集できます。詳細欄の「環境を確定（稼働中は再起動）」で一組を一回保存し、稼働中は一回の再起動へまとめます。詳細の取消は、保存済みの組へ戻します。この組にbeatorajaの候補を含めません。
- 設定XMLの個別参照で同じ正規化済みのパスを選び直した場合は、構成が保持する所有者を再利用し、未採用の別パスだけを新しい入力として読み込みます。環境の確定後は、新しい環境から履歴DBの対象と依存する表示を更新します。候補の選択だけでは、履歴スキーマ操作の対象を変えません。
- 状態表示の由来は、操作履歴ではなく現在の有効なパスから求めます。現在の `song.db` / 設定XMLがLR2ルート由来の標準配置と一致すればLR2ディレクトリからの自動設定、それ以外は個別設定と表示します。個別参照で標準パスそのものを選び直した場合も標準配置として扱い、別の「カスタム」状態は保存しません。
- 同じ `song.db` を選び直した場合もファイルの存在を確認し、パス文字列が変わらなくても検出状態を通知します。表示中の言語変更では、ファイルの再選択や設定画面の開き直しを要求せず、現在の設定元に対応する状態の文言を更新します。

LR2プレビューが一時的に変更する項目の保存・復元は[外部起動](../ui/external-launch.md)を参照します。

#### バックアップの案内

LR2連携でバックアップを有効にした場合は、当該項目の保存に成功した直後に、次回の起動から適用されることを案内します。案内が失敗しても保存済みの値を戻さず、スコアなどの別の局所確定や再試行で同じ案内を重ねません。

### LR2設定の所有・候補・公開

`ApplicationComposition` の `Lr2ConfigSession` が採用先を保持し、`Lr2ConfigOwner` がそのXML全文の正本を一つ所有します。

- 初回の採用後の外部のXMLの変更・破損は、参照・再表示・取消・同じパスの選択・保存前の検証へ取り込みません。次の実際の書込みは、採用した全文と、本アプリケーションで成立した変更から行います。参照・再表示だけでは再保存しません。明示確定では、今回の関連入力を改めて保存できます。新しいプロセスは、その時点のファイルを読み込みます。
- 正本は、config・jukeboxの未知の属性・未知の子と、継続するpathの未知の属性を保持します。削除要求の対象path以外を、一覧の置換の都合で消しません。バイト単位の書式の保持は保証しません。

画面のBMS編集候補は両モード共通の利用者の一覧で、管理登録を含めません。確定一覧は、所有者の小さい変更不能な公開入力から投影します。

- 別の出力操作への切替は、競合する候補の破棄を確認し、実際の受付・最終検証に成功した採用点でBMS候補を破棄します。出力の公開後は最新の確定一覧へ同期し、旧候補の追加・削除や選択を引き継ぎません。採用済みの旧出力を、次のBMS確定で利用者の登録へ復活させません。
- 検索・導入・親フォルダのキャッシュは、登録と分類用の出力配置を一緒に捕捉します。

保存は、短いXMLの排他の中で、正本のコピーへ今回の関連変更だけを適用し、実際の保存に成功した後に、保存した文書を採用します。ディレクトリの準備、生成、DB、UI、プロセスの待機は排他の外です。関連媒体が成立する前は、稼働中の利用側へ混成の組を公開しません。次の明示操作は最新の入力を改めて保存し、その間に確定した無関係な登録を戻しません。未知の要素と管理登録を保ち、成功済みの媒体の省略や、過去の要求の続行は行いません。

走査が確認したルート表記の保存は、[共通の保存主体](settings-persistence.md#項目保存と公開)から確定一覧と導入先だけを通知します。表示中の未確定のBMS候補を採用・破棄せず、破棄時に通知の購読を解除します。検索ルートの実在表記と、DBの直前の保存境界は[起動と走査](startup.md#登録rootの表記と走査入力)を正本とします。

### beatorajaの局所反映

beatorajaのルート、スコア、BMTは、独立した確定操作です。BMTの出力先・生成・整理の契約は[BMT出力](../playlist/bmt-export.md)に従い、本節は設定側の入力と受付を定めます。

| 確定操作 | 使う入力 | 保存・処理 | 要求しないこと |
| --- | --- | --- | --- |
| スコア(使用のON/OFFとプレイヤー) | 確定ルートの `playerpath` から解決したscore.db | 使用方針・プレイヤー・score.dbだけを保存し、有効な組は入力イベントで自動確定する。必要なスコアと全履歴の再取得、現在要求の置換、必須の表示まで待つ。 | 別のルート候補・BMT候補の確定・破棄。外部configの `tablepath` が変わっていても、BMT先の再解決・保存・出力・旧先の整理・管理URLの同期を行わない。共通のスコア限定の完了も、プレイリストURLの補完を予約しない。 |
| ルート | 選択画面で検証した新ルート。確定済みのスコア使用がONなら、必要なプレイヤーとscore.dbも検証する | 確定済みのスコア使用とBMT方針で処理する。再起動は要求しない。 | 別の候補の便乗保存。 |
| BMT(確定と、同じ値での全表の再更新) | 確定ルートとBMT自身の候補。外部configの `tablepath` の変更はこの入口で解決する | 全表の出力と、[BMT出力](../playlist/bmt-export.md#順序と出力契機)に定める必要処理を待つ。 | スコア使用・プレイヤーの不備への依存。別のスコア候補の確定・破棄。 |

ルートの確定では、構成のプレイヤー名が一覧にあれば採用し、なければ名前順の先頭、一覧が空なら空値に揃えます。旧ルートを前提とした未確定のスコア・BMT候補は破棄を確認し、採用時だけ関係する候補を確定値へ戻します。取消・同値・検証の失敗・受付の拒否では、元の候補を保持します。

物理的に異なるBMT先へ変わる場合は、新先の準備の後に設定を採用します。採用後の必要なスコア処理、履歴キャッシュの失効、必須の表示は、BMTのURL・旧先の整理が失敗しても、同じ受理済みTaskで回収します。スコア・UIの二次的な失敗で、BMTの元の原因を置き換えません。通常の自動BMT出力がconfigを動的に解決する規則は、[BMT出力](../playlist/bmt-export.md#有効条件と場所)に従います。

スコアの読込みに失敗した新しい設定の結果として、旧スコアを表示しません。旧情報の退避・復元や失敗要求の固定は行わず、別の有効な設定への変更と再読込みを認めます。必要な読込み・キャッシュの失効・表示のTaskは、終端まで回収します。BMTが失敗した場合も、スコア操作へBMT処理を便乗させず、過去のBMT・スコア要求を失うという理由で、LR2環境の確定・復元・再起動を拒否しません。

### 競合する候補の切替

次の切替では、競合する候補の破棄を確認し、実際に対象となるBMS一覧・LR2詳細パスの範囲名を案内します。

- BMS一覧の編集中に、モード・LR2ルート・LR2詳細パス・通常出力・ROOT出力・追加出力・独立導入先を変更する場合。
- LR2詳細パスの編集中に、BMSまたは出力を変更する場合。

無関係な候補とページ移動は保持します。受理済みの実処理、保存済みの媒体、保存済みの事実は未確定の候補に含めず、受付で実際に競合する変更だけを制限します。

即時保存は、今回の入力を局所的に準備し、有効性と同値を判定してから確認します。取消・選択画面の取消・再実行を意図しない同値の通知・入力エラー・受付の拒否では、元の候補を保持し、新しい保存と実処理を開始しません。BMSの明示確定と出力先の明示再選択は、最新の入力を再保存・再生成できる入口として区別します。

- 確認の承認の後も、必要な実際の受付と最新の確定値による最終検証を行い、その採用点で関係する候補だけを最新の確定値へ戻して保存へ進みます。
- 候補の追加・削除・詳細パスの編集では、確認の後に可否を再検査し、有効な新しい候補の採用時だけ破棄します。候補の編集自体にはLとPの受付を追加せず、BMS一覧は一覧の編集可否、LR2詳細は環境の編集可否を、確認の前後に検査します。BMS候補の編集を、無関係なライブラリ処理の状態だけで拒否しません。予約・自動の再試行・巻戻しは行いません。

モードは今回の選択と他の項目の確定値、LR2ルートは今回解決した標準の組と確定モードだけを使い、詳細パスは自身の組として確定します。稼働中の再起動と候補の破棄は、一回の確認にまとめます。有効な環境を確定した結果、新しいBMS一覧に導入先がなければ、環境の保存は成立し、利用開始前の検査で止めます。自動の代替や旧環境の候補との合成は行いません。

#### 独立導入先

独立導入先は、確定BMS一覧だけを選択肢にして、即時に保存します。

- 必要な候補の破棄の確認を終えた後、最新の入力の最終検証と同期的な保存の短い区間だけ、Lを待機せずに取得します。他の操作がLを保持している間は、交差しない先も拒否し、候補・確定値・元の選択表示を保ちます。Pは取得せず、確認の待機中もLを保持しません。Lの解放だけでは保存せず、次の明示的な選択を待ちます。
- 確認が不要なら、進行中の設定の実操作のTaskを置き換えず、通常の項目保存とページ移動を保ちます。BMS候補の破棄の確認が必要な場合だけ、設定担当の単一操作の所有を使います。設定の実操作中で、かつBMS候補の破棄の確認が必要な間だけ、選択欄を無効表示にし、実際の入口でも確認の前に拒否して、元の候補・確定した導入先・選択表示を保持します。候補の変化と、実操作の開始・終端の双方で可否を更新し、次の明示操作を待ちます。
- BMS候補に追加しただけの場所は選べず、独立導入先の操作からBMS一覧を暗黙に確定しません。BMS一覧の確定に必要な明示代替の先は、同じBMS編集の中で扱います。

一般ページで、現在のインストール先を候補一覧から除いた場合は、「変更後のインストール先」と、確定済みの「現在のインストール先（削除対象）」を表示します。

- 残存する候補に含まれる変更先を選ぶまで、必須入力の表示で確定を拒否します。選択だけでは保存せず、選択後も削除対象は確定まで表示します。
- 候補が0件では、BMSディレクトリの追加または取消を案内し、元から無効な導入先には無効の案内を使います。
- 追加・削除・選択・取消・確定値の反映から、必要性と検証の表示を通知し、一般ページだけで直ちに反映します。

BMS一覧の確定後は、確定候補と保存済みの導入先を揃えて通知し、生成済みのインストール設定ページでも選択を保存値へ反映します。

- 旧導入先を外して明示代替の先を確定した場合は、その代替先を選択し、ルートの追加だけなら導入先を維持します。候補の先頭への補完や、表示の更新のための追加保存は行いません。
- 局所の取消では、編集候補だけを最新の確定一覧へ戻し、確定一覧・導入先・実際の選択を維持します。スタンドアローンの設定保存が公開の前に失敗した場合も、旧確定一覧・導入先・実際の選択を保ち、今回のBMS候補と明示代替の先は次の明示操作まで保持します。

### 保存の受付と処理選択

通常項目の保存にLとPを一律には要求しません。実処理を伴う局所操作は、[操作の競合ポリシー](../core/operation-concurrency-policy.md)の該当する受付を使い、Busyでは保存・後続処理を0件として候補を保ちます。出力配置の未受理の候補は、確定配置へ戻します。

| 確定単位 | 保存後の処理 |
| --- | --- |
| BMS一覧と、必要な場合だけ明示選択した代替導入先 | 今回の最終一覧を関連媒体へ保存し、実行時への反映と必要な差分再読込みを行う。初期接続・表示の同値通知は非保存だが、明示確定では同値でも両媒体を再保存できる。LR2のXMLの正本コピーでは利用者のルートだけを変更し、管理出力の登録を保持する。 |
| スコアの取得元とプレイヤー | 有効な選択時に保存し、スコアだけを再読込みする。保存後に失敗しても、次の有効な入力の保存と再読込みを認める。差分再読込み・BMT・全体の再読込み・再起動を合成しない。 |
| BMTの有効・保持・URL登録・ハッシュ方式 | 今回の旧新の出力先と組を捕捉し、BMT担当の処理の終端を待つ。異なる物理先への変更の順序と失敗時の扱いは[BMT出力のTable URL同期](../playlist/bmt-export.md#table-url同期)に従う。同値の明示再更新も、現在の設定で全表を強制的に再投影できる。 |
| 音声の方式・機器・レート・形式・バッファ・WASAPI | 有効な組だけを保存し、現在の再生Task・譜面・プレイヤーは維持して、次回の開始から使う。品質・並列度は独立した項目、音量は現在の再生へ即時に反映する。デバイステスト自体は追加保存せず、交渉結果を書き戻さない。 |
| 再生方式と必要な実行ファイル、外部画像の有効とパス | 有効な組が成立した時に、それぞれの組だけを自動で確定する。方式は現在のプレイヤー・曲・Taskを維持して、次回の新規開始で置換し、その方式の形式能力で選曲する。操作能力と表示面は実際の置換に伴って更新し、画像は現在の表示へ反映する。`LR2bodyPath` は確定環境から導出する。 |
| 右クリックの項目、履歴プリセット | 一件のレコードを確定し、他のレコードの入力を混ぜない。削除・並替・既定値への復帰は明示操作として保存する。右クリックの項目の保存順は、未確定の行を含む画面順から確定IDだけを投影し、新しい行の確定時にも表示位置を反映する。他の行の未確定の内容は保存しない。保存形式のJSONは変えない。履歴プリセットの確定名と継続編集・削除は[表示対象とプリセット](../playlist/play-history.md#表示対象とプリセット)に従う。 |
| 出力配置と追加先名 | 通常・ROOTはフォルダの選択と移行確認、追加先は追加・削除・改名から、操作対象だけを確定する。取消は副作用なし。未受理の入力は確定配置へ戻し、明示的な再操作では最新の入力を再保存・再生成する。必要な保存、登録の改名、検索ルートのディスク保存、公開と通知まで追跡する。BMS候補を混ぜない。配置条件は[カスタムフォルダと検索対象](#カスタムフォルダと検索対象)に従う。 |
| beatorajaのルート・プレイヤー・派生パス | 有効な選択で、確定方針のBMTを準備して整合する組を保存し、採用後のBMTの部分失敗でも、必要なスコア・キャッシュ・必須の表示を同じTaskで回収する。再起動しない。 |
| モード・LR2の基本パス | モードの選択は、未設定・不正を含む最新の確定パスとともに保存し、ルートの選択・詳細欄の明示確定はパスの組を検証する。稼働中は再起動の受付・閉鎖・合流・後継の起動へ進み、非稼働時はその場で設定を続ける。 |

BMSディレクトリの追加・削除・複数選択・ドラッグ＆ドロップは設定画面内の候補だけを編集し、局所確定で最終一覧を保存します。検索対象から解除したルートの実ファイルは残します。同じ稼働中のライブラリの差分スキャンで退役した所持項目の識別は、導入済みパッケージの全所属から外し、空のパッケージを新規作品ツリーから除きます。導入先を先に別の正常なルートへ保存してから解除する場合も、再選択で退役した行を復活させません。詳細は[ライブラリ変更](../library/mutations.md#退役所属と確定したパッケージ参照)に従います。

稼働中のモード・LR2の組は、確認と先着の受付の後に保存し、通常の終了・後継の起動へ進みます。Busyや保存の失敗では副作用を始めず、Busyの解消・再表示で自動では再試行しません。再起動確認の取消では、保存済みの値へ戻します。

#### 部分的な保存

LR2のXMLと `user.config` は別々に保存するため、一方だけが保存済みになる場合があります。

- 必要な媒体が成立する前は実行時の旧公開値を保ち、部分保存を全成功と通知しません。
- 通常の閉鎖は保存済みの媒体を巻き戻さず、再表示も旧公開値を使います。次回の起動は、ディスク上で成功した各媒体を読み、設定検証を通します。
- 次の明示確定は、最新の入力の関連項目を両媒体へ改めて書き出せます。実行時と同値への明示確定も再保存できます。二媒体全体の原子性・自動の巻戻し・成功段階の管理は追加しません。

#### 追加出力先の改名

追加出力先の改名欄は、編集中の文字列をそのまま保持します。`My`→`My `→`My Charts` の途中の空白も表示と候補に残し、入力だけでは、配置・設定・XML・表の参照を変更しません。ページ移動と、無関係な通常項目の保存でも候補を保持します。通常の閉鎖では、未確定の名前を最新の公開済みの選択先の名前へ戻し、同じViewModelの再表示に持ち越しません。閉鎖と再表示だけでは再保存・巻戻しを行わず、通常の閉鎖の許可条件と受理済みTaskの寿命も変えません。

改名の確定時の正規化、同値の扱い、拒否する名前は[LR2カスタムフォルダ出力](../playlist/lr2-custom-folders.md#出力先と事前検査)に従います。同値の場合、設定画面は自己候補の表示だけを選択先の名前へ揃え、出力の確認・保存・生成へ進まず、無関係な候補を破棄・採用しません。

LR2出力の追加先の改名・削除は、対象の表の不変なヘッダー更新を準備し、DB保存の成功前に表のメモリ上の名前を先に変更しません。配置設定・検索XML・表ヘッダーの必要な保存が成立した後に、新しい組を公開します。追加先名の改名・削除など正本DBの失敗は、生成物の残存として扱いません。確定後の生成失敗と旧先の整理失敗の扱いは[修復と一括反映](../playlist/lr2-custom-folders.md#修復と一括反映)に従います。

### 初回と修復

有効な環境がない初回・修復でも、各項目は通常と同じ局所保存で確定します。ライブラリに依存する処理は、利用者が明示的に開始したときに初めて行います。

- 初回・修復のLR2では、通常・ルートの出力先を一つずつ保存でき、未設定・欠落した他の区分は、その保存を妨げません。未変更で要修復の先を作り直さず、表に依存するROOT登録は初期化時に揃えます。選択した出力先と設定済みの配置の保護条件は保存時に検査し、両方の必須出力先は初期化の開始時に検査します。
- 環境の保存では再起動しません。「この環境で開始」が、確定済みの必須値で一回だけ初期化し、必要な全表のBMT、必須のUI・ホストへの公開を待ってから、初回の完了と設定画面の閉鎖へ進みます。設定不足、処理の失敗、終了要求は型で区別します。
- 通常の起動の準備開始から、必須のUI・ホストへの公開の実際の終端までは、設定からの重複開始と、モード・LR2・beatorajaの組の反映を受け付けません。閲覧と無関係な通常項目の保存は可能です。開始ボタンはライブラリ操作状態と設定操作状態に従って無効にし、連続クリックも同じ受付で拒否します。有効なプロファイルの成功公開で開始表示を更新します。
- 初回・設定不備の案内では、起動の抑止と受付を解放済みなら、元の案内のTaskが未完了でも、同じ設定画面から開始できます。

### 反映範囲の型とスナップショット

各局所入口は、必要な実処理へ直接渡します。`BmsLibraryOptionsSnapshot`、`InstallDestinationWorkflowSettingsSnapshot`、`CustomFolderOutputSettingsSnapshot`、`StartupSettingsSnapshot`、`BeatorajaBmtOptionsSnapshot` は、確定値を操作の開始時に捕捉します。開始済みの操作は途中で設定を読み直さず、次の明示操作だけが新しい確定値を使います。

### 補助操作の対象・受付・閉鎖

LR2の手動同期と、履歴DBの導入・修復・撤去は、確定したモード・LR2ルート・詳細XML・プレイヤーを使います。Table URLの取込みは、確定したbeatorajaのルートを使います。

その対象を変える環境候補だけを破棄確認の対象とします。取消・検証の不成立・実際の受付の拒否では、画面と元の候補を保持して実処理を開始しません。確認の承認だけでは候補を戻さず、実際の受付と最終検査を通った採用点で、関係する候補だけを最新の確定値へ戻します。画面が存続する間、BMS・スコア・BMTなど無関係な候補は保持します。受理済みの処理の入力は、候補の破棄の対象に含めません。

| 補助操作 | 確認と受付 | 終端 |
| --- | --- | --- |
| LR2の手動同期 | 確認へ環境候補の破棄案内をまとめる。実際のLとPの受付に成功した後にだけ、設定画面を閉じる。 | 画面の閉鎖で同期Taskの所有を切らず、準備・保存・後片付けまで待つ。 |
| 履歴DBの導入・修復・撤去 | 導入確認・撤去選択へ破棄案内をまとめる。 | 同じTaskで、DBの変更、稼働中プロファイルの通常成績と全履歴の一括再取得を待つ。 |
| Table URLの取込み | 実際のPの受付を取得する。 | 取得・DB・BMT・通知の実際の終端Taskを設定担当へ返す。完了まで同じ再操作を拒否し、通常の閉鎖や再表示の後も同じTaskを保持する。開始メソッドからの復帰や、サマリーだけを終端としない。 |
| バックアップ | 確定データだけを使う。復元・アプリデータの撤去の確認には、終了時に未確定の候補を次回の起動へ引き継がない案内をまとめる。 | 復元の選択画面の取消、受付の拒否、必須処理の失敗では、元の候補と画面を保持して終了を要求しない。受理済みTaskの合流、通常の終了・後片付け、捕捉済みのDB撤去の順序は変えない。 |

過去に失敗した要求を保持するための、復元・再起動の拒否は設けません。

### カスタムフォルダと検索対象

本節は、設定画面で出力配置とBMSディレクトリを受け付けるときの検査と確認を定めます。出力先の配置条件、`jukebox` との同期、管理領域の整理は[LR2カスタムフォルダ出力](../playlist/lr2-custom-folders.md)を正本とします。

#### 保存前の配置検査

基点の変更・追加先の削除・改名は、表の変更後の実効の絶対パスの集合を[配置条件](../playlist/lr2-custom-folders.md#出力先と事前検査)で検査してから、設定・DB・LR2のXMLへ保存します。追加先の削除で既定の先に集まる場合も、同一・包含を拒否します。

出力基点同士の同一・親子関係は禁止します。既存の `jukebox` 登録に対する配置可否と、保存済みの追加・ルート出力先の転用の拒否は[既存登録との配置可否](../playlist/lr2-custom-folders.md#既存登録との配置可否)に従います。

- BMSディレクトリの追加は、登録済みのルートや出力領域との同一・親子関係を拒否し、出力に必要な登録の削除は保護します。出力先の変更は、対応する出力設定から行います。

#### 導入先の保護

LR2で変更前に有効な `BMSInstallDir` が、今回の通常・追加・ROOT出力先と同一またはその配下になる変更は、候補の採用時と局所確定の最終の配置検査で拒否します。

- 別の確定BMSディレクトリへ先に導入先を変更し、出力先を選び直すよう案内します。
- 比較は共通のパスの正規化を使い、大小文字・末尾の区切りを同一視し、`BMS` と `BMS2` を区別します。
- 保存・XML・表の登録・実際の配置へ副作用を与えず、代替の先を自動で選択しません。
- 初回や既存の不正な導入先を理由に、無関係な段階保存を拒否しません。導入先以外の利用者のルートは、引き続き採用できます。

#### 組込みの予約領域の検査時機

確定したLR2ルートが分かる場合、組込みの `LR2files/CustomFolder` に関する配置条件は[出力先と事前検査](../playlist/lr2-custom-folders.md#出力先と事前検査)に従います。設定側は、次の時機に一回ずつ検査します。

- 起動共通の受理。
- 出力区分の受付後、最初の保存の前。
- LR2ルート・詳細の変更の確認後、保存の前。
- 明示的なBMS登録の保存前。

setterや、通常の走査・表の編集・出力・同期では、組込みを再検査しません。

モードの選択は即時に保存し、再起動後の共通の起動検査で不備を訂正します。プロファイルが未構築の時は、通常・ROOTの選択画面と追加先の追加・改名・削除を、当該セクションだけで確定できます。未設定・旧予約領域の他の区分は、安全な訂正を妨げません。追加先の旧禁止集合は一件ずつ縮小でき、禁止先への新規追加・改名は拒否します。全体の受理までプロファイルとバックエンドを公開しない条件と、旧組込み領域の扱いは[管理領域の整理](../playlist/lr2-custom-folders.md#管理領域の整理)に従います。スタンドアローンでは、使わない出力の残存値だけで起動を止めず、ルートが不明な時に名前から推測しません。

#### 未受理の候補と未登録の追加先名

出力の未受理の候補は確定配置へ戻し、通常の選択・追加・削除・改名から再操作できます。過去の対象・改名・成功段階を復元せず、今回の入力と他の項目の最新の確定値から検証します。通常型が使う追加先名が設定にない場合の出力の停止と保存先の再選択の案内は、[出力先と事前検査](../playlist/lr2-custom-folders.md#出力先と事前検査)に従います。

#### 楽曲検索と一般のBMS一覧からの除外

カスタムフォルダの出力先は、本アプリケーションの管理領域です。

- 通常出力先だけは互換性のため楽曲検索に残し、追加の通常出力先とルートフォルダ出力先は楽曲検索から除きます。いずれも一般ページのBMSディレクトリ一覧、導入候補、フォルダツリーには混ぜません。楽曲検索の対象とLR2の `jukebox` 登録は区別し、出力に必要な登録は維持します。
- 一般のBMS一覧と確定した導入候補から除く範囲は、通常・追加・ROOTの各出力基点の全体とその子孫です。ドライブルートやUNC共有ルートも同じ意味で扱い、大小文字・末尾の区切りの差で除外が変わらないようにします。接頭辞だけが一致する兄弟、別のドライブ・別の共有、無関係な欠落した登録は保持します。
- 実在する管理出力を導入先の保存入口へ渡した場合も拒否し、最新の確定した導入先を保持します。
- 表の削除の対象範囲は基点の全体ではなく、[当該の表ディレクトリ](../playlist/lr2-custom-folders.md#管理領域の整理)です。

#### 保存時の確認

既存の登録を新たに出力の管理領域として採用する場合は、保存時に、管理領域とファイル整理の注意を確認します。

- 通常出力先の同一登録への復元では楽曲検索を維持し、追加・ルート出力先として採用する場所は検索対象から外れることを併記します。
- 保存済みの通常出力先を変更する場合も、その旧パスが検索対象から外れることを同じ確認へまとめます。旧通常出力先を追加・ルート出力先へ転用する場合は、既に管理領域であることを理由に、検索除外の確認を省略しません。

出力の確認は、保存済みの設定と、今回のフォルダの選択・追加・削除・改名が作る対象だけから作り、操作の保存の前に表示します。

- 同値の初期通知では、確認・保存・実処理を始めません。利用者の明示的な再選択・再保存は、最新の入力を再保存・再生成できます。警告の比較元には、確定済みの設定読取り窓口と所有者が保持するBMS登録を使い、別のセクションの未確定の候補を混ぜません。
- 検証エラーは確認より先に拒否します。確認の取消では、未受理の出力候補を復元し、保存・同期・ファイル変更へ進みません。正常に保存した後に同じ役割・パスを継続する場合は再確認せず、警告済みの永続状態も持ちません。

#### LR2の検索ルート候補の取得

登録内容の変更検出用の取得は、現在存在しない登録も比較対象に残し、実処理用の取得は存在する登録だけを使います。取得処理から設定XMLを保存しません。

それぞれの一回の取得で、現在・変更前の通常・追加・ROOT出力先の除外集合を一度だけ構築し、全ルートに適用します。候補が0件、または現在と対象の変更前のROOT出力先がどちらも空なら、プレイリスト全件のスナップショットは取得しません。必要なROOT出力先の計算には、一回の取得結果を共有します。正規化、同一・子パスの除外、親・兄弟パスの保持、登録の列挙順を維持します。別の取得には新しい入力を捕捉し、永続キャッシュは追加しません。

### 保存済み出力配置と内部継続

保存済みの整合した出力配置を構成から公開し、通常の出力はその配置を使います。一回の操作に必要な旧新の入力は同じTaskの終端まで保持し、終了後へ過去の要求・成功段階を持ち越しません。必要な実処理・公開・後片付け・通知を操作Taskで回収し、最新の入力で次の操作へ進めます。

走査で確認した同じ場所の接頭辞の訂正は、保存側では設定の保存先(`PortableSettingsProvider`)の短い保存区間内にある現在の対象キーへ、公開側では現在の設定読取り窓口と適用済みの配置へ、別々に適用します。

- 別の操作で保存だけに成功した別の場所の出力先を、旧公開値で上書きしたり、便乗して公開したりしません。
- 読取りの失敗は保存の失敗として終え、全設定の再読込みや保存済みコピーの常駐は行いません。
- XMLは自身の保存済みの登録へ今回の差分だけを適用し、必要な媒体の成功後にだけ対象値を公開します。

### アプリデータの撤去

アプリデータの撤去は、`song.db` に実際に生成したアプリケーション拡張の表・索引・トリガーと、`playlist_custom_folder_output_status` を対象とします。

- LR2本来の表と索引、未知の利用者の表・索引・トリガー・`sqlite_sequence` 行、譜面ファイルは保持します。アプリケーションの表に属する `sqlite_sequence` 行は撤去します。
- `score.db` の履歴の撤去は別の操作です。
- 対象一覧を明示的に使い、接頭辞による推測や全表の削除へ広げません。

確認の後は、通常のシェルの終了要求を同じUIのDispatcherで先着判定し、新規のLとPの受付を閉じます。要求元は受理だけを待ち、LとPと実際の設定操作のTaskを解放します。通常の終了の取消・通信・保存・再生・後片付けの実際の終端の後に、捕捉したDBパスを撤去し、設定Windowの寿命から独立した窓口で成否を通知して終了します。撤去の失敗、通知の例外、通知不能でも、停止済みの所有者の再開・再初期化は行いません。

### 履歴DBの状態と計測

履歴DBの状態表示はキャッシュを読み、設定画面を開くたびにDBを照会しません。スコアの読込み、対象プロファイルの履歴の読込み、明示的な導入・修復・削除に伴う確認結果で更新します。対象を切り替えた場合は「未確認」に戻し、前のプロファイルの導入済みの状態を使いません。明示操作は変更の前後に状態を確認し、成功した後に履歴の読込みキャッシュも無効にします。

画面の表示、取消、検証、局所保存、必要処理の診断を分けます。メッセージを利用者が閉じるまでの時間を、内部処理の性能値と混ぜません。診断の失敗で、操作の成否を変更しません。
