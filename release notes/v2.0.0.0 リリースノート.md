# 日本語 v2.0.0.0

## 重要なお知らせ

- v2.0.0.0 は、bmson 管理対応に伴い、ライブラリ管理、起動・リロード、インストール、プレイリスト、メンテナンス、LR2 連携を広く見直した大規模アップデートです。
- BeMusicSeeker 管理用 DB スキーマを更新します。更新後の DB は、従来版 BeMusicSeeker および本フォーク v1.2.1.0 以前と互換性がない可能性があります。
- LR2 連携モードで使用する場合は、更新前に `song.db`、`config.xml`、score DB、をバックアップしておくことを強くおすすめします。
- 初回起動、空 DB からの構築、BMS ルートの大規模変更、大量差分の取り込みでは、ファイル列挙、譜面メタデータ解析、リソース状態作成、LR2 `song.db` 同期に時間がかかる場合があります。
- 大規模ライブラリでは `Everything 1.5 (x64)` の導入を強く推奨します。Everything 連携に失敗して通常のファイル列挙へ切り替わる場合は、警告ダイアログを表示するようになりました。
- bmson はライブラリ上の管理対象になりましたが、現時点では内蔵プレイヤーでの再生、通常の外部プレイヤーへの再生渡し、音声ファイル変換、には対応していません。再生したい場合は、`関連付けで開く` などで bmson 対応アプリから開いてください。

## 機能・操作面の変更

### 初期セットアップ / 動作モード

- 初回起動時の言語選択と設定導線を整理しました。
  - 初回起動時は言語選択付きの初回設定ダイアログを表示し、必須設定を入力して `OK` を押すまで初回スキャンを開始しません。
- LR2 と連携しないスタンドアローンモードを追加しました。
  - LR2 の `song.db` を使わず、アプリ配下の `data/song.db` でライブラリを管理します。
  - LR2 を使わない環境でも、BMS / PMS / bmson の検索、インストール、プレイリスト管理、メンテナンスを BeMusicSeeker 側だけで行えます。
- 設定ダイアログを整理し、一般、詳細、外観の各設定を見直しました。
- BMS ディレクトリは `追加` ボタンだけでなく、フォルダをリストへドラッグアンドドロップして追加できるようになっています。

### bmson 管理対応

- `.bmson` を BMS / PMS と同じ「譜面ファイル」として扱えるようにしました。
  - 通常ライブラリ、プレイリスト詳細、インストール / 保留パッケージ、重複ファイルチェック、構成ファイルフルスキャン、フォルダ自動リネーム、導入済み場所の修正などで bmson を管理対象にします。
  - BMS / PMS / bmson を内部的に `ChartFile` / `ChartPackage` として扱う基盤へ整理し、BMS 専用処理が bmson に誤って適用されにくくしました。
- bmson 用の管理テーブルを追加し、title、artist、genre、level、mode hint、MD5、SHA-256、リソース参照、譜面メタデータを BeMusicSeeker 側で保存・更新します。
- 外部プレイリストの SHA-256 entry から、所持 BMS / bmson を解決できるようにしました。
  - 既存 BMS についても MD5 / SHA-256 の対応を保持し、プレイリストや譜面メタデータとの照合に使います。
  - プレイリストサマリーでは、MD5 がある行は MD5 を優先し、MD5 がない SHA-256 only 行だけ SHA-256 で所持判定します。
- bmson 行では、LR2IR、BMS 専用の譜面ビューア、音声変換、文字化けチェックなど、未対応または BMS 専用の操作を表示しないよう整理しました。
- LR2 連携モードでも、bmson は LR2 の `song` / `folder` には書き込まず、BeMusicSeeker 側の管理情報として扱います。

### chart_info / 譜面メタデータ

- BMS / bmson 向けの `chart_info` 生成と保存に対応しました。
  - BPM、TOTAL、DIFFICULTY、NOTES、密度、LN、SCRATCH、変速、判定、演奏時間などを解析します。
  - beatoraja / jbms-parser 互換を意識して、BMS と bmson の解析結果を揃えています。
- 通常一覧とプレイリスト詳細に、`DIFFICULTY`、`MAINBPM`、`MAXBPM`、`MINBPM`、`DURATION`、`JUDGE`、`FEATURE`、`NOTES`、`LONG`、`SCRATCH`、`TOTAL`、`T/N`、`DENSITY`、`PEAK`、`END`、`SOFLAN` などの列を追加しました。
- キーワード検索で、譜面メタデータ由来の条件を指定できるようにしました。
  - 例: `total:undef`、`notes:>=1000`、`feature:ln`、`difficulty:insane`
  - field 補完、プレイリスト名補完、検索履歴、除外、OR、正規表現、数値範囲検索も利用できます。
- `ゼロノート検索` と `解析エラー` 画面を追加・強化しました。
  - `メタデータ解析失敗記録を除去` で保存済みの失敗記録を削除し、再解析対象に戻せます。
  - `#RANDOM` / `#IF` などの条件分岐を含む譜面は、全分岐総当たりではなく安定したメタデータ生成を優先します。0 notes 判定は確認対象を見つけるための手掛かりであり、空譜面の断定ではありません。
- `chart_info` / `chart_digest_map` を含む metadata bundle の import / archive に対応しました。
  - metadata 同梱版パッケージでは初回解析負荷を減らせます。
  - import 済み bundle は `imported_metadata/` へ退避します。

### 起動 / リロード / 大規模ライブラリ

- 起動とリロードの流れを、DB 読み込み、ファイル列挙、差分確認、譜面メタデータ反映、メンテナンス情報、プレイリスト、LR2 `song.db` 同期などの段階に整理しました。
- `Everything 1.5 (x64)` を使った高速ファイル列挙とリソース索引作成を強化しました。
  - BMS 譜面、bmson、音源、画像、動画、テキスト、`.lr2folder` / `folderinfo.txt` などを用途別に列挙します。
  - Everything が使えない場合は managed scan へ fallback しますが、大規模ライブラリでは大きく遅くなるため、警告を表示します。
- 差分が少ない通常起動では、操作に必要な情報を優先して読み込み、重い補助情報の反映をバックグラウンド側で進めるようにしました。
- 一覧表示を独自テーブル表示へ移行し、大量件数でも列設定、ソート、選択、コピー、ツールチップ、プレイリストサマリーを扱いやすくしました。
- 通常ライブラリ、プレイリスト詳細、プレイリストサマリー、保留、新規、重複、メンテナンス系の一覧で、仮想ソートや仮想リスト更新を拡充しました。

### インストール / 保留パッケージ

- `.bmson` 単体、bmson のみのパッケージ、BMS と bmson が混在するパッケージを、新規導入・保留・導入先推定の対象にしました。
- `インストール先を推定` と `マージ先を推定` の用途を整理しました。
  - `インストール先を推定` は、保留パッケージに同梱されているリソースも「導入後に使えるもの」として評価します。
  - `マージ先を推定` は、既所持譜面のみのパッケージやリソースだけを既存フォルダへ寄せたいケース向けに、既存ライブラリ側のリソースだけで推定します。
- 導入先推定では相対パスを重視し、`foo.wav` と `sound/foo.wav` を別リソースとして扱います。
  - 親ディレクトリ参照 `..` を含むリソースは `リソースパス非対応` WARNING になり、自動推定対象外です。
- `INSTL DST TITLE` / `INSTL DST ARTIST`、候補サジェスト、低信頼 WARNING、TITLE/ARTIST tie-break など、導入先推定結果を確認しやすくしました。
- URL から取得したパッケージの導入キュー、保留への追加、キャンセル表示、進捗表示を整理しました。

### プレイリスト / URL / beatoraja

- 複数行選択から `選択中の本体URLを取り込む` / `選択中の差分URLを取り込む` を実行できるようにしました。
  - 同一 URL を重複排除し、対応ファイルとして解決できた URL だけをダウンロードして導入キューへ渡します。
  - ブラウザで開く必要がある URL は、一括取り込みでは開かずにスキップします。
  - 進捗と結果サマリーを表示します。
- 自動ダウンロード導入では、`.bme` / `.bms` / `.bml` / `.pms` / `.bmson` と `.zip` / `.7z` / `.rar` / `.lzh` を対象にします。
  - Google Drive、Dropbox、MediaFire、manbow、venue.bmssearch.net、bmssearch.net など、一部の配布ページ URL 解決に対応しました。
  - Google Drive フォルダ、MEGA、AXFC、ログイン、CAPTCHA、JavaScript 操作が必要なページ、サイズ上限を超えるファイルは自動導入対象外です。
- beatoraja の `tablepath` へ `.bmt` 難易度表キャッシュを出力できるようにしました。
  - `.bmt hash 出力` で `オリジナル`、`md5/sha256をできるだけ補完`、`できるだけsha256のみ` を選べます。
  - `config_sys.jsonに.bmtのURLを登録する` を有効にすると、BeMusicSeeker 管理の `.bmt` URL を `tableURL` に登録し、beatoraja 側の表順を安定させます。
  - `.bmt出力を無効化しても既存ファイルを削除しない` を追加しました。

### LR2 連携 / song.db 同期

- LR2 連携モードでは、BeMusicSeeker が LR2 `song.db` の `song` / `folder` 派生データを生成・同期する方式になりました。
  - 初回や設定変更後は不足 row を補完し、以後はファイル差分、インストール、削除、移動、プレイリスト出力変更に合わせて差分同期します。
  - LR2 側の起動時再帰スキャンをできるだけ発生させない状態を維持します。
- LR2 連携モードでは、LR2 `config.xml` の自動更新設定を手動相当に寄せます。
  - BMS ルートの追加・削除は LR2 SETUP 側ではなく、BeMusicSeeker の `一般` タブで行う運用を推奨します。
- ステータスバーに `LR2 song.db 同期` 状態を表示し、失敗・未完了時は再試行できるようにしました。
- 設定画面に `LR2 song.db データを再同期` を追加しました。
  - 所持譜面とプレイリストを正本として `song` / `folder` を再生成します。
  - 初回設定がまだ成立していない状態では押せないようにしました。
- BeMusicSeeker 管理のカスタムフォルダ、LR2 標準 `LR2files\CustomFolder`、BMS root 配下の `.lr2folder` / `folderinfo.txt` 周辺の同期を改善しました。
- LR2 互換性警告を追加しました。
  - CP932 / Shift_JIS で表現できない譜面パス、長すぎる譜面パス、LR2 が扱えない可能性のあるリソース名、長すぎるリソース参照パスを検出します。
  - BeMusicSeeker 上では該当譜面を削除せず WARNING として表示しますが、LR2 側では選曲や再生に失敗する可能性があります。

### ランキング / LR2IR 関連

- `起動時にLR2IRランキングキャッシュを更新する` を追加し、既定 OFF にしました。
  - ON にすると LR2IR ranking cache XML を起動後に読み込み、`RANKING`、`RANK UPDATE`、`T-SCORE`、`ΔMAX` などの表示用データを更新します。
  - 初回構築や LR2ID 変更後は CPU / DISK 使用率が大きく上がる可能性があります。
- `オフラインスコアのランキング推定を行う` は既定 OFF になりました。
  - ON にすると LR2IR ranking cache の適用時に、ローカルスコアが LR2IR 上のスコアより高い譜面の順位を推定します。
  - 変更は再起動後に反映されます。
- `LR2IRのスコアをDLしIR未送信を検出する` も既定 OFF です。
- `BMS-IRを開く` は MD5 で対象譜面の BMS-IR ページを開くようになりました。
- `http://www.ribbit.xyz` の LR2IR キャッシュに依存する動画候補、入手先候補、ランキングデータ更新などは、外部サイト状況により実質的に動作しない場合があります。

### メンテナンス / 重複 / リソースチェック

- `WARNING` 表示を構造化し、一覧表示用の要約と tooltip の詳細を分けました。
- `重複ファイルチェック` が bmson を含むライブラリに対応しました。
  - 重複フォルダの `マージ先` 操作で、bmson 譜面と同梱リソースもまとめて移動できます。
- `構成ファイルフルスキャン` は BMS / bmson の WAV、BGA、動画、画像不足を確認できます。
  - 通常起動では全譜面のリソース再検証は行わないため、導入後にリソースを追加した場合は行単位の再スキャンまたは全譜面再スキャンを実行してください。
- `LR2互換性警告`、`解析エラー`、`ゼロノート検索`、`重複ファイルチェック` など、メンテナンス系画面の既定列、検索、表示更新を調整しました。

### UI / 外観 / ドキュメント

- アプリケーションテーマ、ダイアログ、スクロールバー、コンテキストメニュー、設定画面、プレイリストプロパティ画面を調整しました。
- 起動時進捗、ステータスバー進捗、URL import 進捗、`.bmt` 出力進捗、LR2 `song.db` 同期進捗などを見直しました。
- 日本語 / 英語マニュアル、検索構文ガイド、README、リリース用 HTML ドキュメント、多言語リソースを更新しました。
- 通常より詳しいログを `application.log` と `install-performance.log` に出せるよう、起動・DB・ファイルスキャン・プレイリスト・LR2 同期・導入先推定まわりのログを追加しました。

- 起動、初期化、ファイル差分確認、`chart_info` backfill、保留推定、重複検索、プレイリスト表示、一覧ソートを大規模ライブラリ向けに最適化しました。
- DB 読み込み、譜面メタデータ反映、リソース状態更新、LR2 `song.db` 同期が競合しにくいように処理順を整理しました。

- プレイリスト更新判定、外部同期 `STATUS`、単体 / 範囲リロード、URL 補完、`.bmt` 出力、LR2 `song.db` 同期の進捗表示とログを強化しました。

## 移行・互換性の注意

- v2.0.0.0 では BeMusicSeeker 関連 DB スキーマが更新されます。更新後の DB は、従来版 BeMusicSeeker および本フォーク v1.2.1.0 以前と互換性がない可能性があります。
- LR2 連携モードでは、更新前に `song.db`、`config.xml`、score DBをバックアップしてください。

- bmson は管理対象ですが、再生と音声変換には未対応です。LR2 の `song` / `folder` へも登録されません。
- 通常起動では全譜面のリソース再検証は行いません。リソースを後から追加した場合は、選択行の再スキャンまたは `全譜面を再スキャン` を実行してください。

# English v2.0.0.0

## Important Notes

- v2.0.0.0 is a major update built around bmson management support. It broadly reworks library management, startup and reload behavior, installation, playlists, maintenance, and LR2 integration.
- The BeMusicSeeker-managed DB schema is updated. After updating, the DB may no longer be compatible with the traditional BeMusicSeeker or this fork's v1.2.1.0 and earlier releases.
- When using LR2 linked mode, backing up `song.db`, `config.xml`, and score DBs before updating is strongly recommended.
- First launch, rebuilding from an empty DB, large BMS-root changes, and large file-difference imports may take time while the app enumerates files, parses chart metadata, builds resource-health information, and synchronizes LR2 `song.db`.
- `Everything 1.5 (x64)` is strongly recommended for large libraries. If Everything integration fails and the app switches to ordinary file enumeration, a warning dialog is now shown.
- bmson is now managed by the library, but built-in playback, normal playback through the configured external player, and audio conversion are not supported yet. To play bmson, open it with a bmson-capable application, for example through file association.

## Feature and Usability Changes

### Initial Setup / Operating Modes

- Improved the first-launch language selection and setup flow.
  - The first launch shows an initial setup dialog with language selection, and the first scan does not start until required settings are filled in and `OK` is pressed.
- Added standalone mode that does not depend on LR2.
  - The library is managed with `data/song.db` under the application directory instead of LR2 `song.db`.
  - Search, install, playlist management, and maintenance workflows for BMS / PMS / bmson can be used without LR2.
- Reorganized the settings dialog and reviewed the General, Advanced, and Appearance settings.
- BMS directories can be added with the `Add` button or by dragging folders onto the list.

### bmson Management Support

- `.bmson` files can now be managed as chart files alongside BMS / PMS.
  - bmson is handled in the normal library, playlist detail, install / pending packages, duplicate file check, full resource scan, folder auto rename, and installed-location repair.
  - Internally, BMS / PMS / bmson handling was reorganized around `ChartFile` / `ChartPackage`, reducing accidental application of BMS-only behavior to bmson entries.
- Added bmson management storage for title, artist, genre, level, mode hint, MD5, SHA-256, resource references, and chart metadata.
- Owned BMS / bmson charts can now be resolved from SHA-256 entries in external playlists.
  - MD5 / SHA-256 mappings are also kept for existing BMS charts and used for playlist and chart-metadata matching.
  - In playlist summaries, MD5 is preferred when present, and SHA-256 is used only for SHA-256-only rows.
- bmson rows no longer show unsupported or BMS-only operations such as LR2IR actions, BMS-only chart viewers, audio conversion, and mojibake checks.
- Even in LR2 linked mode, bmson files are not written to LR2 `song` / `folder`; they are handled as BeMusicSeeker-side management entries.

### chart_info / Chart Metadata

- Added `chart_info` generation and storage for BMS and bmson.
  - The app parses BPM, TOTAL, DIFFICULTY, NOTES, density, LN, SCRATCH, soflan, judge, duration, and related metadata.
  - BMS and bmson results are aligned with beatoraja / jbms-parser compatibility in mind.
- Added columns such as `DIFFICULTY`, `MAINBPM`, `MAXBPM`, `MINBPM`, `DURATION`, `JUDGE`, `FEATURE`, `NOTES`, `LONG`, `SCRATCH`, `TOTAL`, `T/N`, `DENSITY`, `PEAK`, `END`, and `SOFLAN` to the normal library and playlist detail views.
- Keyword search can now use chart metadata conditions.
  - Examples: `total:undef`, `notes:>=1000`, `feature:ln`, `difficulty:insane`
  - Field completion, playlist-name completion, search history, exclusions, OR, regular expressions, and numeric range searches are also available.
- Added and improved `Zero-note Search` and `Parse Errors` screens.
  - `Remove chart metadata parse failure records` clears saved failure records and returns those charts to the reparse target set.
  - Charts with conditional branches such as `#RANDOM` / `#IF` prioritize stable metadata generation instead of exhaustive branch enumeration. The 0-notes result is a clue for investigation, not a definitive statement that the chart is empty.
- Added import and archiving support for metadata bundles containing `chart_info` / `chart_digest_map`.
  - Packages with bundled metadata can reduce first-parse load.
  - Imported bundles are moved under `imported_metadata/`.

### Startup / Reload / Large Libraries

- Startup and reload processing is now organized into phases such as DB load, file enumeration, file-difference check, chart metadata application, maintenance information, playlists, and LR2 `song.db` synchronization.
- Strengthened fast file enumeration and resource-index creation using `Everything 1.5 (x64)`.
  - The app enumerates BMS charts, bmson, audio, images, videos, text files, `.lr2folder` / `folderinfo.txt`, and related data by purpose.
  - If Everything cannot be used, the app falls back to managed scan, but this can be much slower in large libraries, so a warning is displayed.
- For normal launches with few differences, the app prioritizes information required for interaction and continues heavier auxiliary updates in the background.
- The main lists were migrated to a custom table view so column settings, sorting, selection, copy, tooltips, and playlist summaries remain usable with large row counts.
- Virtualized sorting and row updates were expanded across the normal library, playlist detail, playlist summary, pending, new, duplicate, and maintenance views.

### Install / Pending Packages

- Single `.bmson` files, bmson-only packages, and mixed BMS / bmson packages can now be handled as new installs, pending packages, and install-estimation targets.
- Clarified the roles of `Estimate install destination` and `Estimate merge destination`.
  - `Estimate install destination` counts resources bundled in the pending package as resources that will become available after installation.
  - `Estimate merge destination` is for already-owned-only packages or resource-only merge cases, and estimates using only resources already present in the existing library.
- Install-destination estimation now emphasizes relative paths, so `foo.wav` and `sound/foo.wav` are treated as different resources.
  - Resource references containing parent-directory traversal such as `..` receive an `Unsupported resource path` WARNING and are excluded from automatic estimation.
- Added `INSTL DST TITLE` / `INSTL DST ARTIST`, candidate suggestions, low-confidence WARNINGs, and TITLE/ARTIST tie-break behavior to make estimation results easier to inspect.
- Reorganized the install queue, pending addition, cancellation visibility, and progress display for packages obtained from URLs.

### Playlists / URLs / beatoraja

- Added `Import selected main URLs` / `Import selected diff URLs` for multi-row selections.
  - Duplicate URLs are removed, and only URLs that resolve to supported downloadable files are downloaded and passed to the install queue.
  - URLs that need to open in a browser are skipped without opening them during bulk import.
  - Progress and result summaries are shown.
- Automatic download import targets `.bme` / `.bms` / `.bml` / `.pms` / `.bmson` and `.zip` / `.7z` / `.rar` / `.lzh`.
  - Some page-resolution support was added for Google Drive, Dropbox, MediaFire, manbow, venue.bmssearch.net, and bmssearch.net.
  - Google Drive folders, MEGA, AXFC, pages requiring login, CAPTCHA, JavaScript interaction, and files over the size limit are not automatic-import targets.
- Added `.bmt` difficulty-table cache output under beatoraja's `tablepath`.
  - `.bmt hash output` can be set to `Original`, `Complete md5/sha256 as much as possible`, or `Prefer sha256 only as much as possible`.
  - When `Register .bmt URLs in config_sys.json` is enabled, BeMusicSeeker-managed `.bmt` URLs are registered in `tableURL`, stabilizing table order on the beatoraja side.
  - Added an option to keep existing `.bmt` files even when `.bmt` output is disabled.

### LR2 Integration / song.db Synchronization

- In LR2 linked mode, BeMusicSeeker now generates and synchronizes LR2 `song.db` `song` / `folder` derived data.
  - Missing rows are backfilled on first setup or after setting changes, and later updates are synchronized from file differences, installs, deletes, moves, and playlist output changes.
  - This keeps LR2's own recursive startup scan from being needed as much as possible.
- In LR2 linked mode, LR2 `config.xml` automatic DB update settings are adjusted toward manual operation.
  - Adding and removing BMS roots from BeMusicSeeker's `General` tab is recommended instead of editing them in LR2 SETUP.
- Added `LR2 song.db sync` state to the status bar, with retry available when synchronization fails or remains incomplete.
- Added `Resynchronize LR2 song.db Data` to the settings dialog.
  - It regenerates `song` / `folder` using owned charts and playlists as the source of truth.
  - The button is disabled before the initial settings have produced a valid profile.
- Improved synchronization around BeMusicSeeker-managed custom folders, LR2 standard `LR2files\CustomFolder`, and `.lr2folder` / `folderinfo.txt` files under BMS roots.
- Added LR2 compatibility warnings.
  - The app detects chart paths that cannot be represented in CP932 / Shift_JIS, overly long chart paths, resource names that LR2 may not handle, and overly long resource reference paths.
  - BeMusicSeeker only shows these as WARNINGs and does not delete the charts, but LR2 may fail to select or play them.

### Ranking / LR2IR

- Added `Update LR2IR ranking cache on startup`, OFF by default.
  - When enabled, the app reads LR2IR ranking cache XML after startup and updates display data such as `RANKING`, `RANK UPDATE`, `T-SCORE`, and `ΔMAX`.
  - CPU / disk usage may increase significantly during the first build or after changing LR2ID.
- `Estimate offline score rankings` is now OFF by default.
  - When enabled, the app estimates ranks for charts whose local score is higher than the LR2IR score when LR2IR ranking cache data is applied.
  - Changes take effect after restart.
- `Download LR2IR scores and detect unsent IR scores` is also OFF by default.
- `Open BMS-IR` now opens the target chart's BMS-IR page by MD5.
- Video candidates, download-source candidates, ranking data updates, and other features that depend on `http://www.ribbit.xyz` LR2IR cache may effectively not work depending on the external site state.

## Migration and Compatibility Notes

- v2.0.0.0 updates BeMusicSeeker-related DB schemas. After updating, the DB may no longer be compatible with the traditional BeMusicSeeker or this fork's v1.2.1.0 and earlier releases.
- When using LR2 linked mode, back up `song.db`, `config.xml`, and score DBs before updating.
- Back up the portable settings file `config/user.config` if needed.
- Do not run the app directly from the ZIP. Extract it into a writable folder. When updating, keep `config` and `data` and overwrite the main application files.
- If LR2 `song.db` synchronization is incomplete or failed, LR2 may read an old DB. Use `Retry` in the status bar or `Resynchronize LR2 song.db Data` in the settings dialog.
- bmson is managed by the library, but playback and audio conversion are not supported yet. bmson is also not registered into LR2 `song` / `folder`.
- Normal startup does not revalidate resources for every chart. If resources are added later, run a row rescan or `Full scan all charts`.
