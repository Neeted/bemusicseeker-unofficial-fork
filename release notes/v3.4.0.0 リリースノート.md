# 日本語

## 変更点

### 重複音源チェック

- メンテナンスに `重複音源チェック` を追加しました。一つの譜面フォルダの中に、同じ名前の音源が WAV と OGG の両方で置かれている状態（`foo.wav` と `foo.ogg` など）を探します。左ツリーで選ぶと探索を始め、見つかったフォルダをツリーに表示します。
- ツリーの `整理候補一覧` で、見つかったフォルダを確認して整理できます。`選択フォルダを確認` で同名の WAV と OGG を波形で比べ、`STATUS` に `安全（WAV/OGG同等）` または `要注意：WAV/OGG非同等` を表示します。`CONFLICTS` 列には、同名の組の数を表示します。
- `衝突整理` で残す形式（`OGGを残す`／`WAVを残す`）を選び、`選択フォルダを整理` を押すと、残さない形式のファイルを削除します。削除方法は `削除` で `ごみ箱へ移動`（既定）と `完全に削除` から選べます。確認していないフォルダは整理できません。`要注意` のフォルダを含む場合は、確認ダイアログで警告し、続行のチェックを求めます。
- 同等と判定されなかった組は、`STATUS` のツールチップで理由ごとの件数と音質の目安を確認でき、右クリックの `検査結果の詳細をコピー` で組ごとの検査結果を取り出せます。内容は統合候補一覧と同じです。

### 統合候補一覧

- 重複ファイルチェックと分裂配置チェックの統合候補一覧で、同じグループのフォルダ間で `TITLE` 列の値が異なると `STATUS` に `代表TITLE不一致` を表示するようにしました。`ARTIST` 列も同様に `代表ARTIST不一致` を表示します。確認前から表示され、安全性の判定や整理の可否には影響しません。`status:代表TITLE不一致` のように検索欄や除外欄で絞り込めます。
- `STATUS` の補助情報（`WAV/OGG同等`、`代表TITLE不一致`、`代表ARTIST不一致`、`.bmx/.txtの衝突`）を、段階と理由の後ろの一つの括弧に `要注意：同名音源の拡張子違い（代表TITLE不一致, .bmx/.txtの衝突）` のようにカンマ区切りでまとめて表示するようにしました。`.bmx/.txtの衝突` は `安全` のときだけでなく、`要注意` と `統合不可` でも表示します。
- `高速化のための簡易チェック` のラベルを短くし、説明をツールチップへ移しました。
- 検索欄と除外欄に入力補完を付けました。空欄のときに項目の候補を選べ、`status:` に続けて段階や理由、付記を候補から選べます。候補は一覧の表示が0件でも使えます。
- `同名音源の拡張子違い` の警告を、統合によって同じ位置の音源の形式が増える場合だけ表示するようにしました。たとえば一方のフォルダに `foo.wav` だけがあり、もう一方の同じ位置に `foo.ogg` があると、統合後に元の譜面が別の音源を再生する可能性があるため警告します。その名前の音源を持つすべてのフォルダで形式がそろっていれば、警告は出ません。
- `衝突WAV/OGGの同等性を検査` のチェックを追加しました。有効にして `選択グループを確認` を押すと、同名のWAVとOGGが衝突しているときに、OGGがWAVから変換されたものかを波形で判定し、同等と判定された名前を `同名音源の拡張子違い` の警告から外します。衝突したWAVとOGGがすべて同等だったグループは、段階によらず `STATUS` に `WAV/OGG同等` が付きます。確認に時間がかかるため、既定は無効です。
- `衝突整理` の選択（`両方残す`／`OGGを残す`／`WAVを残す`）を追加しました。確認済みのグループで同名のWAVとOGGが衝突した名前について、`選択グループを整理` で一方の形式を `KEEP` のフォルダに残し、もう一方を削除できます。同等と判定されていない組も対象になり、その場合は確認ダイアログで警告します。既定は `両方残す` です。
- `削除` の選択（`ごみ箱へ移動`／`完全に削除`）を追加しました。`選択グループを整理` が削除する重複した譜面と、`衝突整理` で残さない形式の音源に適用します。`完全に削除` はごみ箱を経由しないため、大量の音源を整理するときに処理が速くなります。削除したファイルは元に戻せないため、確認ダイアログで警告します。既定は `ごみ箱へ移動` で、起動のたびに既定へ戻ります。
- `衝突WAV/OGGの同等性を検査` で同等と判定されなかった名前について、`STATUS` のツールチップに理由ごとの件数を `内訳：長さ違い（比較打ち切り） 5／相関不足 3` のように表示するようにしました。OGGが低ビットレート、WAVが8ビット、片方だけモノラルなど、どちらかが低音質版と推察できる場合は、`音質の目安` として件数を表示します。
- 右クリックメニューに `検査結果の詳細をコピー` を追加しました。選択したグループについて、WAVとOGGの組ごとの判定、同等でない理由、フルパス、サンプリング周波数、フレーム数、WAVのビット深度、OGGの平均ビットレート、相関や音量の差などを、タブ区切りでクリップボードへコピーします。表計算ソフトへそのまま貼り付けられます。
- `STATUS` のツールチップを、内容に合わせて横に広がるようにしました。フルパスを含む行が途中で折り返されなくなります。

### プレイリストの本体候補

- プレイリスト詳細の未所持譜面について、その曲の本体フォルダをすでに持っていると推定できる場合に知らせるようにしました。差分だけを入手すればよい行を見分けるための目印です。
- 差分 URL（`URL2`）があり、本体フォルダの候補が見つかった未所持行は、`URL1` 列を専用の色で表示します。行やセルを選択している間も同じ色です。
- 未所持行の右クリックメニューに `本体候補` を追加しました。候補のフォルダを最大5件表示し、選ぶとエクスプローラーで開きます。差分 URL がない行にも表示し、候補がない行には表示しません。
- 候補は、プレイリストに書かれた `TITLE` と `ARTIST` を所持譜面のものと照合して探します。難易度名や差分作者などの表記の違いを取り除いたうえで、曲名が一致し、作者が一致するか近い譜面のあるフォルダを候補にします。プレイリストに作者が書かれていない行は、曲名だけで照合します。

本体候補は推定です。未所持の譜面はファイルが手元にないため、判定に使える情報はプレイリストの `TITLE` と `ARTIST` だけで、原理的に限界があります。本体を持っていても候補が出ない場合や、同じ曲名の別の作品が候補になる場合があります。条件を緩めると見落としは減りますが、誤った候補が増えるため、その釣り合いで現在の条件にしています。譜面のハッシュごとに正しい本体を記録したデータを用意する方法も考えられますが、新しく公開された譜面には対応できないため、採用する予定はありません。

### 通信設定

- 設定画面の `詳細設定` に `通信` を追加しました。次の6項目を数値で変更できます。既定値はこれまでの動作と同じです。
  - `外部難度表の同時取得数`（既定 32 表）
  - `譜面・アーカイブの1ファイルの上限`（既定 512 MiB）
  - `ファイル取得の待ち時間`（既定 30 秒）
  - `外部難度表の取得期限`（既定 300 秒）
  - `外部難度表のHTMLの上限`（既定 10 MiB）
  - `外部難度表のJSONの上限`（既定 100 MiB）
- 大きな配布アーカイブを取得したい場合や、応答の遅い配布元・難度表を使う場合に、上限や待ち時間を伸ばせます。変更した値は、次に開始する取得から使われます。

### 自動アップデート

- 更新ダイアログの `更新` を、起動中の初期化が終わる前でも押せるようにしました。押すとダウンロードがすぐに始まり、初期化と並行して進みます。
- ダウンロードの進み具合をステータスバーに表示し、取消ボタンで更新を取り消せるようにしました。ダウンロード中にアプリを閉じた場合も、更新を取り消してすぐに終了します。取り消した更新は、次回の起動時に改めて案内されます。
- 更新パッケージのダウンロード全体にかかっていた5分の制限をなくしました。受信が続いている間は、回線が遅くてもダウンロードを続けます。

### GitHubのスター

- しばらく使い続けた後の起動時に、このフォーク版のGitHubリポジトリへのスターをお願いする案内を表示するようにしました。このバージョン以降の起動が10回以上になり、その最初の起動から14日以上たつと表示します。`GitHubでスターを付ける` を押すとリポジトリをブラウザで開きます。
- `あとで` を選ぶと、30日以上たち、さらに10回起動した後に改めて表示します。表示は合計3回までで、`GitHubでスターを付ける` でリポジトリを開いた場合と `今後表示しない` を選んだ場合は、その後表示しません。
- 設定画面の `このアプリについて` にも `GitHubでスターを付ける` のリンクを追加しました。

# English

## Changes

### Duplicate Audio Check

- Added `Duplicate audio check` to maintenance. It finds chart folders that contain the same audio name as both WAV and OGG (for example `foo.wav` and `foo.ogg`). Selecting it in the left tree starts the search, and the folders that were found appear in the tree.
- `Cleanup candidates` in the tree lets you check and organize the folders that were found. `Check selected folders` compares each same-name WAV and OGG by waveform and shows `Safe (WAV/OGG equivalent)` or `Caution: WAV/OGG not equivalent` in `STATUS`. The `CONFLICTS` column shows the number of same-name pairs.
- Choose the format to keep with `Collision cleanup` (`Keep OGG` / `Keep WAV`) and press `Organize selected folders` to delete the files of the other format. With `Delete`, you can choose `Move to Recycle Bin` (the default) or `Delete permanently`. Folders that have not been checked cannot be organized. When folders marked `Caution` are included, the confirmation dialog warns about them and asks you to tick a box to continue.
- For pairs that were not judged equivalent, the `STATUS` tooltip shows the count for each reason and the quality hints, and `Copy inspection details` in the context menu copies the inspection result of each pair. The content is the same as in the merge candidates list.

### Merge Candidates

- In the merge candidates list of the duplicate file check and the split placement check, `Representative TITLE mismatch` now appears in `STATUS` when folders in the same group show different values in the `TITLE` column. The same applies to `ARTIST`, shown as `Representative ARTIST mismatch`. These notes appear before verification and do not affect the safety rating or whether the group can be organized. You can filter by them in the search or exclusion box, for example with `status:"Representative TITLE mismatch"`.
- Supplementary notes in `STATUS` (`WAV/OGG equivalent`, `Representative TITLE mismatch`, `Representative ARTIST mismatch`, and `.bmx/.txt collision`) now appear together in one pair of parentheses after the stage and reasons, separated by commas, as in `Caution: same audio name, different extension (Representative TITLE mismatch, .bmx/.txt collision)`. `.bmx/.txt collision` now appears for `Caution` and `Cannot merge` as well as `Safe`.
- Shortened the `Quick check for speed` label and moved its explanation to the tooltip.
- Added suggestions to the search and exclusion boxes. When a box is empty, you can choose from the available fields, and after `status:`, you can choose a stage, reason, or note. Suggestions are available even when the list shows no results.
- The `same audio name, different extension` warning now appears only when merging would add a format for audio at the same relative location. For example, if one folder has only `foo.wav` and another has `foo.ogg` at the same relative location, a chart may play a different audio file after merging, so the warning appears. If every folder containing that audio name already has the same set of formats, the warning does not appear.
- Added the `Check WAV/OGG collisions for equivalence` check. When it is enabled and you press `Verify selected groups`, a same-name WAV and OGG that collide are compared by waveform to judge whether the OGG was converted from the WAV, and names judged equivalent no longer trigger the `same audio name, different extension` warning. A group whose colliding WAV and OGG files were all judged equivalent gets the `WAV/OGG equivalent` note in `STATUS` at any stage. It is disabled by default because verification takes longer.
- Added the `Collision cleanup` choice (`Keep both` / `Keep OGG` / `Keep WAV`). For each colliding same-name WAV and OGG in verified groups, `Organize selected groups` can keep one format in the `KEEP` folder and delete the other. Pairs not judged equivalent are included too, and the confirmation dialog warns about them. The default is `Keep both`.
- Added the `Delete` choice (`Move to Recycle Bin` / `Delete permanently`). It applies to the duplicate charts that `Organize selected groups` deletes and to the audio of the format that `Collision cleanup` does not keep. `Delete permanently` does not use the Recycle Bin, so it is faster when you organize a large number of audio files. Deleted files cannot be restored, so the confirmation dialog shows a warning. The default is `Move to Recycle Bin`, and the choice returns to the default each time the application starts.
- For names that `Check WAV/OGG collisions for equivalence` did not judge equivalent, the `STATUS` tooltip now shows the count for each reason, such as `Breakdown: Length differs (comparison stopped) 5, Insufficient correlation 3`. When one of the files looks like a lower-quality version, for example a low-bitrate OGG, an 8-bit WAV, or only one file being mono, the tooltip shows the counts as `Quality hints`.
- Added `Copy inspection details` to the context menu. For the selected groups, it copies the judgment, the reason for not being equivalent, the full paths, sampling rates, frame counts, WAV bit depth, average OGG bitrate, correlation, volume differences, and more for each WAV and OGG pair to the clipboard as tab-separated text. You can paste it straight into a spreadsheet.
- The `STATUS` tooltip now grows horizontally to fit its content, so lines that contain full paths are no longer wrapped in the middle.

### Base Candidates in Playlists

- For unowned charts in playlist detail, BeMusicSeeker now tells you when it estimates that you already have the song's main folder. Use this to spot rows where you only need the additional chart.
- An unowned row that has a diff URL (`URL2`) and at least one main-folder candidate shows the `URL1` column in a dedicated color. The color stays the same while the row or cell is selected.
- Added `Base candidates` to the context menu of unowned rows. It lists up to five candidate folders, and choosing one opens it in Explorer. The menu also appears on rows without a diff URL, and it does not appear on rows without candidates.
- Candidates are found by comparing the `TITLE` and `ARTIST` written in the playlist with those of the charts you own. After notation differences such as difficulty names and chart authors are removed, a folder becomes a candidate when it contains a chart whose title matches and whose artist matches or is close. Rows whose playlist entry has no artist are compared by title only.

Base candidates are an estimate. An unowned chart has no file on your computer, so the only information available is the playlist's `TITLE` and `ARTIST`, which is an inherent limit. A candidate may be missing even though you own the main package, and a different work with the same title may be listed. Loosening the conditions reduces misses but adds wrong candidates, so the current conditions are a balance between the two. Preparing data that records the correct main package for each chart hash is another possible approach, but it cannot cover newly released charts, so there are no plans to adopt it.

### Network Settings

- Added `Network` to `Advanced` in the settings window. You can change the following six values. The defaults match the previous behavior.
  - `Simultaneous external table downloads` (default 32 tables)
  - `Maximum size per chart or archive file` (default 512 MiB)
  - `Download wait time` (default 30 seconds)
  - `External table fetch time limit` (default 300 seconds)
  - `External table HTML size limit` (default 10 MiB)
  - `External table JSON size limit` (default 100 MiB)
- Raise the limits or wait times when you want to download large archives, or when a download site or difficulty table responds slowly. A changed value applies to downloads started afterward.

### Automatic Updates

- You can now press `Update` in the update dialog before startup initialization finishes. The download starts immediately and runs alongside initialization.
- The status bar now shows the download progress, and its cancel button cancels the update. Closing the app during the download also cancels the update and exits right away. A canceled update is offered again the next time you start the app.
- Removed the five-minute limit on the whole update package download. While data keeps arriving, the download continues even on a slow connection.

### GitHub Star

- After you have used the app for a while, a prompt asking you to star this fork's GitHub repository now appears at startup. It appears once the app has started at least 10 times with this version or later and at least 14 days have passed since the first of those starts. Press `Star on GitHub` to open the repository in your browser.
- If you choose `Later`, the prompt appears again after at least 30 days and 10 more starts. It appears at most three times in total, and it no longer appears once you open the repository with `Star on GitHub` or choose `Don't show again`.
- Added a `Star on GitHub` link to `About this app` in the settings window.
