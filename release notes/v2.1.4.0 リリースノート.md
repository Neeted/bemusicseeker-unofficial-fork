# 日本語

## 変更点

- プレイリスト行の右クリックメニューから、外部キャッシュサービスに依存して実質的に利用できなくなっていた `動画を開く` / `入手先を検索` を削除しました。
  - `本体URLを開く` / `差分URLを開く`、複数選択時の URL 取り込み、MD5-URL マッピング TSV や Stella Uploader (Full) 由来の URL1 / URL2 補完は引き続き利用できます。
- プレイリスト詳細の右クリックメニューに `外部APIから入手先を探す` を追加しました。
  - 選択行の MD5 を外部 API に問い合わせ、見つかった本体パッケージをダウンロードして導入キューへ渡します。
  - 実行前に、正規入手先ではない可能性、再配布許諾の不確実性、外部 API へ MD5 を送信すること、一時ファイルの保存先や処理時間に関する警告を表示します。

## 不具合修正 / 安定性向上

- LR2 連携モードで、`カスタムフォルダ通常出力先` に楽曲が置かれている環境でも曲検索対象に含めるようにしました。
  - 従来版では `カスタムフォルダ通常出力先` と楽曲フォルダが同居している場合があったため、この出力先だけは LR2 の BMS ルートとして曲検索に使います。
  - `追加通常出力先` と `ルートフォルダ出力先` は、LR2 の `<jukebox>` には引き続き登録しますが、検索クエリの肥大化や意図しない楽曲検索を避けるため、本アプリの曲検索対象からは除外します。
  - `カスタムフォルダ通常出力先` は楽曲インストール先としては想定しないため、一般タブの BMS ディレクトリ一覧、インストールタブの新規インストール先候補、ライブラリツリーのフォルダノードには表示しないようにしました。
  - 新しく `カスタムフォルダ通常出力先` を選ぶとき、LR2 に登録済みの BMS ルートと同じ場所、または親子関係になる場所は選択できないようにしました。また、LR2 の `<jukebox>` を手動編集して BMS ルート同士が親子関係になっている場合は、設定保存時に見直しを促します。
  - `カスタムフォルダ通常出力先` を変更すると、変更前の通常出力先そのものが LR2 の BMS ルート登録から外れ、通常出力先として自動追加される探索ルートではなくなることをメッセージで知らせるようにしました。
  - Everything が使えない場合に行う、従来版と同様の通常のファイルシステム走査による列挙でも、`カスタムフォルダ通常出力先` 配下の楽曲が 0 件扱いにならず検索対象に含まれるようになります。
- Everything が正常に検索できた結果、スキャン結果が 0 件だった場合、または Everything が利用できず通常のファイルシステム走査へ切り替わった後もスキャン結果が 0 件だった場合に、既存の `song.db` には楽曲が登録されていれば、誤って `song.db` を空として更新しないように今回の更新をスキップし、BMS ディレクトリ設定や Everything のインデックス状態の確認を促す警告を表示するようにしました。
- BeMusicSeeker が管理者権限で起動している場合、通常権限のエクスプローラーからのドラッグ＆ドロップが Windows により拒否されることがあるため、起動時に警告を表示するようにしました。
- プレイリスト詳細で 50 件以上の URL を一括取り込みする場合、確認ダイアログに警告色の注意文を追加しました。
  - ダウンロード済みファイルやアーカイブ解凍用の一時ファイルが Windows の一時領域（通常は C ドライブ）に作成されること、空き容量や処理時間に注意が必要なことを事前に確認できます。
  - 特に本体 URL の一括取り込みではファイルサイズが大きくなりやすいことも明示しました。
- プレイリスト詳細の COMMENT / MEMO に長い内容が入っている場合、ツールチップを固定幅で折り返して表示するようにしました。
- 終了処理全般の安全確認を強化しました。
  - 通常終了および自動アップデート時に、DB 読み書きやプレイリスト/プレイ履歴のバックグラウンド処理が idle になるまで待ってから終了するようにしました。
  - 処理中の場合は終了まで時間がかかることがありますが、データ整合性を優先するための待機です。
  - 終了直前に SQLite の内部的な close エラーが一瞬表示されることがあったため、終了準備中に限ってユーザー向けのエラーダイアログを出さずログへ記録するようにしました。

# English

## Changes

- Removed the playlist-row context menu actions `Open video` and `Search downloads`, which depended on an external cache service that is no longer usable in practice.
  - `Open main URL` / `Open diff URL`, bulk URL import, and URL1 / URL2 completion from MD5-URL mapping TSV or Stella Uploader (Full) remain available.
- Added `Find source via external API` to the playlist detail context menu.
  - It queries external APIs with the selected row MD5 values, downloads found original packages, and sends them to the install queue.
  - Before running, the app warns that the source may not be official, redistribution permission may be unclear, MD5 values are sent to external APIs, and temporary files/disk space/processing time may need attention.

## Bug Fixes / Stability

- In LR2-linked mode, the `Normal custom folder output destination` is now included in chart scanning when songs are stored there.
  - Legacy versions could have charts and the normal custom folder output destination in the same location, so this destination is treated as an LR2 BMS root for chart scanning.
  - `Additional normal outputs` and the `Root folder output destination` remain registered in LR2 `<jukebox>`, but BeMusicSeeker excludes them from chart scanning to avoid overly broad search queries and unintended chart discovery.
  - Because the normal custom folder output destination is not intended as a chart install destination, it is hidden from the General tab BMS directory list, the Install tab new install destination choices, and the library tree folder nodes.
  - When choosing a new normal custom folder output destination, locations that are the same as, a parent of, or a child of an LR2-registered BMS root are rejected. If LR2 `<jukebox>` was edited manually and BMS roots overlap as parent/child entries, the settings dialog now prompts you to review them when saving.
  - When the normal custom folder output destination is changed, the app now shows a message that the previous destination itself will be removed from the LR2 BMS roots and will no longer be an automatically added search root for the normal output destination.
  - When Everything cannot be used and the app falls back to the normal filesystem traversal used by previous versions, songs under the normal custom folder output destination are included in the scan instead of being treated as zero results.
- If Everything successfully searches and finds 0 charts, or if Everything is unavailable and ordinary filesystem traversal also finds 0 charts, while the existing `song.db` contains songs, the app now skips the `song.db` update to avoid incorrectly writing an empty library and shows a warning asking you to check BMS directory settings and Everything indexing.
- When BeMusicSeeker is started with administrator privileges, the app now shows a startup warning because Windows may reject drag-and-drop from a normally started Explorer window.
- When importing 50 or more playlist detail URLs at once, the confirmation dialog now shows an additional warning in the warning color.
  - The warning calls out that downloaded files and temporary archive extraction files are created in the Windows temporary area, usually on the C drive, and that disk space and processing time may need attention.
  - It also highlights that bulk original URL imports are especially likely to involve large files.
- Playlist detail COMMENT / MEMO tooltips now wrap at a fixed width when the text is long.
- Strengthened shutdown safety checks across the app.
  - During normal exit and automatic updates, the app now waits until tracked database writes, playlist work, and play-history background processing become idle before exiting.
  - Shutdown may take longer while background work is finishing, but this wait is intentional to prioritize data consistency.
  - A rare SQLite close error could briefly appear during the final moments of shutdown. During coordinated shutdown only, this message is now logged instead of shown as a user-facing error dialog.
