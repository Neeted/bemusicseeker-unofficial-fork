# 日本語 v1.1.0.0

4 桁バージョンとして見たときに従来のバージョニング方針がやや不自然に感じられたため、今回は `v1.1.0.0` へまとめて引き上げました。  
また、以下に記載した機能追加や修正に加えて、内部的にはリファクタリングを中心とした変更量もかなり大きかったことも、バージョンをまとめて上げた理由の 1 つです。

## 機能・操作面の変更

### LR2 閏年バグ関連

- 閏年判定ロジックを一般化しました。
  - 従来は `2012`, `2016`, `2020` を列挙して判定していました。
  - BeMusicSeeker の閏年バグ補正には大きく 2 系統あります。1 つ目は閏年とは無関係に DB 上の異常日時を補正する処理で、2 つ目はフォルダ実体の更新日時が閏日周辺かどうかを見る処理です。今回の一般化により、`2000`, `2004`, `2008`, `2024` などを含む、より広い閏年に対応するようになりました。
    1. `song` / `folder` レコードの日時異常を検出して DB を補正する  
       `song.adddate` や `folder.adddate` が負値、または「現在 + 30 日」より未来であれば異常とみなし、`adddate` と `date` を `null` にします。
    2. `folder.date` が日時異常（負値）の場合、フォルダ実体の更新日時が閏日周辺（`2/29-3/1`）であれば現在日時へ補正します。

### プレイリスト

- プレイリストサマリー行をダブルクリックすると、対象のプレイリスト画面へ自動遷移する機能を追加しました。
  - サマリー画面で未所持譜面が増えていた場合に、そのままプレイリストへ移動して `[NO SONG]` を確認する用途を想定しています。導入している難易度表が多い環境で特に便利だと思います。
- プレイリストサマリーに `STATUS` カラムを追加しました。
  - アプリ起動後に行われた外部プレイリスト同期の最新結果を表示します。リンク切れやヘッダ/データ取得失敗などに気が付きやすくし、詳細は tooltip で確認できます。
- プレイリスト明細表示を高速化しました。
  - プレイリスト表示用データの持ち方を見直し、表示専用の軽量な行データへ整理することで、10万譜面規模のプレイリストでもよりスムーズに表示できるようにしました。

### インストール

- 新規 / 保留画面で、選択範囲の BMS パッケージを `一覧から削除` する右クリックメニューを追加しました。
  - 従来からツリー上では個別に `一覧から削除` できましたが、今回は明細で複数選択した場合にも呼び出せるようにしました。
- `[x] 通常インストール時、既所持譜面が残っていても元パッケージを削除する` 設定を追加しました（デフォルト無効）。
  - 従来は通常インストール時、`既にインストールされているファイルはスキップされます。` とダイアログにある通り、既所持譜面は元フォルダに残る仕様でした。これを重複ファイルチェックのマージ処理に近い使用感にするための設定です。有効にすると、パッケージ内の新規譜面を導入した後、元フォルダを残り物ごと削除する挙動になります。
- 保留画面の `ごみ箱へ移動` に `[x] 対象フォルダにBMSファイルが含まれなくなる場合フォルダごと削除する。` オプションを追加しました。
  - ライブラリ画面などでの削除に近い挙動です。保留画面で `ごみ箱へ移動` を選んだ際の確認ダイアログにこのチェックボックスがあります（デフォルト有効）。有効のまま OK を押すと、選択範囲内のすべての BMS パッケージにこの処理が適用されます。ライブラリ画面などでの削除と違い、フォルダごとの確認ダイアログは表示されません。
- 保留ツリーに `既所持譜面のみのパッケージを完全削除` 機能を追加しました。
  - 右クリックメニューに `高度な機能 > 既所持譜面のみのパッケージをごみ箱を経由せずに削除` を追加しました。
- 保留ツリーに `既所持譜面のみのパッケージをリソースのみ上書きする` 機能を追加しました。
  - 右クリックメニューに `高度な機能 > 既所持譜面のみのパッケージをリソースのみ上書きする` を追加しました。音源や BGA に更新があった場合の利用を想定しています。
  - この機能は、リソースのみの上書きからソースファイルの削除までを自動で行うため、上書き先推定はやや保守的な安全寄りの設計にしています。各譜面の hash から既存導入先を確認し、パッケージ内で一意に定まる場合のみ処理されます。単一譜面の既存導入先が複数存在する場合や、パッケージ内で異なる導入先が混在する場合は、そのパッケージの処理をスキップします。
- 保留ツリーに `ゼロノート譜面を無効な拡張子に変更(*.bmx/pmx)` 機能を追加しました。
  - 右クリックメニューに `高度な機能 > ゼロノート譜面を無効な拡張子に変更(*.bmx/pmx)` を追加しました。未所持譜面だと思ったら `.bmx` 化されていた既所持ファイルだった、というケースがよくあるため、その対策として導入しました。
- スマート上書きの拡張設定として `スマート上書き時、*.bmx/*.pmx/*.txt/*.bmson は上書きせず自動採番で保持する` を追加しました（デフォルト無効）。
  - 同梱の `readme.txt` を差分側の `readme.txt` で上書きしてしまう、といった事故を防ぐことを目的としています。通常のスマート上書きでは `サイズ一致かつ更新時刻差が 2 秒以内` を同一ファイルとみなしますが、この拡張設定ではさらに実ファイルのハッシュまで確認し、同一内容のファイルが増殖しないように制御しています。
- 複数パッケージをドラッグ＆ドロップ導入した際の挙動を改善しました。
  - 従来は受け取ったパスを 1 つずつ同期的に推定完了まで処理していたため、ドロップ元のロック時間が長くなっていました。
  - 先にパスだけ受け取って即 return し、推定や展開は後段でバッチ処理する形に変更したことで、ドロップ元のロックを極小化しました。進捗表示もモーダルウィンドウではなくステータスバー表示へ変更し、処理中の追加ドラッグ＆ドロップにも対応しました。

### ゼロノート関連

- `ゼロノート再判定` 機能を追加しました。
  - `ゼロノート検索` ツリーの右クリックメニューに追加しました。LR2 が `karinotes = 0` を記録している譜面のうち、実ファイル上は可視ノートが存在する「怪しい譜面」を手動で洗い出せるようにしました。WARNING 列には `DBに0notesと記録されていますが可視ノートが存在します` と表示されます。重複ファイルチェックと同様に、該当行は着色されます。LR2 ではパースエラーなどで再生できなくても、他プレイヤーや譜面ビューワー上では再生できる譜面が該当する可能性があります。
- `無効な拡張子に変更(*.bmx/pmx)` で名前衝突時に自動解決するようにしました。
  - 同一ハッシュ時はリネーム元ファイルを削除し、異なるハッシュ時は自動採番でリネームを行います。名前衝突ダイアログは出さず、暗黙的に処理されます。
- ゼロノート判定で使用している可視ノート検出用正規表現について、チャンネル文のデリミタ許容を緩和しました。
  - BMS フォーマットの一般的な仕様では、チャンネル文はコマンドと値を区切るデリミタとして半角コロン `:` を使います。しかし、LR2 や beatoraja の挙動を確認したところ、半角スペースのみで区切られた譜面でも再生できるケースがありました。おそらく `[:\s]+` 相当を許容していると考えられます（`jbms-parser` は未確認です）。これまで LR2 で再生できる譜面でもゼロノート判定されてしまうケースがあったため、その誤判定を減らす修正です。

### 文字化けチェック

- 手動での文字化け修正先に `簡体字中国語(GB2312)` と `繁体字中国語(Big5)` を追加しました。
  - 自動推定自体は従来と変わらないため、文字化けチェック画面には引き続き `韓国語(KS_C_5601-1987)` 判定されたものなどが表示されます。今回の変更により、それらを手動で中国語として修正できるようになりました。

### その他

- ステータスバーの活用範囲を拡張しました。
  - 現在は、初期化・ライブラリリロード進捗、外部プレイリスト同期進捗、導入先推定進捗の表示に利用しています。

## 不具合修正 / 安定性向上

- 変更系ファイル操作の実装を抜本的に見直しました（上書き / 移動 / 名前変更 / 削除 / 更新日時変更など）。
  - 従来は読み取り専用属性や一時的なアクセス拒否への対策を局所的に行っていましたが、今回はこれを共通サービス化しました。これにより、BMS インストールに関わるファイル操作全般でアクセス拒否による中断が発生しにくくなっています。挙動イメージとしては `Windows Explorer` に近く、読み取り専用でも削除や上書きができる点も含めてそれに近い動作です。BMS ファイル操作に直接関わらない部分は従来仕様のままです。
- プレイリスト個別リロードの不具合を修正しました。
  - 従来の個別リロードは、外部から取得した JSON を単純に DB へ保存するだけになっていました。今回の修正で、全リロード時と同様に更新日時、メモ、難易度表からの削除フラグも保持するようにしました。
- `WebClient` から `HttpClient` への移行を進めました。
  - 非推奨となっている `WebClient` の利用箇所を `HttpClient` に置き換えました。性能面での寄与は大きくないと思われますし、デグレのリスクもありますが、将来性を見据えての移行です。
- 保留画面からのインストール操作に関わる UI 更新を最適化しました。
  - 保留画面やツリーへの反映を、選択範囲単位でバッチ化しました。逐次反映ではなく、コレクション差し替え寄りの形に整理しています。UI 抑制系の処理自体は Fork 版初期から行っていましたが、今回のラッパー共通化により処理が整理され、通知漏れも修正されています。
- メモリ使用量とライフサイクル管理を見直しました。
  - ライブラリリロード時やプレイリスト切り替え時の参照保持を整理し、メモリリーク的に見えていた無制限な積み上がりを抑制しています。

# English v1.1.0.0

The previous versioning pattern felt a little awkward when viewed as a four-part version number, so this release jumps directly to `v1.1.0.0`.  
Another reason for the larger version bump is that, beyond the user-facing changes listed below, the internal refactoring and structural changes in this release were also fairly substantial.

## Feature and usability changes

### LR2 leap-year bug handling

- Generalized the leap-year detection logic.
  - Previously, the code explicitly checked only `2012`, `2016`, and `2020`.
  - BeMusicSeeker's leap-year bug handling consists of two main paths. One path fixes obviously invalid timestamps in the DB regardless of leap years. The other checks whether the actual folder timestamp is near leap day. After this change, the latter now works for a broader range of leap years such as `2000`, `2004`, `2008`, and `2024`.
    1. Detect abnormal timestamps in `song` / `folder` records and fix the DB  
       If `song.adddate` or `folder.adddate` is negative, or more than 30 days in the future, `adddate` and `date` are cleared to `null`.
    2. If `folder.date` is invalid (negative) and the actual folder timestamp is near leap day (`2/29-3/1`), it is corrected to the current time.

### Playlist

- Added the ability to jump directly to the target playlist by double-clicking a playlist summary row.
  - This is intended for workflows such as noticing an increase in unowned charts from the summary screen and then jumping straight to the playlist to inspect `[NO SONG]` entries. It is especially useful when many difficulty tables are installed.
- Added a `STATUS` column to the playlist summary.
  - It shows the latest result of external playlist sync attempts made after startup, making it easier to notice broken links and failures such as header/data retrieval errors. More details are available in a tooltip.
- Improved playlist detail rendering performance.
  - The playlist display data was restructured around lightweight display rows, allowing even playlists with around 100,000 charts to render and switch more smoothly.

### Installation

- Added a context menu item to remove selected BMS packages from the list in the New / Pending screens.
  - Previously, `Remove from list` was available only per item from the tree. It can now also be invoked for multiple selected entries from the detail view.
- Added the setting `[x] Delete the original package even if already-owned charts remain after normal installation` (disabled by default).
  - Previously, normal installation behaved exactly as the dialog message said: `Already installed files will be skipped.` In practice, already-owned charts were left in the original folder. This setting makes the behavior closer to duplicate-file merge processing. When enabled, the source folder is removed together with the leftovers after new charts from the package are installed.
- Added `[x] Delete the entire folder if it no longer contains any BMS files` to `Move to Trash` in the Pending screen.
  - This makes deletion behave similarly to library-side deletion. The checkbox is available in the confirmation dialog shown from the Pending screen and is enabled by default. If left enabled, it is applied to all selected BMS packages. Unlike library-side deletion, there is no separate confirmation per folder.
- Added `Delete packages that contain only already-owned charts` to the Pending tree.
  - This is available from `Advanced > Delete packages that contain only already-owned charts without using the Recycle Bin`.
- Added `Overwrite resources only for packages that contain only already-owned charts` to the Pending tree.
  - This is available from `Advanced > Overwrite resources only for packages that contain only already-owned charts` and is intended for cases where only audio or BGA files have been updated.
  - Since this feature performs the entire flow automatically, from resource-only overwrite through deletion of the source files, the destination estimation is intentionally conservative. It checks each chart hash against existing install destinations and proceeds only when the package resolves cleanly to a unique destination. If a single chart maps to multiple destinations, or if different destinations are mixed within the same package, that package is skipped.
- Added `Rename zero-note charts to invalid extensions (*.bmx/pmx)` to the Pending tree.
  - This is available from `Advanced > Rename zero-note charts to invalid extensions (*.bmx/pmx)`. It was added because a chart that appears to be "new" often turns out to be an already-owned file that had simply been renamed to `.bmx`.
- Added the Smart Overwrite extension setting `During smart overwrite, keep *.bmx/*.pmx/*.txt/*.bmson by auto-numbering instead of overwriting` (disabled by default).
  - This is intended to prevent cases such as overwriting an existing bundled `readme.txt` with the differential package's `readme.txt`. Normal Smart Overwrite treats files as identical when they have the same size and their modification times differ by no more than two seconds. With this extension enabled, the actual file hash is also checked so that duplicate content does not accumulate unnecessarily.
- Improved behavior when installing multiple packages via drag and drop.
  - Previously, each received path was processed synchronously until destination estimation finished, which kept the drag source locked for too long.
  - The new flow receives the paths first and returns immediately, while estimation and extraction are handled later as batch work. This greatly reduces drag-source lock time. Progress display was also moved from a modal window to the status bar, and additional drag-and-drop operations are now accepted while processing is ongoing.

### Zero-note related

- Added `Recheck zero-note`.
  - This is available from the right-click menu of the `Zero-note search` tree. It allows you to manually identify suspicious charts where LR2 recorded `karinotes = 0`, but the actual file still contains visible notes. The WARNING column shows `Recorded as 0 notes in DB, but visible notes exist`, and affected rows are highlighted just like duplicate-file results. These may be charts that LR2 cannot play due to parse errors or similar issues, but other players or chart viewers can still open.
- Added automatic conflict resolution when using `Rename to invalid extension (*.bmx/pmx)`.
  - If the target name collides and the hashes match, the rename source is deleted. If the hashes differ, the file is renamed using automatic numbering. This is handled silently without a conflict dialog.
- Relaxed the accepted delimiter pattern in the regex used to detect visible notes for zero-note checking.
  - In the commonly known BMS format, channel lines use the half-width colon `:` as the delimiter between command and value. However, when checking actual behavior in LR2 and beatoraja, charts separated only by spaces could still be played. That suggests something equivalent to `[:\s]+` is accepted there as a delimiter (untested in `jbms-parser`). This change reduces false zero-note detections on charts that LR2 can actually play.

### Garbled text check

- Added `Simplified Chinese (GB2312)` and `Traditional Chinese (Big5)` as manual encoding-fix targets.
  - Automatic detection itself is unchanged, so the garbled-text screen will still show files detected as things like `Korean (KS_C_5601-1987)`. This change simply makes it possible to correct those entries manually as Chinese.

### Other

- Expanded the role of the status bar.
  - It is now used to show initialization and library reload progress, external playlist sync progress, and installation destination estimation progress.

## Bug fixes / stability improvements

- Reworked the implementation of mutating file operations (overwrite / move / rename / delete / timestamp changes, etc.).
  - Previously, workarounds for read-only files and temporary access-denied errors were applied only in isolated places. These behaviors have now been centralized into a shared service. As a result, file operations related to BMS installation are much less likely to fail mid-process due to access-denied errors. The intended behavior is closer to `Windows Explorer`, including the practical ability to overwrite or delete read-only files. Parts unrelated to BMS file operations remain largely unchanged.
- Fixed incorrect behavior in single-playlist reload.
  - Previously, single-playlist reload simply stored externally fetched JSON into the DB. It now preserves update timestamps, notes, and deleted-from-table flags in the same way as full reload.
- Continued migration from `WebClient` to `HttpClient`.
  - Places still using the obsolete `WebClient` API were moved to `HttpClient`. The performance impact is probably limited, and there is some regression risk, but the migration was done for long-term maintainability.
- Optimized UI refresh behavior around installation operations from the Pending screen.
  - Pending-screen and tree updates are now handled in batches for the selected range instead of being reflected one by one. The Fork had already been suppressing some UI updates for performance reasons, but this release further reorganizes that logic through shared wrappers and fixes missed update notifications as well.
- Reworked memory usage and lifecycle handling.
  - Reference ownership around library reloads and playlist switching was revised to suppress the previously unbounded memory buildup that could look like a leak.
