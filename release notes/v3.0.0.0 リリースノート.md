# 日本語

## 重要なお知らせ

- v3.0.0.0 は、実行基盤の .NET 10 移行、画面処理基盤の再構成、音声ランタイムの刷新を含むメジャーアップデートです。
- 配布版は Windows x64 向けの自己完結型パッケージになりました。通常は .NET Desktop Runtime を別途インストールする必要はありません。
- 旧バージョンで音声出力に `DirectSound` を使用していた場合、更新後は `WASAPI（共有）` の既定デバイスへ移行します。更新後に設定画面の `オーディオ` カテゴリで出力先を確認し、`テスト再生 & レイテンシ計測` を実行してください。
- 既存の設定、データベース、プレイリストを引き継ぐ更新経路を維持していますが、大規模更新のため、更新前にアプリのデータと、LR2 連携時は `song.db`、`config.xml`、スコア DB をバックアップすることをおすすめします。

## 変更点

### .NET 10 / 配布・更新基盤

- 実行基盤を .NET Framework 4.7.2 から .NET 10 へ移行しました。
- アプリ本体とアップデーターを Windows x64 向けの self-contained / single-file 構成へ移行しました。管理対象のネイティブ DLL、言語ファイル、ドキュメントは引き続き配布パッケージへ同梱されます。
- 新しい配布構成に合わせて自動更新処理を再構成し、更新対象ファイルの管理、更新前バックアップ、失敗時のロールバック、旧構成で不要になった管理ファイルの整理を強化しました。ユーザーが追加したファイルは管理対象と区別して扱います。
- SQLite、アーカイブ展開、JSON、ログ、WPF 支援ライブラリなどの依存関係を現行のパッケージへ整理し、従来同梱していた複数の旧 DLL を廃止しました。
- Ogg Vorbis のデコード処理を NVorbis ベースへ移行しました。

### MVVM / 画面処理基盤

- メイン画面、設定、ライブラリ、プレイリスト、インストール、再生などの状態と処理を、用途別の ViewModel、owner、service へ整理しました。
- 画面側に混在していたコマンド実行、進捗表示、ダイアログ、選択状態、設定保存、バックグラウンド処理の責務を分離し、各操作の開始から完了までを一つの処理主体が管理する構成へ変更しました。
- 非同期処理中の重複操作、古い処理結果による表示の巻き戻り、画面更新と保存処理の競合が起きにくいよう、状態更新と終了処理を整理しました。
- 通常の操作手順やデータ形式はできるだけ維持しつつ、今後の機能追加や不具合修正を安全に行える内部構造へ更新しました。

### 設定ウィンドウ

- メイン画面内に表示していた設定画面を、独立したサイズ変更可能なモーダルウィンドウへ刷新しました。設定中は従来どおりメイン画面を操作できず、保存・キャンセルの挙動や既存の設定値は維持されます。
- 上部タブを左側のカテゴリーナビゲーションへ置き換え、各カテゴリを現代的なセクション、入力欄、パス選択、一覧編集、状態表示へ再構成しました。ウィンドウ幅に合わせて各部品が連続的に伸縮し、本文だけが縦にスクロールします。
- Light / Dark テーマに合わせてボタン、入力欄、ドロップダウン、状態表示、標準タイトルバーが切り替わるようにしました。設定以外の補助ウィンドウも同じ共通テーマ基盤を使用します。
- LR2 連携設定では、LR2 ルートからの標準パス検出に加えて `song.db` と `config.xml` / `config.xmh` の手動指定を引き続き利用できます。直接入力とファイル選択は保存前の編集内容として扱われ、キャンセル時には元の設定へ戻ります。
- オーディオ設定では、テスト結果やエラーなどの長い情報を折り返して表示します。各ドロップダウンはボックス全体から開けるようになりました。
- 設定画面に `右クリック設定` カテゴリを追加しました。`Webページを開く` と `プログラムから開く` の名前、順序、URL テンプレート、対象譜面形式、有効状態などを編集できます。既定では BMS-IR、Mocha、MinIR、rianIR、STELLAVERSE IR が有効です。BMS-IR は BMS 専用です。
- 所持譜面で任意のプログラムを開く `プログラムから開く` サブメニューを追加しました。実行ファイル、引数、名前、順序、有効状態を設定でき、新規項目の引数は `{filePath}` です。
- 右クリック設定の編集は保存時に検証され、キャンセルやウィンドウを閉じる操作では破棄されます。`既定値へ戻す` はいつでも使用でき、保存後に反映されます。設定は次にコンテキストメニューを開いたときから反映されます。
- 更新履歴は「このアプリについて」から独立したリリースノートウィンドウで確認できるようになりました。

### コンテキストメニュー

- 通常一覧、未所持プレイリスト行、プレイログで、同じ右クリック設定から `Webページを開く` を利用できるようにしました。ローカル譜面へ解決できる行では `プログラムから開く` も利用できます。

### 起動・一覧表示の性能改善

- 起動時に必須ではないフォルダーツリー更新、保守情報の作成、外部カタログ取得、並び替えキャッシュ準備などを、操作可能になるまでの待ち条件から分離しました。これらは起動後にバックグラウンドで継続します。
- 起動処理、インストール先推定、プレイリストサマリー生成での不要なオブジェクト作成や再解析を減らしました。
- 単体の BMS / bmson 譜面のインストール先推定で、配置元フォルダー全体を同梱リソースとして走査していた問題を修正しました。大規模なフォルダーから追加した場合の不要な処理や、パッケージ走査が不要な譜面への走査上限警告を防ぎます。
- 通常一覧、プレイリストサマリー、プレイリスト詳細の切り替えを整理し、行・表示モード・選択状態をまとめて反映するようにしました。切り替え途中の不完全な表示や選択のずれを抑えています。
- データだけが更新された場合は、可能な限り列幅や列順などの表示設定を維持するようにしました。

### 譜面メタデータ（chart_info）

- LR2 連携モードで、`song.db` の同期完了を理由に欠落した譜面メタデータの補完を省略してしまう場合がある問題を修正しました。スタンドアローンモードと同じく、実際の保存データを確認して不足分をバックグラウンドで補完します。
- 新規譜面の追加、起動後の補完、LR2 `song.db` 連携で、譜面メタデータの有効性判定と解析失敗記録の扱いを共通化しました。同じ解析失敗の不要な繰り返しを抑え、失敗記録を削除した譜面は次回起動時に再解析対象へ戻ります。
- 既所持譜面の補完では、レベル、難易度、BPM、ノート関連情報など、譜面解析から得られる項目だけを既存の `song` 行へ反映します。曲名、フォルダー、モード、判定設定、favorite、tag、追加日時などの既存情報を維持し、関連データをまとめて保存することで不完全な更新を防ぎます。

### 外部アプリからのドラッグ＆ドロップ

- 7-Zip などのアーカイブ管理アプリから譜面ファイル、フォルダー、アーカイブをドラッグ＆ドロップした際、外部アプリが展開した一時ファイルがインストール開始前に消え、追加に失敗する場合がある問題を修正しました。
- 外部アプリが一時領域に作成した項目は、Drop 操作が完了する前に BeMusicSeeker の管理領域へ安全にコピーし、元のディレクトリ構造を保ったまま非同期のインストールキューへ渡すようにしました。外部アプリ側の元ファイルを移動または削除することはありません。
- インストールは従来どおりバックグラウンドで一件ずつ処理します。待機中の追加をキャンセルした場合、ライブラリを切り替えた場合、またはアプリを終了する場合は、まだインストーラーへ渡していない管理コピーをバックグラウンドで回収します。
- Explorer などから追加する通常のファイルやフォルダー、および BeMusicSeeker が既に管理している一時ファイルは不要に再コピーしません。対応していない形式や一時ファイルの取得失敗も、無反応で終わらず画面上で通知します。

### 音声再生・音声変換

- 従来の BASS.NET マネージドラッパーを廃止し、ManagedBass 4.0.2 へ移行しました。あわせて BASS、BASSmix、BASSenc、BASSWASAPI、BASSASIO、BASS_FX の x64 ネイティブコンポーネントを整理・更新しました。
- 設定画面で選択できる音声出力を `WASAPI（共有）`、`WASAPI（排他）`、`ASIO` に整理し、新規設定の既定値を `WASAPI（共有）` にしました。`DirectSound` は選択肢から外れ、旧設定だけを安全に移行します。
- 保存したデバイスをバックエンド固有の識別情報で追跡するようにし、表示名の変更やデバイス一覧の更新で別の出力先へ誤って切り替わりにくくしました。利用できなくなった保存済みデバイスも設定画面で確認できます。
- 要求したサンプルレート、音声形式、低レイテンシ設定をそのまま使用できない場合、同じバックエンド内の利用可能な構成を試してから、必要に応じて別の可聴バックエンドへフォールバックするようにしました。通常再生が無音用の `NullDevice` へ暗黙に切り替わることはありません。
- `テスト再生 & レイテンシ計測` で、実際に使用したバックエンド、デバイス、サンプルレート、エンジン形式、エンドポイント形式、チャンネル数、レイテンシを表示するようにしました。初期化や再生に失敗した場合も、失敗した段階とネイティブエラーを確認できます。
- WASAPI 共有モードの音量、ミキサー音量、再生中の音量変更、音声テストの終了判定、デバイス選択の保存、音声セッションの解放と再初期化を安定化しました。
- 音声変換のエンコーダー起動、タグ付与、オフラインレンダリングをプロジェクト側で再実装し、従来の WAVE、MP3、AAC、Opus、FLAC、Ogg Vorbis 出力を維持しました。

## 不具合修正 / 安定性向上

- `compat_prefix` が明示されていない外部難易度表で、`tag` または `symbol` から推定した接頭辞に CP932 で表現できない文字が含まれる場合、LR2 のカスタムフォルダーで安全に使用できる `LEVEL ` を初期値にするよう変更しました。明示された接頭辞や保存済みの設定は従来どおり維持されます。
- 再生開始・停止やアプリ終了のタイミングによって音声セッションが残り、次の再生またはデバイステストが失敗する場合がある問題を修正しました。
- ASIO のサンプル形式とサンプルレートの交渉を見直し、ドライバーが要求形式をそのまま受け付けない環境でも、安全な形式へ切り替えて再生できるようにしました。
- 自動更新が途中で失敗した場合の復元処理を強化し、更新前のアプリ構成へ戻せる範囲を広げました。

# English

## Important Notes

- v3.0.0.0 is a major update that moves the application to .NET 10, restructures the UI processing architecture, and refreshes the audio runtime.
- The distributed build is now a self-contained Windows x64 package. A separate .NET Desktop Runtime installation is normally not required.
- If an older version was configured to use `DirectSound`, the setting is migrated to the default device of `WASAPI (Shared)`. After updating, review the output selection in the Settings `Audio` category and run `Test playback & latency measure`.
- The update path is designed to preserve existing settings, databases, and playlists. Because this is a large update, backing up the application data is recommended. When using LR2 linked mode, also back up `song.db`, `config.xml`, and score databases.

## Changes

### .NET 10 / Distribution and Update Infrastructure

- Migrated the application runtime from .NET Framework 4.7.2 to .NET 10.
- Migrated the main application and updater to self-contained, single-file Windows x64 builds. Required native DLLs, language files, and documentation remain included alongside the application where needed.
- Reworked automatic updates for the new package layout, strengthening managed-file tracking, pre-update backups, rollback after failure, and cleanup of obsolete application-managed files. User-added files are handled separately from managed package files.
- Modernized dependencies for SQLite, archive extraction, JSON, logging, and WPF support, and removed multiple legacy DLLs that were previously bundled with the application.
- Migrated Ogg Vorbis decoding to NVorbis.

### MVVM / UI Processing Architecture

- Reorganized state and workflows for the main window, settings, library, playlists, installation, and playback into purpose-specific ViewModels, owners, and services.
- Separated command execution, progress reporting, dialogs, selection state, settings persistence, and background work that had previously been mixed into view code. Each operation now has a clearer owner from start through completion.
- Reworked state publication and shutdown handling to reduce duplicate operations, stale results overwriting newer UI state, and races between UI updates and persistence.
- Existing workflows and data formats are preserved where possible while establishing a safer internal structure for future features and fixes.

### Settings Window

- Replaced the Settings screen embedded in the main window with a separate, resizable modal window. The main window remains unavailable while Settings is open, and existing values and Save/Cancel behavior are preserved.
- Replaced the top tabs with left-side category navigation and reorganized each page using modern sections, fields, path pickers, list editors, and status messages. Controls resize continuously with the window while only the page body scrolls vertically.
- Buttons, fields, drop-downs, status messages, and native title bars now follow the Light / Dark theme. Other auxiliary windows use the same shared window-theme foundation.
- LR2 linked settings continue to support manually selected `song.db` and `config.xml` / `config.xmh` paths in addition to standard paths detected from the LR2 root. Direct edits and file selections remain draft changes until Settings is saved and are discarded on cancel.
- Long audio-test results and errors now wrap across multiple lines, and drop-downs can be opened from the whole control surface.
- Added a `Right-click settings` category to Settings. `Open web pages` and `Open with a program` names, order, URL templates, target chart kind, and enabled state can be edited; BMS-IR, Mocha, MinIR, rianIR, and STELLAVERSE IR are enabled by default, with BMS-IR restricted to BMS.
- Added an `Open with program` submenu for owned charts. Executable, arguments, name, order, and enabled state are configurable, and new entries start with `{filePath}`.
- Right-click settings are validated on Save and discarded by Cancel or closing the window. `Restore defaults` is always available and takes effect when saved. They take effect the next time a context menu is opened.
- Update history is now shown in a separate Release Notes window opened from About This App.

### Context Menu

- The normal list, unowned playlist rows, and Play Log now use the same configured `Open web pages` entries. Rows resolved to local charts also offer `Open with program`.

### Startup and List Performance

- Folder-tree refresh, maintenance hydration, external catalog loading, and sort-cache preparation that are not required for initial use no longer block the application from becoming operable. They continue in the background after startup.
- Reduced unnecessary allocation and repeated parsing in startup, install-destination estimation, and playlist-summary generation.
- Fixed install-destination estimation for single BMS / bmson charts so that the entire containing folder is no longer scanned as bundled resources. This avoids unnecessary work when importing from large folders and prevents scan-limit warnings for charts that do not require package scanning.
- Reworked transitions between the normal library, playlist summary, and playlist detail so rows, view mode, and selection are committed together, reducing partial intermediate states and selection drift.
- Column widths, ordering, and related presentation settings are now retained whenever an update changes data without requiring a layout reset.

### Chart Metadata (`chart_info`)

- Fixed an issue in LR2 linked mode where missing chart metadata could be skipped simply because `song.db` synchronization had completed. As in standalone mode, the application now checks the data that is actually stored and fills missing metadata in the background.
- Unified chart-metadata currentness checks and parse-failure handling across newly added charts, background backfill, and LR2 `song.db` integration. This avoids unnecessary repetition of the same failed parse, while charts whose failure record is removed become eligible for parsing again on the next startup.
- Backfill for an existing chart now updates only chart-derived values such as level, difficulty, BPM, and note-related metadata in its existing `song` row. Existing titles, folders, play mode, judge setting, favorite, tag, and added date are preserved, and related metadata is committed together to avoid partial updates.

### Drag and Drop from External Applications

- Fixed an issue where charts, folders, or archives dragged from archive managers such as 7-Zip could fail to install because temporary files created by the external application disappeared before installation began.
- Items supplied from an external application's temporary area are now copied safely into BeMusicSeeker-managed storage before the Drop operation completes. Their directory layout is preserved when they are passed to the asynchronous install queue, and the original external files are never moved or deleted.
- Installation remains serialized in the background. When a queued install is cancelled, the library is changed, or the application shuts down, managed copies that have not yet been handed to the installer are reclaimed in the background.
- Regular files and folders dropped from Explorer, as well as temporary files already managed by BeMusicSeeker, are not copied unnecessarily. Unsupported drops and failures while acquiring temporary files now produce visible feedback instead of being silently ignored.

### Audio Playback and Conversion

- Removed the former BASS.NET managed wrapper and migrated to ManagedBass 4.0.2. The x64 native BASS, BASSmix, BASSenc, BASSWASAPI, BASSASIO, and BASS_FX components were also consolidated and updated.
- Standardized selectable audio outputs to `WASAPI (Shared)`, `WASAPI (Exclusive)`, and `ASIO`, with `WASAPI (Shared)` as the default for new settings. `DirectSound` is no longer selectable and is retained only as a legacy setting that can be migrated safely.
- Saved devices are now tracked using backend-specific identities, reducing accidental switches when display names change or the device catalog is refreshed. A saved device that is no longer available remains visible in Settings.
- When the requested sample rate, format, or latency configuration cannot be used directly, BeMusicSeeker now tries safe alternatives within the same backend before falling back to another audible backend when necessary. Normal playback never silently falls back to the offline-only `NullDevice`.
- `Test playback & latency measure` now reports the backend, device, sample rate, engine format, endpoint format, channel count, and latency that were actually used. Initialization and playback failures also include the failed stage and native error details.
- Stabilized WASAPI shared-mode volume, mixer volume, live volume changes, audio-test completion, device-selection persistence, and audio-session cleanup and reinitialization.
- Reimplemented encoder startup, tagging, and offline rendering in project-owned code while preserving WAVE, MP3, AAC, Opus, FLAC, and Ogg Vorbis output.

## Bug Fixes / Stability

- For external difficulty tables without an explicit `compat_prefix`, inferred prefixes containing characters that cannot be represented in CP932 now default to `LEVEL ` so they can be used safely by LR2 custom folders. Explicit prefixes and previously saved settings remain unchanged.
- Fixed cases where an audio session could remain active after playback stopped or the application closed, causing the next playback or device test to fail.
- Improved ASIO sample-format and sample-rate negotiation so playback can safely retry with a supported engine format when the driver rejects the original request.
- Strengthened recovery when an automatic update fails partway through, increasing the range of cases that can be restored to the pre-update installation.
