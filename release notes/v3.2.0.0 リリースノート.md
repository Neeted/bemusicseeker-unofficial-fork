# 日本語

v3.2.0.0 では、インストール先の推定をより高精度にし、取り込み後の自動推定で導入先が確定したパッケージを自動でインストールできるようにしました。

リソース健康度は、従来の `#WAV`・`#BMP` の定義数ではなく譜面内で実際に使用するファイルを基準に計算するようにしました。未使用の定義を除外するため、より信頼性の高い値になります。

このほか、設定、外観テーマ、一覧、ランプビューアなどの画面を調整しました。

> [!IMPORTANT]
> **保存済みの健康度を新しい計算基準へ更新するには、再スキャンが必要です。**
>
> アプリを更新しただけでは、保存済みの件数は新しい使用ファイル基準で再集計されません。必要に応じて、`ファイルスキャン` → `全譜面を再スキャン` を実行してください。

> [!NOTE]
> **更新後の初回起動では、所持譜面の譜面情報を解析し直します。**
>
> 譜面情報の解析を改良したため、同梱のメタデータに含まれない所持譜面は、更新後の初回起動で譜面情報を解析し直します。譜面数によっては数分以上かかり、その間はステータスバーの `譜面情報の補完` に処理済みの件数と対象の譜面数が表示されます。補完中は譜面の削除・移動や試聴などを開始できないため、完了してから操作してください。

## 変更点

### インストール先推定

- `マージ先を推定` を廃止し、`インストール先を推定` に統一しました。既所持譜面だけのパッケージも、同じ操作で推定できます。
- 推定の計算方法を見直し、同梱リソースの多い本体パッケージも、同梱リソースの少ない差分作品も、同じ方法で導入先を判断できるようにしました。同梱分を含めた充足率が同じ場合は、譜面で使用するファイルが既に多くそろっている候補を優先するようにしました。

### インストール

- 保留ルートと個別パッケージの一覧上部に `推定`・`インストール`・`クリア` の操作バーを追加しました。譜面を1件または複数選択し、右クリックメニューと同じ導入先の推定・推定先へのインストール・導入先のクリアを実行できます。
- 設定画面の `インストール` → `導入先の自動推定` に `取り込み後の自動推定で導入先が確定したら、自動インストールする` を追加しました（既定はOFF）。有効にすると、取り込み時の自動推定が正常に完了した後、今回の推定で導入先が確定したパッケージを確認画面なしで導入します。
- 手動で開始した推定や、既に保留されているパッケージは自動導入の対象外です。上書きと元パッケージの削除は既存の設定に従います。
- フォルダや書庫を取り込むときの保留パッケージの分け方を見直しました。差分ごとに別の音源を使っていても、previewや背景画像などを同梱するフォルダは1つのパッケージとして扱い、同梱ファイルも一緒にインストールします。同梱ファイルがなく別々の曲の差分を集めたフォルダは、譜面ごとに分けて曲ごとに推定・インストールします。同梱ファイルのない同じ曲の差分は、タイトルとアーティストが（難易度表記を除いて）揃えば1つのパッケージにまとめます。
- 保留画面の健康度とリソース不足警告を、設定した導入先、未設定なら先頭候補へ同梱リソースを配置した場合の状態で表示するようにしました。WAV・BGA・MOVIEに加え、STAGEFILE・BACKBMP・BANNERも同じ基準で確認できます。導入先を設定した後も、不足があれば警告を表示します。
- 推定対象全体の音源が導入後も不足する、または完全性を確認できず導入先の自動確定を見送った場合に、`導入後音源不足` / `導入後音源未確認` を表示し、行を警告色にするようにしました。`TITLE/ARTIST未確認` と同時に表示できます。推定時の理由は手動で導入先を変えても残り、再推定で更新されます。
- 保留画面から開く `譜面プロパティ` も同じ配置基準でリソースを確認し、確認基準と確認先を表示するようにしました。
- LR2連携で、最近追加した曲がない状態からインストールしたときも、アプリを再起動せずにLR2の新曲フォルダが表示されるようにしました。

### リソース健康度

- `WAV`・`BGA`・`MOVIE` の計算対象を、`#WAV`・`#BMP` の定義全体から、譜面内で使用が指定されたファイルへ変更しました。未使用の定義は数えず、同じファイルを複数の定義番号で参照していても1件として扱います。
- パーセンテージを「存在するファイル数 ÷ 使用するファイル数 × 100」に変更し、従来の不足時の追加減点をなくしました。例えば、使用ファイル4件のうち3件があれば75%です。不足が残っている場合は100%と表示しません。
- 使用ファイルがない種類は `-` と表示します。定義のない参照番号による無音ノーツなどは、不足に含めません。

### 譜面プロパティ

- 一覧の右クリックメニューに `譜面プロパティ` を追加しました。ローカルに実ファイルのある譜面を1件選んで開けます。保留パッケージ内の譜面にも対応しています。
- BMS・PMS・bmsonの不足・確認不能なファイル、未使用リソース定義、未定義参照番号を確認できます。STAGEFILE・BACKBMP・BANNERなどの補助画像も不足確認の対象です。
- BMS・PMSは `#WAV01 file.wav` などのコマンド風の表記で、bmsonは本来の項目名で表示します。表示された文字は選択してコピーできます。

### プレイリストのインポート

- プレイリストツリーのルートを右クリックして開く `プレイリストをインポート` に、難易度表リスト・内蔵表・URL／ファイルからの読み込みをまとめました。複数の入力元から選んだ表を右側の一覧で確認し、一度にインポートできます。
- 難易度表を名前・記号・分類・URLの部分一致で検索できるようにしました。分類単位や検索結果全体の選択・解除、登録済みURLや同名候補の非表示にも対応しています。タブや検索条件を変えても選択は残ります。
- 外部候補は表名の直前の分類を折りたたんで表示し、分類を展開した長い一覧も滑らかにスクロールできるようにしました。
- インポート直前に登録済みのページURL・ヘッダーURLを再確認し、同じURLの読み込みを省くようにしました。除外や失敗がある場合は、成功・同URL・同名・失敗の件数と対象を結果画面で確認できます。

### プレイリスト

- プレイリストのプロパティ・一括編集・セルの編集・BMT保存順の移動・削除などが、再読込みや別の処理の実行中で受け付けられないとき、操作を行わずに「別のライブラリ操作が実行中のため、操作を開始できません。」の警告を一回だけ表示するようにしました。無言で終わる場合や、エラーとして表示される場合がなくなりました。編集中の入力は保持され、完了後に自分でもう一度実行できます。
- 起動直後にURLの補完が反映されたあとでも、表のプロパティを保存できるようにしました。
- フォルダの順序が自動の表で、フォルダを削除するか名前なしへ改名しても、自動整列のままになるようにしました。
- 表示言語を切り替えても、内蔵の難易度推定表・リコメンド表が更新されたと扱われないようにしました。
- beatorajaの難易度表URLの取込みで、取得に失敗してBMTキャッシュから復元した表にも、設定の `出力フォルダ既定値`を適用するようにしました。
- 旧版で階層付きの出力名（例: `A\B`）を保存した表の出力先が、現在の単一名の規則で別の表と同一または親子になる場合も、起動や他の表の操作が失敗しないようにしました。重なった表だけ LR2 フォルダの出力を止め、表名と出力先を警告で知らせます。出力名を変更すれば出力されます。旧階層のファイルは自動で移動・削除しないため、LR2 の選曲画面に古いフォルダが残る場合は手で削除してください。

### 設定

- 多くの設定を、項目の変更時に保存・反映する方式へ変更しました。音声やスコア取得元なども、有効な選択がそろうと設定画面を閉じずに反映されます。BMSディレクトリやBMT出力、右クリック設定の各項目などは、確定ボタンで反映します。
- 動作モードやLR2ディレクトリの変更時は再起動を確認します。`song.db`・`config.xml`の個別変更は `詳細` 内でまとめて確定し、1回の再起動で反映できます。beatorajaディレクトリの変更は再起動せずに反映します。
- 詳細設定に分散していたインストール関連の設定と確認メッセージを `インストール` へ集約しました。インストール先、フォルダの命名、取り込み・新規インストール、導入先の自動推定、上書き・元パッケージの整理、確認メッセージの6グループで確認できます。
- 設定名と説明文を整理し、URL1/URL2列クリックでの自動取得と自動推定後の導入の違い、上書き・削除、確認メッセージの対象を分かりやすくしました。
- 設定画面の初回表示を改善し、各ページは初めて選んだときに準備するようにしました。ページを切り替えても編集中の入力を保持します。
- 利用開始に必要な設定に不備があると、設定画面の下部に `対応が必要な設定` を表示するようにしました。「ページ名: 理由」の項目から該当する欄へ移動でき、不備のあるページには印が付きます。起動時の確認で止まった場合も、警告に修正が必要な設定を表示します。

- LR2のバックアップと最適化は、ONにしたときに保存先が未指定ならフォルダ選択を開き、ONと保存先をまとめて保存するようにしました。保存先はONにする前にも選べ、OFFにしても保存先は残ります。
- 音声デバイス一覧は音声ページを開いたときに取得するようにしました。取得中も他の設定の編集・保存・取消やページの切り替えを続けられます。
- 詳細設定の初期化設定に `起動時のソートキャッシュ準備範囲` を追加しました。`準備しない`・`基本のみ（既定）`・`標準`・`すべて` から選べ、変更は次回起動から適用されます。従来は `すべて` 相当の範囲を準備していました。事前生成しない列も、選択時には通常どおりソートできます。

# English

v3.2.0.0 makes installation destination estimation more accurate. Packages whose destinations are determined by automatic estimation after import can now be installed automatically.

Resource health is now calculated from the files actually used by each chart instead of the number of `#WAV` and `#BMP` definitions. Unused definitions are excluded, making the values more reliable.

This release also refines the UI in Settings, appearance themes, lists, the Lamp Viewer, and more.

> [!IMPORTANT]
> **Rescan charts to update saved resource health to the new calculation basis.**
>
> Updating the app does not automatically recalculate saved resource counts using the new used-file basis. As needed, run `File scan` → `Rescan all charts` to update them.

> [!NOTE]
> **The first start after updating analyzes chart information again for your charts.**
>
> Because chart information analysis has been improved, owned charts not covered by the bundled metadata are analyzed again on the first start after updating. This can take several minutes or more depending on the number of charts. Meanwhile, `Complete chart information` in the status bar shows the number of processed and target charts. Deleting or moving charts, starting a preview, and other library operations cannot start until it finishes.

## Changes

### Installation Destination Estimation

- Removed `Estimate merge destination` and unified it with `Estimate install destination`. The same command can also estimate destinations for packages containing only charts you already own.
- Revised the estimation method so that main packages with many bundled resources and add-on charts with few bundled resources are evaluated in the same way.  When availability including bundled resources is equal, candidates that already contain more of the files used by the chart are now preferred.

### Installation

- Added an operation bar with `Estimate`, `Install`, and `Clear` above the chart list for the Pending root and individual packages. Select one or more charts to use the same destination estimation, installation to the estimated destination, and destination clearing actions as the context menu.
- Added `Install automatically when estimation after import determines a destination` under `Install` → `Automatic destination estimation` in Settings (OFF by default). When enabled, packages whose destinations were determined by the current import's automatic estimation are installed without a confirmation dialog after estimation completes successfully.
- Manually started estimation and packages already pending are excluded from automatic installation. Overwriting and source package deletion follow the existing settings.
- Revised how imported folders and archives are split into pending packages. A folder that bundles previews, background images, or other referenced files is treated as one package even when each chart uses different key sounds, and the bundled files are installed together. A folder of charts for different songs with no bundled files is split per chart, so each song is estimated and installed separately. Charts for the same song with no bundled files are grouped into one package when their titles and artists match after difficulty labels are ignored.
- Resource health and missing-resource warnings in the pending view now reflect the configured destination, or the first candidate when no destination is set, including bundled resources that would be installed there. The same basis applies to WAV, BGA, MOVIE, STAGEFILE, BACKBMP, and BANNER. Missing-resource warnings remain visible after setting a destination.
- Added `Audio missing after installation` / `Audio after installation unverified` warnings and highlighted rows when automatic destination selection is withheld because audio would remain missing or its completeness cannot be verified for the estimated group. These warnings can appear alongside `TITLE/ARTIST unconfirmed`. The reasons recorded during estimation remain after manual destination changes and are updated by a new estimation.
- `Chart properties` opened from the pending view uses the same resource placement basis and displays the verification basis and path.
- In LR2 mode, installing a song when no songs were recently added now shows LR2's new song folder without restarting the app.

### Resource Health

- `WAV`, `BGA`, and `MOVIE` now count files used by the chart rather than all `#WAV` and `#BMP` definitions. Unused definitions are excluded, and the same file is counted once even when referenced through multiple definition numbers.
- Percentages now use “existing files ÷ used files × 100,” without the previous additional penalty for missing files. For example, three existing files out of four used files gives 75%. A category with missing files is never displayed as 100%.
- Categories with no used files display `-`. Undefined reference numbers, such as those used for silent notes, do not count as missing files.

### Chart Properties

- Added `Chart properties` to the list context menu. Select one chart with a local file to open it, including charts inside pending packages.
- Inspect missing or unverifiable files, unused resource definitions, and undefined reference numbers in BMS, PMS, and bmson charts. Auxiliary images such as STAGEFILE, BACKBMP, and BANNER are also checked for missing files.
- BMS and PMS entries use command-style notation such as `#WAV01 file.wav`, while bmson entries use their native field names. Displayed text can be selected and copied.

### Playlist Import

- Combined the table list, built-in tables, and URL / file input in the `Import playlists` window, opened from the playlist tree root's context menu. Review tables selected from multiple sources in the list on the right and import them together.
- Added substring search by table name, symbol, category, or URL. Select or clear a category or all search matches, and hide registered URLs or candidates with existing names. Selections remain when changing tabs or search conditions.
- External candidates start with the categories immediately above table names collapsed. Long lists scroll smoothly even with categories expanded.
- Registered page and header URLs are checked again before import, avoiding duplicate loads. When items are skipped or fail, the result dialog shows separate counts for successful imports, duplicate URLs, duplicate names, and failures, along with samples of the affected items.

### Playlists

- When playlist properties, bulk edit, cell edits, BMT order moves, deletions, and similar operations cannot start because a reload or another operation is running, the operation is not performed and the warning "Another library operation is in progress." is shown once. Operations no longer end silently or appear as errors. Your input in an open window is kept, so you can run the operation again after the other one finishes.
- You can now save table properties even after URL completion is applied right after startup.
- In a table whose folder order is automatic, deleting a folder or renaming it to no name keeps the automatic ordering.
- Switching the display language no longer makes the built-in difficulty estimation and recommendation tables count as updated.
- When a beatoraja table URL cannot be fetched and the table is restored from the BMT cache, it now also uses the `Output folder defaults` setting.
- If a table saved by an older version with a hierarchical output name (for example `A\B`) now has an output location that is identical to, or nested with, another table's under the current single-name rule, startup and operations on other tables no longer fail. Only the overlapping tables stop outputting their LR2 folders, and a warning shows the table names and locations. Change the output name to resume output. Files in the old hierarchy are not moved or deleted automatically, so delete outdated folders yourself if they remain in the LR2 song selection screen.

### Settings

- Most settings are now saved and applied when each item is changed. Audio and score source selections also take effect once a valid combination is selected, without closing Settings. BMS directories, BMT output, and individual context menu actions still use confirmation buttons.
- Changing the operation mode or LR2 directory prompts for a restart. Individual changes to `song.db` and `config.xml` can be confirmed together under `Details` and applied with a single restart. Changes to the beatoraja directory take effect without restarting.
- Moved installation settings and confirmation messages from Advanced settings to `Install`. They are organized into six groups: installation destination, new folder naming, import and new installation, automatic destination estimation, overwriting and source package cleanup, and confirmation messages.
- Clarified setting labels and descriptions, including the distinction between automatic retrieval from URL1/URL2 cell clicks and installation after automatic estimation, the handling of overwrites and deletion, and which operations display confirmation messages.
- Improved the initial opening of Settings. Each page is prepared when first selected, and edits are preserved when switching pages.
- Settings now shows `Settings that need attention` at the bottom when a setting required to start using the library has a problem. Each "Page: reason" entry takes you to the field, and pages with problems are marked. When the startup check stops, the warning also lists the settings that need correction.
- Using scores, external images, BMT output, and external players are no longer saved until the required directory or file is available, and the reason is shown below the field.
- Enabling LR2 backup and optimization now opens a folder selection when no destination is set, and saves the option together with the destination. You can choose the destination before enabling the option, and turning it off keeps the destination.
- Audio devices are now loaded when opening the Audio page. You can continue editing, saving, or canceling other settings and switching pages while the list loads.
- Added `Startup sort cache preparation` to the initialization section in Advanced settings. Choose `None`, `Basic only (default)`, `Standard`, or `All`; changes apply from the next application start. Previous versions prepared the equivalent of `All`. Columns that are not prepared can still be sorted normally when selected.

- When another library operation is running, such as the information completion right after startup, choosing delete, move, auto-rename, or duplicate cleanup from the right-click menu, clearing history, rescanning all charts, "Resync LR2 song.db data" or changing the install destination in Settings, or starting a preview now shows "Another library operation is in progress." Previously these could be skipped without any message.

### Lamp Viewer

- Fixed the viewer opening far from the main window or off-screen when Windows display scaling differs between monitors.
- The viewer opens centered on the main window, with its position and size adjusted to fit the destination monitor's work area.
- Text measurements and labels inside graphs now update when moving the viewer between monitors with different scaling settings. Selection, scroll position, and display mode are preserved.
- The viewer can now be selected directly from the taskbar.

### Diagnostic Logs

- App and Windows versions, monitor configuration, and display scaling are now recorded in `log/application.log` at startup to help investigate display issues.
- Unexpected errors are now recorded in local logs without automatic transmission.
