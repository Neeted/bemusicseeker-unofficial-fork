  - プレイリスト単体を選んだ場合は、そのプレイリストに含まれる譜面だけへ絞り込み、FOLDER 列にはプレイリスト内フォルダ名を表示します。

  - 外部データを再取得し、プレイリスト名、記号、フォルダ接頭辞、フォルダ名を選択項目だけ初期値へ戻せるようにしました。フォルダ名の初期化は保存済み `output_dir` をクリアし、実効フォルダ名はプレイリスト名から生成されます。

  - カスタムフォルダ出力種別の一括適用は、ステータスバーに進捗を表示し、`.bmt` 出力の再生成や後段同期用の一時データ生成を行わずに処理します。
  - カスタムフォルダ出力後の LR2 `folder` table 同期は、汎用の LR2 `song.db` 同期と区別できるステータスバー文言で表示するようにしました。
  - カスタムフォルダ出力種別をすべて OFF にしたときは、削除済みの `.lr2folder` や物理ファイルが無い LR2 `folder` row も整理対象として扱います。
- beatoraja `.bmt` 出力で、未変更プレイリストの再生成を省略する差分更新を追加しました。
  - manifest には playlist の hash / 更新日時と実 `.bmt` の更新日時 / サイズを記録し、一致する場合は起動時などの全体確認でも table data projection と gzip 書き込みを省略します。
  - 旧 manifest の `contentHash` は廃止し、旧 manifest は所有ファイル cleanup 情報として読み取った後、新形式へ自然に置き換えます。
  - `BMT OUTPUT` の切り替えやプレイリスト削除では、影響する managed `.bmt` と BeMusicSeeker 管理 `tableURL` だけを操作するようにしました。
- LR2 カスタムフォルダ出力を拡張しました。
  - 通常出力先を複数登録できるようにし、プレイリストごとに `OUTPUT` 列 / プロパティ / 一括変更から出力先を選べるようにしました。追加出力先の表示名は出力先フォルダ名です。
  - `ルートフォルダにする` が ON のプレイリストでも `OUTPUT` の保存値は保持し、実効出力先は従来通りルートフォルダ出力先を優先します。
  - 追加通常出力先の削除時は、参照中プレイリストを通常出力先へ戻す確認を表示し、追加通常出力先のフォルダ名変更時は参照中プレイリストの保存値と出力先を移行するようにしました。
  - `OUTPUT` やルートフォルダ設定の変更でカスタムフォルダの出力先が変わった場合、変更前のプレイリスト出力フォルダはフォルダごと削除されます。
  - ユーザ定義出力にプレイリスト全体の `ALL` を追加し、クリア / DJ レベルは状態別サブフォルダ内に `ALL` とフォルダ別 `.lr2folder` を出力するようにしました。
  - RANDOM、BPM 順、BP 順、プレイ回数順、最終プレイ順の出力種別を追加しました。RANDOM は `ORDER BY random()` と `#MAXTRACKS 1` を使います。
  - RANDOM 版は通常フォルダ群の後ろにまとめて出力し、クリア状態別フォルダは `0 NO PLAY` から `7 P.A` までの番号付きフォルダ名にして、LR2 の TITLE 順表示でも状態順に並びやすくしました。
  - BPM 順は `chart_info.mainbpm`、BP 順は `score.minbp`、プレイ回数順は `score.playcount`、最終プレイ順は LR2 play history schema の `bms_lr2_last_play` を参照します。欠損や未プレイは末尾に並びます。
  - 既存プレイリストでは、保存済みの `ignore_folder_output` に新しい出力種別の除外 bit が無いため、新しい出力種別は出力対象になります。不要な場合はプロパティまたは一括変更で OFF にしてください。
  - 各プレイリスト出力フォルダ配下の `.lr2folder` は BeMusicSeeker 管理領域として整理し、通常出力先 / ルート出力先直下の管理外フォルダは触らないようにしました。
  - 起動時のカスタムフォルダ自動修復は軽量判定を使い、未変更時の全 `.lr2folder` command 監査を省略します。
  - カスタムフォルダ出力完了状態を記録し、未変更かつ物理 `.lr2folder` / 出力フォルダ / 格納先フォルダの mtime が変わっていないプレイリストは、次回起動時の playlist entry 読込 / projection / LR2 `folder` row lookup / 再 materialize 対象から外すようにしました。物理 `.lr2folder` の存在確認には起動時の列挙結果または出力先単位の grouped enumeration を使います。
  - 起動時の外部 `.lr2folder` 同期では、BeMusicSeeker 管理のプレイリスト出力フォルダ配下をディレクトリ単位で除外します。通常出力先 / ルート出力先直下の管理外フォルダは、引き続き外部カスタムフォルダとして扱います。
  - 起動時のカスタムフォルダ自動修復では、DB row の stale 判定を効率化しました。

## 不具合修正 / 安定性向上

- アプリ本体と同梱 DLL を x64 前提に整理しました。
  - `EverythingBridge_x64.dll` など x64 専用コンポーネントに合わせ、配布パッケージから x86 版のネイティブ DLL を除外しました。
  - `SevenZipExtractor.dll` と `OggVorbis.NET64.dll` は実行時に明示ロードせず、通常の managed 参照として読み込むようにしました。ダウンロード zip の Zone.Identifier が展開後ファイルへ残った場合でも、特定機能を使ったタイミングで managed DLL の `Assembly.LoadFrom` / `Assembly.LoadFile` が失敗する構造を避けています。
- 単体譜面をドライブルートや大量のサブディレクトリを含む場所から保留に入れた場合に、導入先推定の周辺リソース探索が広がりすぎ、進捗停止やメモリ使用量増大につながる可能性があった問題を修正しました。
  - 導入先推定用の source surface 探索に上限を設け、通常のBMSパッケージ範囲を大きく超える場合は探索を打ち切るようにしました。
  - 打ち切った場合は部分的な探索結果で推定せず、`探索上限` WARNING を表示して手動指定できる状態にします。
- 260文字を超えるような長いパスの譜面ファイルを、可能な限り通常の譜面として読み込めるようにしました。
  - BeMusicSeeker 側で読み取れる長パス譜面は DB に登録し、LR2 で扱えない可能性がある場合は従来の `LR2パス長超過` WARNING として表示します。
  - 読み取り不能な譜面があっても初期化中にファイルごとのエラーダイアログを出さず、他の譜面の登録を継続して診断ログへ集約するようにしました。
  - 内蔵プレーヤー、譜面ビューア登録、Explorer / 関連付けで開く、音声ファイル変換、導入、移動、削除、拡張子変更、スマート上書きなどの主要なファイル操作でも、BeMusicSeeker 内部の存在確認やコピー/移動/削除を長パス対応にしました。
  - root scan の fallback 列挙、beatoraja `.bmt` 出力、LR2 カスタムフォルダ出力、LR2 バックアップでも、BeMusicSeeker 内部のファイル読み書き / 列挙 / 削除 / コピーを長パス対応にしました。
  - 外部アプリ自体が長パスを受け付けない場合でも、BeMusicSeeker 側ではファイルが存在しないものとして扱ったり、成功扱いにしたりしないようにしました。
- アプリケーション終了時の処理を安全にしました。
  - DB 処理、譜面/メタデータのファイル IO、起動後バックグラウンド処理が残っている場合は、整合性を保てる区切りまで待ってから終了するようにしました。
  - 従来は即時終了していたタイミングでも、終了前に短い待機が発生する場合があります。データベースや出力ファイルを安全に閉じるための待機ですのでご了承ください。
  - SQLite の prepared statement が例外時にも確実に解放されるようにし、終了時に DB を閉じられない可能性を下げました。
- LR2 連携モードの `song.db` 同期で、既存データに実ファイルと大文字小文字の表記が異なる path 行が含まれていると同期に失敗する場合があった問題を修正しました。
  - 起動時のファイル確認結果を正として扱い、存在しない古い path 行を整理してから同期できるようにしました。
  - 従来版 BeMusicSeeker や LR2 で作成された `song.db` から引き継いだ環境でも、同じ起動処理の中で自然に復旧しやすくなります。
- 上部内蔵プレイヤーの曲名表示と一覧選択の同期を改善しました。
  - サブタイトル付き譜面で、上部プレイヤーの曲名にサブタイトルが重複して表示される場合があった問題を修正しました。
  - 上部プレイヤーの次/前の曲操作や動画プレイヤーとの切り替え後も、再生中の譜面名が古い表示のまま残らないようにしました。
  - 曲名、サブタイトル、アーティストの表示状態を ViewModel 側で管理し、一覧選択、BMS 再生、動画表示の切り替えで表示元が混線しにくい構造にしました。

# English v2.1.0.0

## Changes

### Important: Custom Folder Output Destinations

⚠️This section concerns the initial setup process for first-time users of this app. It's not particularly relevant for those who are already using the app.

- In LR2-linked mode, the `Normal output destination` is now specified directly as a BeMusicSeeker setting instead of being chosen from LR2 `<jukebox>` BMS roots.
  - The normal output destination, additional normal outputs, and root-folder output destination are treated as BeMusicSeeker-managed custom-folder output destinations. Required `<jukebox>` entries are synchronized on save and repaired at startup.
  - The settings dialog excludes BeMusicSeeker-managed custom-folder output destinations from the BMS directory list and new install destination choices.

### Automatic Updates

- Added automatic update support from the startup update notification.
  - Updating to v2.1.0.0 itself still requires the usual manual overwrite: download the release zip, extract it, and overwrite the existing portable app files.
  - After you are running v2.1.0.0 or later, future releases such as v2.2.0.0 can be applied from the startup update dialog by selecting an update package.
  - The update dialog can offer both the app-only package and the package bundled with analyzed metadata. The metadata bundle provides the latest analyzed metadata that can be shown in playlists even for charts you do not currently have.

### Logging

- INFO-level logs are now written during normal startup.
  - `application.log` and `install-performance.log` are written under `log/` instead of next to the executable.
  - Large log files are rotated under `log/archive/`.
  - Log files are written as UTF-8 without BOM.

### Play Log

- Added a `Play Log` tree view for browsing LR2 / beatoraja play history.
  - For LR2, plays are recorded after installing BeMusicSeeker history tables, indexes, and triggers into the selected player's `score.db` from the settings dialog.
  - From the `Backup` tab in the settings dialog, you can remove only the LR2 play-log triggers to stop future recording, or remove the history tables as well.
  - For beatoraja, the view reads best-update history from `scorelog.db` in the player folder selected in beatoraja integration. Plays without updates, including interrupted plays, do not become list rows.

## Bug Fixes / Stability

- Consolidated the app and bundled DLLs around x64.
  - x86 native DLLs are no longer included in the release package, matching x64-only components such as `EverythingBridge_x64.dll`.
  - `SevenZipExtractor.dll` and `OggVorbis.NET64.dll` are now loaded as normal managed references instead of explicit runtime loads. This avoids the previous `Assembly.LoadFrom` / `Assembly.LoadFile` path that could fail only when a feature was first used if Zone.Identifier metadata remained on extracted files.
- Fixed a case where adding a single chart from a drive root or another directory with many subdirectories could make install-destination estimation scan far too much surrounding content, potentially stalling progress and growing memory usage.
  - Source-surface scanning for install estimation is now bounded and stops when the source is far larger than a normal BMS package.
  - When the scan is stopped, BeMusicSeeker does not estimate from partial results; it shows a `scan limit` warning so the destination can be set manually.
- Made very long chart paths usable in more BeMusicSeeker operations.
  - Charts that BeMusicSeeker can read are registered normally, while charts that may exceed LR2's legacy path limits are still shown with the `LR2 path too long` warning.
  - Startup scan no longer shows one error dialog per unreadable chart file; unreadable files are aggregated into diagnostics while other charts continue to load.
  - Built-in playback, chart-viewer registration, Explorer / file-association open actions, audio conversion, install, move, delete, extension rename, and smart overwrite now use long-path-aware existence checks and internal copy/move/delete operations.
  - Root scan fallback enumeration, beatoraja `.bmt` output, LR2 custom folder output, and LR2 backups also use long-path-aware internal read/write, enumeration, delete, and copy operations.
  - If an external app itself cannot accept a long path, BeMusicSeeker does not reinterpret that as a missing internal file or a successful operation.
- Made application shutdown safer.
  - When database work, chart/metadata file IO, or startup background work is still running, the app now waits until a safer consistency boundary before closing.
  - In some cases, closing the app may now wait briefly where previous versions exited immediately. This wait is intentional so the database and output files can be closed safely.
  - Prepared SQLite statements are now finalized even when an exception occurs, reducing the chance of a database close failure during shutdown.
- Fixed a case where LR2-linked `song.db` sync could fail when existing rows contained paths whose letter casing no longer matched the actual files.
  - Startup file checks are now treated as the source of truth, and stale path rows that no longer exist are cleaned up before sync continues.
  - This makes environments inherited from older BeMusicSeeker versions or LR2-created `song.db` files more likely to recover naturally during normal startup.
- Improved synchronization between the top built-in player title display and the selected list row.
  - Fixed duplicate subtitles in the top player title for charts that have a subtitle.
  - Fixed cases where the displayed title could remain on an older chart after using next/previous in the top player or after switching back from the movie player.
  - Title, subtitle, and artist header state is now managed by the ViewModel so list selection, BMS playback, and movie display changes are less likely to mix stale display sources.
