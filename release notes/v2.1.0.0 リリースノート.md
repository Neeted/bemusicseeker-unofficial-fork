# 日本語 v2.1.0.0

## 変更点

### インストール / 保留パッケージ

- 保留画面から推定導入先へインストールした直後の新規画面で、保留中の `INSTL DST` が残らないようにしました。
  - `INSTL DST` は保留パッケージの導入先を決めるための一時状態として扱い、導入後の場所は `PATH` で確認する方針に揃えました。
  - 保留中の導入先推定状態、導入先 metadata、候補サジェストは、導入後の新規表示へ引き継がれません。
- 新規インストールで、同じ譜面を含む複数のパッケージを同時に投入した場合、導入に成功した先行パッケージと重複する後続パッケージを `既に導入済み` WARNING 付きで保留へ残すようにしました。
  - 保留画面から推定導入先へインストールする場合と同じく、同一バッチ内で先に導入対象になった譜面 hash を導入済み相当として扱います。

### プレイリスト

- プレイリストサマリー行をドラッグしたときに、プレイリストツリーが譜面追加のドロップ先として反応しないようにしました。
  - プレイリストへ追加できる譜面行またはプレイリスト詳細行だけをドロップ対象として扱います。
  - 追加対象が空のドロップで、プレイリストの `last_update` や revision が更新されないようにしました。
- プレイリストサマリーで、beatoraja `.bmt` 出力順と出力対象を制御できるようにしました。
  - `BMT SORT` 列を追加し、`config_sys.json` に登録する BeMusicSeeker 管理 `.bmt` URL の順番として使うようにしました。
  - `BMT SORT` 昇順表示中は、サマリー行のドラッグアンドドロップ、または右クリックメニューの先頭/末尾移動で順番を変更できます。フィルター中の並べ替えでは非表示行の相対位置を保持します。
  - `BMT OUTPUT` 列を追加し、チェックを外したプレイリストは `.bmt` 出力と BeMusicSeeker 管理 `tableURL` から除外するようにしました。
  - `BMT SORT` だけを変更した場合は `.bmt` 本体を再生成せず、`config_sys.json` の URL 順だけを同期します。

# English v2.1.0.0

## Changes

### Install / Pending Packages

- Newly installed rows no longer keep the pending `INSTL DST` value after installing pending packages to an estimated destination.
  - `INSTL DST` is treated as temporary pending-package state. After installation, the installed location should be checked with the `PATH` column.
- New install now keeps later packages that duplicate a successfully installed earlier package pending with an `Already Installed` warning when multiple packages containing the same chart are added in one batch.
  - This matches the duplicate handling used when installing pending packages to estimated destinations.

### Playlist

- Playlist tree nodes no longer react as chart-add drop targets when dragging rows from the Playlist Summary view.
  - Only chart rows and playlist-detail rows that can be added to a playlist are accepted by the playlist tree.
  - Empty playlist-add drops no longer update playlist `last_update` or revision metadata.
- Playlist Summary can now control beatoraja `.bmt` output order and per-playlist output.
  - Added `BMT SORT`; BeMusicSeeker-managed `.bmt` URLs in `config_sys.json` are registered in this order.
  - When sorted by `BMT SORT` ascending, summary rows can be reordered by drag and drop or moved to the top/bottom from the context menu. Hidden rows keep their relative positions while filters are active.
  - Added `BMT OUTPUT`; disabling it excludes that playlist from `.bmt` output and managed `tableURL` registration.
  - Changing only `BMT SORT` synchronizes URL order without regenerating `.bmt` files.
