# 日本語 v2.1.0.0

## 変更点

### 重要: カスタムフォルダ出力先の設定

- LR2 連携モードの `通常出力先` は、LR2 の `<jukebox>` 登録済み BMS ディレクトリから選ぶのではなく、BeMusicSeeker の設定値として直接指定する方式に変更しました。
  - 通常出力先、追加通常出力先、ルートフォルダ出力先は BeMusicSeeker 管理のカスタムフォルダ出力先として扱い、必要な `<jukebox>` 登録は保存時や起動時修復で同期します。
  - 設定画面の BMS ディレクトリ一覧と新規インストール先候補は、BeMusicSeeker 管理外の BMS ディレクトリを表示します。

### プレイログ

- LR2 / beatoraja のプレイ履歴を `プレイログ` ツリーから一覧表示できるようにしました。
  - LR2 では、設定画面から選択中プレイヤーの `score.db` に BeMusicSeeker 用の履歴 table / index / trigger を導入した後のプレイが記録対象になります。
  - 設定画面の `バックアップ` タブから、LR2 プレイログの trigger のみを削除して今後の記録を止めるか、履歴 table も含めて削除できるようにしました。
  - beatoraja では、beatoraja 連携で選択しているプレイヤーフォルダの `scorelog.db` から best 更新履歴を読み取ります。更新が無かったプレイや途中終了したプレイは一覧行にはなりません。
  - SCORE、BEST DJ、BEST RATE、BP、COMBO、CLEAR の更新遷移、TYPE、OPTION / OP HISTORY、判定数、演奏時間などを一覧で確認できます。beatoraja の BEST DJ / BEST RATE はスコア表示用に読み込んだノーツ数を使って計算します。beatoraja の更新履歴行では、LR2 と同じ粒度で取れない実プレイ判定や OPTION は表示しません。
  - 一覧上部に、判定数、プレイ数、演奏時間、各種更新数、CLEAR 更新内訳をまとめた専用サマリー行を追加しました。
  - beatoraja の判定数、プレイ数、演奏時間は、プレイヤーの日別累計を使い、選択中の画面期間に対する値としてサマリー行に表示します。beatoraja の単曲行の演奏時間は引き続き空欄です。
- プレイログ右上のドロップダウンメニューで、表示対象と FOLDER 列の表示方法を切り替えられるようにしました。
  - `プリセット: <名前>` は、設定画面の `プレイログ FOLDER 表示プリセット` で選んだプレイリストに含まれる譜面だけへ絞り込み、FOLDER 列には各プレイリストの表示記号とレベルを表示します。
  - `FOLDER: <名前>` は行の絞り込みは行わず、期間ツリーと検索欄で選ばれた履歴を残したまま、FOLDER 列だけをそのプリセット基準で表示します。プリセット外の譜面は FOLDER が空欄になります。
  - プレイリスト単体を選んだ場合は、そのプレイリストに含まれる譜面だけへ絞り込み、FOLDER 列にはプレイリスト内フォルダ名を表示します。
- 設定画面の `プレイリスト` タブに `プレイログ FOLDER 表示プリセット` を追加しました。
  - `追加` / `編集` から別ウィンドウを開き、プリセット名と対象プレイリストを複数選択できます。
- プレイログの右クリックメニューから、MD5 が解決できる行は BMS-IR、SHA-256 が解決できる行は Mocha / MinIR、所持譜面へ解決できる行は Explorer / 譜面ビューアを開けるようにしました。

### インストール / 保留パッケージ

- 保留画面から推定導入先へインストールした直後の新規画面で、保留中の `INSTL DST` が残らないように修正しました。
  - `INSTL DST` は保留パッケージの導入先を決めるための一時状態として扱い、導入後の場所は `PATH` で確認する方針に揃えました。
  - 保留中の導入先推定状態、導入先 metadata、候補サジェストは、導入後の新規表示へ引き継がれません。
- 新規インストールで、同じ譜面を含む複数のパッケージを同時に投入した場合、導入に成功した先行パッケージと重複する後続パッケージを `既に導入済み` WARNING 付きで保留へ残すようにしました。
  - 保留画面から推定導入先へインストールする場合と同じく、同一バッチ内で先に導入対象になった譜面 hash を導入済み相当として扱います。
- 既所持譜面が混じる保留パッケージの導入先推定で、既所持先が複数に分かれた場合の判定を改善しました。
  - hash 多数決、リソース / メタデータ評価、候補フォルダ内の譜面数を順に使い、それでも同等で設定が ON かつ TITLE / ARTIST が高一致なら第1候補を自動設定します。
  - 第1候補を自動設定した場合も、複数候補があったことを示す WARNING と候補サジェストを残すようにしました。

### プレイリスト

- プレイリストサマリー行をドラッグしたときに、プレイリストツリーが譜面追加のドロップ先として反応しないように修正しました。
  - プレイリストへ追加できる譜面行またはプレイリスト詳細行だけをドロップ対象として扱います。
  - 追加対象が空のドロップでは、プレイリストの `last_update` や revision を更新しません。
- プレイリストサマリーで、beatoraja `.bmt` 出力順と出力対象を制御できるようにしました。
  - `BMT SORT` 列を追加し、`config_sys.json` に登録する BeMusicSeeker 管理 `.bmt` URL の順番として使うようにしました。
  - `BMT SORT` 昇順表示中は、サマリー行のドラッグアンドドロップ、または右クリックメニューの先頭/末尾移動で順番を変更できます。フィルター中の並べ替えでは非表示行の相対位置を保持します。
  - サマリー行のドラッグ中に挿入先を太線で表示し、ドロップ後の選択行が移動したプレイリストへ追従するようにしました。
  - `BMT OUTPUT` 列を追加し、チェックを外したプレイリストは `.bmt` 出力と BeMusicSeeker 管理 `tableURL` から除外するようにしました。
  - `BMT SORT` だけを変更した場合は `.bmt` 本体を再生成せず、`config_sys.json` の URL 順だけを同期します。
- プレイリストサマリーの右クリックメニューに `一括変更...` を追加しました。
  - 選択行に対して、カスタムフォルダ出力種別、`OUTPUT`、ルートフォルダ、外部同期、`.bmt` 出力をセクション単位で一括適用できます。
  - 外部データを再取得し、プレイリスト名、記号、フォルダ接頭辞、フォルダ名を選択項目だけ初期値へ戻せるようにしました。フォルダ名の初期化は保存済み `output_dir` をクリアし、実効フォルダ名はプレイリスト名から生成されます。
  - ダイアログ全体の OK は置かず、各セクションの適用ボタンを押した項目だけが更新されます。
  - カスタムフォルダ出力種別の一括適用は、ステータスバーに進捗を表示し、`.bmt` 出力の再生成や後段同期用の一時データ生成を行わずに処理します。
  - カスタムフォルダ出力後の LR2 `folder` table 同期は、汎用の LR2 `song.db` 同期と区別できるステータスバー文言で表示するようにしました。
  - カスタムフォルダ出力種別をすべて OFF にしたときは、削除済みの `.lr2folder` や物理ファイルが無い LR2 `folder` row も整理対象として扱います。
- beatoraja `.bmt` 出力で、未変更プレイリストの再生成を省略する差分更新を追加しました。
  - manifest には playlist の hash / 更新日時と実 `.bmt` の更新日時 / サイズを記録し、一致する場合は起動時などの全体確認でも table data projection と gzip 書き込みを省略します。
  - 旧 manifest の `contentHash` は廃止し、旧 manifest は所有ファイル cleanup 情報として読み取った後、新形式へ自然に置き換えます。
  - `BMT OUTPUT` の切り替えやプレイリスト削除では、影響する managed `.bmt` と BeMusicSeeker 管理 `tableURL` だけを操作するようにしました。
- LR2 カスタムフォルダ出力を拡張しました。
  - 通常出力先を複数登録できるようにし、プレイリストごとに `OUTPUT` 列 / プロパティ / 一括変更から出力先を選べるようにしました。追加出力先の表示名は出力先フォルダ名です。
  - `ルートフォルダにする` が ON のプレイリストでも `OUTPUT` の保存値は保持し、実効出力先は従来通りルートフォルダ出力先を優先します。
  - 追加通常出力先の削除時は、参照中プレイリストを通常出力先へ戻す確認を表示し、追加通常出力先のフォルダ名変更時は参照中プレイリストの保存値と出力先を移行するようにしました。
  - `OUTPUT` やルートフォルダ設定の変更でカスタムフォルダの出力先が変わった場合、変更前のプレイリスト出力フォルダはフォルダごと削除されます。
  - ユーザ定義出力にプレイリスト全体の `ALL` を追加し、クリア / DJ レベルは状態別サブフォルダ内に `ALL` とフォルダ別 `.lr2folder` を出力するようにしました。
  - RANDOM、BPM 順、BP 順、プレイ回数順、最終プレイ順の出力種別を追加しました。RANDOM は `ORDER BY random()` と `#MAXTRACKS 1` を使います。
  - RANDOM 版は通常フォルダ群の後ろにまとめて出力し、クリア状態別フォルダは `0 NO PLAY` から `7 P.A` までの番号付きフォルダ名にして、LR2 の TITLE 順表示でも状態順に並びやすくしました。
  - BPM 順は `chart_info.mainbpm`、BP 順は `score.minbp`、プレイ回数順は `score.playcount`、最終プレイ順は LR2 play history schema の `bms_lr2_last_play` を参照します。欠損や未プレイは末尾に並びます。
  - 既存プレイリストでは、保存済みの `ignore_folder_output` に新しい出力種別の除外 bit が無いため、新しい出力種別は出力対象になります。不要な場合はプロパティまたは一括変更で OFF にしてください。
  - 各プレイリスト出力フォルダ配下の `.lr2folder` は BeMusicSeeker 管理領域として整理し、通常出力先 / ルート出力先直下の管理外フォルダは触らないようにしました。
  - 起動時のカスタムフォルダ自動修復は軽量判定を使い、未変更時の全 `.lr2folder` command 監査を省略します。
  - カスタムフォルダ出力完了状態を記録し、未変更かつ物理 `.lr2folder` / 出力フォルダ / 格納先フォルダの mtime が変わっていないプレイリストは、次回起動時の playlist entry 読込 / projection / LR2 `folder` row lookup / 再 materialize 対象から外すようにしました。物理 `.lr2folder` の存在確認には起動時の列挙結果または出力先単位の grouped enumeration を使います。
  - 起動時の外部 `.lr2folder` 同期では、BeMusicSeeker 管理のプレイリスト出力フォルダ配下をディレクトリ単位で除外します。通常出力先 / ルート出力先直下の管理外フォルダは、引き続き外部カスタムフォルダとして扱います。
  - 起動時のカスタムフォルダ自動修復では、DB row の stale 判定を効率化しました。

# English v2.1.0.0

## Changes

### Important: Custom Folder Output Destinations

- In LR2-linked mode, the `Normal output destination` is now specified directly as a BeMusicSeeker setting instead of being chosen from LR2 `<jukebox>` BMS roots.
  - The normal output destination, additional normal outputs, and root-folder output destination are treated as BeMusicSeeker-managed custom-folder output destinations. Required `<jukebox>` entries are synchronized on save and repaired at startup.
  - The settings dialog excludes BeMusicSeeker-managed custom-folder output destinations from the BMS directory list and new install destination choices.

### Play Log

- Added a `Play Log` tree view for browsing LR2 / beatoraja play history.
  - For LR2, plays are recorded after installing BeMusicSeeker history tables, indexes, and triggers into the selected player's `score.db` from the settings dialog.
  - From the `Backup` tab in the settings dialog, you can remove only the LR2 play-log triggers to stop future recording, or remove the history tables as well.
  - For beatoraja, the view reads best-update history from `scorelog.db` in the player folder selected in beatoraja integration. Plays without updates, including interrupted plays, do not become list rows.
  - The list shows update transitions for SCORE, BEST DJ, BEST RATE, BP, COMBO, and CLEAR, along with TYPE, OPTION / OP HISTORY, judge counts, playtime, and related values. beatoraja BEST DJ / BEST RATE are calculated using the note count already loaded for score display. For beatoraja update-history rows, actual-play judges and OPTION values that cannot be obtained at LR2 granularity are not shown.
  - Added a dedicated summary row above the list for judge count, play count, playtime, update counts, and CLEAR update breakdowns.
  - beatoraja judge count, play count, and playtime are now shown in the summary row for the selected screen period by using the player's daily totals. Individual beatoraja rows still leave playtime blank.
- The drop-down menu at the top-right of the Play Log view can switch both the display target and how the FOLDER column is projected.
  - `Preset: <name>` filters rows to charts included in the playlists selected in `Play Log FOLDER Display Presets`, and the FOLDER column shows each playlist symbol plus level.
  - `FOLDER: <name>` does not filter rows; it keeps rows selected by the period tree and search box, and only projects the FOLDER column using that preset. Charts outside the preset have an empty FOLDER value.
  - Selecting a single playlist filters rows to charts in that playlist and shows the playlist folder name in the FOLDER column.
- Added `Play Log FOLDER Display Presets` to the `Playlist` tab in the settings dialog.
  - `Add` / `Edit` opens a separate window where you can enter a preset name and select multiple target playlists.
- The Play Log context menu can now open BMS-IR for rows with a resolved MD5, Mocha / MinIR for rows with a resolved SHA-256, and locally resolved charts in Explorer / the chart viewer.

### Install / Pending Packages

- Fixed newly installed rows keeping the pending `INSTL DST` value after installing pending packages to an estimated destination.
  - `INSTL DST` is treated as temporary pending-package state. After installation, the installed location should be checked with the `PATH` column.
  - Pending destination-estimation state, destination metadata, and candidate suggestions are not carried over to the New view after installation.
- New install now keeps later packages that duplicate a successfully installed earlier package pending with an `Already Installed` warning when multiple packages containing the same chart are added in one batch.
  - As with installing pending packages to estimated destinations, chart hashes installed earlier in the same batch are treated as already installed.
- Improved install-destination estimation for pending packages that mix already-owned and missing charts when the owned charts resolve to multiple destinations.
  - The resolver now checks hash majority, resource / metadata evaluation, and candidate folder chart counts before falling back to first-candidate auto-apply when the setting is enabled and TITLE / ARTIST evidence is strong.
  - When the first candidate is auto-applied, a warning and destination suggestions are still kept so the ambiguous candidates remain visible.

### Playlist

- Fixed playlist tree nodes reacting as chart-add drop targets when dragging rows from the Playlist Summary view.
  - Only chart rows and playlist-detail rows that can be added to a playlist are accepted by the playlist tree.
  - Empty playlist-add drops do not update playlist `last_update` or revision metadata.
- Playlist Summary can now control beatoraja `.bmt` output order and per-playlist output.
  - Added `BMT SORT`; BeMusicSeeker-managed `.bmt` URLs in `config_sys.json` are registered in this order.
  - When sorted by `BMT SORT` ascending, summary rows can be reordered by drag and drop or moved to the top/bottom from the context menu. Hidden rows keep their relative positions while filters are active.
  - Summary row drag and drop now shows a bold insertion marker, and the selection follows the moved playlists after dropping.
  - Added `BMT OUTPUT`; disabling it excludes that playlist from `.bmt` output and managed `tableURL` registration.
  - Changing only `BMT SORT` synchronizes URL order without regenerating `.bmt` files.
- Added `Bulk edit...` to the Playlist Summary context menu.
  - Custom folder output types, `OUTPUT`, root folder, external sync, and `.bmt` output can be applied to selected rows by section.
  - Selected rows can now reload external data and reset only the chosen playlist properties: name, symbol, folder prefix, and folder name. Resetting the folder name clears the saved `output_dir`; the effective folder name is generated from the playlist name.
  - The dialog has no global OK; only the apply button in each section updates that setting.
  - Bulk custom folder output changes show status bar progress and skip `.bmt` regeneration and temporary data generation for later sync stages.
  - The LR2 `folder` table sync after custom-folder output now uses status-bar text distinct from the general LR2 `song.db` sync.
  - Disabling all custom-folder output types also treats already-removed `.lr2folder` files and LR2 `folder` rows without physical files as cleanup targets.
- beatoraja `.bmt` output now skips regeneration for unchanged playlists.
  - The manifest records playlist hashes/update time and actual `.bmt` timestamp/size, and matching entries skip table data projection and gzip writing even during full checks such as startup.
  - The old manifest `contentHash` field has been removed. Old manifests are still read as owned-file cleanup information, then naturally rewritten in the new format.
  - `BMT OUTPUT` changes and playlist deletion now operate only on the affected managed `.bmt` files and BeMusicSeeker-managed `tableURL` entries.
- LR2 custom folder output has been expanded.
  - Multiple normal output destinations can now be registered, and each playlist can choose its destination from the `OUTPUT` column, playlist properties, or bulk edit. The display name is the output folder name.
  - Playlists with `Make root folder` enabled keep their saved `OUTPUT` value, while the effective output destination still prioritizes the root-folder output destination.
  - Removing an additional normal output confirms that playlists using it will return to the normal output destination; renaming an additional normal output migrates referenced playlists and their output destination.
  - When `OUTPUT` or root-folder settings change a custom-folder output destination, the previous playlist output folder is deleted as a whole folder.
  - User-defined output now includes an `ALL` folder for the whole playlist. Clear and DJ level output now create status subfolders containing both `ALL` and per-folder `.lr2folder` files.
  - Added Random, BPM sort, BP sort, Play count sort, and Last play sort output types. Random output uses `ORDER BY random()` with `#MAXTRACKS 1`.
  - RANDOM variants are grouped after the normal folders, and clear-status folders are named from `0 NO PLAY` through `7 P.A` so LR2's TITLE sort keeps them in status order.
  - BPM sort uses `chart_info.mainbpm`, BP sort uses `score.minbp`, Play count sort uses `score.playcount`, and Last play sort uses `bms_lr2_last_play` from the LR2 play history schema. Missing or unplayed rows are placed last.
  - Existing playlists do not have ignore bits for newly added output types in `ignore_folder_output`, so newly added output types are output by default. Turn them off from playlist properties or bulk edit if they are not needed.
  - `.lr2folder` files under each playlist output folder are treated as BeMusicSeeker-managed output, while unmanaged folders directly under the normal/root output destination are left untouched.
  - Startup custom-folder auto-repair uses lightweight checks and skips full `.lr2folder` command auditing when nothing has changed.
  - Completed custom-folder output state is recorded so unchanged playlists whose physical `.lr2folder` / output-folder / container-folder mtimes have not changed are skipped from playlist entry loading, projection, LR2 `folder` row lookup, and rematerialization on the next startup. Physical `.lr2folder` presence checks use the startup enumeration result or grouped enumeration for the output directories.
  - Startup external `.lr2folder` sync excludes BeMusicSeeker-managed playlist output folders by directory. Unmanaged folders directly under the normal/root output destination remain external custom folders.
  - Startup custom-folder auto-repair uses a more efficient stale-row check.
