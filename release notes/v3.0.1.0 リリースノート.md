# 日本語

## 修正内容

v3.0.0.0 で LR2 連携を初めて設定した際に、LR2 で扱えない文字（`ê` など）を含むフォルダーや `.lr2folder` があると、song.db の同期全体が失敗する問題を修正しました（[Issue #11](https://github.com/Neeted/bemusicseeker-unofficial-fork/issues/11)）。

この不具合は **v3.0.0.0 で導入されたもので、影響するバージョンは v3.0.0.0 のみ**です。v2.1.6.0 以前から存在していた問題ではありません。

- **影響を受ける方**：v3.0.0.0 で初めて LR2 連携で利用を開始した方、または BeMusicSeeker とまだ連携していない song.db を指定し、初回実行相当の状態で起動した方で、上記の非対応文字を含むパスがある場合。
- **影響を受けない方**：v2.1.6.0 以前から、同じ song.db で LR2 連携を継続利用していた方。

v3.0.1.0 では、非対応パスが混在していても、ほかの対象の同期を完了できる従来の動作に戻しました。非対応パスにある譜面を BeMusicSeeker で管理し、「LR2互換性警告」から確認できる点も従来どおりです。LR2 自体が扱えるパスの範囲に変更はありません。

# English

## Fixes

Fixed an issue where setting up LR2 integration for the first time in v3.0.0.0 caused the entire song.db synchronization to fail if folder or `.lr2folder` paths contained characters unsupported by LR2 (such as `ê`) ([Issue #11](https://github.com/Neeted/bemusicseeker-unofficial-fork/issues/11)).

This regression was **introduced in v3.0.0.0 and affects only v3.0.0.0**. It was not a pre-existing issue in v2.1.6.0 or earlier.

- **Affected users**: Those who first started using LR2 integration in v3.0.0.0, or selected a song.db that had not previously been linked to BeMusicSeeker and started the app in an equivalent first-run state, with paths containing the unsupported characters described above.
- **Unaffected users**: Those who had continued using LR2 integration with the same song.db since v2.1.6.0 or earlier.

v3.0.1.0 restores the previous behavior: synchronization can complete for the other items even when unsupported paths are present. As before, charts at unsupported paths remain managed by BeMusicSeeker and can be found under “LR2 compatibility warnings.” The paths supported by LR2 itself have not changed.
