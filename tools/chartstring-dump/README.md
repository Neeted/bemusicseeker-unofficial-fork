# chartstring-dump

Reference diagnostic tool for `chart_info.charthash` compatibility work.

The tool compiles against the local `songdata-updater` sources and
`lib/jbms-parser.jar`, but does not modify either reference repository.
It decodes each chart with jbms-parser, applies `BMSPlayerRule.validate(model)`,
and writes the hash of `model.toChartString()` as JSONL.

Example:

```powershell
& .\tools\chartstring-dump\run.ps1 --list paths.txt --chart-string-dir artifacts\chartstring-dump\strings
```

If Java is not on `PATH`, set `-JavaHome` or `JAVA_HOME`.

For beatoraja / songdata-updater production DB parity, run the dump with the
same runtime as beatoraja. Current beatoraja bundles JDK 21 under
`D:\beatoraja\jre`, and `Double.toString(double)` output differs from JDK 17
for some chart string values such as very large `TOTAL`.

```powershell
& .\tools\chartstring-dump\run.ps1 `
  -JavaHome C:\Users\kazuk\.jdks\ms-17.0.16 `
  -JavaRuntimeHome D:\beatoraja\jre `
  --list paths.txt `
  --chart-string-dir artifacts\chartstring-dump\jdk21-strings
```

`-JavaHome` is used for `javac`; `-JavaRuntimeHome` is used for the actual
dump execution. Use `-JavaRuntimeHome D:\beatoraja\jre` when checking hashes
against DB rows generated by the bundled beatoraja runtime.

## 固定参照によるsmoke検査

今後のsmoke検査で使用する公開source・jarのhashとJDKの版・配布元は [reference-manifest.json](reference-manifest.json) に固定します。以前のローカル参照と同一版の復元ではありません。sourceとjar、compile用JDK 17.0.16+8、runtime用JDK 21.0.8+9を展開し、配布物のhashをmanifestと照合してから、次の3つの絶対pathを持つ準備JSONを作ります。

```json
{
  "songDataUpdaterRoot": "C:/references/songdata-updater",
  "javaHome": "C:/references/jdk-17.0.16+8",
  "javaRuntimeHome": "C:/references/jdk-21.0.8+9"
}
```

Compatibility moduleの `Suite.chartstring-java` は `BMS_TEST_CHARTSTRING_REFERENCE_JSON` に指定された準備JSONを読みます。実javac/javaの成功、JSONの `ok:true` と `charthash` の存在を確認します。固定hashとのparityはこのsmokeの保証に含めません。準備物のhash照合と、実際のcompile・実行能力の確認は別に行います。

`-OutputDir` は絶対pathも受け付けます。生成classesは常にその下の `classes` に置き、既定値では従来の `artifacts/chartstring-dump/classes` を使います。テストはケース専有の絶対出力先を渡します。システムのJava導入やPATH変更は不要です。
